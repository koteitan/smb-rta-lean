# 横の土管から地上への切り替え

**主張.** マリオが横の土管に入ったフレームから、ちょうど 282 フレーム後に地上で操作できます。本物の走りの入り口の状態 1 つについて、全部のフレームの全部の入力で示します（Start と Select は除く）。仮定が 1 つあります（`GMerge`）。ほかの入り口の状態については、入力なしで、仮定なしで示します。ほかのピクセル、端数、速さ、大きいマリオ、3 つのピクセルでの本物の入り方、連続する 21 フレームでの本物の入り方です。例外が 1 つあります。入るフレームの終わりで `x` が 16 の倍数だと 378 フレームかかります。ここで示したどの状態も 282 フレームより短くなりません。この例外は、歩いても落ちても口には届きません（下を見てください。この理由づけは Lean にしていません）。

`m₀` は 1-1 の最初のマシンです。`run(m, w)` は入力 `w` の本物のフレームを動かした後のマシン、`frame(m, i)` はその 1 フレームです。`ctl(m)` は `controllable` です。`0^k` は入力なしの `k` フレームです。`I` は 64 通りの入力です。A、B、上、下、左、右の全部の組み合わせで、反対向きの同時押しも含みます。`P` は本物の走りで入る 1 フレーム前のマシン、`E = frame(P, 右)` は入るフレームの終わりのマシンです。`x₀` は右側が口に入る最初の `x` です（[横の土管に入る](SidePipe-ja.md)）。`z` は口のピクセルのうち 16 の倍数のものです。`P[x]` は、入るフレームの終わりが `x` になるように `P` の `x` を書き換えたものです。`E_x = frame(P[x], 右)` です。`Exact(m, n)` は `∀ k, 1 ≤ k ≤ n → ( ctl(run(m, 0^k)) ↔ k = n )` のことです。

```
entered      :  ctl(P)  ∧  E では土管の処理が始まっている  ∧  x(E) = x₀
allInputs    :  GMerge  →  ∀ w ∈ I^282 :  ctl(run(E, w))  ∧  ∀ k, 1 ≤ k < 282 → ¬ctl(run(E, w[..k]))
noInput      :  Exact(E, 282)
otherPixels  :  ∀ x ∈ {x₀, …, x₀ + 15} ∖ {z} :  P[x] から入る  ∧  x(E_x) = x  ∧  Exact(E_x, 282)
                                                ∧  run(E_x, 0^282) = run(E, 0^282)
zeroPixel    :  P[z] から入る  ∧  x(E_z) = z  ∧  Exact(E_z, 378)
otherMoved   :  ∀ c ∈ moved :  Exact(c(E), 282)  ∧  run(c(E), 0^282) = run(E, 0^282)
otherBig     :  P で大きいマリオにしても入る  ∧  Exact(E_big, 282)
otherRoutes  :  ∀ d ∈ {1, 2} :  本物の走りが x = x₀ + d で入る  ∧  Exact(その終わり, 282)
grid         :  ∀ d < 21 :  本物の走りが d フレーム多く立ってから歩いて入る  ∧  Exact(その終わり, 282)
```

## しくみ

`gchain` はもう一方の切り替えと同じ確認です。入り口から入力なしをたどり、各フレームで全部の入力を動かし、入力なしの結果と比べます。ここでは 282 フレーム動かします。

ほかの入り口の状態には、もっと短い確認を使います。`mergeTo` は入力なしで 186 フレーム動かし、その間ずっと操作できないことを確かめ、同じフレームの `E` からのマシンと全部のフィールドを比べます。`eq_of_sameM` がそれをマシンの等しさにします。1 フレームはマシンと入力の関数です。だからそこから先は 2 つの走りは同じ走りです（`merged`）。残りの 96 フレームは動かしません。ここに仮定はありません。フレーム数を比べるより多くのことが言えています。地上でのマシンがサイクル数まで同じです。

## 位置が関係しない理由

コードを読み、上の実行で確かめました。

1. 入るフレームで、衝突の処理が切り替えタイマーを設定し、土管の処理を始めます。
2. 土管の処理の間、衝突の処理はすぐ戻ります。だから土管には二度と当たらず、タイマーの設定は 1 回だけです。土管のタイルの中にいても関係ありません。
3. 土管の処理はマリオを毎フレーム 0.5 ピクセル右へ歩かせ、`x` の下位 4 ビットが 0 になると止めます。タイマーは毎フレーム 1 ずつ減ります。この 2 つは互いに関係しません。歩くのは長くても 30 フレームで終わります。
4. タイマーは 160 フレーム目に終わります。画面が消え、RAM の大部分が消えます。`x`、その端数、速さはなくなります。161 か 162 フレーム目から（`z` より右の 2 ピクセルでは 186 フレーム目から）、どのピクセルからでもマシンは同じです。そのあと 25 フレームでエリアを作り、97 フレームで土管から上がります。

**例外.** 入るフレームで `x` の下位 4 ビットが 0 だと、タイマーの設定を飛ばします。タイマーは前の切り替えの 0 のままで、最初の減算で一周します。160 フレームではなく 256 フレーム動きます。96 フレーム多いので 378 です。

入るフレームの終わりで `x` を書き換えても、これは見えません。書き換える前にタイマーはもう設定されているからです。そこに `z` を書いても 282 のままです。だから `otherPixels` と `zeroPixel` は 1 フレーム前に書き、入るフレームをその `x` で動かします。

**`z` に届かない理由.** マリオは、右を向いていて `x₀` 以上の最初の地面のフレームで入ります。空中では土管が止めて押し戻します。地面で左を向いていても止められます。だから入る 1 フレーム前は `x < x₀` か、押し戻された後です。速さは毎フレーム 2.5 ピクセル以下です。よって本物の入り方は `x ≤ x₀ + 2` で、`z` はそれより右です。`otherRoutes` の走りは `x₀ + 1` と `x₀ + 2` です。

だから `x` が大きくても切り替えは短くなりません。[1-1 のルート](../docs/route-1-1-ja.md) の 852 フレームの下限は変わりません。

## 測ったけれど定理にしていないこと

* 本物の入り方 63 個: `x₀`、`x₀ + 1`、`x₀ + 2` を、同じ走りの前にブロックの上で 0〜20 フレーム待って。全部 282 です。
* ジャンプとブレーキの探索で見つけた本物の入り方 87 個（`x`、端数、速さのどれかが違う）: `x₀` が 52 個、`x₀ + 1` が 30 個、`x₀ + 2` が 5 個で、それより右はありません。速さは 1/16 から 37/16 ピクセル毎フレームです。全部 282 です。
* ピクセル `x₀ + 16` から `x₀ + 26`（左側が口に入る）を 1 フレーム前に書いたもの: 入って、全部 282 です。`x₀ + 27` は入りません。
* 64 通りの入力をそれぞれ 282 フレーム押し続けたものと、64 通りのランダムな列 30 本: 282 フレーム目に操作できて、それより前はできず、そのフレームの key は入力なしと同じです。
* Select を押し続ける: 282 です。Start は `I` にありません。Start はゲームを一時停止するので切り替えは長くなります。切り替えの 161〜185 フレーム目で試したものは無視されます（282）。試したほかのフレームでは一時停止し、60 フレーム後にもう一度押すと 342 です。
* TAS は 570 に `x₀ + 1` で入り、852 に操作できます。

## 前提（Lean では証明していない）

* `GMerge`: `E` から同じフレーム数でたどり着いた 2 つの状態の key が等しければ、同じ入力で次も等しい。`allInputs` の仮定で、[地下への切り替え](PipeTransition-ja.md) と同じです。上の測定はこれを支えますが、証明ではありません。
* 全部の入力を動かしたのは、入り口の状態 1 つだけです。ほかの状態は入力なしです。
* 書いた状態だけを含みます。どの走りのどの入り方でも 282 フレームだとは言っていません。本物の入り方が `x ≤ x₀ + 2` であることは上の理由づけで、ここの定理ではありません。
* `otherPixels`、`zeroPixel`、`otherMoved`、`otherBig` の状態は書き換えたもので、そのままたどり着けることは示していません。大きいマリオは本物のキノコで動かしていません。
* 画面の左端が最初のページにないと、コードはもっと短いタイマーを設定します。口は最初のページにあり、画面の左端がマリオより右に来ることはないので、この分岐は通りません。これはコードから読んだことで、Lean にはしていません。ここの実行はどれも画面が最初のページにあります。
* 敵、コイン、ゲームのタイマーは走りごとに違い、動かしたのは上の走りだけです。この部屋に敵はいません。
* Start と Select は入力に含めていません。

## 時間

確認はエミュレータで約 31,000 フレームです。全部のフレームで 64 通りの入力を残しました（18,330 フレーム、約 6.5 秒）。確認の目安の 5 秒より長いです。減らすには一部のフレームで入力を減らすしかなく、そうすると定理は全部の入力について言えなくなります。画面が消えているのは 282 フレームのうち 25 フレームだけで、そこを省いても約 9% しか減りません。確認全体はネイティブで約 11 秒です。

**ファイル.** `Theorems/SideTransition.lean`、非公開の `Proof/SideTransition.lean`。

**再現.**

