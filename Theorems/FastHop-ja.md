# 旗の横の速いジャンプ

**主張.** ジャンプは、覚えている速さの絶対値を読みます。ぶつかるとマリオは止まりますが、この値は消えません。なので、ぶつかった直後のジャンプは、速さがなくても速いジャンプになれます。止まっていて覚えている速さが高いマリオについて:

* 空中で左右を押さないフレームは、覚えている速さ、速さ、進む向きを変えません。
* 地面のフレーム、または空中で左右を押すと、覚えている速さは `|v|` になり、空中のしきい値より小さくなります。

なので速いジャンプをするには、ぶつかってから跳ぶまで左右を押せず、地面に着いた最初のフレームで跳ぶしかありません。すると足が土台の中のフレームごとに押し戻され、旗の範囲に届きません。

```
absCheck        :  範囲の全部の状態で、移動ルーチンは上の 2 点どおりに動く
no_update       :  フレームが 2 点に従い、フレーム j + d のあと覚えている速さが A 以上  →  フレーム j は更新していない
fast_hop_short  :  土台の上に入る前の位置は P_f より左、足が中のフレームは押し戻す、ジャンプは 1 フレーム  →  P₂(g) < P₀
fast_hop_rules  :  absCheck = true        （非公開、native_decide）
```

Lean: `Theorems/FastHop.lean`、非公開の `fast_hop_rules`。

## しくみ

`absCheck` はゲームの移動ルーチン（`PlayerMovementSubs`）を速さ 0 から動かします。`no_update` はジャンプから逆にたどります。フレームのあとに値がまだ高ければ、ぶつかってからのフレームは書き込んでいません。進む向きが変わらないので、[旗を下からつかむ](PoleGrab-ja.md) の規則でフレームごとに押し戻され、そこの `no_grab_near` で終わります。

## 前提（Lean では証明していない）

* ルーチンは単独で確かめています。本物のフレームがそれに従うこと、ぶつかってから跳ぶまでのフレームの `ran` がルーチンどおりであることは、[最高速の上限](TopSpeed-ja.md) と同じ種類の前提です。Lean では `no_update` と `fast_hop_short` の仮定です。
* 確かめた範囲: 覚えている速さはしきい値と最高速。端数の全部、左右の全部、当たり判定のマスクの全部、3 つの状態。向きは右、進む向きは右か左（これで加算値が 2 倍かそうでないかを覆う）、走りの速さの両方。その間の覚えている速さは動かしていません。
* `no_update` は進む向きを扱いません。`fast_hop_short` は押し戻しを仮定として受け取ります。これは進む向きが変わらないことと当たり判定の規則から出ますが、1 つの Lean の主張にはつないでいません。

**ファイル.** `Theorems/FastHop.lean`、非公開の `Proof/FastHop.lean`。

**再現.**
```
.lake/build/bin/smbrta abs-check     # 範囲のルーチンをプログラムで（0 differ、1 秒）
```
