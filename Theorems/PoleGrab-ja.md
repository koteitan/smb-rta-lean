# 旗を下からつかむ

**主張.** 上昇中に旗をつかむには、旗の範囲、つまり土台のブロックの左の端より先にいる必要があり、そこへは上から行くしかありません。
土台の横ではゲームがマリオを押し戻します。左に動くと足の押し戻しが右向きになりますが、1 フレームに 1 ピクセルまでです。なので着地できる位置には
上限があり、小さなジャンプでは進みません。あるフレームで十分に後ろにいれば、間に合う時刻に旗をつかめません。

1/256 ピクセルの単位で書きます。`P₂` は動いたあと、判定の前の位置です。`P₀` は範囲の左端、`e` は足が土台の上の位置に入るフレーム、`L = e + k` は地面に
着くフレーム、`m` はそのあと土台の横にいるフレーム数、`g = L + m + 1` はつかむはずのフレームです。

```
landing_far   :  k ≥ 2  →  P(L) ≤ P₂(e) + 256·(k − 3) + 32
landing_one, landing_zero  :  k ≤ 1  →  P(L) ≤ P₂(e) − 256
landing_left  :  e のあと左右を押さない  →  P(L) ≤ P₂(e) − 256
hop_le        :  P(L + m + 1) ≤ P(L) − 16·m
grab_le       :  P₂(g) ≤ P(g) + 32
no_grab_far   :  P₂(e) + 16·v_top·(t − e) ≤ B,  B + 32 < P₀,  L ≤ t + 3,  k ≥ 2,  m ≥ 2  →  P₂(g) < P₀
no_grab_near  :  P(L) ≤ P₂(e) − 256,  m ≥ 1  →  P₂(g) < P₀
pole_rules    :  土台の近くの全部の状態で、判定のルーチンは下の規則どおりに動く
```

どちらの `no_grab` も `P_f + 16·v_top ≤ P₀ + 224` が必要です。`P_f` は足が土台の上の位置に入るところです。

Lean: `Theorems/PoleGrab.lean`、非公開の `pole_rules`（`native_decide`）。

## 規則

| マリオ | ルーチンのすること |
|---|---|
| 落下中で足が土台の中、右に動いている、または進む向きが右 | 速さ 0、1 ピクセル戻す、右をふさぐ |
| 落下中で足が土台の中、それ以外 | 速さ 0、1 ピクセル進める、左をふさぐ |
| 落下中で土台の上面に落ちる | 上昇中につかめる高さより上に着地する |
| 土台の横か、その横の地面で、右に動いているか止まっている | 速さ 0、1 ピクセル戻す、右をふさぐ |
| 同じ場所で、左に動いている | 何もしない、右をふさぐ |
| 上昇中で旗の範囲、土台の上面より上 | 旗に触る |

`maskCheck`: 左がふさがれていると、空中で止まっているマリオは左に動き出さない。

## しくみ

速さ 0 から 1 フレームで届く速さは 1/8 ピクセル／フレームまでです（`a_max ≤ 512`）。なので動きだけで進むのは 1 フレームに 1/8 ピクセルまでです。
すると足が土台の中のフレームで進むのは 1 ピクセルまで、横のフレームでは 1/16 ピクセル以上戻ります。着地の前のフレームが前に押すなら左がふさがれるので、
着地で戻されます。そのフレームが戻すなら、そこで戻っています。足し合わせると `landing_far` になります。

`no_grab_far` について: `k = 2` では、`e` の前のフレームは土台より左なので、`P₂(e)` は土台から 1 フレームの動き未満です。`k ≥ 3` では、1 ピクセルずつ進める
フレームは `L − e` 個ありますが、`e` が早くなり、上限 `B` は 1 フレームごとに `16·v_top` ずつ小さくなります。これは増える分より大きいです。

## 前提（Lean では証明していない）

* 定理は、判定が `Side`、`InBlock`、`MaskL` に従うフレーム（[最高速の上限](TopSpeed-ja.md) の `Frame`）についてのものです。本物のフレームがそうなっていることは、
  そこと同じ種類の前提です。ルーチンは単独で確かめ、フレームの残りとつないではいません。
* `pole_rules` を確かめた範囲: 小さいマリオ。旗の列はオブジェクトのコードと面のデータからブロックバッファに書く。位置は土台の横に初めて触れるところから `P₀` の 1 ピクセル
  先まで。高さは土台の上面から地面まで。速さは −0.75 ピクセル／フレーム以上。落下の速さは最高まで。上昇の速さはジャンプの最初のフレームのもの。定理の中で
  マリオはこの位置の範囲にとどまります。`k ≤ 2` では `P₀` の 0.5 ピクセル先まで、`k ≥ 3` では `e` がもっと早くなるからです。
* `L ≤ t + 3` と `m ≥ 2` はジャンプから来ます。上昇中につかめる高さになるのはジャンプの 3 フレーム目だけです（`m = 2`）。速いジャンプでは 2 フレーム目です（`m = 1`）。これは
  [ジャンプの高さ](Jump-ja.md) の定理です。速いジャンプでは、左右を押すと覚えている速さの絶対値が更新されるので、`e` のあと左右を押せません。これはコードから読みました。
* 上限 `B` は入力です。[1-1 の道筋](../docs/route-1-1-ja.md) ではエミュレータの探索から取っています。
