# 空中の速さの上限

**主張.** マリオの速さが 1.5625 ピクセル／フレーム（空中のしきい値）より遅いとします。空中ではそのまま
しきい値を超えず、1 フレームに 1.5 ピクセル以下しか進みません。しきい値を超えられるのは地面のフレームだけです。
なので、空中の `K` フレームと、そのあとの任意の `n` フレームで進むのは、`1.5·K` ピクセルと、`n` だけで決まる
上限の和以下です。後ろの部分のフレームを前の部分に移しても、上限は増えません。

1/256 ピクセルの単位で書きます。`A` はしきい値（速さの値）、`a_max` は最大の摩擦の加算値、`dbound` は
[進める距離の上限](Reach-ja.md) のものです。

```
B             =  256·A − 1 + a_max
capDist(0)    =  0
capDist(n+1)  =  max(16·(A − 1) + capDist(n),  16·min(v_top, ⌊B/256⌋) + dbound(B, n))

step_cap      :  |v| < A  →  |v'| < A、または地面のフレームで Φ' ≤ B
dist_capped   :  |v(0)| < A  →  P(n) − P(0) ≤ capDist(n)
air_run       :  |v(0)| < A、空中 K フレーム  →  |v(K)| < A かつ P(K) − P(0) ≤ 16·(A − 1)·K
landing_bound :  |v(0)| < A、空中 K フレーム、そのあと n フレーム  →
                 P(K + n) − P(0) ≤ 16·(A − 1)·K + capDist(n)
landing_later :  16·(A − 1)·(K + k) + capDist(n) ≤ 16·(A − 1)·K + capDist(n + k)
air_cap_room  :  (K, n) = (7, 46): 121.75 ピクセル以下、(K, n) = (5, 47): 121.25 ピクセル以下
```

Lean: `Theorems/AirCap.lean`、非公開の `air_cap_room`（数は `native_decide`）。

## しくみ

しきい値より遅いと、空中のフレームでは低いほうの速さの上限を使います。速さはそこまで戻され、端数は残ります。
地面で高いほうの上限を使えるのは、進む向きのボタンと B（または走りのタイマー）のときだけで、そのフレームで
向きは進む向きになります。なので、しきい値に届いた直後は `Φ = |V| ≤ 256·A − 1 + a_max` です。
[進める距離の上限](Reach-ja.md) の `Φ` の上限はこれを見ていません。上限の速さに向きの分を足すことと、次のフレームで
最大に増えることを許しています。

`capCheck` は、しきい値のすぐ下の 4 段の速さの全部の状態（端数、向き、進む向き、走りの速さの全部）を、全部の入力で
1 フレーム動かします。約 47 万フレームで 4 秒です。それより遅いときは、ポテンシャルの `stepOk` で足ります。1 フレームでは
しきい値に届きません。

## 前提（Lean では証明していない）

* 横の動きのフレーム `hstep` の前提。[進める距離の上限](Reach-ja.md) のページにあります。
* 何にも触れないこと。壁やブロックに当たると速さがほぼ 0 になり、そのあとの距離は減るだけです。
