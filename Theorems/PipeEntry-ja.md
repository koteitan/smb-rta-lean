# 縦の土管に入る

**主張.** 判定のルーチンが縦の土管の処理を始めるのは、次の全部が成り立つときだけです。下ボタンを押している。上昇中でない。足が土管の上面の着地の深さにある。
両足が土管の上にある（左足が左の列、右足が右の列）。なのでマリオはある位置の範囲にいる必要があります。位置の上限によると、フレーム 367 まではその範囲より左です。
フレーム 368 より前には入れません。

名前は土管のオブジェクトと判定のコードから来ます。`c` は土管の左の列（そのページの中）、`r` は上面の行、`pg` はページです。`a_R` と `a_L` は `x` から右足と左足までの距離、
`a_Y` は `y` から足までの距離、`d` は着地の深さです。

```
a_L  = 15 − a_R                     （足は 16 ピクセルの箱の中で左右対称。pipeCheck で確かめる）
T_y  = BlockBufferTopY + 16·r       土管の上面
x_lo = 16·(c + 1) − a_R             ここから右足が右の列に入る
x_hi = 16·(c + 1) − 1 − a_L         ここまで左足が左の列にある
L    = 256·(256·pg + x_lo)          範囲の左端の位置（1/256 ピクセル）

rule(x, y, vy, ud)  ⇔  (ud ∧ 4 ≠ 0)  ∧  0 ≤ vy  ∧  T_y ≤ y + a_Y < T_y + d  ∧  x_lo ≤ x ≤ x_hi
```

`ud` は `Up_Down_Buttons`、`vy` は符号つきの `Player_Y_Speed` です。`vy = 0` も含みます。なので土管の上に立っているマリオも、下を押せば入ります。地面にいるフレームは
毎回、着地のコードを通るからです。TAS はこの入り方です。

`P = 256·(256·ページ + x) + 小数部` です。`P₂(t)` はフレーム `t` で動いたあとの位置で、そのフレームの判定はこれを読みます。`P'(t)` は判定のあとの位置です。`Enter t` はフレーム `t` の判定が
土管に入ることです。`P₀` は最初に操作できるフレームの位置です。`N` と `D` は [出だしの最適性](Opening-ja.md) のもの、`v_top` は走る最高速です。

```
enters_eq_rule        :  pipeCheck  →  ∀ s ∈ cases,  enters(s) = rule(s)
unchanged_of_not_rule :  pipeCheck, s ∈ cases, ¬rule(s)  →  ルーチンの番号は変わらない
window_of_enters      :  pipeCheck, s ∈ cases, enters(s)  →  x_lo ≤ x ≤ x_hi
enter_needs           :  pipeCheck, s ∈ cases, enters(s), 0 ≤ f  →  L ≤ 256·(256·pg + x) + f
no_enter_left         :  pipeCheck, s ∈ cases, 0 ≤ f, 256·(256·pg + x) + f < L  →  ¬enters(s)

no_entry_of_left      :  (∀ t, Enter t → L ≤ P₂(t)),  (∀ t ≤ T, P₂(t) < L)  →  ∀ t ≤ T, ¬Enter t
no_entry_by           :  (∀ t, Enter t → L ≤ P₂(t)),  (∀ t ≤ N, P₂(t) ≤ B),  P'(N) ≤ B,  |v'(N)| ≤ v_top,
                         フレーム N, N + 1, … が連続,  B + 16·v_top·(T − N) < L  →  ∀ t ≤ T, ¬Enter t
model_left            :  最初の N ステップで dist ≤ D,  ステップ N + k で dist ≤ D + c·k,  P₀ + D + c·(T − N) < L
                         →  T までの全ステップで P₀ + dist < L

pipe_gap（非公開）    :  P₀ + D + 16·v_top·(367 − N)  <  L  ≤  P₀ + D + 16·v_top·(368 − N)
pipe_model, pipe_model_no_enter, pipe_no_entry（非公開）  :  `opening` のモデルでもフレームでも、フレーム 367 までは入らない
```

フレーム 367 の上限は `L` に 112/256 ピクセル（0.44 ピクセル）足りません。フレーム 368 では 528/256 ピクセル越えます。

Lean: `Theorems/PipeEntry.lean`、非公開の `Proof/PipeEntry.lean`（`pipe_rules`、`pipe_gap`、`pipe_model`、`pipe_model_no_enter`、`pipe_no_entry`）。

## しくみ

`pipeCheck` は、土管の上面の 2 つのタイルを 1 つ目のブロックバッファに書き、ゲーム自身の `PlayerBGCollision` を `cases` の全部の状態で動かします。ルーチンの番号を `rule` と比べます。
入るときは、土管の高さに立っていることと `x` が変わらないことも確かめます。入らないときは、番号が変わらないことを確かめます。`rule_of_cases` がこれをフレームの話に移します。

ページは面のデータから数えます。土管までの（土管を含む）オブジェクトの組で、2 バイト目のビット 7 が立っているものの数です。`levelOk` は、土管のオブジェクトが入れるタイルで描かれる種類であることと、
それより前にその種類のものも、ページを直接決めるものもないことを確かめます。

規則から上限へ: 入るフレームでは `L ≤ P₂` です。フレーム `N` までの上限は出だしの `D` です。`N` のあとは 1 フレームに `16·v_top` までです（[最高速の上限](TopSpeed-ja.md)）。
`pipe_gap` は `native_decide` でこの 2 つを比べます。

## エミュレータでの TAS との比較

これはエミュレータでの実行です。Lean ではありません。

| 実行 | 結果 | `rule` との関係 |
|---|---|---|
| TAS のフレーム 368、下 | 入る。番号は `rule` のとおり | 範囲の左端 |
| フレーム 362 .. 367 のそれぞれで下 | 入らない | 範囲より左 |
| 368 からボタンなし、`x = x_hi` になる最初のフレームで下 | 入る | 右端 |
| 368 からボタンなし、`x = x_hi + 1` になる最初のフレームで下 | 入らない | 右端の先 |
| フレーム 368 で下＋右 | 入らない | フレームのコードが `ud` を消す（下を参照） |

TAS の距離はフレーム 32 から 362 まで毎フレーム上限に一致します。そのあとは上限より遅れます。土管の上でボタンを押さず、減速するからです。

## 前提（Lean では証明していない）

* **ルーチンは単独で確かめています。** 定理は、判定が `rule` に従うフレーム（[最高速の上限](TopSpeed-ja.md) の `Frame`）についてのものです。Lean では `pipe_no_entry` の仮定 `hE` です。入るフレームの状態は `cases` の中にあり、
  土管のページにあり、位置は `P₂` である、という仮定です。ルーチンとフレームの残りはつないでいません。
* **確かめた範囲.** `cases` は小さく保つために和集合です。`x` は範囲の少し左から少し右まで。高さは上面の少し上から上面の行の下端まで。立っている状態、落下の速さは最高まで（空中の 2 つの状態で）、
  ジャンプの上昇の速さ。下を押す、押さない。速さは左右の最高速と 0 です。これに加えて次の 4 つです。範囲と着地の深さの端で、全部の速さと、それに合う進む向き、上下ボタンの全部の組。ほかの向き。しゃがんでいない大きいマリオ。
  下を押して着地するときの、ページの全部の `x`。ほかの状態は動かしていません。判定が読むのはボタンのビット、`vy` の符号、`y` の下位 4 ビット、足の 2 つのタイルだけです。これはコードから読みました。確かめてはいません。
* **しゃがんだ大きいマリオ** は `cases` に入っていません（そのフラグのシンボルがないため）。足の判定では小さいマリオと同じ道を通ることをコードから読みました。
* **ブロックバッファは手で書いています。** 土管のオブジェクトから書きます。ゲームのオブジェクトのコードで描いたものではありません。1 つ目のバッファとページ 0 を使います。ルーチンはページの下位 1 ビットしか読まないからです。本物のフレームは
  土管のページで 2 つ目のバッファを読みます。下位ビットが同じページは同じバッファを使います。バッファに土管のタイルがあるのはマリオがそのページの近くにいる間だけであることは、コードから読みました。`hE` に「土管のページ」とあるのはこのためです。
* **縦の土管を始めるのはこのルーチンだけで、このタイルだけです。** コードから読みました。`levelOk` のオブジェクトの形式も、面の読み込みのコードから読みました。
* **下を押すことの意味.** `rule` は判定のときの `Up_Down_Buttons` についてのものです。地面で左か右を押しながら下を押すと、フレームのコードがこれを消します（コードから読み、フレーム 368 で確認）。これは入る機会を減らすだけです。
* **位置の上限.** `pipe_no_entry` の `hopen`、`hB`、`hv`、`hn` は仮定です。出どころは [出だしの最適性](Opening-ja.md) と [最高速の上限](TopSpeed-ja.md) で、それらの前提を引き継ぎます。最初の `N` フレームは開けた平らな地面でモデルに従い、
  そのあとのフレームは `Frame` に従う、という前提です。
* **証明していないこと: フレーム 368 に届くこと.** `pipe_gap` が言うのは、上限がフレーム 368 で `L` を越えることだけです。368 で実際に入るのは、エミュレータでの TAS です。
