# fast accel

**命題.** 1-1 で操作できるようになった最初のフレームから、本物のコントローラで、マリオは
**34 フレーム**で走りの最高速（2.5 ピクセル／フレーム）に達することができ、33 フレーム以下では
達することができない。

```
upper :  ∃ w ∈ PadA^34,  v(Full(ctx, w)) ≥ v_top
lower :  ∀ σ ∈ (PadA × {着地する, しない})^{≤ 33},  v(Relax(ctx, σ)) < v_top
```

Lean: `fast_accel : FastAccel.Bounds sy ctx padInputsA relaxInputs 33 34`。

* `Full` は本物のエミュレータ（モデルではない）。`PadA` は、本物のコントローラで Start と
  Select を除いて押せるボタンの組み合わせ 36 通り。
* `Relax` は緩めたモデル。横の状態と、地面か空中かのフラグだけを持ちます。ジャンプは
  ゲームと同じように始まり、空中ではどのフレームの終わりにも着地できます。

**入力（fast accel）.**

| フレーム | 入力 | 何が起きるか |
|---|---|---|
| 1 | 左 | 左を向く |
| 2 | 下 | 速さ 0、進む向きを向いている向き（左）に合わせる |
| 3 | A + 右 | ジャンプ。空中では左向きのままなので、向きと進む方向がずれて加速が 2 倍 |
| 4–23 | 右 | 空中で加速 |
| 24–25 | B + 右、右 | 着地。速さが空中の最高速の上限を上げるところまで来ている |
| 26 | 左 | もう一度左を向く |
| 27 | A + 右 | 2 回目の後ろ向きジャンプ |
| 28–34 | 右 | 34 フレーム目で最高速 |

左右同時押しなしの TAS（tasvideos 提出 6456）も同じ出だしで、34 フレームで最高速に届きます。

**モデルからゲームへ.** 本物の動きは、どれも緩めたモデルの動きのどれかになります。空中の
処理は縦のバイトを読まず（`relax-indep`: 縦の値を変えたステップ 106,441,560 回で違い 0）、
本物の着地もどこかのフレームで起きるからです。位置も関係しません（`relax-indep … pos`:
違い 0）。なので、開けた場所で Start と Select を使わないなら、33 フレーム以内で最高速に届く
本物の入力はありません。このつなぎの部分は、Lean ではなくプログラムで確かめたものです。

**ファイル.** `Theorems/FastAccel.lean`、非公開の `Proof/FastAccel.lean`。

**再現.**
```
.lake/build/bin/smbrta relax-layers 50          # 緩めたモデルの最短: 34
.lake/build/bin/smbrta realize 34               # 届く入力を見つける（約 40 分）
.lake/build/bin/smbrta relax-indep 33           # と: 33 pos
lake build Proof.FastAccel   # 非公開のプロジェクトで、約 16 分
```
