# 地上: 1085 フレームまでに旗に届かない

**主張.** 地上で操作できるようになったとき、マリオは止まっていて、横方向の状態は 1-1 の最初と同じです。どのフレームでも地面か空中かを自由に選べるモデルで、最初の 40 フレームに TAS より先に行けるのは 464/256 ピクセルまでです。そのあとは 1 フレームに 2.5 ピクセルまでです。なので 1085 フレーム目（852 で操作できてから 233 フレーム後）に TAS より先に行けるのは 480/256 ピクセルまでです。旗の範囲の左端は、そのフレームの TAS より 528/256 ピクセル先です。なので届きません。[旗を下からつかむ](PoleGrab-ja.md) が必要とする 32/256 ピクセルを足しても、16/256 ピクセル余ります。

単位は 1/256 ピクセルです。`A` は本物の走りで地上で操作できるようになったときのマシンです。`s₀` は 1-1 の最初の横方向の状態です。`I` は [進める距離の上限](Reach-ja.md) の入力の集合で、フレームごとに地面、ジャンプの開始、空中のどれかと、右、左、下、上、B の全部の組み合わせと、タイマーが 0 かどうかです。`d(w)` は `s₀` から `hstep` で `w` を動かしたときの `16·v'` の合計です。`P(A)` は `A` での位置です。`P₀` は旗の範囲の左端で、`256·(256·ページ + 柱の列の x − 10)` です。ページはステージのデータから読みます。

```
start   :  control(A)  ∧  A の横方向の状態 = s₀
within  :  ∀ w ∈ I*,  |w| ≤ 31      →  d(w) ≤ 9424
after   :  ∀ w ∈ I*,  |w| = 31 + k  →  d(w) ≤ 9424 + 16·v_top·k
reached :  ∃ w ∈ I⁴⁰,  d(w) = 9424 + 16·v_top·9 = 15184
gap     :  P(A) + 9424 + 16·v_top·(233 − 31) + 32  <  P₀
short   :  ∀ w ∈ I*,  |w| ≤ 233  →  P(A) + d(w) + 32 < P₀
```

TAS の 852 フレーム目からと比べると:

| 操作できてからのフレーム数 | TAS のフレーム | TAS の距離 | 上限 | TAS より先 |
|---|---|---|---|---|
| 40 | 892 | 14720 | 15184 | 464 |
| 233 | 1085 | 138224 | 138704 | 480（範囲に入るには 528） |

ぶつかることは `hstep` の外にあります。最初にぶつかるのがフレーム `j` の走りについて:

```
hit_short :  9 ≤ j,  ぶつかる,  そのあとは TopSpeed.Frame のフレームなら何でも  →  P(233) + 32 < P₀
hit_last  :  j = 233,  ぶつかる  →  P(233) + 32 < P₀
          ぶつかる:  P(j) ≤ P(A) + d(pre ++ [i]) − 256   または   P(j) ≤ P(A) + d(pre) + 256
noHit     :  A での衝突の処理は、x から 4 ピクセル以内、y から 40 ピクセル上まで、横にぶつからない
mask      :  右に動いていて左に壁があるとき、左をふさいだ hstep は hstep と同じか、止まる
```

Lean: `Theorems/SurfaceRun.lean`（`runCheck`、`maxCheck_spec`、`within_of_check`、`after_of_check`、`hit_bound`、`hit_short`、`hit_last`、`statement_of_check`）、非公開の `surface_checks`、`surface_run`、`surface_numbers`、`surface_hit`（`native_decide`）。

## しくみ

**最初の状態.** マシンは本物の走りから作ります。[旗に触ってから城まで](CastleWalk-ja.md) の走りの前の部分で、自前の入力です。地上で操作できるようになるところまで動かします。そこで横方向の状態と位置を読みます。状態は 1-1 の最初と同じです。

**モデル.** `hstep` はフレームの横方向の部分です。モデルはフレームごとに地面、ジャンプの開始、空中を自由に選びます。なので土管から歩いて落ちること、段差から落ちること、どの高さに着地することも含みます。マップのことは何も使いません。だから [出だしの最適性](Opening-ja.md) の測ったジャンプの長さは要りません。

**探索.** `hstep` は位置を読みません。なので `maxCheck` は、横方向の状態ごとに、そこに来る走りの一番長い距離を 1 つだけ持ちます（`Cov`。[速いジャンプ](FastTakeoff-ja.md) と同じです）。距離に、残りのフレームの `dbound` を足しても上限以下なら、その状態は捨てます（`dist_le`）。全部の入力を含むことは `maxCheck_spec` で証明しています。30 フレーム目のあとに残る状態はありません。この上限はモデルの中でちょうどです。`reached` がその入力を与えます。1 小さい上限では `runCheck` が false になります。一番良い走りは 31 フレーム目からずっと最高速です。

モデルの一番良い走りは本物の走りではありません。滞空なしで着地と踏み切りをします。本物の限界はもっと小さいです。[ルートのページ](../docs/route-1-1-ja.md) のエミュレータの探索では 892 フレーム目に 144/256 ピクセルでした。このページのためには動かし直していません。464/256 ピクセルで足りるので、この差は問題になりません。

**ぶつかること.** 横のぶつかり方は 4 通りです（`TopSpeed.Frame.impedeP` と処理のコード）:

| そのフレームの速さ | 処理がすること | 扱い |
|---|---|---|
| 右に動いているか止まっていて、右に壁 | 速さ 0、1 ピクセル戻る、次のフレームは右がふさがる | 最初のぶつかり: `P(j) ≤ P(A) + d(pre ++ [i]) − 256` |
| 左に動いているか止まっていて、左に壁 | 速さ 0、1 ピクセル進む、次のフレームは左がふさがる | 最初のぶつかり: `P(j) ≤ P(A) + d(pre) + 256` |
| 左に動いていて、右に壁 | 何もしない、次のフレームは右がふさがる | 最初のぶつかり、上と同じ式 |
| 右に動いていて、左に壁 | 何もしない、次のフレームは左がふさがる | `mask`: 次のフレームはモデルのフレームと同じか、`P` が動かずに止まる。この止まりは最初のぶつかりとして扱う |

止まると向きと動く方向の状態が変わるので、得になるかもしれません。これは `hit_bound` で扱います。最初のぶつかりまでは `dbound` で距離を抑えます。そのあとは `Frame` なら何でも（もっとぶつかってもよい）`TopSpeed.chain_reach` で `reach(255, n)` までです。表 `hitTable` で、`j` が 9 から 31 までの全部について、この合計が上限以下であることを確かめます。31 フレームより後は探索の上限で足ります。`j ≤ 8` では合計が大きすぎます。そのフレームではぶつかりません。これが `noHit` です。マリオは土管の上にいて、本物のマシンの衝突の処理は、まわりで横にぶつかりません。

別の確認として（定理ではなくプログラム）、ぶつかりをどのフレームでも許し（1 から 8 フレーム目も、ふさがれたボタンも含む）、モデルを 40 フレーム探索しました。`TopSpeed.reach` で状態を捨てると、15184 を超えるものはありません。なのでモデルの中では、ぶつかっても得になりません。

## 前提（Lean では証明していない）

* 本物のフレームは、最初のぶつかりまで `hstep` のとおりに動く。TAS では 853 から 1085 までの 233 フレーム全部で `hstep` とエミュレータが一致します（プログラム、違いなし）。土管から落ちるところ、階段、段差も含みます。最初の違いは 1086 フレーム目で、土台にぶつかるところです。
* ぶつかったあとのフレームは `TopSpeed.Frame` である。[最高速の上限](TopSpeed-ja.md) と [進める距離の上限](Reach-ja.md) の前提です。敵もそのページのとおりで、死ぬとき以外、これらのバイトを書きません。
* 1 から 8 フレーム目のマリオは `noHit` の箱の中にいる。`dbound` からどちらの向きにも 4 ピクセル未満で、ジャンプは 1 フレームに 5 ピクセルまでしか上がりません。これと確認の結びつきは Lean にはありません。`noHit` の速さは 0、±1/16、±1/2 ピクセル／フレームです。処理は速さを符号でしか読まないからです。
* Lean の `mask` の端数は 0、128、255 です。全部の端数をプログラムで動かすと、同じフレームが 2,288,640 回、止まるのが 46,080 回、ほかは 0 回でした。
* 画面の左端は `Frame` に入っていません。止まって、`P` は前のフレーム以下のままなので、2 番目のぶつかりと同じに扱えますが、Lean にはありません。
* 最初の状態は本物の走り 1 つです。ほかの走りは定理に含みません。エミュレータでは: 852 の TAS は `A` と横方向の状態、位置、高さが同じです（RAM の違いは 17 バイトで、タイマーと乱数です）。横の土管に入るときの端数、速さ、向きを変えても、同じ 282 フレーム後に同じ状態になります。852 より遅く操作できるようになって状態が同じなら、`short` は `|w| ≤ 233` の全部で成り立つので、そのまま使えます。
* Start と Select は含めていません。
