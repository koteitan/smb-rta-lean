# 最高速の上限

**命題.** 動く床、ツタ、うず潮、土管、旗、斧、城のループ、ステージの入り口、画面の左端から離れて
いれば、マリオは 1 フレームに 2.5 ピクセル（走りの最高速）より多く右へ進むことはなく、速さが最高速を
超えることもない。最高速で何にも触れずに走ると、ちょうど 1 フレーム 2.5 ピクセル進む。なので、
最高速に乗ったあとは、触れられるもの（ブロックの下や横、踏める敵）をどう使っても、走るより右へは
行けない。

位置は 1/256 ピクセル単位で `P = 256·(256·page + x) + 端数`。`v_top` は走りの最高速。

```
Frame.bound :  |v| ≤ v_top  →  |v'| ≤ v_top  ∧  P' − P ≤ 16·v_top
chain_bound :  P(n) − P(0) ≤ 16·v_top·n
Frame.gain  :  V' ≤ max(V, 0) + a_max          （V = 256·v + subspeed。fast accel の GainBound）
attain      :  最高速で右 + B を 20 フレーム: 毎フレーム P' − P = 16·v_top
```

Lean: `Theorems/TopSpeed.lean`（`Frame.bound`、`chain_bound`、`Frame.gain`。計算を使わずに証明）、非公開の
`top_speed`（各処理の確認と `attain`。`native_decide`）。

## 分け方

ROM の中で、マリオの速さや位置を書き換える命令を、解析済みコードから全部拾いました。上で除いた場面と
やられたときを除くと、それは 5 つの処理の中にあり、1 フレームの中でこの順に動きます。それぞれを
エミュレータで単独で動かし、読むバイトの、ふつうの範囲の全部の値で確かめました。

| 処理 | 確かめたこと | 回数 |
|---|---|---|
| `GetPlayerAnimSpeed`（地面にいるとき） | 速さと subspeed はそのままか、両方 0。`RunningSpeed` と進む向きは範囲内のまま | 1000 万 |
| `X_Physics` | 速さの上限と加速の量は表の値。ダッシュのタイマーは範囲内のまま | 1500 万 |
| `ImposeFriction` | `|v| ≤ v_top` が保たれる（上限で頭打ちになる）。`V = 256·v + subspeed` として `V' ≤ max(V, 0)` + 加速の量 | 2400 万 |
| `MoveObjectHorizontally` | `P' = P + 16·v` | 2100 万 |
| `ImpedePlayerMove`（横の当たり判定） | 速さは 0 かそのまま。`P` は −256、0、+256 のどれかだけ動き、+256 は `v ≤ 0` のときだけ | 130 万 |

ブロックを下から叩く処理と敵を踏む処理は、これらのバイトに書き込みません。変えるのは縦の速さと、
空中にいるかどうかだけです。

`Frame` は 1 フレームをこの 5 つの事実で表したもので、`Frame.bound` と `chain_bound` は算数で出ます。
右へ押される唯一の場合（`ImpedePlayerMove`）は `v ≤ 0` のときだけなので、そのフレームの移動は
多くても 256 で、16·v_top より小さくなります。

## 前提（Lean では証明していない）

* 書き換える命令の一覧に漏れがないこと: 解析済みコードから拾い、1-1 の最初のブロックとクリボーの
  あたりでランダムに約 39 万フレーム遊んで確かめた（ほかの書き換えは出なかった）。
* 各処理が、確かめたバイトの、ふつうの範囲の値だけで決まること（`Player_State` は地面か空中、
  当たり判定のビットは下の 2 ビットだけが消える）。page は、ステージの page の範囲の両端の
  0、1、30、31 で確かめた。移動の処理と横の当たり判定では、page は 1 回の繰り上がりつきの足し算に
  しか使われないため。
* Start と Select を押さないこと。

**ファイル.** `Theorems/TopSpeed.lean`、非公開の `Proof/TopSpeed*.lean`。

.lake/build/bin/smbrta top-check all     # 5 つの処理の確認と attain を、プログラムとして実行
