# 地下への切り替え

**主張.** マリオが縦の土管に入ったフレームから、ちょうど 91 フレーム後に地下で操作できるようになります。本物の走りで得た 1 つの入る状態については、
すべてのフレームのすべての入力（Start と Select は除く）についてこれを示します。これには 1 つの仮定（`Merge`）を使います。ほかの入る状態については、入力なしの場合を
仮定なしで示します。

`m₀` は 1-1 の開始の機械です。`run(m, w)` は入力 `w` で本物のフレームを進めた機械です。`ctl(m)` は `controllable` です。`0^k` は入力なしの `k` フレームです。
`I` は 64 個の入力です。A、B、上、下、左、右のすべての部分集合で、逆向きの同時押しも含みます。`E = run(m₀, witness)` は入るフレームの終わりの機械です。
`S` は、本物の走りでマリオが土管の範囲に立っている機械です。`D` は下だけの入力です。

```
entered     :  ctl(run(m₀, witness の最後のフレームを除く))  ∧  最後のフレームのあと土管のルーチンになる
allInputs   :  Merge  →  ∀ w ∈ I^91 :  ctl(run(E, w))  ∧  ∀ k, 1 ≤ k < 91 → ¬ctl(run(E, w[..k]))
noInput     :  ∀ k, 1 ≤ k ≤ 91 → ( ctl(run(E, 0^k)) ↔ k = 91 )
otherMoved  :  ∀ c ∈ moved :  ( ∀ k, 1 ≤ k ≤ 91 → ( ctl(run(c(E), 0^k)) ↔ k = 91 ) )
                              ∧  key(run(c(E), 0^91)) = key(run(E, 0^91))
otherBig    :  ∀ k, 1 ≤ k ≤ 91 → ( ctl(run(big(E), 0^k)) ↔ k = 91 )
stand       :  ∀ d < 21 :  run(S, 0^d) で D を押すと土管に入る。そのフレームの終わりを E_d として
                           ∀ k, 1 ≤ k ≤ 91 → ( ctl(run(E_d, 0^k)) ↔ k = 91 )
```

| 入る状態 | 切り替え中の入力 | 結果 | 仮定 |
|---|---|---|---|
| `E`: 本物の走り、最高速、着地のフレームで入る | `I` のすべて、すべてのフレーム | 91 フレーム目に操作でき、それより前は操作できない | `Merge` |
| `E` | なし | 同じ | なし |
| `E` を書き換えたもの（`moved`）: 範囲の 9 ピクセルのそれぞれ。速さ 0、最高速の半分と最高速を左右に（進む向き、顔の向き、覚えている速さの絶対値も）。位置の端数。速さの端数。走りの速さ。走りのタイマー | なし | 同じ。そのフレームで `key` も等しい | なし |
| `E` を書き換えたもの: 大きいマリオ | なし | 同じ | なし |
| 本物の走りで範囲に立つ: 入るフレームを 21 個続けてずらす。21 フレームの格子のすべての位置になる | なし | 同じ | なし |

`key` は、`SavedJoypadBits` と `JoypadBitMask` の Start と Select 以外のビットを除いた RAM と、`pad` と ROM を除いた機械のほかの欄です。`key` が等しければ `ramKey` も等しくなります。

Lean: `Theorems/PipeTransition.lean`（`Statement`、`statement_of_check`、`first_control`、`chain_spec`）、非公開の `pipe_checks`（`native_decide`）と `pipe_transition`。

## しくみ

`chain` は入る状態から入力なしの道をたどります。各フレームで集合のすべての入力を動かし、入力なしの結果と `key` で比べます。入力なしの状態が最後のフレームでだけ操作できることも
確かめます。全部でエミュレータの約 10,000 フレームです。

`chain_spec` は、この確認を `run(E, 0^k)` についての主張に直します。帰納法です。ここには仮定がありません。なので `noInput`、`otherMoved`、`otherBig`、`stand` は仮定なしです。

任意の `w` については、`key_of_chain` が `key(run(E, w)) = key(run(E, 0^|w|))` を長さの帰納法で示します。その段階で `Merge` を使います。`key` には `ctl` が入っているので、
`first_control` が出ます。

## 前提（Lean では証明していない）

* `Merge`: `E` から同じフレーム数で着いた 2 つの状態の `key` が等しければ、同じ入力のあとの `key` も等しい。そのような 2 つの状態の違いは、`SavedJoypadBits`、`JoypadBitMask` の
  Start と Select 以外のビット、`pad` だけです。支えになる事実は次のとおりです。証明ではありません。逆アセンブルで `JoypadBitMask` を読むのは 1 か所だけで、その 2 ビットに絞っています。`runFrame` は
  `pad` を上書きします。読み書きを記録したエミュレータの実行（入力なしと全ボタン）では、91 フレームのどれでも `SavedJoypadBits` は書かれる前に読まれていません。測定では、64 個の入力の間で
  RAM が違うのはこの 2 バイトだけで、機械のほかの欄は違いません。
* 示したのはこれらの入る状態だけです。どの走りのどの入る状態でも同じになる、とは言っていません。敵の位置、スクロール、タイマーは走りごとに違い、動かしたのは上の走りだけです。TAS の状態からの
  エミュレータの実行でも 91 フレームでした。これは証明には入っていません。
* すべての入力を動かしたのは `E` からだけです。ほかの入る状態は入力なしです。
* 書き換えた状態は、そのままの形で本物の走りから行けるとは示していません。`E` のバイトを直接書いています。
* `I` に Start と Select は入っていません。Start は一時停止で、長くするだけです。これはコードから読みました。証明に入らないエミュレータの実行で、41 フレーム目から毎フレーム 1 回ずつ
  Start を押しました。場面の切り替えのフレームの一部では無視され、91 フレーム目に操作できました。それ以外では一時停止のままでした。45 フレーム後にもう 1 回押すと、操作できるのは 45 フレーム遅れました。Select を 1 フレームだけ押す実行は、91 フレームのどこでも結果を変えませんでした。
* `moved` の範囲の 9 ピクセルは、足の位置の値から計算しています。ちょうどそこで下を押すと入ることはエミュレータの実行で見ました。これは土管に入る条件の話で、この定理の中身ではありません。
* フレームはエミュレータのフレームです。エミュレータは [エミュレータ](../docs/emulator-ja.md) のとおりに確かめましたが、本物の機械と同じだとは証明していません。
