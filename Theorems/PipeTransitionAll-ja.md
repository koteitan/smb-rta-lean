# 地下への切り替えの長さを決めるもの

**主張.** これは部分的な結果です。切り替えは 91 = 48 + 43 フレームです。はじめの 48 フレームで土管のタイマーが切れます。残りの 43 フレームは、リスト `R` の外のすべてのバイトのすべての値について長さを証明しました。はじめの 48 フレームは、挙げた 77 個の入る状態でだけ証明しました。すべての走りのすべての入る状態で 91 になることは、仮定のもとでだけ定理です（`every_entry`）。書き換えた状態の一部と、ゲームタイマーが 000 の状態（コードでは数フレームだけ起こりえます）では成り立ちません（下の表）。

`m₀` は 1-1 の開始の機械です。`run(m, w)` は入力 `w` で本物のフレームを進めた機械です。`ctl(m)` は `controllable` です。`0^k` は入力なしの `k` フレームです。`E` は[地下への切り替え](PipeTransition-ja.md)の、入るフレームの終わりの機械です。`T = run(E, 0^48)` は土管のタイマーが切れたときの状態です。`m[i]` は RAM のバイト `i` です。

`core(m)` は、レジスタ、プログラムカウンタ、ROM、PPU の欄、コントローラのシフト状態、サイクル数の偶奇、フレーム数の偶奇です。`pad` は含みません（フレームが上書きします）。RAM も含みません。下の `core(M) = core(...)` では、`M` の記録が切れていて RAM が 2048 バイトであることも含みます（`SameCore`）。

`T` の*位置* `v` は、フレームの境目のドット `d ≤ 9`、サイクルの偶奇、フレームの偶奇、PPU 制御のミラーの 1 ビット（増分のビット。面の縦の列を書いたあとで立ちます）を決めた `T` です。全部で 80 個です。

`R`（120 バイト）、`RE`（282 バイト）、`Rvar ⊂ R`（81 バイト）は動かして求めます。`Rfix = R \ Rvar`（39 バイト）です。`entries` は `E`、書き換えた 63 個の状態、本物の 13 個の状態です（下に書きます）。

```
decided     :  ∀ T の位置 v, ∀ M :  core(M) = core(v)  ∧  (∀ i ∈ R, M[i] = v[i])
                 →  ∀ k, 1 ≤ k ≤ 43 → ( ctl(run(M, 0^k)) ↔ k = 43 )
ends        :  同じ M で :  ∀ i, (i ∈ R ∨ v からの走りが i を書いた)  →  run(M, 0^43)[i] = run(v, 0^43)[i]
atEntry     :  ∀ M :  core(M) = core(E)  ∧  (∀ i ∈ RE, M[i] = E[i])
                 →  ∀ k, 1 ≤ k ≤ 91 → ( ctl(run(M, 0^k)) ↔ k = 91 )
entryStates :  ∀ m ∈ entries, t = run(m, 0^48) として :
                 ∀ k, 1 ≤ k ≤ 91 → ( ctl(run(m, 0^k)) ↔ k = 91 )
                 ∃ T の位置 v :  core(t) = core(v)  ∧  ∀ i ∈ Rfix, t[i] = v[i]
                 ∀ M :  core(M) = core(t)  ∧  (∀ i ∈ R, M[i] = t[i])  →  ∀ k, 1 ≤ k ≤ 43 → ( ctl(run(M, 0^k)) ↔ k = 43 )
otherPage   :  画面が別のページにある 3 個の状態 :  ∀ k, 1 ≤ k ≤ 91 → ( ctl ↔ k = 91 )
lag         :  6 個の物が近くにある 6 個の状態 :  ちょうどフレーム L で操作できる。L > 91
other       :  1 バイトを立てた 3 個の状態 :  ちょうどフレーム L で操作できる
died        :  ゲームタイマーが 000 :  ∀ k, 1 ≤ k ≤ 100 → ¬ctl

every_entry :  ∀ M, t = run(M, 0^48)、v = t のドット、偶奇、ビットの T の位置 として :
                 (H1) ∀ k, 1 ≤ k ≤ 48 → ¬ctl(run(M, 0^k))
                 (H2) dot(t) ≤ 9  ∧  core(t) = core(v)
                 (H3) ∀ i ∈ Rfix, t[i] = v[i]
                 (H4) ∀ k, 1 ≤ k ≤ 43 → ( ctl(run(t, 0^k)) ↔ ctl(run(t の Rvar を v の値にしたもの, 0^k)) )
               →  ∀ k, 1 ≤ k ≤ 91 → ( ctl(run(M, 0^k)) ↔ k = 91 )
```

`decided` と `atEntry` では、`R` や `RE` の外のバイトは何でもかまいません。`R` には、敵のバイト、マリオの位置と速さ、`HorizontalScroll` のほかの画面の位置、ブロックの地図のバイトがありません。ですから、これらはフレーム 49 から 91 を変えません。

ほかの長さになる場合です。

| `E` を書き換えた状態 | 操作できるまでのフレーム |
|---|---|
| `HalfwayPage` が 0 でない | 75 |
| `WarpZoneControl` が 0 でない | 228 |
| `GameTimerExpiredFlag` が 0 でない | 229 |
| クリボー 6 匹が 0、2、4、8 ピクセルおき | 93、94、92、92 |
| ノコノコ 6 匹が 4 ピクセルおき | 93 |
| ハンマーブロス 6 匹が 4 ピクセルおき | 96 |
| ゲームタイマーが 000 | 操作できない。フレーム 91 で死ぬ（Lean はフレーム 100 まで。エミュレータではフレーム 325 で 1 機減る） |

Lean: `Theorems/PipeTransitionAll.lean`（`decided_of_check`、`end_of_check`、`Statement`、`statement_of_check`、`every_entry`）、非公開の `pipe_all_checks`（`native_decide`）、`pipe_all`、`pipe_all_entries`。`decided_of_check` と `every_entry` が使う公理は `propext`、`Classical.choice`、`Quot.sound` だけです。

## しくみ

**記録した走りが決める.** エミュレータは、走りが書く前に読んだバイトを記録できます。`decided_of_check` はこう言います。`ref` からの記録した走りが `R` のバイトしか読まないなら、`core(M) = core(ref)` で `R` の値が `ref` と同じ機械 `M` は、ほかのバイトが何であっても、毎フレーム同じ値、同じレジスタ、同じ操作の可否になります。証明は、記録する機械と `M` を並べたシミュレーションです。256 個の命令、NMI、PPU の時間、コントローラ、DMA のそれぞれで示します。2 つのカウンタの差は偶数でかまいません。この証明に ROM は出てきません。

**フレーム 48 で切る理由.** フレーム 48 で土管のルーチンが切り替えを始め、ゲームエンジンの残りは飛ばされます。フレーム 49 で面の準備が RAM を消します。この消去は 1 フレームより長くかかり、NMI のないフレーム 50 で終わります。ですから、物、マリオの位置と速さ、画面の位置は、`HorizontalScroll` を 1 回読むほかは、フレーム 48 のあと読まれません。記録でも確かめました。`T` からの走りが読むのは 2048 バイトのうち 111 バイトで、基準の走り全部を合わせても 120 バイトです。最後の 17 フレームは、ルーチン自身の入力で部屋に落ちます。

**確認** はエミュレータで動かします。約 14,600 フレーム、5 秒です。

* `decided`: `T` の 80 個の位置から、記録した 43 フレームの走り。
* `entries`: 77 個の入る状態のそれぞれで、操作できない 48 フレーム、フレーム 48 の比較、記録した 43 フレーム。書き換えた状態は次のとおりです。敵なし。クリボー 2〜5 匹を 0、8、24 ピクセルおき。ノコノコ 5 匹。クリボーとノコノコ。クリボー 5 匹とパワーアップ。大きいマリオ、パワーアップの各段階。スターのタイマー。ファイアボール、ブロックの物、コイン。スクロールの 4 つの位置。マリオのページ。スクロールのバイト。フレームタイマーの 0 と最大値。全体を止めるタイマー。間隔タイマー。フレームカウンタ。数字（全部 0、全部 9、スコア、トップスコア、コイン、ゲームタイマー 999 と 001）。乱数のバイト。音なし。面の音楽 4 つ、イベントの音楽 3 つ、効果音 3 つ、ノイズの効果音。いくつかを同時に。本物の状態は、土管の範囲にあと 0、25、…、300 フレーム立ってから下を押します。

`Rvar` のバイト: フレームカウンタ、音楽の状態、`HorizontalScroll`、全体を止めるタイマー、マリオの大きさとパワーアップ、間隔タイマー、フレームタイマー、乱数、ステータス行の数字。`Rfix` のバイト: ルーチン、モードとタスク、ポーズ、効果音のバッファとキュー、面の指定のバイト、`AltEntranceControl`、面と世界の番号、タイマーの読み直しと時間切れと途中開始のフラグ、画面と PPU のミラー、ジョイパッドのマスク。これらは 77 個の状態のどれでも違いません。（`R` にはスタックのページの 1 バイトもあります。次の命令をオペランドにした命令が読みます。記録には数えられます。下の測定では、どの値でも長さは変わりません。）

**測ったけれど定理にしていないこと.** プログラムで、走りが読むバイトを 1 つずつ、ほかの 255 個の値のすべてにしました。

* `T` から、111 バイト: 長さが変わるのは `OperMode`、`OperMode_Task`、`GamePauseStatus`、`VRAM_Buffer_AddrCtrl`、`GameTimerExpiredFlag`、`HalfwayPage`、`AreaPointer`、`EntrancePage`、`AltEntranceControl` だけです。音、数字、乱数、タイマー、スクロール、大きさ、パワーアップでは何も変わりません。
* `E` から、282 バイト: 上のものと、`GameEngineSubroutine`、`ChangeAreaTimer`、`WarpZoneControl`、`AreaType`、それに `Enemy_ID`、`EnemyFrenzyBuffer`、`EnemyFrenzyQueue`、`AreaParserTaskNum`、音楽のポインタ、面のデータのポインタ、スプライトのオフセット、VRAM バッファの長さのありえない値です。土管のルーチンのままで 91 より短くなるのは、`ChangeAreaTimer` そのもの（44 フレームから）、`HalfwayPage` と `AreaPointer`（75 フレームから）だけです。

TAS 自身の入る状態をプログラムで動かしました。91 フレーム後に操作でき、(H1)、(H2)、(H3) が成り立ち、`R` しか読みません。`Rvar` の 21 バイトが `T` と違い、`T` の値にしても 43 フレームです。ですから (H4) も成り立ちます。

フレームの時間（消去がはみ出すフレーム 49 を除く）: ゲームの処理が終わるドットは、89,342 のうち、`E` と TAS の状態で 67,047 まで、クリボー 5 匹で 80,332 までです。クリボー 6 匹は、16 ピクセル以上離れていれば 88,024 までで、はみ出しません。もっと近いとはみ出します。

## 前提（Lean では証明していない）

* (H1)、(H2)、(H3): 任意の入る状態でのはじめの 48 フレーム。このあいだ敵、物、音が動きます。それらのすべての状態で、タイマーが毎フレーム 1 減ること、フレームがはみ出さないこと、`Rfix` の値が変わらないことは、証明していません。動かしたのは 77 個の状態と TAS の状態だけです。コードから読める理由は次のとおりで、Lean では確かめていません。土管のルーチンは毎フレーム動き、タイマーを 1 回減らします。敵やパワーアップとの当たり判定は、マリオのルーチンが操作のルーチンでないと飛ばされます。
* (H4): `Rvar` の値。`decided` は `T` の値だけ、`entryStates` は 77 個の状態の値だけです。本物の走りの多くは数字や乱数が違うので、(H4) がなければ含まれません。これらのバイトは読まれて分岐に使われるので、記録では外せません。(H4) を支えるのは上のプログラムで、1 バイトずつしか変えていません。
* 本物の走りのどれでも `Rfix` が `T` の値であること。`HalfwayPage ≠ 0` なら 75 です。コードでは、1 機減ったときだけ立ち、次の面が始まるときに消えるので、マリオが土管に入れるときは 0 です。`AreaPointer` は、最初に操作できるフレームですでにこの面のデータの値です（`m₀` で測りました）。効果音のバッファは動かした状態で 0 です。もっと長い効果音がないとは言っていません。
* 本物の走りで 6 個の物が近くに集まらないこと。証明していません。動かした 6 個の状態では、はみ出しは切り替えを長くするだけです。
* ゲームタイマーが 000 でマリオが生きている時間は、本物の走りで 24 フレームまでです。そのとき切り替えのあと操作できません。+91 の例外で、遅くなる側です。
* 入力なしだけです。すべての入力は `E` からだけ、仮定 `Merge` のもとで動かしました（[地下への切り替え](PipeTransition-ja.md)）。Start と Select は含みません。
* 書き換えた状態がそのままたどり着けることは示していません。たとえば大きいマリオはここでは書き換えで、走りで作ってはいません。
* フレームの境目でゲームの処理の途中にある状態は (H2) の外です。画面が別のページの状態も、名前テーブルのビットで (H2) の外です。土管の位置とスクロールのコードから、この土管の本物の入り方では 48 フレームのあいだ画面は 1 つのページにあると読めますが、Lean では証明していません。
* フレームはエミュレータのフレームです。[エミュレータ](../docs/emulator.md)を見てください。
