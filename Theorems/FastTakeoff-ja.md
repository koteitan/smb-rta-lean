# 速いジャンプ

**主張.** 地下の部屋でマリオは床まで落ち、走り、レンガのかたまりに跳び乗ります。全部の入力について、床から 1.5625 ピクセル／フレーム以上で跳ぶと、かたまりの角を間に合うように越えられません。
フレーム 557 で、かたまりの右端に届きません。右に動いているとき、フレーム 500 までのジャンプは、足が低いあいだ、角より左にとどまれません。左に動いているとき、フレーム 500 までのジャンプは
モデルの中にありますが、とても後ろにいるので、そのあと何をしても届きません。フレーム 500 より後のジャンプは、最高速だけで届かないとわかります。

1/256 ピクセルの単位で書きます。走りは次の形です: 落下の空中 `A` フレーム、地面 `g` フレーム、ジャンプのフレーム `T`、空中 `L` フレーム、そのあと目標のフレーム `n` まで何でも。
`v` はフレーム `T − 1` の速さ、`v_A` は空中のしきい値、`c_P` は角、`G_P` は目標、`G` は探索する地面のフレーム数の上限です。「低い」とは、落下のあとから `T + L` までの
全部のフレームで `P < c_P` のことです。

```
no_right_takeoff   :  g ≤ G,  v ≥ v_A,  低い  →  起こらない
left_short         :  g ≤ G,  v ≤ −v_A,  地面の g フレームで P < c_P  →  P(n) < G_P
late_short         :  g > G,  低い  →  P(n) ≤ c_P − 1 + 16·v_top·(n − T − L) < G_P
fast_takeoff_short :  |v| ≥ v_A,  低い  →  P(n) < G_P
```

この部屋では `A = 34`（フレーム 460..493）、`G = 6`（ジャンプは 494..500）、`L = 8`、`n = 557` です。`P` は部屋の最初の位置から始まります。ピクセルの端数は何でもかまいません。
ページは 0 です。`c_P` はかたまりの面データと横の加算値から計算します。`G_P` はかたまりの右端と足の加算値から計算します。`G_P` は、569 で横の土管に入るために 557 で必要な位置です
（[1-1 の道筋](../docs/route-1-1-ja.md)）。

Lean: `Theorems/FastTakeoff.lean`、非公開の `fast_takeoff_right`、`fast_takeoff_goal`（`native_decide`）。

## しくみ

`hstep` は `P` を読みません。そこで `roomCheck` は横の状態ごとに、そこへ来る走りの `P` の最小と最大を覚えます。`Cov` は、この 2 つがその状態を通る全部の走りの `P` をはさむ、という性質です。
この併合で探索は小さくなります。1 フレームの状態は最大 1229 個、`hstep` は全部で約 122,000 回です。

`|v|` が最後のジャンプまでにしきい値へ届かない状態は捨てます。`Φ ≥ |V|` です。フレーム `T − 1` で `|v| ≥ v_A` なら `Φ ≥ θ = 256·v_A − 255` です。`Φ` は 1 フレームに `g_fast` までしか増えません。
`Φ` の上限が `θ` より下のあいだは `g_slow` までです（`keep_of_run`）。これらは [進める距離の上限](Reach-ja.md) の `Facts` から来ます。

フレーム `T − 1` ごとに 2 つを確かめます。

* `rightOk`: しきい値以上で右に動く状態から、ジャンプのフレームと空中 `L` フレームを走らせ、角より左にいるものだけを残します。何も残りません。実は空中 1 フレームで何も残らなくなります。
* `leftOk`: しきい値以上で左に動く状態について、`H` を `P` の最大、`Q` を `Φ` の上限の最大とします。`H + dbound(Q, n − T + 1) < G_P` を確かめます。`dbound` は `|V|` を右向きの速さのように扱うので、
  向きを変えるのにかかるフレームを使っていません。それでも 9 ピクセル以上の余裕があります。

## 前提（Lean では証明していない）

* 定理は、開けた場所の `hstep` の走りについてのものです。`P` は 1 フレームに `16·v` 動きます。本物のフレームがこれに従うことはエミュレータの確認です（`hstep` は TAS と 460 から 557 までの全部のフレームで一致します）。定理ではありません。
* 最初の状態（止まっている、右を向いている、進む向き 0、走りの速さ 0）は TAS のフレーム 459 から読みました。それより前の入力でこれが変わらないことは、道筋の固定長の確認によるもので、定理ではありません。
* `A = 34` とフレーム 494 の床は、入力によらない落下から来ます。エミュレータの確認です。
* `L = 8` は [ジャンプの高さ](Jump-ja.md) の `jump_block3` から来ます。Lean の中で `hstep` とつないではいません。ここで使うのは `late_short` だけです。右に動く場合は空中 1 フレームで足ります。
* ジャンプが速いかどうかは、その前のフレームの速さで決めています。何かに当たった直後のジャンプは、速さとは別に覚えている絶対値を読みます。この場合はこの定理の外です（道筋の手順 5）。
* 角に当たる場合はこの定理の外です。「低い」は当たらないことを仮定しています。道筋の手順 5 で扱います。
* 部屋の左の壁はモデルに入っていません。なので壁に触れる走りはこの定理の走りではありません。探索で左に動いてジャンプするものは全部、エミュレータで壁に止められた位置より左にいます（数回の走りで見ただけで、証明ではありません）。なのでこれらは実際のゲームでは起こらないと思われます。そして壁に止められた走りは、この定理に含まれません。`left_short` は壁を使いません。
