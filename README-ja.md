# smb-rta-lean

スーパーマリオブラザーズのスピードランの事実を、Lean 4 で確かめるプロジェクトです。

## 定理

| 記号 | 定理 | 命題 | 状況 |
|---|---|---|---|
| 1-1 | [fast accel](Theorems/FastAccel-ja.md) | 小さいマリオが、陸のステージの最初のように地面で止まっていて、周りに何もないなら、本物のコントローラで、34 フレームで走りの最高速に達することができ、33 フレーム以下では達することができない。 | 34 フレームでできる: 定理。33 以下は無理: 緩めたモデルでの定理 |
| 1-2 | [TAS fast accel](Theorems/TasFastAccel-ja.md) | 同じ条件で、左右同時押しを許すと、32 フレームで走りの最高速に達することができ、31 フレーム以下では達することができない。 | 32 フレームでできる: 定理。30 以下は無理: 緩めたモデルでの定理。31 は無理: 全探索 |
| 1-3 | [出だしの最適性](Theorems/Opening-ja.md) | 1-1 の最初から、開けた平らな地面で、n ≥ 32 フレームで、マリオは 2.5·n − 41.94 ピクセルより多く右へ進むことはない。TAS の出だしはちょうどその距離を進む。 | 横の 1 フレームの組み立てと、ジャンプの長さの範囲を前提とした定理（探索は約 4 秒） |
| 1-4 | [縦の土管に入る](Theorems/PipeEntry-ja.md) | 下を押していて、上昇中でなく、足が土管の上面の着地の深さにあり、両足が土管の上にあるときに限り、マリオは縦の土管に入る。位置の上限によると、フレーム 367 ではその範囲にまだ 0.44 ピクセル足りない。なのでフレーム 368 より前には入れない。 | 規則に従うフレームについての定理。規則は、土管の上面の近くの全部の状態で判定のルーチンと比べて確かめた（約 3 秒）。368 に届くことはエミュレータでの TAS |
| 2-1 | [地下への切り替え](Theorems/PipeTransition-ja.md) | マリオが縦の土管に入ったフレームから、ちょうど 91 フレーム後に地下で操作できる。本物の走りの 1 つの入る状態では Start と Select を除くすべてのフレームのすべての入力で、ほかの位置、速さ、大きいマリオ、続けてずらした 21 個の入るフレームでは入力なしで示す。 | 1 フレームに 1 状態であることをエミュレータで `native_decide` により確かめた（約 4 秒）。任意の入力については、ボタンをそのまま写すバイトだけが違う状態は同じように動く、と仮定する |
| 3-1 | [空中の速さの上限](Theorems/AirCap-ja.md) | 1.5625 ピクセル／フレームより遅いと、マリオは空中ではそれを超えず、超えられるのは地面のフレームだけ。なので、空中 K フレームとそのあとの n フレームで進むのは、1.5·K ピクセルと n だけで決まる上限の和以下。 | 横の動きのフレームの前提のもとでの定理（約 4 秒の確認） |
| 3-2, 5b-2 | [ジャンプの高さ](Theorems/Jump-ja.md) | 全部の跳ぶ速さと A の押し方について: 旗を上昇中につかめる高さで上昇するフレーム、かたまりに乗れる最も早いフレーム、地面に落ちる最も早いフレーム。 | ゲームの移動ルーチンについての定理、当たり判定なし（約 6 秒） |
| 3-3 | [速いジャンプ](Theorems/FastTakeoff-ja.md) | 地下の部屋で、全部の入力について、床から 1.5625 ピクセル／フレーム以上で跳ぶと、レンガのかたまりの角を間に合うように越えられない。右に動いていると、フレーム 500 までのジャンプは足が低いあいだ角より左にとどまれない。左に動いていると後ろにいすぎる。それより後のジャンプは最高速だけで届かない。 | 横のフレームのモデルの上の定理。最初の状態、落下、足が低い 8 フレームは前提。 確認は約 2 秒 |
| 3-4 | [横の土管に入る](Theorems/SidePipe-ja.md) | 横の土管に入るのは、地面に着地するか立っているフレームで、右を向いていて、右側が土管の口に入っているときだけ。空中では止められる。 | 規則に従うフレームについての定理。規則は、口の近くの全部の状態で判定のルーチンと比べて確かめた（約 3 秒） |
| 5b-1 | [旗を下からつかむ](Theorems/PoleGrab-ja.md) | 旗の土台の横ではマリオは押し戻され、前に進むのは 1 フレームに 1 ピクセルまで。なので着地できる位置には上限があり、小さなジャンプでは進まない。あるフレームで十分に後ろにいれば、間に合う時刻に旗をつかめない。 | 当たり判定の規則に従うフレームについての定理。規則は、土台の近くの全部の状態でルーチンと比べて確かめた（約 4 秒） |
| 共通-1 | [最高速の上限](Theorems/TopSpeed-ja.md) | 動く床やツタ、土管などから離れていれば、マリオは 1 フレームに 2.5 ピクセルより多く右へ進むことはない。最高速で何にも触れずに走ると、ちょうど 2.5 ピクセル進む。 | 各処理の確認: 定理。書き換える処理がそれだけであること: 解析済みコードから |
| 共通-2 | [進める距離の上限](Theorems/Reach-ja.md) | 1-1 の最初から n フレームで、マリオは、最高速の上限と同じ条件では 2.5·n − 23.25 ピクセル（n ≥ 22）、開けた場所では 2.5·n − 38.375 ピクセル（n ≥ 28）より多く右へ進むことはない。 | 最高速の上限と同じ前提、と横の 1 フレームの組み立てを前提とした定理。TAS の入力は 2.5·n − 41.94 ピクセル |

各ページに、主張、Lean が証明していること、前提とその確かめ方、再現のしかたがあります。
1 つの定理は `Theorems/` の 3 つのファイルです: `Name.lean`（主張と、計算からそれが出ること）、
`Name.md`、`Name-ja.md`。

## 共通の部分

* [準備](docs/setup-ja.md) — `smbrta.json` を書き、ROM を置き、`python3 prove.py` を実行する（ROM は含まれません）。
* [エミュレータ](docs/emulator-ja.md) — Lean で書いたファミコンと、その確かめ方。
* [1-1 の道筋](docs/route-1-1-ja.md) — 1-2 が始まるフレームの下界に向けた途中経過（区間ごとに、定理、エミュレータでの確認、未解決）。
* [しくみ](docs/method-ja.md) — ゲームのコードを動かすモデル、たどり着ける状態の証明書、
  緩めたモデル、絞り込んだ正確な探索。

## 構成

```
Smbrta/      ライブラリ: ファミコン（Machine, Cpu）、TAS、名前の表、証明書、モデル
Theorems/    定理ごとに、主張 1 つとページ 1 つ（英語、日本語）
docs/        共通のページ
tools/       値の取り出し、テストデータ
Config.lean  リポジトリの外のファイルの場所（smbrta.json。見本は smbrta-tmpl.json）
Main.lean    コマンド（`smbrta`）
prove.py     smbrta.json から、定理の確認まで全部を実行する
```
