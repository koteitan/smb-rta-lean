# 着地から速いジャンプまでのフレーム

**主張.** 速いジャンプで直接つかむことは、ジャンプの前のフレームについての条件 1 つで除けます。フィールド `reads`（フレーム `T' − 1` の終わりの覚えている速さは空中のしきい値 `A` 以上）です。`PoleJoin.ApproachCases` のフィールド `ground` はなくなりました。代わりのフィールドはありません。踏み切りの前のフレームは、地面で始まらなくてもかまいません。踏み切りは、着地のあとのどのフレームでもかまいません。

`L` は着地のフレーム、`T'` は踏み切りのフレーム、`g` は触るフレーム、`q` は土台より左のフレームです。`abs(j)` は `seq j`（数えるフレーム `j` の終わりの機械）の覚えている速さです。`v₂(j)` はフレーム `j` の移動の終わりの速さです。`P₂(g)` は触るフレームの移動の終わりの位置です。`P₀` は旗の範囲の左端です。`FastLink` は `A ≤ abs(L)` と、フレーム `q < j ≤ L` の `stop_step` と押し戻しの規則です。

```
stored_step        :  1 ≤ j < g   →   abs(j) = |v₂(j)|  ∨  abs(j) = abs(j − 1)
approach_of_cases  :  reads,  L < j < T' の stored_step,  q < j ≤ L の stop_step   →
                        FastLink   ∨   ∃ j,  L < j < T'  ∧  13 ≤ |v₂(j)|
fast_near          :  FastLink,  L + 2 ≤ g,  L のあとのフレームは地面か上昇中   →   P₂(g) < P₀
fast_late          :  L < j < g,  13 ≤ |v₂(j)|,  L のあとのフレームは地面か上昇中   →   P₂(g) < P₀
fast_short         :  速いジャンプ,  g = T' + 1   →   P₂(g) < P₀
```

## 証明の流れ

`stored_step` は `StopRead.stored_end` の 2 つの場合です。地面と、空中で左右を押すときは、フレームは `ImposeFriction` を動かし、覚えている速さ `|v₂|` で終わります。空中で左右を押さないときは、覚えている速さを保ちます。フレームの速さ、状態、ジャンプについては何も求めません。

`approach_of_cases` は踏み切りから逆にたどります。`reads` から `A ≤ abs(T' − 1)` です。`L < j < T'` で `A ≤ abs(j)` のフレーム `j` をとります。覚えている速さを書いたなら、`|v₂(j)| = abs(j) ≥ A ≥ 13` です。保ったなら `A ≤ abs(j − 1)` で、1 つ前のフレームで同じことを調べます。なので、着地のあとのあるフレームが移動の終わりに 13 以上の速さを持つか、`A ≤ abs(L)` です。

* `A ≤ abs(L)`: 着地のあとのフレームは、どれも覚えている速さを保ちました。これから `FastLink` が出ます。前は `T' = L + 1` のときだけ使っていました。`fast_pushes` は、足が土台の中のフレームが毎回押し戻すことを示し、`hop_short` が触る位置を抑えます。`fast_near` はいまはどの `g ≥ L + 2` でも使えます。着地のあとのフレームは、1 つごとに上限を 16/256 ピクセル手前に動かします。
* 着地のあとのフレーム `j` で `13 ≤ |v₂(j)|`。土台の横では、押し戻されて始まるフレームの `v₂` は −12 から 2 です。なのでフレーム `j` は土台の横より左で始まり、フレーム `j + 1` は土台の横より左か、そこから押し戻されて始まります。`hopState_iter` がこれを `g` まで運びます。前の `fast_late` は `j = T' − 1`、`g = T' + 1` のときだけでした。

前は、2 つ目の場合の `j = T' − 1` をフィールド `ground` からとっていました。踏み切りの前のフレームは地面で始まりジャンプを読まないので、`|v₂|` を書く、というものです。いまは、覚えている速さを書いたフレームがどこにあっても、帰納法が見つけます。

## `T'` のジャンプから `ground` が出ないわけ

考えていた道筋はこうです。モデルのフレーム `T'` は踏み切りなので、機械は立っているときに新しく押された A を読む。なのでフレーム `T' − 1` では A を押しておらず、フレーム `T' − 1` の始まりで立っていた。1 つずつ見ます。

1. モデルの踏み切りは機械と結びついていません。`direct` は `q`、`L`、`T'`、ジャンプの道筋 `a`、縦の状態 `u` をデータとして与えます。触る高さと向き（`touchY`、`touchRising`）は、機械と結びついていないフィールドです。なので「フレーム `T'` はジャンプを読む」は新しいフィールドになります。
2. そのフィールドがあれば、「フレーム `T' − 1` はジャンプを読まない」は `PrevKeep` の歩きから出せそうです。フレームの終わりで、前のフレームの A のビット 7 は、プレイヤーのルーチンでのパッドのビット 7 です。これは Lean には書いていません。要らないからです。
3. 「フレーム `T' − 1` の始まりで立っていた」は出ません。`T'` のジャンプから出るのは、フレーム `T' − 1` の終わりの状態が 0 であることです。フレーム `T' − 1` は機械の着地のフレームでありえます。`L + 1 < T'` がこれを除くのは、`L` が機械の最後の着地のときだけです。`L` も機械と結びついていません。

なので、この結びつきはフィールドを 1 つ増やし、`ground` は閉じません。上の場合分けには、どちらも要りません。

## `reads` は残る

`reads` は、モデルのジャンプの種類と機械を結ぶただ 1 つのものです。種類はジャンプの道筋のフィールドです。モデルの踏み切りが読む覚えている速さ `v` について `fast = (A ≤ v)` です（`Jump.arcStart`）。`reads` は、機械の覚えている速さも `A` 以上だと言います。機械のバイトについての主張なので、モデルだけの条件にはできません。

`reads` がないと、1 つの場合が残ります。モデルのジャンプは速く、機械の覚えている速さは `A` より小さい場合です。このとき触るのは `g = T' + 1` です。`T' = L + 1` で、足が土台の中のフレームが 2 つのときを見ます。着地の上限は `P'(L) ≤ P₂(e) − 224 < P₀` で、`hop_short` には `P'(L) < P₀ − 16` が要ります。位置だけでは 16/256 ピクセル足りません。

ジャンプの道筋を機械から読めば、`reads` は出ます。フレーム `T'` がジャンプを読み（1 つの状態）、その縦の 1 歩が機械の覚えている速さでの `vstep` であればよいです。`VertModel.vert_model` がその 1 歩を与えます。その証明は覚えている速さの仮定を使わず、状態 0 からはジャンプを止める値の条件が空です。これはジャンプの道筋（1-1-f-6-3）の仕事です。

## 本物のフレームで

`stop-read-check`（exit 0、29 秒）。触る前の数えるフレームのすべてで `stored_step` を調べます。着地のあとの踏み切りで、`A` 以上の覚えている速さを読むもののすべてで、次を調べます。踏み切りから着地まで逆にたどり、覚えている速さ `|v₂|` で終わる最初のフレームで `|v₂| ≥ A`。そのようなフレームがなければ `abs(L) ≥ A`。`L` は踏み切りの前の、機械の最後の着地です。

| 走り | 回数 | フレーム | `\|v₂\|` で終わる | ほかは保つ | 着地のあと `abs ≥ A` の踏み切り（書いたフレームあり、なし） | 悪いもの |
|---|---|---|---|---|---|---|
| ムービー、操作から触るまで | 1 | 239 | 238 | 1 | 6 (3, 3) | 0 |
| 操作からランダムな入力 | 100 | 29,055 | 28,651 | 404 | 25 (24, 1) | 0 |
| ムービーのフレームからランダムな入力 | 100 | 15,777 | 15,680 | 97 | 28 (26, 2) | 0 |
| ホップ: A を押して離す、右ありとなし | 33 | 5,750 | 5,750 | 0 | 17 (16, 1) | 0 |

2 つの場合はどちらも本物のフレームに現れます。`fast_short` により、`Run` を満たす走りには速いジャンプの直接つかみがありません。なのでそのような走りでは、`reads` を前提つきで使うことはありません。

## 証明していないこと

* フィールド `reads`: モデルの速いジャンプは、`seq(T' − 1)` で空中のしきい値以上の覚えている速さを読む。
* `Run.stored_step` は、`Run.stop_step` と同じく、`frames` の条件（`state`、`collide`）、`keep` の条件（`cleanE`、`noStore`）、触るのは操作できてから `farN` フレーム以内であることを使います。

ROM の新しいチェックはありません。非公開の証明は変わりません。

[ポールのジャンプを機械から読む](f-6-3-PoleJump-ja.md) で、数えるフレームの踏み切りと空中のステップを証明し、速い区分を本物の保存された速さから読む弧を定義しました。フレームの終わりの結果には、縦の5バイトの保存を明示した条件として使います。`Run.direct` の任意の弧の `reads` は残ります。新しい走りのフィールドには置き換えていません。
