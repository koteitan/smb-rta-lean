# ImpedePlayerMove を通る位置

`ImpedePosition.routine_return` は、本物の機械で、呼び出し元に戻るまでの処理を証明します。前提は `Good`、入口のプログラムカウンタ、ROM の検査です。最初のスタックポインタ、フラグ、側と速さのバイトは任意です。

R を入口、B を戻った機械とします。位置 P の単位は 1/256 ピクセルです。検査した分岐で決まる d は −1、0、1 のどれかです。

```
k ≤ 65
pc(B) = returnPc(R)
SP(B) = SP(R) + 2
P(B) ≡ P(R) + 256·d  (mod 2²⁴)
```

速さは、分岐に従って元のままか 0 になります。位置の端数と横のサブ速さは変わりません。d が正なら、入口の符号付き速さは 0 以下です（`positive_only`）。符号付きバイトの境目も、実際の比較命令のとおりです。

`exact_of_mod` は、P(R) が下端から 1 ピクセル以上あり、P(R) + 256 が上端より小さいとき、位置の合同式を等式にします。この余白の条件がなければ、結論は合同式です。

`piece0_spec` は、値が任意で変化しないスタックポインタについて、検査した命令の区間を証明します。検査はスタックの全バイトを追います。入口の 65,536 通り、ピクセルの 512 通り、ページの 1,024 通り、末尾の 1 通りをつなぎます。`routine_return` は、保存したスタックから、呼び出し元への実際の復帰命令も証明します。

`trace_call` は、待機ループ、現在のフレーム、命令を実行する残り時間の条件のもとで、フレーム内の命令列にある呼び出しにこの結果を使います。`ordinary_step` は、位置の 3 バイトに書かない 1 命令が位置を保つことを言います。どちらも局所的な結果です。スクロール処理のあとの全命令がこの条件を満たすことは、まだ証明していません。

`positive_effect` は、入口の速さが正なら、速さを保つ場合は位置も保ち、速さが 0 になる場合はちょうど左へ 1 ピクセル動くことを証明します。`SurfaceFrames.AfterP.impede_return` は、位置の余白の条件から、呼び出し一回について既存の `AfterP` の関係を与えます。この関係の最初の機械は、スクロール処理ではなく呼び出しの入口です。フレーム全体のフィールドは外していません。

## 残ること

`SurfaceFrames.AfterP` と `CollideS` は前提のままです。呼び出しは複数回起こりえます。スクロール処理の位置とフレーム開始時の位置との関係が必要です。[画面端の補正](e-2-10-3-4-ScreenClamp-ja.md)、つた登り、足場、移動処理の添字付き書き込みもつなぐ必要があります。この結果では `Route.Run` のフィールドを増減していません。

**ファイル:** `Theorems/ImpedePosition.lean`、非公開の `Proof/ImpedePosition.lean`。

## 実データでの検査

`pos-after-real FM2 200` は TAS と自作の入力で 128,679 フレームを検査しました。押し戻しは 3,053 回、画面端の補正は 13,551 回です。入口の `Good`、復帰、速さ、端数、位置の合同式、余白と補正先の範囲の失敗は 0 回でした。スクロール処理のあと、二つの処理の外で位置に書く命令も 0 回でした。実行は終了コード 0 です。対象は、操作できる状態で始まり、ルーチン・モード・タスクに書かないフレームです。これは実行例の検査であり、全フレームについての証明ではありません。

ROM の検査は、押し戻しが 430 ms、画面端の補正が 6 ms で、ともに真でした。二つの非公開の事実は `native_decide` で生成します。実データで見た補正は一方の画面端だけで、ROM の検査と一般定理は両方を扱います。

[PositionPieces](e-2-10-3-5-PositionPieces-ja.md) は、復帰の合同式と位置の余裕から正確な一回分の効果を出し、フレームの切れ目で明示した効果を足します。すべてのフレームで切れ目を作ることと、全体の上限は未証明です。
