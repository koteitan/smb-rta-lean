# 1-1 全体: 1-2 は 1748 より前に始まらない

**命題.** 走りが `Run` の全部の仮定を満たすなら、1-2 が始まるフレーム `L` について `L ≥ 1748 + j` です。`j` は、タイマーが動かないフレームのうち、切り替えの 1 フレームずつを除いた数です。TAS は `j = 0`、`L = 1748` です。

**これは仮定つきの定理です。** `Run` の仮定を全部の走りについて証明してはいません。このページはその仮定の一覧です。

フレームは 1-1 で最初に操作できるフレームを 0 として数えます。`E` はすべてのフレームを数えた番号です。`E_a`、`C_r`、`E_b`、`C_s`、`g`、`c` は `lag` のフレーム（`j` に数えるフレーム）を除いて数えた番号です。

```
P₁ = E_a                 縦の土管に入るフレーム
X₁ = C_r − E_a           地下への切り替え
P₂ = E_b − C_r           地下で操作できてから横の土管まで
X₂ = C_s − E_b           地上への切り替え
P₃ = g                   地上で操作できてから旗に触るまで
W  = c − g               触ってから城まで
E  = C_s + c + j         城に入るフレーム
T                        E でのタイマー
c_E                      E でのインターバルタイマーの位相
```

定理のつながり:

```

X₁ ≥ 91                                                        Run.change₁（パート b。1 フレームごとの仮定から）
P₂ ≥ 111                                                       room_join（パート c）
X₂ ≥ 282                                                       Run.change₂（パート d。1 フレームごとの仮定から）
(g ≥ 234 ∧ W ≥ 132) ∨ (240 ≤ g ≤ 241 ∧ W ≥ 126) ∨ (g ≥ 242 ∧ W ≥ 125)    pole_touch_castle（パート e、f）
E = P₁ + X₁ + P₂ + X₂ + P₃ + W + j                             Run.hE（clock の規則から）
401 ≤ T + ⌈P₁/24⌉ + ⌈P₂/24⌉ + ⌈P₃/24⌉                          Run.hT（clock の規則から）
─────────────────────────────────────────
E + T ≥ 1588 + j                                               sum_ge
(c_E + E) mod 21 = (3 + j) mod 21                              Run.hc（clock の規則から）
```

`E = C_s + c + j`、タイマーの式、格子の式は `Run` のフィールドではなくなりました。`clock` から証明します（`Run.hE`、`Run.hT`、`Run.hc`）。`D ≥ 33` とレベルが変わるフレームの式は `flag` から証明します（`Run.hD`、`Run.hL`）。`change₁` と `change₂` もフィールドではなくなりました。`chg` から証明します（`Run.change₁`、`Run.change₂`）。`level_ge_of_parts` はこのほかに `2 ≤ q ≤ 90` を使います。ゲームの値で計算して確かめます。また ROM での確かめ `pipe_end`、`side_bound`、`side_end`、`side_start`、`RoomChecks`（`screen_facts`、`screen_timer_same`、`screen_rt`）、`flag_checked` と、星の旗の待ち時間が 6 以上であることを使います。これらは非公開の定理で、仮定ではありません。

`route_1_1` は `Merge`、`GMerge`、`Cond`、H3 を使いません。`Run` のフィールドにも定理の引数にもありません。6 個の物が近くに集まらないことも使いません。はみ出すフレームは `lag` のフレームで、`keep₁` と `keep₂` が扱います。これらはちょうどの長さの定理のものです。

## 2 つの切り替え（`chg`）

`chg` には本物の機械の列が 1 本あります。`seq n` はフレーム `n` が始まるときの機械で、`seq (n + 1)` はフレーム `n` が残したものです。`clock` と同じです。`r(n)` は `n` より前の `lag` でないフレームの数です（`seen`）。

```
seq(n + 1) = frame(seq n, inp n)
r(a₁) = E_a + 1,   r(b₁) = C_r + 1,   r(a₂) = E_b + 1,   r(b₂) = C_s + 1
entry₁ : Entry(seq a₁)                     ctl₁ : ctl(seq b₁)
entry₂ : Entry2(0, seq a₂)                 ctl₂ : ctl(seq b₂)
room : Room(seq b₁),  b₁ ≤ n < a₂ → (∀ j, SiteOK(trₙ(j))) ∧ rt(seq n) = rt(r)
keep₁ : a₁ ≤ n < b₁ ∧ kind(n) = lag  →  left₁(seq n) ≤ left₁(seq(n + 1))
places₁ : a₁ ≤ n < b₁ ∧ inPipe(seq n)  →  ∀ j, Places(trₙ(j))
noStart₁ : a₁ ≤ n < b₁ ∧ coreFrame(seq n)  →  inp n に Start はない
quiet₁ : a₁ ≤ n ≤ b₁ ∧ ExitAt(seq n)  →  Quiet ∧ Song ∧ Shape (seq n)
keep₂ : a₂ ≤ n < b₂ ∧ kind(n) = lag  →  left₂(seq n) ≤ left₂(seq(n + 1))
noStart₂ : a₂ ≤ n < b₂ ∧ coreFrame(seq n)  →  inp n に Start はない
quiet₂ : a₂ ≤ n ≤ b₂ ∧ ExitAt(seq n)  →  Quiet(seq n)
first₂ : a₂ ≤ n < b₂  →  left₂(seq n) ≠ 0
```

ここから:

```
E_a + 91 ≤ C_r                                               Run.change₁（PipeRun.bound と pipe_end）
timer(seq a₂) ≥ 160                                          ScreenPage.entry_long（room と RoomChecks）
─────────────────────────────────────────
E_b + 282 ≤ C_s                                              Run.change₂（EndRun.bound と side_bound、side_end）
```

`left` はフレームの境目で読みます。ルーチンがはみ出すフレームはルーチンの途中で終わり、次のフレームが `lag` のフレームです。

**`lag` のフレームは `left` を変えません。** 各切り替えで、インターバルタイマーの位相が動かないフレームのうち、`left` が減るのは 1 つだけで、それが `setup` です。これは数えるフレームで、その番号が `z₁`、`z₂` です。ほかのそういうフレームでは `left` は変わりません。`change-scenes` は、本物の入る状態から、入力なし、ランダムな入力、Start を 2 回、はみ出すように 6 個の物をあるフレームに書いた場合で、これを示します。

| 切り替え | 走り | フレーム | はみ出した走り | `lag` のフレーム | `left` が減った `lag` のフレーム | `left` が 2 以上減ったフレーム | 操作までの最小（`lag` を除く） |
|---|---|---|---|---|---|---|---|
| 地下へ | 237 | 24,767 | 67 | 3,200 | 0 | 0 | 91 |
| 地上へ | 356 | 125,628 | 54 | 26,176 | 0 | 0 | 282 |

調べていないこと:

* フレームがはみ出したのは、物を書き込んだ状態だけです。書き換えのない走りでは、切り替えの中のこういうフレームは、ポーズのほかは `setup` だけです。
* 地上への切り替えの最後の 122 フレームでは、6 個の物を書いてもはみ出しませんでした。ここの `lag` の規則はポーズでだけ確かめました。

これらのフィールドは 1 フレームごとの仮定で、証明していません。`seq` と `pipe`、`room`、`pole` のつながりはフレームの番号だけです。

## 仮定が空でないこと

`route-check` は、本物のフレームから `Run` の数を読みます。

| 走り | 操作の変わり目 | 触る | 城 | T | E + T | 1-2 |
|---|---|---|---|---|---|---|
| TAS | 368, 459, 570, 852 | 1092 | 1218 | 370 | 1588 | 1748 |
| TAS の 1089 のあと、左、A、A、A | 368, 459, 570, 852 | 1093 | 1219 | 369 | 1588 | 1748 |

どちらも数の仮定を全部満たし、`L` は式と一致します。`route-check` は `chg` も読みます。`a₁, b₁, a₂, b₂` = 369, 460, 571, 853 で、`lag` を除いて 1 を引くと 368, 459, 570, 852 です。入るときの `left` は 91 と 282 で、条件はどちらも成り立ちます。`z₁, z₂` = 418, 732 で、位相が動かないほかのフレームはなく、`left` が 2 以上減るフレームもありません。`changes-check FM2 pause F D` は、380、416、450、575、730、845 のポーズで同じ数を、50 または 60 の `lag` のフレームとともに出します。切り替えの中には Start を受けつけないフレームがあり、そこではムービーがずれて、確認は 2 つめの切り替えを終えずに終了コード 1 で終わります。`clock` の規則は、どちらの走りでも全部のフレームで成り立ちます（作業用のプログラム）。地上の構造は `pole-join-check` で、同じ走りに成り立つことを確かめました。部屋の構造は TAS について、リポジトリに入れていない作業用のプログラムで確かめました。全部のフィールドを Lean の項として TAS から作ってはいません。

## いちばん危ない場合

和 `E + T` に余裕はありません。1 小さいと 1-2 は 1727 です。和を 1 小さくする場合が 1 つだけあります。

```
g = 241,  W = 125   →   E = 1218,  T = 369,  和 1587
```

`W = 125` は実際に起こります。左に動いていない遅いジャンプで、端数が 176/256 ピクセル以上のときです（位置を書き換えた本物のフレーム）。これを除くのは `slow_tight` で、`g ≤ 241` では前のフレームで左に動いていて端数が 176/256 ピクセルより小さいことを示します。このとき `W ≥ 126` であることは `flagTight` の仮定で、測定です。

土台の高さの落下が 3 フレーム以下であること（`fall`、`fallCheck`）もここで使います。

TAS の 1085 の状態から位置を 16/256 から 160/256 ピクセルまで 10 通り動かし、A、B、左、右の全部の入力で 1093 まで調べました。1092 と 1093 のどの触りも `W ≥ 126` でした。
