# 実際の当たり判定の読みでの地図の値

`RoomBlocks.blocks_trace` は、既存の「コイン以外の地図のバイトは保たれる」という不変条件を、開始時と同じフレーム内にいる各命令で使える形にします。前提は `blocks_frame` と同じです。検査した歩きとコード、開始時の部屋の状態、各命令の `SiteOK`、開始時の `Solid` です。元のフレーム終端の定理は変えていません。

`blocks_run_trace` はこれを部屋のフレーム列に使います。`Route.Run.roomBlocksTrace` は、その Run に対する補題です。部屋で最初に操作できるフレームから横パイプに入るフレームの直前まで、各フレーム内にいるすべての命令で、コイン以外のバッファのバイトは地図と一致します。Run のフィールドは足していません。既存の `Run.roomBlocks` は、最後の境目も含めてフレームの境目を扱います。

## 実際の命令列で返るタイル

`RoomCollision.frame_returned_map` は、命令ごとの不変条件を[当たり判定の呼び出し全体](c-7-5-8-RoomCollision-ja.md)と合わせます。`Route.Run.roomCollisionMap` は、既存の部屋のフィールドから不変条件と時間の上限を与えます。

そのフレーム内の実際のプレイヤーの呼び出しで、次を前提とします。

- 当たり判定の処理の検査、`Good`、入口のプログラムカウンタ、プレイヤーの番号。
- 待機ループの検査。これは既存の `RoomPair.VChecks.idle` にある事実です。
- 入口の位置と ROM のずれから計算した添字がバッファ内にあり、その地図のバイトがコインではないこと。

すると、同じフレームの命令列で実際に読み、元の呼び出し元に復帰し、A はその地図のバイトになります。読みまで 93 命令以内、そのあと復帰まで 25 命令以内です。実際の読みでの `Solid` は証明から導きます。新しい Run のフィールドとして仮定してはいません。命令を実行する時間の上限も、既存の `roomSites` から出ます。

## 着地に残ること

`land_at` には、着地のフレームで到達する特定の足の呼び出し、そのずれの添字、その呼び出しでの移動後の位置が必要です。計算した添字が床のコインでない場所になることと、呼び出し元のタイルの判別と着地の書き込みをフレームの終わりまで追うことも必要です。読みの時点で地図と一致することは証明できました。正しい呼び出しの選択、場所の特定、その後の分岐は残ります。`stand_wall` と `wall` も残ります。フレーム全体の着地探索は始めていません。

**ファイル:** `Theorems/RoomBlocks.lean` と `Theorems/RoomCollision.lean` への追加、新しい `Theorems/RoomCollisionMap.lean`。Run の補題は新しい補助ファイルに置き、`Route.lean` と元の型は保っています。

## 検査の結果

`room-floor-check FM2 60` は終了コード 0 でした。TAS と自作入力の 59,811 フレームで、82 回のコインの消去、410,104 回のプレイヤーの呼び出し・読み・復帰を調べ、食い違いと未完了は 0 回でした。既存の ROM の検査も真で、2,572 ms でした。新しい補題のために検査や探索は増やしていません。
