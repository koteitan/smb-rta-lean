# 操作の始めに画面の左端は彼の後ろ

**主張（第 25 回）.** 地上のフレーム（`SurfaceFrames.OnFrames`）のフィールド `edge₀` は定理です。edge(m) = 256·left(m) + 255 とします（`SurfaceRead.edgeOf`。left(m) は画面の左端のピクセルとページで、m のプログラムの中で見つけた補正の 2 つのオペランドで読みます、`ScreenClamp.places`）:

```
edge_zero :  Start(B, m)  ∧  StartK(m0, m)  ∧  Numbers(m0, B, J)   →   edge(m) ≤ P(m)
AreaRun.edge₀ :  0 < g  →  edge(seq 0) ≤ P(seq 0)                  （OnFrames.areaRun で証明）
```

`Start(B, m)` は、横の土管からの切り替えの行が与える操作の始めの状態です（`Route.Run.start`）。`StartK(m0, m)` は、m が操作できるフレームを始めることです（`FrameKeep.StartK`）。`Numbers` は、操作の始めの機械 `B.m` の ROM の確認 `numbersCheck` が言うことです。

**証明.**

- `Start` にフィールドが 2 つ増えました: `edgeX` と `edgeP`。`B.m` のプログラムで見つけた補正の 2 つのオペランドで、m は `B.m` のバイトを持ちます。行の確認（`rowStart`）は、操作のある行のどの状態も、この 2 つのバイトを `B.m` の値で知っていることを求めます。`start_of_state` はそこから 2 つのフィールドを証明します。この確認は `rowsStart` の一部なので、`startCheck`（[1-1-d-2-3](d-2-3-SideChangeEnd-ja.md) の行）と `SideChangeSound.startCheckK`（音の表つきの行、[1-1-d-3-4-2](d-3-4-2-SideChangeSound-ja.md)、ルートが使う方）の一部です。
- `numbersCheck` は `B.m` についてさらに 3 つを確かめます: `B.m` は `m0` のプログラムとプログラムのマスクを持つ（`Numbers.prgB`、`Numbers.maskB`）。edge(B.m) ≤ P(B.m)（`Numbers.edgeB`）。
- 操作できるフレームを始める機械は、`m0` のプログラムとマスクを持ちます（`StartK` のフィールド `prg`、`mask`）。補正のオペランドはプログラムだけから読みます（`SurfaceRead.places_congr`、`findOp_congr`）。なので m のオペランドは `B.m` のものです。なので edge(m) = edge(B.m) ≤ P(B.m) = P(m) です。
- 数えるフレームがあるとき、操作の始めの機械は操作できるフレームを始めます: 0 < g なら、触るフレームまでの `K` のフレームはそう始まり（引数 `hst`）、その最初は `seq 0` です。`OnFrames.areaRun` は `Numbers`、`Start`、`hst` から `AreaRun` を作り、この結果を `edge₀` として持ちます。`OnFrames.readAllB`、`OnFrames.edge_behind`（新しい引数 `Ar`）、`surface_of_frames` は前のフィールドの代わりにこれを使います。`Surface.base₁` は 1 ≤ g のときに求めます。それを使うただ 1 つの場所（`PoleJoin.hB_of_line`）には 1 ≤ e ≤ g のフレームがあります。

**フィールド.** なくなった: `OnFrames.edge₀`。増えた: なし。変わった（すべて証明済み）: `Start`（`edgeX`、`edgeP`）、`numbersCheck` と `Numbers`（`prgB`、`maskB`、`edgeB`）、`AreaRun`（`edge₀`）、`Surface.base₁`（1 ≤ g のときに求める）。

**測ったこと.** 第 24 回、非公開の機械での native のチェックで、[1-1-d-2-3](d-2-3-SideChangeEnd-ja.md) の行が操作の始めに 2 つのバイトを知っていることが分かりました。第 25 回、音の表つきの行も入れてもう一度走らせました（非公開のプロジェクトの一時ファイル、走らせたあと消した）: 3 つの行のリストすべてが、操作のあるどの状態でも両方のバイトを `B.m` の値で知っていて、edge(B.m) ≤ P(B.m) で、`B.m` は `m0` のプログラムを持ちます（exit 0）。操作の始め（動画のフレーム 852）で edge − P = −14081 です: 彼は端より 56 px 右にいます。

## フィールド `edge`（1 フレーム）は残る

```
edge :  1 ≤ j < g  →  edge(seq j) ≤ max(base(seq (j − 1)), P(seq j))        base(m) = max(P(m), edge(m))
```

**コードがすること（コードから読んだ。スクロールの処理がすることは [1-1-e-2-10-3-12](e-2-10-3-12-ScrollRule-ja.md) で証明した。ほかは証明していない）.** スクロールの処理は、プレイヤーのルーチンの終わり（`Q`）の最初の呼び出しです。左端を Y px 動かします。0 ≤ Y ≤ X で、X はこのフレームの動きの整数ピクセル（ジャンプ台が動かないとき）に、足場がスクロールに加える力を足したものです。Y は X か X − 1 で、X = 1 なら 1 です。動かすのは 4 つのバイトが許すときだけです: スクロールの止めが 0、画面の上の彼の場所のバイトが 80 以上、横の当たりのタイマーが 0、1 ≤ X ≤ 128（バイトとして）。画面の上の彼の場所のバイトは、前のフレームでプレイヤーを描くとき（プレイヤーのルーチンと敵のあと）に書かれます。それはそのときの pixel − left の 256 での余りです。当たったあとプレイヤーが点滅するフレームでは書かれません。スクロールのあと画面の端の補正が走り、そのあと当たり判定のルーチンが走ります。

**1 フレームの証明がこの回に入らない理由.**

- 画面の上の彼の場所のバイトは前のフレームから来ます。なので証明には、そのバイトと各フレームの始めの位置の関係（フレームからフレームへの不変条件）か、それを言う 1 つの状態の新しい条件が要ります。
- 端より 1 px 左で始まるフレーム（測ったフレームの始め 5,440、[1-1-e-2-10-3-10](e-2-10-3-10-ScreenEdge-ja.md)）では、そのバイトは 255 で、80 以上です。そこでスクロールを止めるのは横の当たりのタイマーだけです: 彼をそこに置いた押し戻しがそれをセットします。なのでその関係にはタイマーも要ります。
- 端の 2 つのバイトは、フレームの始めから `Q` まで追われていません: `CtrlKeep` の歩きがプレイヤーのルーチンまで保つバイト（`CtrlKeep.keepA`）にも、`FrameKeep.guardE` が守るバイトにも入っていません。`AfterKeep` の歩きは `Q` からフレームの終わりまで 1 つのバイトを追い、そのバイトへのどの書き込みでも止まります。スクロールは `Q` のすぐあとで両方のバイトを書きます。なので `Q` までの保ちには `keepA` の新しいバイト（すべてのパートの歩きが変わる）が要り、スクロールのあとの保ちには、スクロールの書き込みのあとから始まる歩きと、`guardE` の守るバイト 2 つ（フィールド `keep.cleanE` がより多くを求める）が要ります。
- スクロールの規則そのもの（Y とその条件）は、この回に、それらのバイトを分かっている値にして ROM のコードを区切って証明しました: [スクロールの規則](e-2-10-3-12-ScrollRule-ja.md)（`ScrollRule.scroll_rule`。スクロールの処理の呼び出し全体、呼び出しの次の命令まで、端を位置にして: `ScrollRule.scroll_edge`）。上のほかの 3 つは残ります。スクロールのあとの保ちは、いまは呼び出しの次の命令からだけ要ります。

## 1 フレームの押し戻しの数と `Moves.stop` は残る

コードでは、当たり判定のルーチンは押し戻し（`ImpedePlayerMove`）を多くて 1 回呼びます。足場のルーチンはもう一度呼べます。スクロールの処理からあとの歩きはオブジェクトを知らないので、そのルーチンに来ます。押し戻しの数の上限には、オブジェクト（敵の枠に足場がないこと）を歩きの状態の分かっている部分にすることが要ります。`Moves.stop` はその上限を要ります。どちらも残ります。下に測ったこと: 1 フレームの呼び出しのいちばん多い数。

`edge-real FM2 256`（exit 0、native で 44 分、67 MB。第 24 回と同じ走りで、どのフィールドも成り立つ）。端が動いたのは 137,955 フレームのうち 11,289 で、戻ったことはなく、1 フレームに多くて 3 px で、そのフレームの彼の動きより多く動いたことはありません（left(b) − left(a) ≤ pixel(Q) − pixel(a)）。走りの最初のフレームのほかのどのフレームの始めでも、画面の上の彼の場所のバイトは pixel − left mod 256 でした。P の単位は 1/256 px です: 端が動いたフレームでのいちばん小さい P(b) − edge(b) の 20,225 は 79 px です。
