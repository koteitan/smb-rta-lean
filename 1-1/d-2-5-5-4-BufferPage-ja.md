# コインを消したフレームはページ 0 で終わる

**主張.** 部屋のフレームが、画面のバッファの制御 0 か 6 で始まり、制御 6 で終わるなら、ページ 0 で、ページ上の位置 16 から 180 px で終わります。証明しました。ROM の確認は 1 つです（[BufferEnd](d-2-5-5-3-BufferEnd-ja.md) の歩き 2 つにページを加えたもの。ネイティブで約 100 秒）。フレームの始めのページはどの値でもかまいません。そこでフィールド `buffer₂` はなくなりました。横の土管に入るフレームは制御 0 で始まり、入口での最初の画面のバッファの 5 バイトは証明されます。

名前は [BufferEnd](d-2-5-5-3-BufferEnd-ja.md) のものです。`c` は画面のバッファの制御、`x(m)` はページ上の位置、`page(m)` はページです。`Q` は動きの終わり（`PlayerSubs`）です。

## 主張の式

```
finX(B)      :=  c が 6 でないと分かっている   ∨   （x の区間が内側   ∧   ページが 0 と分かっている）

end_frame    :  walkE(r'),   RoomCond(r', K_B, m),   ∀ j, SiteOK(tr(j)),   c(frame m i) = 6
                →   16 ≤ x(frame m i) < 181   ∧   page(frame m i) = 0
end_of_rows  :  [b, a) で RoomMap.map_of_rows の条件,   keepCheck,   startCheckC,   endCheck,   b ≤ n < a,   c(seq(n + 1)) = 6
                →   16 ≤ x(seq(n + 1)) < 181   ∧   page(seq(n + 1)) = 0

Run.end₂     :  c(seq(a₂ − 1)) = 6   →   16 ≤ x(seq(a₂ − 1)) < 181   ∧   page(seq(a₂ − 1)) = 0
Run.buf₂     :  EntryAt(L₅, seq a₂)                                                  （定理。フィールド buffer₂ はなくなった）
```

`Run.buf₂`: `c(seq(a₂ − 1)) = 6` なら、`Run.end₂` からページ 0 で 16 ≤ x < 181 です。`Run.coin₂`（ラウンド 24）によれば、そう始まるフレームは入りません。しかしこのフレームは入ります。だから制御は 6 ではありません。`Run.ctl₂` から制御は 0、つまり基準の値で、`EntryBuffer.buffer_of_rows` が 5 バイトを与えます。

Lean: `Theorems/BufferEnd.lean`（`MX` の `pI`、`xSbc`、`pSbc`。`pageSplit`、`cov_pageSplit`、`zoneX`、`finX`、`fin_spec`、`end_frame`、`end_step`、`end_of_rows`）、`Theorems/Route.lean`（`Run.end₂`、`Run.buf₂`。フィールド `buffer₂` を消した）。非公開の確認は今も `Proof/BufferEnd.lean` の `buffer_end_check` です。公開のファイルにゲームのデータはありません。

## しくみ

**スクロールの処理は当たりの処理より前にあります.** プレイヤーのルーチンでは、動きの終わりのあとにスクロールの処理があり、そのあとに当たりの処理があります。部屋ではスクロールは止まっていて、画面の端は部屋の条件で分かっています（左の端はページ 0、右の端は同じページで 255 ピクセル先）。スクロールの処理は、画面外のビットのルーチンに、プレイヤーが 2 つの端に対してどこにいるかを聞きます。画面の外にいれば、端に置きます（クランプ）。クランプは端のページを書きます。

**ページ 0 以外はどれも左の端へのクランプで終わります.** スクロールの処理でのページを p とします。

* p が 1 から 128: 右の端に対してページの差が負です。ビットは「画面の外」で、左の端へのクランプがページ 0 を書きます。
* p が 129 から 254: 右の端より 1 ページ以上左にいて、左の端より 1 ページ以上左にいます。ビットはやはり「画面の外」で、クランプがページ 0 を書きます。
* p = 255: 左の端に対してページの差は 0 か 1 です。1 ならビットは「画面の外」です。0 ならピクセルの差から上のビットが立ったビットが出ます。クランプがページ 0 を書きます。
* p = 0 は、クランプがあってもなくても 0 のままです。

**コインのフレームがページを書くのはそこだけです.** 頭、足、横の読みでコインを見つけると、消去に行き、当たりのルーチンから戻ります。横の当たりでの押し戻しも戻ります。だからコインを消すフレームは押し戻さず、スクロールの処理のあとはページを書きません。

**歩き.** 抽象機械は、2 つのバイトのビットが全部分かっているときだけ引き算をします。そこで画面外のビットのルーチンで、右の端から位置を引くところ（`xSbc`、プレイヤー、`X = 0`、`Y = 1`）で、位置の区間が `[16, 181)` の内側でページが分かっていなければ、ページを 256 の値に分けます（`pageSplit`）。ページ 128 と 255 では位置も値に分けます。そうしないと、最初の引き算の分からない借りが、本物の機械が通らない道を作り、その道ではページが変わらないからです。ページを引くところ（`pSbc`）で、ページが分かっていて 0 でなければ、キャリーを分けます。すると上の表のとおりにすべての道が終わります。フレームの終わりで `finX` は、制御が 6 かもしれないときにページが 0 と分かっていることを求めます。2 つの歩き（制御 0 からと 6 から）は通り、制御が 6 かもしれないフレームの終わりではどれもページが 0 と分かっています。

**探索（証明の一部ではない）.** キーはページを分けて持ちます。画面外のビットのルーチンとスクロールの処理では、レジスタ、フラグ、位置、ピクセルの差も持ちます。スクロールの処理からの呼び出しで、上のビットが立ったビットを読むところでは、次に左の端へのクランプが来ます。そこで状態はページ、位置、ピクセルの差、A、4 つのフラグを忘れ、256 に分けた状態はまた 1 つになります。ページが分かっていて 0 でない状態は、合流するまで表を使わずに進めます。この合流がないと、確認はネイティブで 491 秒かかりました。

**大きさ.** 制御 0 からの歩き: 3,012,444 段、探索の状態 371,378、失敗 0、18.5 秒。制御 6 から: 3,620,300 段、439,580 状態、失敗 0、22.9 秒（ラウンド 25: 1,218,211 段と 1,776,901 段）。メモリは最大 2.3 GB。制御が 6 かもしれないフレームの終わりは 168 と 84 で、どれもページが 0 と分かっています。2 つの歩きの確認はネイティブで 83 秒です（ラウンド 25: 68 秒）。非公開の `Proof.BufferEnd` は `prove.py` 全体の中で 120 秒でした（ラウンド 25: 80 秒）。数秒より長いです。

**表（証明の一部ではない）.** 確認は表を畳み込みで作っていました。その累積は組で、射影で読んでいたので、追加のたびに配列がコピーされ、時間は表の大きさの 2 乗で増えました。今は先に組を分解します。表の作り方を変えただけで、表の中身は同じです。同じ変更を `BufferCoin`（ラウンド 24 の確認: ネイティブで前 89 秒、後 32 秒）、`EntryHeight`、`EntryHeightBig`、`RoomPause`、`ScreenPage` にもしました。同じ畳み込みは `RoomMap`、`RoomVert`、`SideEntryRest`（ほかのパートのファイル）に残っています。

## 測ったこと（定理ではない）

`buffer-ctl-check FM2 300 real`（終了コード 0）: 映像の部屋と、部屋での映像のフレームから始めた自前の走り 1,200 本（種類 0 と 1、小さいと大きい、300 本ずつ）。[BufferEnd](d-2-5-5-3-BufferEnd-ja.md) と同じです。

| 走り | フレーム | 入る | コインのフレーム（終わりで制御 6） | そのうちページ 0 の 16 から 180 px で終わるもの | 制御 6 で始まる入るフレーム |
|---|---|---|---|---|---|
| 映像 | 111 | 1 | 13 | 13 | 0 |
| 種類 0、小さい | 125,891 | 102 | 1,019 | 1,019 | 0 |
| 種類 0、大きい | 113,761 | 126 | 1,229 | 1,229 | 0 |
| 種類 1、小さい | 66,202 | 218 | 1,178 | 1,178 | 0 |
| 種類 1、大きい | 69,677 | 208 | 1,245 | 1,245 | 0 |

これらの走りでは、どのフレームもページ 0 で始まります。だから定理の、始めが別のページの場合には届きません。`buffer-ctl-check FM2 1000 page`（終了コード 0、新しい）は、それを自前の状態で調べます: 映像の部屋のフレーム（小さいか大きい）のページと位置を乱数のバイトで書きかえ（ページの半分は 0）、乱数の入力で最大 40 フレーム進めます。2,000 本、78,664 フレーム。4,291 フレームがページ 0 以外で始まり、3,310 フレームがページ 0 以外で終わります（どれもページ 255: 左の端の壁の中に置かれて左に押し戻されたもの）。2,355 フレームが制御 6 で終わり、どれもページ 0 の 16 から 180 px で終わります。そのどれもページ 0 以外では始まりません: ページ 0 以外で始まるフレームはクランプで左の端に置かれ、そこではコインを読みません。

だから部屋の条件のどの状態でもどのフレームでもページが 0 というわけではありません。ページ 0 で終わるのはコインを消すフレームだけです。どのフレームでもページを保つには、壁の近くの位置の範囲が要ります。
