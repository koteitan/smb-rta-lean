# 部屋のフレームでのジャンプを止める値と前のフレームの A

**主張.** 隠し部屋で入るより前の各フレームの終わりで、機械について 2 つの関係が成り立ちます。ジャンプ中ならジャンプを止める値は 1 です。前のフレームの A のビット 7 は A のビット 7 と同じです。[ジャンプの最初のフレーム](c-7-5-1-RoomVert-ja.md) はフレームの始まりでこの 2 つを使います。これは [部屋をつなぐ](c-5-RoomJoin-ja.md) のフィールド `halt` と `prevA` でした（項目 1-1-c-7-5）。今は走りの本物の機械の上の定理です。新しい仮定はありません。証明は [ブロックの地図](c-7-12-RoomMap-ja.md) がすでに使うものだけを使います。

`st` はプレイヤーの状態、`d` はジャンプを止める値（`DiffToHaltJump`）、`p` は前のフレームの A（`PreviousA_B_Buttons`）、`a` は A と B（`A_B_Buttons`）です。`fm(n)` は部屋のフレーム `n` の終わりの機械、`C` は最初の操作、`E` は入るフレームです。`M` はフレームの始まりの機械、`end` は終わりの機械、`rt` はルーチンのバイトです。

```
Pair(m)   :  (st(m) = 1 → d(m) = 1)  ∧  p(m) & 80 = a(m) & 80

pair_frame:  RoomCond(M),  各命令が SiteOK,  R(x(M), y(M)),  rt(end) = rt_部屋
             →  R(x(end), y(end))                                 (関係 R ごとに 1 つの歩き)
pair_of_rows: m が切り替えの時間の段にあり,  m は操作できる  →  Pair(m)
pair_run  :  ∀ n,  b₁ ≤ n < a₂  →  Pair(seq(n))
Run.roomPair: ∀ n,  C ≤ n < E  →  Pair(fm(n))
```

Lean: `Theorems/RoomPair.lean`（`keepXY`、`nextOK`、`markP`、`phP`、`finP`、`pair_frame`、`knHalt`、`knPrev`、`splitLda`、`pair_step`、`rowsCheck`、`pair_of_rows`、`pair_run`、`RoomWalks`）、`Theorems/RoomJoin.lean`（`InRoom.pair`、`RoomRun.varc_of`）、`Theorems/Route.lean`（`Run.roomPair`、`Run.inRoom`）。非公開の `Proof/RoomVert.lean`。

## 方法

**印のある歩き.** 歩きは [ブロックの地図](c-7-12-RoomMap-ja.md) の 1 フレーム全部の歩きで、[RoomVert](c-7-5-1-RoomVert-ja.md) の枠組み（`walkV`、`frame_of_walkV`）を使います。各状態は印を持ちます。`[]` は機械で関係が成り立つこと、`[1]` は成り立たないかもしれないことを表します。各ステップの前に印を決めます（`markP`）。

* ステップの与えるどの状態も、2 つのバイトのビットを関係を示せるだけ知っているなら（`nextOK`）、印は `[]` です。
* そうでなく、印が `[]` で、ステップが 2 つのバイトのどちらかに書くかもしれないなら（`keepXY` が成り立たない）、印は `[1]` です。
* ほかのときは印はそのままです。`[]` のままのステップはどちらのバイトにも書きません。[1 ステップの補題](d-3-4-1-StepWrites-ja.md) によるか、コインを消す書き込みで、これはブロックバッファにしか書きません。

フレームの終わりで印は `[]` か、ルーチンのバイトが分かっていて部屋のものでありません（`finP`）。`Φ(j) = (印 [] → R(x(tr(j)), y(tr(j))))` はすべての命令で成り立ちます。ですから関係とともに始まりプレイヤーのルーチンで終わるフレームは、関係とともに終わります（`pair_frame`）。

**2 つの関係.**

* `halt`: `x = st`、`y = d` です。ジャンプは状態 1 を書き、数命令あとに止める値 1 を書きます。歩きはどちらの値も知っています。最初の書き込みのあと印は `[1]`、2 つ目のあと `[]` です。ほかの分かっている状態（0、2、3）を書いても `[]` です（`knHalt`）。
* `prevA`: `x = p`、`y = a` です。プレイヤーのルーチンは新しい A と B を書きます。印は `[1]` です。ゲームエンジンは最後に、`a` を読んで `p` に書くことでそれを写します。そのような読み込みの前に、歩きは印 `[1]` の状態を `a` のビット 7 の 2 つの値に分けます（`splitLda`）。すると書き込みのあと、2 つのバイトのビット 7 は分かっていて同じです。印は `[]` です（`knPrev`）。2 つの部分ではビット `spent` がビット 7 を持ちます。ですから探索は書き込みまで 2 つを分けたままにします。

ポーズで終わるフレームはゲームエンジンを走らせません。どちらのバイトにも書かないので、印は `[]` のままです。

**最初の操作で.** 部屋への切り替えの時間の段は、操作できる機械で `st = 2` と、`p` と `a` のビット 7 を知っています（`rowsCheck`、`pair_of_rows`）。

**さらに 2 つのバイト.** 項目 1-1-c-7-1-2 は、この種類の歩きをさらに 2 つ、それぞれ 1 つのバイトで使います（`x = y`）。プレイヤーの状態は 0、1、2 のどれか（`checkSt`）、大きさの変化は 0（`checkSz`）。それぞれ約 3.5 秒です。最初の操作では、段を 1 回たどる中でこれらも調べます（`rowsCheck` の中の `rowQ`）。なので段をたどるのは 1 回です（プログラムで 25 秒、前と同じ）（[部屋のフレーム: プレイヤーのルーチンでの状態](c-7-1-2-RoomCut-ja.md)）。

**すべてのフレーム.** `RoomMap.cond_of_rows` は、`b₁` から `a₂` までの各フレームの始まりで部屋の条件を出します。`SiteOK`（`roomSites`）と各フレームの終わりのルーチンのバイト（`roomStay`）とあわせて、フレームの帰納法で `pair_run` が出ます。`Run.roomPair` は部屋のフレーム `n` を `base` のフレーム `b₁ + (n − C)` に置きます。これは `a₂` より前です。

| ROM の確認 | 表 | プログラムでの時間 |
|---|---|---|
| `checkH`（止める値） | 36,165 | 3.7 秒 |
| `checkA`（A） | 36,175 | 3.5 秒 |
| `rowsCheck` | 時間の段 | 2.5 秒 |

`checkA` の最初の試みは、`a` のすべての読み込みで分け、部分を分けたままにしませんでした。探索がそれらをまとめたので、書き込みの前にビット 7 が失われました（印 `[1]` の終わりが 6 つ）。ビット `spent` を使うと通りましたが、遅くなりました（11 秒、98,441 状態）。部分がプレイヤーのルーチン全体で分かれたままだったからです。今は、`p` への書き込みが続く `a` の読み込みでだけ分け、印 `[]` でビットを消します。

## 本物のフレームで確かめたこと

プログラム `room-pair-check FM2 [N]`。確認のあと、部屋の各フレームを最初の操作から走らせます。ムービーと、4 種類の自分の入力のそれぞれ `N` 回です（150 フレームまで。種類 0 は Start と Select も含めてどのボタンも押します）。部屋の各フレームの終わりで 2 つの関係を確かめます。

| 走り | 部屋のフレーム | フレームの終わりで関係が成り立たない |
|---|---|---|
| ムービー、最初の操作から入るまで | 110（と最初の操作の機械） | 0 |
| どのボタンも、Start と Select も（50 回） | 7,500 | 0 |
| B と右（50 回） | 7,500 | 0 |
| B と左（50 回） | 7,500 | 0 |
| 壁（50 回） | 7,500 | 0 |

ROM の確認は真です。`checkH` 3.9 秒、`checkA` 3.9 秒、`rowsCheck` 3.2 秒、`apartP`。`room-vert-check` も自分のフレームで 2 つの関係を数えます。そこでも成り立たないものは 0 です。

## 仮定（Lean で証明していないこと）

新しいものはありません。証明は、部屋のフレームの各命令の `SiteOK`（`chg.roomSites`、項目 1-1-d-2-4-2）と、部屋への切り替えの段を出す切り替えの条件を使います。[ブロックの地図](c-7-12-RoomMap-ja.md) と同じです。

**ファイル.** `Theorems/RoomPair.lean`、非公開の `Proof/RoomVert.lean`。

**再現.**
```
.lake/build/bin/smbrta room-pair-check FM2 [N]    # 確認（約 10 秒）と本物のフレーム
```
