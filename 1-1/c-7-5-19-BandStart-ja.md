# 角より左のフレームのあとの、152 ピクセルより上のフレーム

[地下の部屋をつなぐ](c-5-RoomJoin-ja.md) のフィールド `low_at` は、壁に触らないとき、`C + 37` から `C + 43` までで、角かその先で、136 から 151 ピクセル（`cornerY + 16` より上）で終わるジャンプのフレームに残っています（[ジャンプを通した縦のページ](c-7-5-18-RoomHigh-ja.md)）。そこでは、大きさがわからないとブロックの左側の歩きが通りません。また大きなプレイヤーは、かたまりの左の列の上のコインを取るフレームで押し戻されません（[かたまりの角での大きなプレイヤー](c-7-14-1-BigApproach-ja.md)）。

このページはそこでの当たり判定を証明しません。定理が求めるのはもっと少ない、ということを示します。角の先に出るのは、最高速で 1 フレームまでで足ります。なので、1 つ前のフレームが角より左なら、最高速だけで証明できます。フィールドが求めるのは、1 つ前のフレームが角かその先のフレームだけです。

## 主張

`P(n)`、`y(n)` は、フレーム `n` の終わりの位置（1/256 ピクセル単位）と高さです。`c_P` は角（51 ピクセル）、`S_low = 415/256` ピクセル、`top` は最高速です。1 フレームで動くのは多くて `16·top = 640/256` ピクセル（2.5 ピクセル、`move_top`）。`cy = cornerY`（136 ピクセル）。

```
low_at（フィールド、狭めた）:
  NoWall → C + 37 ≤ n ≤ C + 43 → n ≤ t₀ → cy ≤ y(n) → ¬OnFloor(n) → c_P ≤ P(n) → y(n) < cy + 16
    → c_P ≤ P(n − 1)                                   （新しい前提）
    → P(n) ≤ c_P + 16·top − 1                          （前は  P(n) ≤ c_P + S_low）

low_by（証明。前は  P(n) ≤ c_P + S_low）:
  C ≤ n ≤ C + 43 → n ≤ t₀ → P(n) ≤ c_P + 16·top − 1
  新しい場合、y(n) < cy + 16 で P(n − 1) < c_P:   P(n) ≤ P(n − 1) + 16·top ≤ c_P − 1 + 16·top   （move_top）

NumFacts（ROM の数、room_nums の中で native_decide）:
  low_top（新しい）:  S_low ≤ 16·top − 1
  hit_J:             c_P + (16·top − 1) + dbound(stopPhi, 98 − 37) < G_P          （前は S_low で）
  hit_F:             c_P + (16·top − 1) + fastDist(stopPhi, 98 − 41) < G_P        （前は S_low で）
  hit_late:          43 < j ≤ 98 で  min(c_P + (16·top − 1) + 16·top·(j − 43), c_P + stopSlack) + fastDist(stopPhi, 98 − j) < G_P
```

`low_by` のほかの場合は `P(n) ≤ c_P + S_low`（床のフレーム `low_floor_at`、152 ピクセルかそれより下のジャンプのフレーム `low_jump`、壁 `wall_low`）か `P(n) < c_P`（`C + 37` より前）を与え、`low_top` でそれらは `≤ c_P + 16·top − 1` になります。これを使うのは `stop_short` だけで、`C + 43` までの止まり（`hit_J`、`hit_F`）と、それより後の止まりの前の `C + 43`（`hit_late`）で読みます。

`C + 98` での余裕（ゴールまで足りない分、1/256 ピクセル）。`S_low` のときと、いまの `16·top − 1`（639）のとき: `hit_J` は 225 と 1、`hit_F` は 241 と 17、`hit_late` は 1521 以上と 1297 以上。

## 測ったこと

`room-approach-check FM2 300 1`（大きい。最初の操作で大きさのバイトを大きいにした、作った状態）と `… 300 0`（小さい）: TAS と自分の入力の 2,700 の走りで、前の `low_at` のフレームのうち 136 から 151 ピクセルで終わるもの:

| 大きさ | 前の `low_at` のフレーム | そのうち 136 から 151 ピクセル | 1 つ前のフレームが角より左（証明） | 1 つ前のフレームが角かその先（フィールド） |
|---|---|---|---|---|
| 大きい | 103 | 55 | 48 | 7 |
| 小さい | 50 | 3 | 2 | 1 |

どれも角から `16·top − 1` より先に出ません。前の強い主張（そのようなどのフレームでも `P ≤ c_P + S_low`）も、すべてで成り立ちます。

## 残っていること

- 1 つ前のフレームも角かその先にある、136 から 151 ピクセルのフレームの `low_at`。その高さでのブロックの左側の当たり判定が要ります。移動の終わりでの大きさのバイト（`SizeKeep` の歩きはフレームの始めと終わりでしか与えない）、コインか空のセル、そこでの `RoomCorner` の歩きです。

**ファイル。** `Theorems/RoomJoin.lean`: `RoomFields.low_at` を狭め、新しい `NumFacts.low_top`、`hit_J`、`hit_F`、`hit_late` は `16·top − 1` で、`low_by` の結論、`stop_short`。非公開: `room_nums`（`Proof/RoomJoin.lean`）の `low_top`。プログラム `room-approach-check`（上の数）。

**再現。**
```
.lake/build/bin/smbrta room-approach-check FM2 300 1      # 大きい。最後を 0 にすると小さい
```
