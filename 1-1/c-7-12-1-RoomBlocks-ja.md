# 部屋の地図のブロックは変わらない

**主張.** 地下の部屋での最初の操作から横の土管に入るフレームまでのどのフレームでも、2 つのブロックバッファのバイトのうち、地図でコインでないものは地図の値のままです。レンガはレンガのまま、床は床のまま、壁も土管もそのままです。これは項目 1-1-c-7-12 の「1 のビット」の部分の、コインでないバイトについての証明です。0 のビットは [部屋のブロックの地図](c-7-12-RoomMap-ja.md) が証明しています。仮定はそのページと同じ（各命令での `SiteOK`）で、新しい仮定はありません。この定理を使うルートの定理はまだありません。`land_at` は出ません（最後の節）。

`B` は 2 つのブロックバッファの 416 バイト、`M` は地図（`RoomMap.mapRef`）、`coins` は頭のための読み出しが返しうるタイルのうち空でないもの（この ROM では 1 つ）です。`z` はブロックバッファのルーチンのポインタがあるゼロページのバイト、`o` はルーチンのオフセットがあるバイト、`t` はルーチンが読んだタイルがあるバイトです。3 つともコードから読みます（`ptrOf`、`offOf`、`tileOf`）。`m(d)` は `m` の RAM のバイト `d` です。

```
Solid(m)       :  ∀ d ∈ B,  M(d) ∉ coins  →  m(d) = M(d)
adr(m)         =  m(z) + 256·m(z + 1) + m(o)
Coin(m)        :  m(t) ∈ coins  ∧  (adr(m) が B のバイト  →  m(adr(m)) = m(t))

writeAddr_eq   :  STA (zp),Y のアドレス  =  ポインタ + Y                    readAddr_eq:  LDA (zp),Y でも同じ
readVal_eq     :  LDA (zp),Y のアドレスが RAM にある  →  読むバイトはそこの RAM のバイト
step_lda_izy   :  LDA (zp),Y は読んだバイトを A に入れ、RAM を保つ
step_sta_zp    :  STA zp は A をそのバイトに書き、A を保つ（step_sta_zp_a）
step_tay, step_ldy_zp, step_lda_imm  :  TAY: Y = A。LDY zp: Y = そのバイト。LDA #: Y は変わらない。どれも RAM を保つ
erase_other    :  消す命令はそのアドレスのバイトだけを書く
blocks_frame   :  checkK、codeOK、RoomCond(m)、各命令で SiteOK、Solid(m)   →   Solid(frame(m, i))
solid_of_rows  :  rowsCheckB、InRowsT(m)、control(m)   →   Solid(m)
blocks_run     :  map_of_rows の仮定、BChecks、rowsCheckR   →   ∀ n ∈ [b, a],  Solid(seq(n))
Run.roomBlocks :  確かめ、Run   →   ∀ n ∈ [b₁, a₂],  Solid(seq(n))
room_blocks_run（非公開）  :  この ROM の確かめでの Run.roomBlocks。Run のすべてのフィールドを持つ走りについて
```

## 方法

**ブロックバッファに書くのはコインを消す命令だけ.** 部屋の 1 フレームの歩きは、コインを消す命令のほかのどの状態でも、その 1 歩が `B` のバイトに書きえないことを求めます（`RoomFall.mayWrite`）。失敗なしで通ります。[部屋のブロックの地図](c-7-12-RoomMap-ja.md) で、頭がブロックに当たる 2 か所に来る状態がないことは、すでに分かっています。

**消す命令が書くバイトにはコインがある.** 消す命令は、ポインタ `z` と、バイト `o` から読んだ Y のオフセットで、空のタイルを書きます。抽象機械はポインタを知りません。しかしブロックバッファのルーチンは、同じポインタと同じオフセットでタイルを読んでいて、そのタイルはコインでした。これは抽象状態が持たない、機械についての事実です。歩きは印でこれを運びます（`RoomVert.frame_of_walkV`）。鎖の 1 歩ずつが、機械の上の 1 命令です:

| 印 | そのかけらの場所 | その 1 歩のあとで成り立つこと |
|---|---|---|
| `[3]` | 読み出しの 3 バイト前の `STA o` | バイト `o` は A |
| `[6]` | `TAY` | Y はバイト `o` |
| `[4]` | 読み出し `LDA (z),Y` | `adr` が `B` のバイトなら、A は `adr` のバイト |
| `[5]` | 読み出しのあとの `STA t` | `adr` が `B` のバイトなら、`adr` のバイトはバイト `t` |
| `[9]` | どこでも。バイト `o`、バイト `t`、ポインタに書きうる 1 歩がないあいだ | `Coin`。状態がバイト `t` を知っていて、それがコインのときだけ付く |
| `[7]` | 消す命令の 4 バイト前の `LDY o` | `Coin`、そして Y はバイト `o` |
| `[10]` | `LDA #` | `Coin`、そして Y はバイト `o` |
| `[8]` | 消す命令 `STA (z),Y` | `Solid` |

消す命令でのアドレスはポインタ足す Y なので `adr` です。`SiteOK` がそれを `B` の中に置きます。なのでそこのバイトはバイト `t` で、コインです。コインがあるバイトは、地図でもコインです。`Solid` が、ほかのバイトには地図のタイルがあり、それはコインでないと言うからです。なので消す命令は `Solid` のバイトを変えません（`erase_other`）。歩きは、消す命令にいる状態に印 `[8]` があることを求めます。1 歩だけの印がほかの場所に来たら落とします。`[9]` も、そのバイトに書きうる 1 歩で落とします。`codeOK` は、読み出しと消す命令のまわりのコードを ROM で確かめます。

最初の形には、`STA o`、`TAY`、`LDY o`、`LDA #` の命令の補題がありませんでした。`STA o` でアキュムレータを 256 通りの値に分け、読み出しと消す命令で抽象状態が Y とバイト `o` を知るようにしました。通りましたが、表は 216,515 状態、21.7 秒でした。4 つの補題がこの分割の代わりです。

**最初の操作で.** 部屋への切り替えの段は、ブロックバッファのすべてのバイトを知っています。`rowsCheckB` は、[2 組のバイト](c-7-5-2-RoomPair-ja.md) の確かめ `rowsCheck` に、操作できる状態ごとの条件を 1 つ足したものです。`B` のバイトのうち地図でコインでないものを、地図の値で知っていることです。`rowsCheck` の非公開の証明は、今はこれから出します（`rowsCheck_of_B`）。なので段の計算は 1 回です。

| ROM の確かめ | 大きさ | プログラムでの時間 |
|---|---|---|
| `checkK`（印つきの歩き） | 探索 210,206 歩（表 36,210）、失敗なし | 4.4 秒（探索 2.3 秒） |
| `codeOK` | 26 個の条件 | 0 秒 |
| `rowsCheckR`（`rowsCheck` の代わり） | | 30.6 秒（`rowsCheck` は 29 秒） |

## 本物のフレームでの確かめ

プログラム `room-floor-check FM2 [N]`: 地図、確かめ、そして TAS の部屋での最初の操作から、TAS と、5 種類の自作の入力を `N` 本ずつ（199 フレームまで）。各フレームを 1 命令ずつ走らせます。

| 走り | フレーム | 消す命令 | 書くバイトにコインがない | バイト `t` が書くバイトでない | アドレスがポインタ足すバイト `o` でない | Y がバイト `o` でない | 最後の読み出しが別のアドレス、またはコインでない | 消す命令が書いていない `B` のバイトが変わるフレーム | `Solid` でなく始まるフレーム |
|---|---|---|---|---|---|---|---|---|---|
| TAS | 111 | 13 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| 自作の入力、5 種類 × 60 | 59,700 | 69 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |

地図: 空でもコインでもないバイトは 113 個、コインは 19 個です。床の 2 段は、1 つ目のバッファのすべての列と、2 つ目のバッファの半分の列で 1 つのタイルです。2 つ目のバッファの残りの半分は、そこが空です。

## これから出ないこと

* **`land_at`**（壁に当たらなければ `C + 34` で立つ）。足が床のタイルを読めば、そのフレームは着地します。読み出しはポインタ `z` を通り、どのバイトを読むかは位置で決まります。バッファと列はページとピクセルから来て、2 つ目のバッファでは床の段の半分が空です。なので `land_at` には、足の読み出しでのポインタを位置から知ること（アドレスを作るルーチン）と、位置の上限からの足の列が要ります。最初に立つのが `C + 34` より前でない、測った 301 本の走りは、どれも `C + 34` で立ちます。
* 左の壁と角についてのフィールド（`wall`、`stand_wall`、`low_at` など）にも同じものが要ります。読み出しがどこかを、位置から知ることです。
* コインのバイト: 地図で 0 のビットだけが分かっています（地図のページ）。本物のフレームではコインか空です。それは証明していません。
