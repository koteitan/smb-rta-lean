# 旗に触ってから城まで

**主張.** 下に挙げた触る状態からは、旗を直接つかむと（上昇中で、終わりの処理がすぐ始まる高さ）、城に入るのは、位置の端数が 80/256 ピクセル以上なら触ったフレームの 126 フレーム後、それ未満なら 127 フレーム後です。ほかの 8 つの高さで触ると 160 フレーム以上かかります。挙げていない状態にはもっと早いものがあります。すべての触る状態の下界ではありません。

`E` は触ったフレームのマシン、`I` は 64 通りの入力（A、B、上、下、左、右の全部の組み合わせ。Start と Select は除く）、`0^k` は入力なしの `k` フレームです。

```
entered      :  E では旗に触っている
allInputs    :  GMerge  →  ∀ w ∈ I^126:  castle(run(E, w)) ∧ ∀ k, 1 ≤ k < 126 → ¬castle(run(E, w[..k]))
otherStates  :  つかむ前のジャンプの状態と、直接つかめる x のそれぞれで:  1 ≤ k ≤ 126 について castle(run(E', 0^k)) ↔ k = 126
anyFraction  :  位置が取れる端数のそれぞれで:  1 ≤ k ≤ 125 について ¬castle(run(E', 0^k))
otherTouch   :  ほかの 8 つの高さのそれぞれで:  1 ≤ k ≤ 159 について ¬castle(run(E', 0^k))
```

Lean: `Theorems/CastleWalk.lean`、非公開の `castle_checks`、`castle_walk`（`native_decide`）。

## しくみ

確認はエミュレータの本物のフレームで動かします。そこへ行くために、1-1 の最初から土台の横の地面まで自前の入力で走ります。[地下への切り替え](b-1-PipeTransition-ja.md) の縦の土管を通り、地下の部屋と横の土管を抜け、右と B と数回のジャンプで進みます。最後のフレームの位置と上下の値を書き換えて、つかむ直前の状態を作ります。

測ったけれど全部は定理にしていないこと: 長さは、端数、進む向き、走りの速さ、覚えている速さで変わります。このページの状態では端数の境目は 80/256 ピクセルです。TAS の状態では 48/256 ピクセルで、TAS には 32/256 ピクセルの余裕があります。左に動いていない遅いジャンプで端数が 176/256 ピクセル以上だと、触った + 125 です。速いジャンプでつかむと、触った + 1 か + 2 です。ほかの高さでの触りは 153〜164 フレームでした。本物の走りが届く範囲でこれらが起きないことは [操作から城まで](f-5-PoleJoin-ja.md) で扱います。旗の範囲の 4 ピクセルのうち、直接つかめるのは左の 2 ピクセルだけです。右の 2 ピクセルでは先に頭が柱に当たり、もっと低い位置で触ります。

## 前提（Lean では証明していない）

* `GMerge`: ボタンをそのまま写すバイトだけが違う状態は同じように動く。`allInputs` の仮定で、[地下への切り替え](b-1-PipeTransition-ja.md) と同じです。
* 全部の入力を動かしたのは、触った状態 1 つだけです。ほかの状態は入力なしです。
* 旗のところの状態は、本物の走りの最後を書き換えたもので、そのままたどり着けることは示していません。敵、スクロール、タイマーが違う走りは含みません。
* `anyFraction` は 1/16 ピクセルの倍数の 16 通り（位置は 1/256 ピクセル単位で `16·v` ずつ動く）と最大の端数です。位置の端数がいつもその倍数であることは証明していません。
* Start と Select は入力に含めていません。

**ファイル.** `Theorems/CastleWalk.lean`、非公開の `Proof/CastleWalk.lean`。

**再現.**
```
.lake/build/bin/smbrta castle-check     # 端数ごと、高さごとのフレーム数と確認（true、約 5 秒）
```
