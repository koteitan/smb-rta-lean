# 横の土管の入口の画面のバッファ

**主張.** 部屋のフレームが、画面のバッファの制御が 0 で始まり、横の土管のルーチンで終わるなら、そのフレームは入口の基準の 1 つの最初の画面バッファで終わります。バッファのオフセットと、その 4 バイトです。ROM の 1 つの確認（部屋のフレームの歩き）で証明しました。そこで `Route.Run` は、入るフレームが制御 0 で始まる走りには、横の土管の入口でこの 5 バイトを求めません。入るフレームが制御の立った状態で始まる走りには、まだ求めます（新しいフィールド `buffer₂`）。[高さ](d-2-5-4-EntryHeight-ja.md) と合わせて、`chg.entry₂` は 9 バイトでなく 3 バイトを求めます（1-1-d-2-5）。

フレームの始まりで制御が 0 でないのは、前のフレームがコインを消したときです。ラウンド 23 で、部屋のどのフレームの始まりでも制御が 0 か 6 であることを証明しました（[部屋を通る画面のバッファの制御](d-2-5-5-1-BufferControl-ja.md)、`Run.ctl₂`）。入るフレームの始まりで 6 でないことは証明していません。

名前は [横の土管の入口の高さ](d-2-5-4-EntryHeight-ja.md) のものです。`c(m)` は画面のバッファの制御（`VRAM_Buffer_AddrCtrl`）です。`L₅` は 5 バイトです: 最初の画面バッファのオフセット（`VRAM_Buffer1_Offset`）と、そのバイト 0、1、2、7。`V` は入口の基準です。それぞれ機械 `v` と、それが与えるバイトの表 `X` です。

## 定理

```
EntryAt(L, m)   :=  ∃ (v, X) ∈ V,  ∀ i ∈ X,  i ∈ L  →  m[i] = v[i]
K_B             :=  K_T ∪ { c の全部のビット }
finB(B)         :=  B は rt ≠ e_s を知る   ∨   ∃ (v, X) ∈ V,  ∀ i ∈ X ∩ L₅,  B は m[i] = v[i] を知る

buffer_frame    :  WalkOK(finB),  RoomCond(K_B, m),  ∀ j, SiteOK(tr(j)),  rt(frame(m, i)) = e_s      →   EntryAt(L₅, frame(m, i))
buffer_of_rows  :  [b, a) での RoomMap.map_of_rows の仮定,  確認,  b ≤ k < a,
                   c(seq k) = c(r),   rt(frame(seq k, inp k)) = e_s                 →   EntryAt(L₅, frame(seq k, inp k))

Run.buffer₂     :  c(seq(a₂ − 1)) = c(r)   ∨   EntryAt(L₅, seq a₂)                   （フィールド、新しい。ラウンド 24 で狭めた、下を見よ）
Run.buf₂        :  EntryAt(L₅, seq a₂)                                                （定理）
entryAt_of_buf  :  EntryAt(L₅, m)  ∧  EntryAt(R₃, m)   →   EntryAt(R₈, m)
chg.entry₂      :  EntryAt(R₃, seq a₂)                                                （3 バイト。前は R₉）
```

`R₈` は `restIdxY` の 8 バイト、`R₃ := R₈ \ L₅` です（`restIdxB`）: エリア音楽のバッファ、イベント音楽の待ち、足す音の長さ。`c(r) = 0` です。`WalkOK` と歩きは高さのページのもので、高さの分け方はありません。

**`entryAt_of_buf`.** `EntryAt` は全部のバイトに 1 つの基準を取ります。2 つの基準は `R₃` で一致します: 一方が与える `R₃` のバイトは、どちらも同じ値で与えます（`agreeCheck`）。だから 5 バイトの基準が 3 バイトも与えます。

**`Run.buf₂`** は `Run.y₂` と同じです。フレーム `a₂ − 1` は部屋のフレームで、横の土管のルーチンで終わります。`c(seq(a₂ − 1)) = c(r)` なら `buffer_of_rows` がバイトを出します。そうでなければ `buffer₂` が出します。

Lean: `Theorems/EntryBuffer.lean`（`finB`、`keyB`、`optsB`、`buffer_frame`、`ctlI`、`bufIdx`、`hpB`、`knownB`、`bufferCheck`、`agreeCheck`、`Facts`、`factsOf`、`buffer_of_rows`）、`Theorems/EntryHeight.lean`（歩き、`WalkOK`、`frame_end`）、`Theorems/Route.lean`（`restIdxB`、`RoomChecks.buffer`、`Run.buffer₂`、`Run.buf₂`、`entryAt_of_buf`、`Run.chgK`）、非公開の `Proof/EntryHeight.lean`（`entry_buffer_walk`、`entry_buffer_agree`、`buffer_facts`）。公開のファイルにゲームのデータはありません。名前 `VRAM_Buffer_AddrCtrl` を `ScreenPage.namesOf` に加えました。

## しくみ

**フレームの始まり.** 割り込みの処理は、制御が指す画面バッファを描き、そのあと空にします。オフセットと最初のバイトに 0 を書き、制御を 0 にします。制御が 0 なら、これは最初のバッファです。コインを消して制御が立っていれば 2 つ目のバッファで、最初のバッファは記録を持ったままです。だから歩きには制御が要ります。

**入るフレームはコインを取らない.** 頭か足のコインは、横の判定の前に当たり判定のルーチンを終わらせます。横のコインは、土管のタイルの代わりに横の判定のタイルになります。だから歩きのどの道も、コインを取ってから横の土管のルーチンを書くことはありません。

**タイマーの桁.** ゲームタイマーのコードは、ルーチンがプレイヤーの操作より小さいとき動きません。横の土管のルーチンはそうです。

**色の回転.** これらの道で最初のバッファに書くコードはこれだけです。8 フレームに 1 回、バッファのオフセットに 1 つの記録を書き、記録の長さをオフセットに足します。だからフレームは、空のバッファ（オフセット 0、最初のバイト 0）か、この 1 つの記録で終わります。これが 2 つの基準です。1 つ目はオフセットと最初のバイトを与え、2 つ目は 5 バイト全部を与えます。

**空のバッファのあとのバイト.** オフセットが 0 のとき、バイト 1、2、7 は前の記録（色の回転か、タイマーの桁）が残したままです。1 つ目の基準はこれらを与えないので、何も求めません。

**探索（証明の一部ではない）.** キーには制御が入ります。制御がないと、フレームの終わりのアイドルループの状態が、フレームの始まりの状態と合わさります（キーが同じです）。始まりが知っている制御がなくなります。横の土管のルーチンのときは、キーに 5 バイトも入ります。

**大きさ.** 172,402 ステップ、10,547 分岐、失敗 0、39,574 状態。プログラムで: 探索 2.1 秒、確認 5.8 秒。

## 測ったこと（定理ではない）

フレームの始まりで制御を知らない歩き（`entry-height-check FM2 N walkbuf`）:

| フレームの始まりの制御 | ステップ | 失敗 | 横の土管のルーチンで終わるフレームの終わり | その終わりのバッファ |
|---|---|---|---|---|
| 基準のもの（0） | 172,402 | 0 | 8 | 空（オフセット 0、最初のバイト 0）。または色の記録 1 つ（オフセット 7） |
| 知らない | 271,716 | 114 | 232 | 228 個が失敗: オフセットはバッファが許すどの値も取る |

**制御を出すのに要るもの.** フレームの終わりで制御が立つのは、そのフレームがコインを消したときだけです。地図では、いちばん近いコインは口の列の 3 列左です。1 フレームは、速さのバイトがどの値でも、プレイヤーを 1 列より少なく動かします。移動は速さの上 4 ビットだけを足すからです。だからコインを消すフレームの次に、入るフレームは来ません。これを証明するには、抽象の機械でこの 2 フレームの位置が要ります。コインを見つける読み出しで位置を分ける前のフレームの歩きと、口より左の位置からの入るフレームの歩きです。これはしていません。

## 直前のフレームについて証明できた部分

`EntryBufferNear.map_coin` は、`Solid` の下で実際に読んだコインが地図でもコインであることを証明します。非公開の `Proof/EntrySolidFacts.lean` の `entry_coin_gap` は、地図のすべてのコインが口より 3 列以上左にあることを確認します。`read_separation` と `not_short_move` は条件付きの位置関係を証明します。読み出しのずれが 1 列未満なら、両方を読むプレイヤーの位置は 18 ピクセル以上離れます。それ未満の 1 フレームの移動とは両立しません。

実際の 2 フレームの命令から、その読み出し位置と移動量を導く部分は未証明です。口の最初の位置から、コイン以外の地図を知って歩いた試行にも、抽象的な失敗が 63 個ありました（2,016,392 ステップ）。バッファの証明ではありません。`buffer₂` はそのままです。

## 本物のフレームで

プログラムです（`entry-height-check FM2 400 real`、約 3 分）。ムービーの入るフレームと、部屋のムービーのフレームから自分の入力で、小さいプレイヤーで 400 走り、大きいプレイヤーで 400 走り。

| 走り | 入った数 | 入るフレームの始まりで制御が 0 | 5 バイトが基準のもの | 入口のバッファ（オフセット: バイト 0、1、2 … 7） | `R₃` が基準のもの |
|---|---|---|---|---|---|
| ムービー（ムービーのフレーム 763） | 1 | 1 | 1 | 基準のもの | 1 |
| 小さい | 142 | 142 | 142 | 空で色の記録の残りがあるもの 90、色の記録 1 つ 35、空でタイマーの記録の残りがあるもの 17 | 142 |
| 大きい | 151 | 151 | 151 | 色の記録 1 つ 38、空で色の記録の残りがあるもの 99、空でタイマーの記録の残りがあるもの 14 | 151 |

タイマーの記録の残りがある 31 個では、それはバイト 1 と 2 です。1 つ目の基準はこれらを与えません。制御が立って終わるフレームのあとに来るどの入口も、そのフレームから 16 フレーム以上あとです。

## ラウンド 23: 部屋を通る制御

[部屋を通る画面のバッファの制御](d-2-5-5-1-BufferControl-ja.md)（1-1-d-2-5-5-1）は、部屋のどのフレームも、最初の操作から入るフレームまで、制御が 0 か 6 で始まることを証明します（`Run.ctl₂`）。このページの歩きは、制御 0 からも 6 からも、制御 0 か 6 で終わります。最初の切り替えの段は、部屋の最初の操作で制御を 0 と知ります。そこで `buffer₂` は、入るフレームの始まりの制御 6 だけを除きます。コインのフレームと入るフレームの位置を追う歩きを 2 通り作りましたが、大きくなりすぎました。数はそのページにあります。`buffer₂` は変わりません。

## ラウンド 24: フィールドを狭めた

`buffer₂` は今 `c(seq(a₂ − 1)) ≠ 6 ∨ (seq(a₂ − 1) で page = 0 ∧ 16 ≤ x < 181) ∨ EntryAt(L₅, seq a₂)` です。`Run.buf₂` は、最初の場合を `Run.ctl₂` で（制御は 0 か 6 なので、6 でなければ基準の 0）、真ん中の場合を `Run.coin₂` で扱います（[BufferCoin](d-2-5-5-2-BufferCoin-ja.md): そういうフレームは入らない）。そこでこのフィールドが求めるのは、入るフレームの前のフレームがコインを消したなら、ページ 0 の 16 から 180 px で終わった、ということだけです。

## 道筋で変わったこと

* `Run.chg : ChangesK … (restIdxB sy nmS m0)`: 横の土管の入口で 3 バイト。
* `Run` に新しいフィールド `buffer₂` があります。
* `RoomChecks` に新しいフィールド `buffer : EntryBuffer.Facts …` があります。道筋の非公開のファイル（5 回）と急ぎの音楽の非公開のファイル（1 回）で `buffer_facts` から作ります。

## 仮定（Lean で証明していない）

* `buffer₂`: 入るフレームは画面のバッファの制御 6 で始まらない、またはページ 0 の 16 から 180 px で始まる、または入口の 5 バイトは基準のもの（ラウンド 24）。`Run.ctl₂` と `Run.coin₂` により、これは、ページ 0 の 16 から 180 px の外での制御 6 の始まりだけを除きます。ラウンド 25（[BufferEnd](d-2-5-5-3-BufferEnd-ja.md)、1-1-d-2-5-5-3）: 制御 6 で終わるフレームは 16 から 180 px で終わる（`Run.end₂`）ので、`buffer₂` が求めるのはそこでのページ 0 だけになりました。
* `chg.entry₂`: 入口の 3 バイトは基準の値: エリア音楽のバッファ、イベント音楽の待ち、足す音の長さ。ゲームタイマーが要ります（[部屋のフレームを通る音楽のバイト](d-2-5-1-RoomMusic-ja.md)）。
* 部屋の各命令の `SiteOK`（`chg.roomSites`）。前と同じです。
