# 着地直前の状態と足の呼び出しへの接続

部分結果です。`RoomRun.no_stand_before_land` は `NoWall` のもとで着地のフレームより前に立たないことを証明します。`before_land_mem` は最後の直前状態が既存の落下の集合にあることを、`before_land_step` は最後の一歩が移動のままか着地かの二択になることを与えます。`stand_wall` と既存の落下の結果は使いますが、`land_at` と `floor_at_of` は使いません。`floor_at_of` は内部で `land_at` を使うため、その逆向きの証明には使えません。

`RoomCollision.readAddress_from_coords` と `returned_map_from_coords` は、呼び出しの入口の座標が移動後の座標と同じなら、実際の添字を使って移動後の位置で読み出し先と地図の返り値を表せることを証明します。座標が保たれること自体の証明ではなく、新しい Run のフィールドにもしていません。

着地のフレームを、TAS、10 種類の乱数入力、2 種類の固定入力の 13 走りで測りました。足の呼び出しは各 2 回、計 26 回でした。スクロール処理の入口からの位置と縦座標の変化は 0 回で、返り値は 26 回とも対応する地図の床の値でした。13 走りとも最後は立っていました。添字は ROM から選ぶ左足と次の右足のものです。この測定は任意の `NoWall` の走りの証明ではありません。

`FrameModel` の移動後の位置と `SubsOnce` の唯一性だけでは、その後の呼び出しへの到達・座標の保存・添字の選択は出ません。そこを証明して床の場所を特定し、`Run.roomCollisionMap` を使い、返り値から着地の分岐と状態の書き込みを追う必要があります。`land_at` は残り、フィールドの増減はありません。

**ファイル:** `Theorems/RoomLanding.lean`。

`BIT` の命令の歩きは証明済みになりました。[RoomFootPrefix](c-7-5-10-RoomFootPrefix-ja.md) は局所的な確認のもとで、実際の足の呼び出しの座標と添字を出し、`Run.roomCollisionMap` につなぎます。13 通りの入力の左右の足、合計 26 回で確認が通りました。前の足の処理の切れ目ではスタックの高さを誤っていました。スクロール処理の入口より 2 低くなります。すべての着地でこの局所条件が成り立つことと、呼び出し後の着地の分岐は未証明です。
