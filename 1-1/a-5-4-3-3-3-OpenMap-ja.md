# 最初のフレームのブロックバッファ、ジャンプ台、プレイヤーの状態

**主張.** 操作できるときから数えるフレーム `N`（`N = 32`）までのどのフレームでも（数えるものも数えないものも）、2 つのブロックバッファは操作のときの機械 `m₀` の
ものと同じで、ジャンプ台のバイトは 0 で、プレイヤーの状態は 0、1、2 のどれかです。なので [本物のフレームでの出だし](a-5-4-OpenFrames-ja.md) のフィールド `st` と
`spring` はもう仮定ではありません。代わりに、これらのフレームの各命令に 1 つの条件を求めます（`map`、`MapOK`）: 添字やポインタを通った書き込みはプレイヤーの状態、
ジャンプ台のバイト、ブロックバッファを書かず、ブロックバッファのルーチンの読み出しは最初のブロックバッファの中にある、という条件です。

ブロックバッファは、当たり判定が読む 13 行 16 タイルの 2 つの表です。`B` はその 416 バイトの集合です。操作のときには 5 種類のタイルがあります: 空、地面、
レンガ、中身のある 2 種類のブロックです。どれもジャンプ台でも、つかまれるタイルでもありません。

`seq(n)` はフレーム `n` が始まるときの機械、`ix(t)` は数えるフレーム `t` が始まるフレーム、`fm(t) = seq(ix t)` です。`tr_n(k)` はフレーム `n` の `k` 命令あとの
機械です。`st(m)` はプレイヤーの状態、`js(m)` はジャンプ台のバイトです。`R` はブロックバッファのルーチンの `LDA (zp),Y` の場所、`addr(m)` はそれが読む番地、
`val(m)` はそれが読むバイトです。

```
MapAt(m)    :=  ∀ d ∈ B,  m(d) = m₀(d)   ∧   js(m) = 0   ∧   st(m) ≤ 2
MapOK(m)    :=  store:  m の添字やポインタを通った書き込みは st、js、B のバイトを書かない
                read:   pc(m) = R  →  addr(m) は RAM にあり、そのバイトは最初のブロックバッファ（B₁ ⊂ B）にある
```

```
readVal_ram     :  m は記録していない,  addr(m) < 0x2000   →   val(m) = m(addr(m))
s_tstep         :  CleanK(m),  A が m を覆う,  RdOK(m)   →   歩きの 1 歩のどれかが m の 1 歩を覆う
map_frame_start :  mapCheck,  FrameStart(m),  MapAt(m),  ∀ k: CleanK(tr(k)) ∧ RdOK(tr(k)),  frame(m, i) は操作できる状態で終わる
                   →   FrameStart(frame(m, i))  ∧  MapAt(frame(m, i))
map_run         :  列の各フレーム n ∈ [a, b) で同じ   →   ∀ n ∈ [a, b],  MapAt(seq n)
Begin.map₁      :  check (TitleStart),  titleMapCheck   →   MapAt(seq 1)  ∧  st(seq 1) = 0                 （どの入力でも。Start も）
Lags.mapAt      :  lagCheck,  pauseCheck,  mapCheck,  Lags,  FrameStart(seq 1),  MapAt(seq 1),  b ≤ ix(E),
                   ∀ n ∈ [1, b), ∀ k: MapOK(tr_n(k))   →   ∀ n ∈ [1, b],  MapAt(seq n)
Real.stSpring   :  確認,  Real（フィールド map あり）,  FrameStart(seq 1),  MapAt(seq 1)
                   →   ∀ t ∈ [1, N],  t < E  →  st(fm t) ∈ {0, 1, 2}  ∧  js(fm t) = 0                     （前のフィールド st と spring）
map_reads       :  map_frame の条件   →   フレームの中で NMI が来ない各読み出し R で、∀ d ∈ B,  m(d) = m₀(d)      （R での歩きの 1 歩がそれを求める）
フィールド map  :  ∀ n,  1 ≤ n ≤ ix(N),  n < ix(E),  ∀ k:  MapOK(tr_n(k))
```

ここでの `CleanK` は、操作中のフレームのガードの `PipeWrites.Clean`（フィールド `lags.clean`）に、プレイヤーの状態、ジャンプ台のバイト、`B` の保護を加えたものです。
これは `Clean` と `MapOK` の書き込みの部分から出ます（`cleanK_of`）。`RdOK` は `MapOK` の読み出しの部分です（`rdOK_of`）。ROM のない定理が使う公理は `propext`、
`Classical.choice`、`Quot.sound` だけです。`#print axioms route_1_1` に `sorryAx` はありません。

Lean: `Theorems/OpenMap.lean`（`map_reads`、`liveT_all` を使う）。`Theorems/OpenFrames.lean` の `StSpring`、`Real.stSpring`、フィールド `Real.map`。`Theorems/Route.lean` の `Run.pipeOpening`、
`Run.pipeOpenB`。非公開の `Proof/OpenMap.lean`（`open_map_check`、`open_title_map_check`）。

## しくみ

**操作のとき.** [タイトルの Start から操作まで](0-5-3-TitleStart-ja.md) の近い状態は、2 つのブロックバッファのどのバイトも知っています。`titleMapCheck` は近い状態
と保留の状態のそれぞれからどの入力でもフレーム 0 をもう一度歩き、操作できる終わりのそれぞれで、`B` が `m₀` の値で、ジャンプ台のバイトが 0 で、プレイヤーの状態が
0 であることを求めます（ネイティブで約 2.5 秒）。

**1 フレーム全部.** 歩きは `FrameKeep`（[パート f](f-6-19-FrameKeep-ja.md)）のもので、[操作から土管までの各フレームはアイドルループで始まる](a-5-5-3-2-StartRun-ja.md)
の `walk_check` と同じです。違いは次のとおりです。

* `B` のバイトとジャンプ台のバイトを見張ります。始めに値を知っていて、フレームの終わりでもう一度求めます。プレイヤーの状態とあわせて保護します。添字やポインタを
  通った書き込みはこれらに触れません（`MapOK.store`）。
* プレイヤーの状態は始めに 0、1、2 のどれかとして知っています（始めの状態は 6 つ）。フレームの終わりでは、知っていて 2 以下か、フレームが操作できない状態で
  終わる（ルーチン、タスク、モードのどれかが操作のときのものでないと分かる）ことを求めます。
* ブロックバッファのルーチンの読み出しで、歩きはポインタを知りません。読み出しが `B` の中にあり（`MapOK.read`）、歩きが `B` のどのバイトも知っていれば、読むバイトは
  5 つのタイルのどれかです: `val(m) = m(addr(m)) = m₀(addr(m))`（`readVal_ram`、`Sim`）。なので歩きはタイルごとに 1 本の道をたどります（`tstep`。
  `ScreenPage.readStep` を使う）。ジャンプ台のバイトを立てるルーチン（ジャンプ台のタイルに着地する）とつかまる状態にするルーチン（つかまれるタイルに触る）は、
  タイルを定数と比べます。タイルが分かっていれば、その分岐には行きません。

探索は、当たり判定のゼロページの一時バイト（読み出しから比較までタイルを置く場所）を忘れず、そこでは表を `A` とこれらのバイトで分けます。探索は証明の一部では
ありません。これがないと歩きは違うタイルの道を合わせてしまい、89 のフレームの終わりで失敗しました（つかまる状態、ジャンプ台のバイト 1）。

| 歩き | 段 | 分岐 | 失敗 | 表 | 時間 |
|---|---|---|---|---|---|
| `mapCheck` | 865,443 | 86,197 | 0 | 59,377 | 探索 4.9 秒、確認とあわせて 6〜7 秒。非公開の証明は `titleMapCheck` とあわせて 8.6 秒 |

**フレームからフレームへ.** `map_run` は、`StartRun.starts_dep` と同じく、数えるものも数えないものも全部のフレームでの帰納法です。フレームは操作できる状態で
終わります。数えるフレームは `lags.ctl` から、数えないフレームは [LagFrames](a-5-5-3-LagFrames-ja.md) の確認から（`Lags.known_end`）。なので終わりの状態は 0、1、2
のどれかです。`Real.stSpring` は `b = ix(t)` とします。

## 本物のフレームでの確認

プログラム `open-map-check FM2 300`。操作のときの機械から、数えるフレーム 33 までの各フレームを 1 命令ずつ走らせます。

| 走り | フレーム | 命令 | ブロックバッファのルーチンの読み出し | `MapOK` でない | `B` が `m₀` と違う、`js ≠ 0`、`st > 2` で始まるフレーム |
|---|---|---|---|---|---|
| 自分の入力（300）、TAS（1）、最初の 4 フレームのどれかで 43〜82 フレームのポーズ（60） | 27,261 | 74,386,942 | 82,929 | 0 | 0 |

* これらのどのフレームでも、エリアの読み込みは走らず、画面は動きません。位置は 78 px 以下のままです。高さの上のバイトは 1 です。
* 地面の上では、どのフレームも同じ高さで、縦の速さとその端数 0 で始まります。
* 添字やポインタを通った書き込みは、ポーズのバイトも `CtrlKeep.spareI` のバイトも書きません。
* TAS の操作のときのブロックバッファは `m₀` のものです。

## 仮定（Lean で証明していないもの）

* **`map`**: フレーム 1 から数えるフレーム `N` まで（それも含む）のフレームの各命令の `MapOK`。1 命令ごとの条件です。画面が十分に動いてエリアの読み込みが
  バッファを書くとき、または最初のバッファの外を読むとき（彼はページ 0 にいるので、読む列は最初のバッファのものです）に成り立たなくなります。これらのフレームでは
  どちらも起きません。この回から読み出しは最初のバッファの中と求め（前はどちらかのバッファの中）、数えるフレーム `N` のフレームも含めます。
  [出だしの平らな地面](a-5-4-3-4-1-OpenFlat-ja.md) が両方を使います。
* **もう仮定でないもの**: `st` と `spring`（1-1-a-5-4-3-3-3）。
* **もう仮定でないもの**: `flat`（1-1-a-5-4-3-4-1）。番地の分かっているビットでタイルを読む歩きは足の下の地面が見えます。新しいフィールド `ground` とあわせて
  定理になりました（[出だしの平らな地面](a-5-4-3-4-1-OpenFlat-ja.md)）。
* **証明していないもの**: `jump`（1-1-a-5-7）。空中の高さをフレームからフレームへ追っていません（`vstep` と [ジャンプの高さ](c-2-Jump-ja.md) の弧が与えます。
  パート c はジャンプの最初の 8 フレームでそうしました）。
