# C + 35 での大きなプレイヤーの遅い跳び

[かたまりの角での大きなプレイヤー](c-7-14-1-BigApproach-ja.md) は 1 つの仮定、フィールド `Approach.slowBig` を残しました。最後の低いフレームが角の先にある大きなプレイヤーが、`C + 35`（落下のあとの最初のフレーム）で遅く跳ぶと、かたまりの右の端を越えるのは `C + 98` より後だ、というものです。このページはそれを証明します。このフィールドはなくなりました。

## 前の上限で足りなかった理由

前の上限は、最後の低いフレームの 1 つ前のフレーム `P(s − 1) ≤ c_P − 1` から始め、空中のフレームを空中の速さ（1 フレーム 384/256 ピクセル）で足し、着地のあとのフレームを `capDist` でおさえます。遅い組 `(10, 17)` では、`C + 98` でゴールを 319/256 ピクセル越えていました。

まず 2 つのもっと細かい上限を測りました。どちらもまだ足りません。
- 着地のあとのフレームの正確な表（どの状態からも、各フレームで一番よい入力）: 10 フレームから先は `capDist` より 304/256 ピクセル小さいです。組 `(11, 16)` は閉じます（ゴールまで 113/256 ピクセル足りない）。組 `(10, 17)` はまだ 15/256 ピクセル越えます。
- 空中の速さの上限より下のどの状態からも、着地の前の空中のフレームを正確に: 得はありません。空中の速さで 8 フレーム飛ぶと、表で一番よい状態に着きます。

そこで、`s − 1` での状態とその位置をいっしょにおさえる必要があります。`s − 1` で空中の速さで動いているなら、彼はもっと後ろにいます。部屋の最初のフレームからの探索がこれを与えます。

## 主張

`P` の単位は 1/256 ピクセルです。`c_P` は角（51 ピクセル）、`G_P` はゴール（かたまりの右の端）です。`T1 + 1` は跳ぶフレーム、`s = T1 + 1 + u.low` は最後の低いフレーム、`L` はかたまりの上のフレーム、`t₀` はゴールを越えた最初のフレームです。ジャンプの表の遅い組 `q = (q₁, q₂)` は `q₁ ≤ u.low`、`q₂ ≤ u.k` を満たします。ここでは `(10, 17)` と `(11, 16)` です。`hdist(x, is)` は、状態 `x` からフレームの列 `is` が `P` を動かす距離です（モデル `hstep`）。

```
dist_table:  tableOk(T, n)  →  定義域の状態 x と入力 i₁ … i_k（k ≤ n）で
               hdist(x, i₁ … i_k) ≤ T[k][x]
  tableOk(T, n):  0 ≤ T[0][x]、そして  16·v(hstep(x, i)) + T[k][hstep(x, i)] ≤ T[k + 1][x]
                  すべての状態 x、すべての入力 i、すべての k < n で

search_cov:  P(C) ∈ [P0, P1]、落下の空中のフレーム 34 個、跳ぶフレーム、さらに空中のフレーム k 個、
             跳ぶフレームから先の各フレームの終わりで P < c_P
             →  search(k) のある項目 (x, lo, hi) が状態 x を持ち、lo ≤ P ≤ hi
             （それらのフレームでは一番大きい P を c_P − 1 に切る）

slow_short:  遅い組 q、K = 98 − (34 + q₁)、B = 98 − (35 + q₂) で:
             search(q₁ − 1) の終わりの状態、空中の速さの上限より下、P < c_P、
             そのあと空中のフレーム a 個とフレーム b ≤ B 個、a + b ≤ K
             →  P + hdist(…) < G_P

slowCheck（新しい確認 Checks.slowLand）: 各遅い組 q と各 b ≤ B で
  c_P − 1 + 384·(K − b) + max { T[b][x] : x は空中の速さの上限より下 }  <  G_P
  または、各 a ≤ K − b と、search(q₁ − 1) のあと空中のフレーム a 個の各項目 (x, lo, hi) で
  hi + T[b][x]  <  G_P
```

`landed_short` の場合 `T1 = C + 34`、遅い跳び、`¬LowAt(s)`: `s₂ = T1 + q₁ ≤ s − 1` とします。`C` から `s₂` までのフレームは探索のフレームです。落下のフレームは空中のフレーム、`C + 35` は跳ぶフレーム、`s − 1` までのどのフレームも角より左です（`left_at`）。`s₂` で彼は空中の速さの上限より下です（`capped_along`）。`s₂` から `L` までは空中のフレームで、`t₀ − L ≤ B`、`t₀ − s₂ ≤ K` です。よって `slow_short` から `P(t₀) < G_P` で、`G_P ≤ P(t₀)` に反します。

## 確認

`slowCheck` は、定義域のすべての状態とすべての入力で `hstep` を 1 回ずつ走らせます。129,024 個の状態、38 個の入力です。その配列の各項目は自分の状態を持ちます（`inv_trans`）。`trOk` は各状態が自分の番号の場所にあることを確かめます。だから表の確認は配列からフレームを読み、`hstep` をもう一度は走らせません。探索は `hstep` を自分で走らせます。`C + 45` まで、1 フレームの状態は多くて 581 個です（落下のあとは 250 個）。

`C + 98` での余裕（ゴールまで足りない分、1/256 ピクセル）:

| 組 | 着地のあとのフレーム | `c_P − 1` から（1 行目） | 探索から（2 行目） |
|---|---|---|---|
| (10, 17) | 45 | 241 | 401 |
| (10, 17) | 46 | −15 | 145 |
| (11, 16) | 46 | 369 | 529 |
| (11, 16) | 47 | 113 | 273 |

2 行目が要るのは、組 `(10, 17)` で着地のあと 46 フレームのときだけです。

確認はネイティブで約 44 秒かかります（そのうち 33 秒が `hstep` の 1 回の通し）。これは非公開の定理 `land_dist` で、自分のファイル `Proof/LandDist.lean` にあります。ROM しか要らないので、ほかの非公開の証明と並んでビルドされます。
