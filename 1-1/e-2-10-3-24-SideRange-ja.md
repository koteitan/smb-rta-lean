# エリアの読み込みの外の、横のタイマーに届きうる書き込み

第 33 回は、フィールド `sideW` を横の当たりのタイマーに届きうる書き込みでだけ求めました（[横のタイマーに届きうる書き込み](e-2-10-3-22-SideNear-ja.md)）: 絶対アドレスに添え字を足した書き込みで、ある添え字がその元のアドレスからタイマーに届くもの、またはポインタを通した書き込み（`NearW`）。ここでは、2 つのコードの外にある、そのような書き込みのそれぞれで、歩きがこれを証明します。2 つのコードとは、エリアの読み込みのコードと、頭がブロックに当たるときのコードです。だからフィールドは、その 2 つのコードにある書き込みでだけ求めます。

**主張（第 34 回）.** 次のように書きます。

```
s          = 横の当たりのタイマー、RAM の添え字として
SideW(m)   := m での添え字かポインタを通した書き込みは s を書かない
NearW(m)   := 第 33 回（ある添え字が元のアドレスを s に運ぶ、絶対アドレスに X か Y を足した書き込み、または STA (zp),Y）
Resid(m)   := AreaParserCore ≤ pc(m) < GetBlockBufferAddr        （エリアの読み込みのコード）
              または PlayerHeadCollision ≤ pc(m) < BlockObjectsCore （頭がブロックに当たるときと、そこから呼ぶたたかれたブロックのルーチン）
```

`SideRange.near_side`: `PushTimer.pix_end` の仮定から、フィールド `posW` と `sideW` を除いたものを満たす操作中のフレームをとります（待ちのループで始まり、各命令は `FrameKeep.guardE` の `CleanK` を満たし、どの命令もルーチン、モード、タスクをアドレスで書かず、n₀ でプレーヤーのルーチンに来る）。すると、n₀ より後の最初の kq でスクロールの処理の呼び出しに来て、

```
フレームの中の ∀ j ≥ kq:  NearW(trace j) ∧ ¬Resid(trace j)  →  SideW(trace j)
```

`rCheck` が ROM の上の確かめです（自前の実行で数秒で真）。公理: `propext`、`Classical.choice`、`Quot.sound`。ゲームのデータはありません: コードの場所は 4 つの記号（`AreaParserCore`、`GetBlockBufferAddr`、`PlayerHeadCollision`、`BlockObjectsCore`。`tools/smb-symbols.txt` に新しく加えた）で、逆アセンブルから読みます。

**歩き.** `walkR` は、そこでの `AfterKeep` の 1 つ目の歩きの状態から、スクロールの処理の呼び出しで始まり、フレームの終わりまでたどります。どのバイトも追いません。守りは `FrameKeep.guardE` で、その `CleanK` は `FrameKeep.Frames` のフィールド `cleanE` です。ルーチン、モード、タスクをアドレスで書くところで道は止まります（フィールド `noStore`）。`Resid` でない `NearW` の書き込みで、歩きは、状態が許すどの行き先も s を外れることを求めます（`missK`）: X か Y を通すなら添え字のどの値でも、ポインタを通すなら、ポインタの上のバイトのどの値でも、下のバイトと Y の和の最小から最大までのどの値でも（`missP`）。そこで添え字とポインタを知るために、3 つのものを使います:

1. **表の状態での範囲.** 表の状態は、`Sim` が読まない `log` に範囲 lo ≤ X ≤ hi と lo' ≤ Y ≤ hi' を持ちます（`bnd`）。表の状態からの歩きは、その切れ端から始まります: X、次に Y を、範囲の中のその値に分けます。値が 17 より少なく、知っているビットが許す値を範囲が除くときです（`pieces`、`pieces_cov`）。状態が表の状態で覆われるのは、知っているビットがその表の状態以下で、X と Y の値が範囲の中にあるときだけです（`coverR`、`bok_of_leB`）。だから `INX; CPX #13; BNE` のようなループの数えは 0..12 の範囲を保ちます。知っているビットだけなら 0..15、さらにそれより広がります。
2. **いくつかの命令の前の分け.** `TXA`、`INX`、`DEX` と X を通した書き込みの前で、わからないビットが高々 4 なら X をその値に分けます。`TYA`、`INY`、`DEY`、`STA abs,Y` の前で Y も同じです（`splitR`、`cov_splitR`）。切れ端は知られた値で命令を通ります。
3. **届かない書き込みをこえるゼロページ.** 書き込みの添え字がわからないとき、TaintRun の一歩は守りの外のバイトをすべて忘れます。添え字かポインタを通した書き込みのあと、歩きは、前の状態が知っていて書き込みが書かないゼロページのバイトをそれぞれ取り戻します（`fixR`、`StepWrites.keep_step`）。だから物の番号、一時の値、ゼロページのポインタは、絶対アドレスの表への書き込みをこえて残ります。

定理 `okR_spec` は、m を覆う状態での `okR` を `NearW(m) ∧ ¬Resid(m) → SideW(m)` にします: 書き込みの行き先は元のアドレスと添え字の和（`PushTimer.abx_t`、`PushTimer.aby_t`）、またはポインタと Y の和（`izy_t`）で、それは `missK` が確かめる行き先の 1 つです。

**ルートでは.** `OnFrames` のフィールド `sideW` は前提を 1 つ多く求めます: `Resid(trace n)`。

```
sideW : ∀ j, 1 ≤ j → j < g → side(seq j) ≠ t₁₆ →
          ∀ k n, arrAt ≤ k → k ≤ n → pc(trace k) = PlayerSubs → frame(trace n) = frame(fm j) → NearW(trace n) → Resid(trace n) → SideW(trace n)
```

第 33 回のフィールドは定理 `OnFrames.sideWAt` です（`Resid` の書き込みではフィールドから、ほかでは `near_side` から）。`numbersCheck` に確かめ `SideRange.rCheck` が 1 つ加わり、`AreaRun` にそれからのフィールド `rg` が 1 つ加わりました。フィールドが求めるものは少なくなりました: 同じフレームで、各フレームでは `Resid` の書き込みだけです。プログラムの `NearW` の書き込み 50（添え字を通したもの 41、ポインタを通したもの 9）のうち、29 が `Resid` にあります（エリアの読み込みに 27、頭がブロックに当たるときに 2）。

**測ったこと.**

| 確かめ | 何を | 結果 |
|---|---|---|
| 自前の実行の探索（`SideRange.rFails`） | スクロールの処理の呼び出しからの歩きの探索 | 外れ 0。届いた状態 19,751、表の状態 16,803 |
| 自前の実行での計算 | 1-1 のエリアの種類での `rCheck` | 真 |
| 自前の実行の試しの探索 | 範囲がない、または分けがない同じ歩き | 範囲がないと、そのほかの物の当たりの印への 2 つの書き込み（ハンマーとプレーヤーの当たり）で 10 の外れ。そこでは X は、そのほかの物のループが 8 から数え下げる物の番号。分けがないと、その 2 つとそのほかの物の位置のルーチンで 5 の外れ。ゼロページがないインタプリタの試しの探索も同じ 2 つの書き込みで外れた。知っているビットだけ（第 33 回の歩き）の探索は 24 の場所で外れた |
| 自前の実行の試しの探索 | `Resid` の書き込みでも求めた歩き | 6 つの場所で 140 の外れ: エリアの読み込みのメタタイルのバッファへの 4 つの書き込みとブロックのバッファへのポインタを通した書き込み、彼がたたくブロックのポインタを通した書き込み。道は最初の外れで止まるので、その後ろの書き込みは数えていない |
| `surface-frames-check FM2 200`、`edge-real FM2 256` | `sideW`（狭めたフィールド）、`sideWAt (a theorem)`（第 33 回のフィールド、`NearW` のすべての書き込みでの `SideW`） | どちらも外れ 0。`surface-frames-check`: 8 組、239,510 フレーム、確かめたのは 215,433 フレーム、書きかえた状態も含む。`edge-real`: 5 組、画面外のビットのルーチンに来る 137,955 フレーム、タイマー高々 1 で終わる 108,634 フレーム。外れるのは、きれいに始まらないフレームでの古い保存された速さと `after` だけで、数は第 30 回から第 33 回と同じ |

**ここで証明していないこと.** `Resid` の書き込みでの `SideW`:

- エリアの読み込みのバッファへの書き込み（メタタイルのバッファ、エリアの物の長さと位置、キノコの台の半分の長さ。26 の書き込みとポインタを通した 1 つ）。その添え字は、フレームをこえて残るバイトから来ます: たとえば RAM のバイト（階段の制御）を位置とする ROM の表から読む行や、エリアのデータの中の物の位置。1 フレームの歩きはそれを知りません。フレームをこえる不変な性質が要ります。
- 彼がたたくブロックの、ポインタを通した 2 つの書き込み（`PlayerHeadCollision` の中と、ブロックの上を見るルーチンの中）。ポインタの上のバイトはゼロページにあり、フレームをこえて残るバイト（ブロックのスプライトの位置）からの X を通したゼロページへの書き込みが、歩きの知る限りでは、それを書きかえます。

第 35 回は、細かい表と分けを 1 つ加えて、そのうち 4 つを除くすべてを証明します（[エリアの読み込みのループの、横のタイマーに届きうる書き込み](e-2-10-3-25-SideLoop-ja.md)）: フィールドは、ポインタを通した 3 つの書き込みと、城の行のループの書き込みでだけ求めます。`numbersCheck` は `rCheck` のかわりに `SideLoop.lCheck` を持つので、このファイルの `near_side` はもうルートでは使いません。`SideLoop` はその歩きを使います。
