# 横のタイマーに届きうる書き込み

第 32 回はフィールド `sideW` を作りました（[彼を動かす押し戻しは横のタイマーを 16 にする](e-2-10-3-20-PushTimer-ja.md)）: 横の当たりのタイマーが高々 1 で終わる数えるフレーム（ロックが 0 で場所のバイトがしきい値以上）では、スクロールの処理からフレームの終わりまでのどの命令でも、添え字かポインタを通した書き込みはタイマーを書かない。ここでは、いくつかの種類の書き込みを除くすべての命令でこれを証明し、フィールドはそれらでだけ求めます。

理由: タイマーはゼロページとスタックのページの外の RAM のバイトです。`X` を通したゼロページへの書き込みの行き先はゼロページの中です。絶対アドレスに添え字を足した書き込みは、元のアドレスから高々 255 バイト先までしか届かないので、たいていの元のアドレスからはどの添え字でもタイマーに届きません。

**主張（第 33 回）.** 次のように書きます。

```
s          = 横の当たりのタイマー、RAM の添え字として（スクロールの処理の読み込みから）
SideW(m)   := m での添え字かポインタを通した書き込みは s を書かない
NearW(m)   := m で、絶対アドレスに X か Y を足した書き込みで、ある添え字 0..255 がその元のアドレスを s に運ぶもの（RAM の鏡を法として）、
              またはポインタを通した書き込み（STA (zp),Y）
```

`PushTimer.sideW_far`: 256 ≤ s で、m の命令コードのあとの 2 バイトがプログラムの半分のアドレスにあり、¬NearW(m) なら、SideW(m)。

`PushTimer.sideW_of_near`: m を覆う PushTimer の歩きの状態で（歩きはそこで `okS` を求める: 割り込みが待っていない、命令とその次の 2 バイトがプログラムの半分にある）、(NearW(m) → SideW(m)) → SideW(m)。

`PushTimer.pix_end` は、スクロールの処理からの各命令 m で、PosW(m) ∧ SideW(m) のかわりに PosW(m) ∧ (NearW(m) → SideW(m)) を求めるようになりました。`sCheck` に 256 ≤ s が加わりました。

定理は `PushTimer.sideW_far`、`PushTimer.sideW_of_near`（公理 `propext`、`Quot.sound`）です。ゲームのデータはありません: 命令コードは 6502 のもの、元のアドレスはプログラムから読みます。

**証明.** m の命令コードで分けます（`PipeWrites.wTarget` の書き込み）:

* `X` つきゼロページの `STA`、`STY`、`DEC`、`INC`: 行き先は (オペランド + X) mod 256 で、256 ≤ s より小さい。
* `X` つき絶対アドレスの `STA`、`DEC`、`INC`、`ROR`、`Y` つき絶対アドレスの `STA`: 行き先は元のアドレスに添え字を足したもの。¬NearW(m) は、どの添え字 0..255 でもそれがタイマーでないと言う（`PositionKeep.farB_spec`）。
* `STA (zp),Y`: NearW(m)。

**測ったこと.**

| 確かめ | 何を | 結果 |
|---|---|---|
| ROM（逆アセンブルの試しの一覧） | `NearW` の書き込み | プログラム全体で、タイマーの 0 から 255 バイト下の元のアドレスからの、絶対アドレスに添え字を足した書き込みが 41、ポインタを通した書き込みが 9。たいていはエリアの読み込み（メタタイルのバッファ、エリアの物の長さと位置） |
| 自前の試し（試しの探索） | フィールドからでなく、歩きが知っていること（添え字、ポインタのバイト）から `SideW` を求めた PushTimer の歩き | 21 から 24 の場所で外れる。どれも `NearW` の書き込み: メタタイルのバッファ、エリアの物の長さと位置、ポインタを通したブロックのバッファ（コインと斧、敵の足もと、彼がたたくブロック、つる）、ハンマーの敵の位置、そのほかの物の当たりの印。そこでは歩きは添え字を知らない（TaintRun はビットを知る。一部のビットがわからない添え字に `INX`、`DEX` をすると忘れる）。添え字と `Y` を表のキーに入れ、`INX`、`DEX`、`INY`、`DEY` の前で添え字を分けた探索は、300,000 回で終わらなかった（167,395 状態、13 の場所で 194 の外れ。添え字がちょうどタイマーに届く値と知られているものもある: 本当の機械が通らない道） |
| `surface-frames-check FM2 200`、`edge-real FM2 256` | `sideW`（狭めたフィールド、フィールドのフレームで）、`sideW on every frame (measured only)`（スクロールの処理からの、すべてのフレームのすべての命令での `SideW`） | どちらも外れ 0。`surface-frames-check`: 8 組、239,510 フレーム、確かめたのは 215,433 フレーム、書きかえた状態も含む。`edge-real`: 5 組、画面外のビットのルーチンに来る 137,955 フレーム、タイマー高々 1 で終わる 108,634 フレーム。外れるのは、きれいに始まらないフレームでの古い保存された速さと `after` だけで、数は第 30 回から第 32 回と同じ |

**ルートでは.** フィールド `sideW` は、より少ない命令で、より多くのフレームで求めます。前（第 32 回）:

```
sideW : ∀ j, 1 ≤ j → j + 1 < g → side(seq j) ≤ 1 → lock(seq j) = 0 → thr ≤ pfs(seq j) →
          ∀ k n, arrAt ≤ k → k ≤ n → pc(trace k) = PlayerSubs → frame(trace n) = frame(fm j) → SideW(trace n)
```

いま:

```
sideW : ∀ j, 1 ≤ j → j < g → side(seq j) ≠ t₁₆ →
          ∀ k n, arrAt ≤ k → k ≤ n → pc(trace k) = PlayerSubs → frame(trace n) = frame(fm j) → NearW(trace n) → SideW(trace n)
```

ここで t₁₆ = `PushTimer.pushT` は、押し戻しがタイマーに書く値（16）で、押し戻しのコードから読みます。ロックが 0 で場所のバイトがしきい値以上、とはもう求めず、タイマーが押し戻しの値で終わらないどのフレームでも求め（タイマー高々 1 で終わるフレームのかわりに）、旗に触る前の最後の数えるフレームでも求めます: [補正が止めるフレームは画面の左端で終わる](e-2-10-3-23-StopClamp-ja.md) がそれらのフレームで使います。だから新しいフィールドは古いものより弱くはありません: 各フレームではより少なく、より多くのフレームで求めます。

**ここで証明していないこと.** `NearW` の書き込みでの `SideW`。証明するには、歩きがそれらの書き込みで添え字を抑え（メタタイルのバッファの行は 0 から 12、エリアの物は 0 から 2、そのほかの物は 0 から 8）、ブロックのバッファのポインタがブロックのバッファを指すと知る必要があります。TaintRun の歩きはビットだけを知り、ループで数える添え字を忘れます。範囲を知る歩きか、添え字を表のキーに入れてループの数えを追う歩きが要ります。
