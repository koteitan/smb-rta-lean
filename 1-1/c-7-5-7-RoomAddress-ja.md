# 部屋のブロックバッファの列のポインタ

**部分結果です。** 小さい `GetBlockBufferAddr` ルーチンは、32通りの列・バッファの指定から、地図の対応するポインタを作ります。どのスタックの値でも成り立ちます。`RoomAddress.pointer_of_check` は、ルーチンの入口で A がその指定を持つ実際の機械から、40命令以内に返る位置まで来て、ポインタが分かることを証明します。非公開の ROM の確認 `room_address_check` は 8,192 通りを、ネイティブで約 0.74 秒で確かめます。

指定 `a` のポインタは次です。

```
バッファの始まり + (a / 16) * 半分のバッファ長 + (a % 16)
```

入口とポインタのバイトは、既存の `EntryHeight.hpOf` でコードから読みます。公開ファイルに ROM のバイトや番地はありません。共通の引数はループの外で作ります。各場合で作り直す最初の測定は遅く、90秒で止まりました。定理の仮定と結果は変えていません。

## 横位置の計算

`encoded_eq_selector` は、横のずれをピクセルに足し、桁上がりをページに足し、ページの偶奇とピクセルの上位4ビットを合わせた値が、2つのバッファを1周とする横位置の列指定に等しいことを証明します。`selector_lt` は指定が 32 未満であることを示します。`bytes16_eq` はポインタの上下バイトからの復元です。いずれも一般のビットの等式で、Lean 標準の `bv_decide` で証明しています。Mathlib や ROM の仮定は使いません。

ポインタの補題自体は A が分かるところからです。新しい [RoomCollision](c-7-5-8-RoomCollision-ja.md) は、プレイヤーの呼び出しについて、任意のずれの添字から座標、行、実際のタイルの読み、復帰までを証明します。フレーム全体の位置や着地への接続は別に残ります。

## 着地にまだ要るもの

`Solid` は、バッファ内の添字が分かれば床のタイルを与えます。今回の結果は、小さいルーチンの終わりで列のポインタを与えます。`RoomCollision` は、呼び出し内での座標と行の計算、実際の読みまでのポインタの保存を証明しました。`land_at` をなくすには、各足の呼び出しでのフレーム内の移動後の位置、必要な地図の場所、その後の着地の分岐が要ります。`stand_wall` と `wall` にも同じフレーム全体の接続が残ります。3つのフィールドはそのままで、新しい走りのフィールドはありません。

フレーム全体の試行は、最初の落下の着地直前の状態、コイン以外の地図全部、横位置の上位4ビットから始めました。最初の有限探索は 1,062,638 ステップ、169,175 状態で、2,433 状態が未処理でした。ポーズした終端を認め、30万状態の上限を使うと、2,236,722 ステップ、300,001 状態、未処理 2,638、診断上の失敗 77 でした。証明でも実機の反例でもありません。抽象化で横位置と列のつながりが失われるので、より大きな探索は残していません。

## 本物のフレーム

拡張した `room-floor-check` は、列のルーチンでの指定を位置の式と比べます。タイルの読みのポインタと番地も、指定した列と Y による値と比べます。既存のコインの消去、地図の保存、着地の確認も残します。`room-jump-check` と `room-stand-check` は、動画と独立したランダム入力で既存の部屋のフィールドを確かめます。

Lean: `Theorems/RoomAddress.lean`。非公開の確認: `Proof/RoomAddress.lean` の `room_address_check`。Route の型は変えていません。

最後の全体 `prove.py`、新しい非公開の確認、`room-jump-check FM2 100`、`room-stand-check FM2 100`、`room-floor-check FM2 60` はすべて終了値 0 でした。床の確認の 59,811 フレームで、列の指定・ポインタ・読み出し先の 410,104 回すべてが式に一致し、食い違いは 0 でした。実機の確認は残る証明の代わりではありません。最後の道筋と新しい定理の公理の確認も終了値 0 で、`sorryAx` はありません。
