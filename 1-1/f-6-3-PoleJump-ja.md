# ポールのジャンプを機械から読む

**部分結果です。** 立った状態から新しく A を読む、数えるフレームは、スクロール処理に着くと、前の数えるフレームの機械の高さと保存された速さによる `VertJump.jumpOff` になります。ジャンプ中で上昇し、ジャンプを止める値も得ます。`take_subs` は既存のフレームの条件でこれを証明します。`take_end` は、明示した5バイトの条件 `VEnd` の下で、フレームの終わりにも同じ結果を与えます。`PoleJoin.Run` のフィールドは増減していません。`direct` の任意の弧と、その `reads`、`path`、`atY`、`atRising` は残ります。

## 1フレームのつながり

新しいファイルは `Theorems/PoleJump.lean` です。

- `vert_jumpH` と `vert_airH` は、既存の移動の歩きが終端で求めるジャンプの停止値も取り出します。`VertJump.vert_jump`、`VertAir.vert_air` と同じ ROM の確認を使います。
- `atV_of_atFrame` は `FrameModel.AtFrame` から使う条件を示します。機械が正常、ルーチンの位置とスタック、操作中のルーチン、場所の種類、プレイヤーの状態、ばねの動きなし、水泳なし、大きさの変更なしです。
- `take_read` は時間の条件を持つ本物のフレームを、プレイヤーのルーチンからスクロール処理まで追います。命令数は `FrameModel.moveLen` 以下です。新しい A は、そこで `SavedJoypadBits` の A が入り、`PreviousA_B_Buttons` の A が切れていることです。入力パッドとその読みを同じとは仮定しません。
- `take_subs` は `OnFrames.readE_at` と `StopRead.keep_at` を使います。高さ、立った状態、保存された速さは `seq(j-1)` のものです。触るフレーム自身（`j ≤ g`）にも使えます。
- `air_subs` は同じフレームの条件と、空中の状態、`HaltOK`、`PrevOK` を使います。モデルの保存された速さを 0 にしても縦の動きは同じです。実機の保存された速さが 0 という意味ではありません。

フレームの条件は引数で明記しています。操作・モデル・摩擦・待機ループの確認、`OnFrames`、各フレームの始めの条件、`AreaRun`、最初の速さ 0 と位置、範囲の上限 `g ≤ farN`、数えるフレームの範囲です。ポールの道筋の既存の `frames` と `keep` から使うものです。`PrevOK` は既存の前のボタンの確認と `OnFrames.prevAll` で最初の操作から保てます。停止値は踏み切りと空中の補題が与えます。新しい走りの条件を隠してはいません。

## スクロール処理のあとに残るもの

`VEnd` は、高さ、高さの端数、縦の速さ、端数のカウンタ、プレイヤーの状態（`SurfaceFrames.vHard`）が、スクロール処理から数えるフレームの終わりまで保たれることです。**明示した仮定**であり、地上のすべてのフレームで証明したものではありません。既存の `vAfter` の範囲は早いフレームに限られ、最後のジャンプ全体には使えません。

`end_vertical` は `VEnd` と空中の状態から、縦の状態の9成分がすべて保たれることを示します。下向きの力、原点、停止値、A は `OnFrames.kAt` によります。縦の力は `vfAt` によります。その例外は立った状態で終わるので、空中の状態が保たれることと矛盾します。そこから `take_end` と `air_end` がフレームの終わりの実際の状態を与えます。この保存を使うのは触る前だけです。触るフレーム自身は、つかむ処理で変わる前のスクロール処理で読む必要があります。

## 弧と `reads`

`arcM` は与えた縦の状態の列に、モデルのカウンタ `k`、`low`、`above` を付けます。`arcOf` の踏み切りの速い・遅いの区分は、本物の `seq(T-1)` の保存された速さから決めます。`reads_of_machine_arc` は、この定義した弧について、速いならその保存された速さが `AirFastSpeed` 以上であることを証明します。今の `Run.direct` が自由に与える弧との一致は証明していません。

`arcM_start` は、実際の踏み切りが地面の高さからで、保存された速さが `TopSpeed.top` 以下なら、モデルの始まりの集合に入ることを示します。`arcM_step` は、まだモデルが止まる条件を満たさないとき、1回の実際の縦のステップからモデルの次の状態を与えます。`path_of_frames` はこれらから `VertModel.vmach` 上の `JumpPath` を作ります。地面からの踏み切り、保存された速さの範囲、各空中フレームのステップ、触るまでモデルが止まらないこと、長さの上限はすべて明示した仮定です。道筋でこれらを証明したわけではありません。

`arcM_atY` と `arcM_atRising` は、与えた接触時の状態についてすぐに成り立ちます。道筋には、その状態が実際の接触の機械であり、自由なフィールド `touchY`、`touchRising` に一致することがまだ要ります。この終端の一致自体には途中の空中フレームは不要ですが、`path` には要ります。

非公開の `Proof/PoleJump.lean` は、移動の補題とスタック・停止値を合わせた `vmach` 上でも、モデルのつかむ高さの確認をします。別の ROM の確認です。既存の道筋とモデルは変えていません。

## 確認と残る仕事

拡張した `stop-read-check FM2 100` は、本物の踏み切りと空中フレームのスクロール処理で、縦の状態をモデルと比べます。5バイトが保たれた場合は、フレームの終わりも比べます。5バイトが変わるフレームは別に数え、`VEnd` を満たすとは仮定しません。`pole-join-check FM2` でも既存の道筋を確かめます。

道筋の仮定を消すには、地面からの実際の踏み切り、その空中フレームでの5バイトの保存、モデルの残る範囲条件、実際の接触とのつながりが要ります。今のフィールドを、より強い条件や無関係な条件に置き換えることは削除ではないので、今回はフィールドをそのまま残しました。

最後の全体ビルドと両コマンドは終了値 0 でした。数える 50,821 フレームで、踏み切り 873 回と空中の 26,622 回がスクロール処理でモデルに一致しました。測定した `VEnd` の下では、終端でも踏み切り 873 回と空中の 25,543 回が一致しました。5バイトのどれかが変わる 1,185 フレームは別に数えました。試した踏み切りでは保存された速さが `TopSpeed.top` を超えるものはありませんでした。`vmach` 上のつかむ高さの確認も通りました。道筋と新しい定理の公理の確認は終了値 0 で、`sorryAx` はありません。
