# 地上への切り替えの長さを決めるもの

**主張.** これは部分的な結果です。切り替えは 282 = 160 + 122 フレームです。はじめの 160 フレームで土管のタイマーが切れます。残りの 122 フレームは、リスト `R` の外のすべてのバイトのすべての値について長さを証明しました。はじめの 160 フレームは、挙げた 20 個の入る状態についてだけ証明しました。どの走りのどの入る状態でも長さが 282 であることは、仮定のもとでだけ定理です（`every_entry`）。書き換えた状態の中には、これが成り立たないものがあります。

**短くなる場合.** コードの 2 つ目のタイマーを動かしました。入る 1 フレーム前に画面が最初のページにないと、マリオは入り、切り替えは 174 フレームです。108 フレーム短くなります（Lean。書き換えた 2 個の状態）。そのような状態に届いた走りはありません。コードから読むと、本物の走りでは届きません（下に書きます。この理由は Lean にしていません）。ですから [1-1 のルート](../docs/route-1-1-ja.md) のフレーム 852 の下限は変わりません。ただし、この理由に頼っています。

`m₀` は 1-1 の開始の機械です。`run(m, w)` は入力 `w` で本物のフレームを進めた機械です。`ctl(m)` は `controllable` です。`0^k` は入力なしの `k` フレームです。`P` と `E` は、[横の土管から地上への切り替え](d-1-SideTransition-ja.md)の、入るフレームの前と終わりの機械です。`T = run(E, 0^160)` は土管のタイマーが切れたときの状態です。`m[i]` は RAM のバイト `i` です。

`core(m)` は、レジスタ、プログラムカウンタ、ROM、PPU の欄、コントローラのシフト状態、サイクル数の偶奇、フレーム数の偶奇です。`pad` は含みません（フレームが上書きします）。RAM も含みません。下の `core(M) = core(...)` では、`M` は記録がオフで RAM が 2048 バイトでもあります（`SameCore`）。

`T` の*位置* `v` は、フレームの境目のドット `d ≤ 9`、サイクルの偶奇、フレームの偶奇を決めた `T` です。全部で 40 個です。PPU 制御のミラーの増分のビットは、どれでもオフです。地上と違い、部屋では面の縦の列を書かないからです。

`R`（116 バイト）、`RE`（218 バイト）、`Rvar ⊂ R`（73 バイト）は動かして求めます。`Rfix = R \ Rvar`（43 バイト）です。`entries` は `E`、書き換えた 13 個の状態、本物の 6 個の状態です（下に書きます）。

```
decided     :  ∀ T の位置 v, ∀ M :  core(M) = core(v)  ∧  (∀ i ∈ R, M[i] = v[i])
                 →  ∀ k, 1 ≤ k ≤ 122 → ( ctl(run(M, 0^k)) ↔ k = 122 )
ends        :  同じ M で :  ∀ i, (i ∈ R ∨ v からの走りが i を書いた)  →  run(M, 0^122)[i] = run(v, 0^122)[i]
atEntry     :  ∀ M :  core(M) = core(E)  ∧  (∀ i ∈ RE, M[i] = E[i])
                 →  ∀ k, 1 ≤ k ≤ 282 → ( ctl(run(M, 0^k)) ↔ k = 282 )
entered     :  P は入る  ∧  P で画面は最初のページにある
entryStates :  ∀ m ∈ entries, t = run(m, 0^160) として :
                 ∀ k, 1 ≤ k ≤ 282 → ( ctl(run(m, 0^k)) ↔ k = 282 )
                 core(t) = core(t のドット、偶奇、ビットの T)  ∧  ∀ i ∈ Rfix, t[i] = T[i]
                 ∀ M :  core(M) = core(t)  ∧  (∀ i ∈ R, M[i] = t[i])  →  ∀ k, 1 ≤ k ≤ 122 → ( ctl(run(M, 0^k)) ↔ k = 122 )
real        :  本物の 6 個の状態はどれも入る。画面は最初のページにある
shorter     :  画面が最初のページにない P の 2 個の状態 :  入る  ∧  ∀ k, 1 ≤ k ≤ 174 → ( ctl ↔ k = 174 )
timer       :  E のタイマーを v に書き換えた状態、2 個の値 :  ∀ k, 1 ≤ k ≤ 122 + v → ( ctl ↔ k = 122 + v )
lag         :  6 個の物が近くにある 2 個の状態 :  ちょうどフレーム L で操作できる。L > 282
flag        :  時間切れのフラグを立てた状態 :  ちょうどフレーム 427 で操作できる
died        :  ゲームタイマーが 000 :  ∀ k, 1 ≤ k ≤ 300 → ¬ctl

every_entry :  ∀ M, t = run(M, 0^160)、v = t のドットと偶奇の T の位置 として :
                 (H1) ∀ k, 1 ≤ k ≤ 160 → ¬ctl(run(M, 0^k))
                 (H2) dot(t) ≤ 9  ∧  t の増分のビットがオフ  ∧  core(t) = core(v)
                 (H3) ∀ i ∈ Rfix, t[i] = v[i]
                 (H4) ∀ k, 1 ≤ k ≤ 122 → ( ctl(run(t, 0^k)) ↔ ctl(run(t の Rvar を v の値にしたもの, 0^k)) )
               →  ∀ k, 1 ≤ k ≤ 282 → ( ctl(run(M, 0^k)) ↔ k = 282 )
```

`decided` と `atEntry` では、`R` や `RE` の外のバイトは何でもかまいません。`R` には、敵のバイト、マリオの位置と速さ、`HorizontalScroll` と `VerticalScroll` のほかの画面の位置、ブロックの地図のバイトがありません。ですから、これらはフレーム 161 から 282 を変えません。`every_entry` の `M` は任意の機械です。入る状態でなくてもかまいません。

ほかの長さになる場合です。はじめの 3 つは 282 より短くなります。

| 状態 | 書いた場所 | 操作できるまでのフレーム |
|---|---|---|
| 画面がページ 2 と 3、マリオがページ 2 | `P` | **174**（Lean） |
| 画面のページのバイトだけを 255 | `P` | **174**（Lean。測定: 129 以上のすべての値） |
| 切り替えのタイマーを `v` | `E` | **122 + v**（Lean は 2 個の値。測定: 1 以上のすべての `v`。0 は 378） |
| 時間切れのフラグ | `E` | 427（Lean） |
| クリボー 6 匹が 0 ピクセルおき、ハンマーブロス 6 匹が 4 ピクセルおき | `E` | 283、284（Lean） |
| クリボー 6 匹が 2、4、8 ピクセルおき、ノコノコ 6 匹が 4 ピクセルおき | `E` | 283、283、282、283（測定） |
| ゲームタイマーが 000 | `E` | 300 フレーム操作できない（Lean）。着いたところで死にます。エミュレータでは 1 機減り、フレーム 800 に 1-1 で操作できます |

`HalfwayPage` と `WarpZoneControl` は[縦の土管の切り替え](b-2-1-PipeTransitionAll-ja.md)の長さを変えますが、こちらの長さは変えません。両方を立てて 282 です（Lean。1 個の状態）。`WarpZoneControl` は `RE` にないので、`atEntry` がすべての値を含みます。

Lean: `Theorems/SideTransitionAll.lean`（`Statement`、`statement_of_check`、`every_entry`、`no_control_before`）。[地下への切り替えの長さを決めるもの](b-2-1-PipeTransitionAll-ja.md)から `decided_of_check`、`end_of_check`、`entryFacts_of_check`。そのページの `Statement` と `every_entry` は縦の土管の入る状態についてのものなので、このファイルに同じ証明で別に置きました。非公開の `side_all_checks`（`native_decide`）、`side_all`、`side_all_entries`。`every_entry` が使う公理は `propext`、`Classical.choice`、`Quot.sound` だけです。

## しくみ

**記録した走りが決める.** [縦の土管のページ](b-2-1-PipeTransitionAll-ja.md)と同じ定理です。`ref` からの記録した走りが `R` のバイトしか読まないなら、`core(M) = core(ref)` で `R` の値が `ref` と同じ機械は、毎フレーム同じ値、同じ操作の可否になります。

**フレーム 160 で切る理由.** フレーム 160 で土管のルーチンが切り替えを始め、ゲームエンジンの残りは飛ばされます。フレーム 161 で面の準備が RAM を消します。この消去は、そのフレームの終わりでもまだ動いています。ですから、物、マリオの位置と速さは、フレーム 160 のあと読まれません。記録でも確かめました。`T` からの走りは 2048 バイトのうち 107 バイトを読み、基準の走り全部では 116 バイトです。そのあと、面を作る 25 フレームと、土管から上がる 97 フレームが続きます。

**確認** はエミュレータで動かします。約 13,700 フレーム、約 5 秒です。

* `decided`: `T` の 40 個の位置から、記録した 122 フレームの走り。
* `entries`: 20 個の入る状態のそれぞれで、操作できない 160 フレーム、フレーム 160 の比較、記録した 122 フレーム。書き換えた状態は次のとおりです。クリボー 5 匹。クリボー 5 匹とパワーアップ。大きいファイアマリオとスターのタイマー。ファイアボール、ブロックの物、コイン。スクロールのバイト。フレームタイマー、全体を止めるタイマー、間隔タイマー、フレームカウンタを全部最大に。全体を止めるタイマーのほかを 0 に。数字を 9 にしてコイン 99。数字を 0 にしてゲームタイマー 001。乱数を 0 に。乱数を 255 に。音。`HalfwayPage` と `WarpZoneControl`。本物の状態は次のとおりです。[横の土管から地上への切り替え](d-1-SideTransition-ja.md)の `x₀ + 1` と `x₀ + 2` での入り方。床に立って 0、5、10、15 フレーム待ってから歩いて入る走り。

**5 秒に近づけるために外したもの.** 縦の土管の確認には 77 個の入る状態があります。こちらは 1 個に 3 倍のフレームがかかります。ですから、その確認の書き換えた 63 個の状態はこの確認に入れていません。プログラムでこの入る状態から動かすと、全部 282 です。増分のビットがオンの位置も外しました。そのため (H2) はビットがオフであることを求めます。

`Rvar` のバイト: フレームカウンタ、音楽の状態、`HorizontalScroll`、全体を止めるタイマー、マリオの大きさとパワーアップ、`HalfwayPage`、間隔タイマー、フレームタイマー、乱数、ステータス行の数字。`Rfix` のバイト: ルーチン、モードとタスク、ポーズ、効果音のバッファとキュー、面の指定のバイト、`AltEntranceControl`、`JoypadOverride`、面と世界の番号、タイマーの読み直しと時間切れのフラグ、画面と PPU のミラー、ジョイパッドのマスク、デモのタイマー、プレイヤーの数のバイト、`PrimaryHardMode`、音のルーチンのいくつかのバイト、フレームタイマー 1 つ。これらは 20 個の状態のどれでも違いません。

**測ったけれど定理にしていないこと.**

* `T` から、107 バイトを 1 つずつ、ほかのすべての値に: 長さが変わるのは `OperMode`、`OperMode_Task`、`GamePauseStatus`、`VRAM_Buffer_AddrCtrl`、`GameTimerExpiredFlag`、`AreaPointer`、`EntrancePage`、`AltEntranceControl`、`JoypadOverride` だけです。全部 `Rfix` にあります。122 より短くなるのは `AltEntranceControl` だけです。これはルーチン自身がフレーム 160 で書くバイトです。
* `E` から、218 バイトを 1 つずつ: 各バイトで 10 個の値（0、1、2、16、64、127、128、255、もとの値 ± 1）を試し、どれかで長さが変わるバイトはすべての値を試しました。ですから、ほかの値でだけ長さが変わるバイトは見落とします。長さが変わるのは 15 バイトです。282 より短くなるのは次のとおりです。

| `E` で書き換えたバイト | 短くなる値の数 | フレーム |
|---|---|---|
| `ChangeAreaTimer` | 159 | 123 から 281 |
| `GameEngineSubroutine`（土管のルーチンでなくなる） | 8 | 1、18、163、187 |
| `Player_Y_HighPos` | 124 | 163 |
| `OperMode_Task` | 1 | 163 |
| `Player_State` | 2 | 60 |
| `EnemyFrenzyQueue` | 3 | 3、5 |
| `AreaParserTaskNum` | 10 | 1 |

  残りの 8 バイトは、長くなるか操作できなくなるだけです: `EnemyFrenzyBuffer`、`AreaPointer`、`EntrancePage`、`JoypadOverride`、`GameTimerExpiredFlag`、`OperMode`、`VRAM_Buffer_AddrCtrl`、`GamePauseStatus`。
* `P` で、入るフレームが読む 184 バイトを 1 つずつ、ほかのすべての値に: 本物と違うタイマーで入るのは 2 通りだけです。画面のページのバイトが 129 以上だと短いタイマーです。[横の土管から地上への切り替え](d-1-SideTransition-ja.md)のピクセル `z` でフレームが終わると、タイマーはそのままです。`x` を書いても、画面の左端を書いて押されても同じです。ページのバイトが 1 から 128 だと入りません。`P` でタイマーに 5 を書いて `z` で入ると、切り替えは 127 = 122 + 5 です。
* 画面が偶数のページで、マリオも同じページ: 入り、174 です。奇数のページだと入りません。口が偶数のページのブロックバッファにあるからです。
* 本物の入り方 42 個（ブロックの上か床で 0 から 20 フレーム待つ。全部 `x₀`）: 全部 282 で、(H1) から (H4) が成り立ちます。
* TAS 自身の入る状態: 282 フレーム後に操作でき、(H1) から (H4) が成り立ち、`R` しか読みません。`Rvar` の 23 バイトが `T` と違います。

## 短くなる状態に届かない理由

コードから読み、本物の走りで測りました。どれも Lean にしていません。

* **画面のページ.** 部屋が始まるとき、画面のページは `EntrancePage` から決まります。この部屋では 0 です。部屋で操作できるようになる前にスクロールロックがオンになり、オンのあいだ画面はスクロールしません。本物の走りで、部屋で最初に操作できるフレームから入る前のフレームまでの 168 フレーム全部を測りました。ページは 0、ロックはオンです。確認の本物の 7 個の入り方でページが 0 であることは `entered` と `real` が示します。
* **タイマー.** 入るフレームが書きます。ピクセル `z` だけ書きません。その 168 フレームでは 0 です。ですから、コードの 2 つの値のほかにするには書き換えが要ります。
* **ルーチンとタスク.** ルーチンは入るフレームが決めます。`OperMode_Task` は遊んでいるあいだゲームのタスクで、その 168 フレームでは 1 つの値です。
* **マリオの状態と高さ.** 入るには地面にいる必要があります。`Player_Y_HighPos` は高さのページで、床では 1 です。
* **面を読むバイト.** `AreaParserTaskNum` は画面が 32 ピクセル動くと始まります。`EnemyFrenzyQueue` は、面を読むあいだに面の物が書きます。どちらも、その 168 フレームでは 0 です。

## 前提（Lean では証明していない）

* (H1)、(H2)、(H3): 任意の入る状態でのはじめの 160 フレーム。すべての状態で、タイマーが毎フレーム 1 減ること、フレームがはみ出さないこと、`Rfix` の値が変わらないことは、証明していません。動かしたのは 20 個の状態、本物の入り方 42 個、TAS の状態だけです。コードから読める理由は次のとおりで、Lean では確かめていません。土管のルーチンは毎フレーム動いてタイマーを 1 減らします。当たり判定のルーチンは、土管のルーチンのあいだはすぐ戻ります。
* (H4): `Rvar` の値。`decided` は `T` の値だけ、`entryStates` は 20 個の状態の値だけです。本物の走りは数字や乱数が違うので、(H4) がなければ含まれません。これらのバイトは読まれて分岐に使われるので、記録では外せません。(H4) を支えるのは上の測定で、1 バイトずつしか変えていません。それと上の本物の入り方です。
* 本物の走りのどれでも `Rfix` が `T` の値であること。`AreaPointer` と `EntrancePage` は部屋の面のデータから決まります（部屋で最初に操作できるフレームで測りました）。効果音のバイトは証明では外せていません。上の測定では、どの値 1 つでも長さは変わりません。
* 本物の入り方すべてで画面が最初のページにあること、`x` が 16 の倍数でないこと（[横の土管から地上への切り替え](d-1-SideTransition-ja.md)）。はじめのものは上の理由です。`every_entry` はこの 2 つを直接には使いません。短いタイマーの 2 個の状態は、フレーム 160 で (H1) を満たし、(H2) と (H3) を満たしません（測りました）。定理から、そうなるはずです。
* 本物の走りで 6 個の物が近くに集まらないこと。部屋に敵はいません。動かした 6 個の状態では、はみ出しても 282 以上です。
* ゲームタイマーが 000 でマリオが生きている場合: 切り替えのあと操作できません。+282 の例外で、遅くなる側です。
* 入力なしだけです。すべての入力は `E` からだけ、仮定 `GMerge` のもとで動かしました（[横の土管から地上への切り替え](d-1-SideTransition-ja.md)）。Start と Select は含みません。
* 書き換えた状態がそのままたどり着けることは示していません。
* [1-1 全体](0-1-Route-ja.md) はこの定理を使いません。その `change₂` は切り替えの[はじめのフレーム](d-2-2-SideChangeBound-ja.md)と[最後のフレーム](d-2-3-SideChangeEnd-ja.md)から出します。`every_entry` と `no_control_before` は (H1) から (H4) を満たす走りについてちょうどの長さを出します。すべての走りが満たすことは、ここでは示していません。
* フレームはエミュレータのフレームです。[エミュレータ](../docs/emulator.md)を見てください。
