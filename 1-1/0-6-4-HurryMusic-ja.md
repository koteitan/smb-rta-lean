# 急ぎの音楽が鳴る走り

**命題.** 急ぎの音楽が鳴る走りでは、1-2 は 1748 フレームより前に始まりません。城に入るフレームを `E` とすると `q · (t0 − u) ≤ E + 3q` です。ゲームの値 `q = 24`、`t0 = 401`、`u = 100` では `E ≥ 7152` です。

**これは仮定つきの定理です。** 仮定は `HurryMusic.Run` のフィールドです。`First(n)` は、フレーム `n` が音楽を始める最初のフレームであることです。すべての `m ≤ n` で `hurryOn(seq m) = false`、そして `hurryOn(seq (n + 1)) = true` です。

```
clock, order   Frames（各フレームは Step と plan に従う）と、区間の順序
next           seq(n + 1) = frame(seq n, inp n)
title          タイトルで Start を押してからフレーム 0 まで（TitleStart.Begin）
read₀          s(0).t = timer(seq 0)
k, hk, on      k ≤ E + 1,  hurryOn(seq k) = true
base = b       音楽の前のフレームが操作中になるフレーム
start          b = 1  ∨  Start(seq b)                 （1 つの状態: 操作中か登場中。HurryFrame を参照）
音楽を始める最初のフレーム n について:  n < k,  First(n)  ⟹
  ctl          b ≤ n,   b ≤ j < n  ⟹  ctl(seq (j + 1))  （これらの各フレームは操作できる状態で終わる）
  clean        b ≤ j ≤ n  ⟹  ∀ i,  CleanM(tr_j(i))     （これらのフレームの各命令）
  below        s(n + 1).t ≤ timer(seq (n + 1))       （1 フレーム）
L, after       E < L
```

`Start` と `CleanM` は [急ぎの音楽を始めるフレーム](0-6-4-2-1-HurryFrame-ja.md) のものです。`tr_j(i)` はフレーム `j` の `i` 命令あとの機械です。`ctl(m)` は `m` が操作できる状態であることです。

前は `start` を音楽を始めるフレームそのものに求めていました。今はフレーム `b` にだけ求めます。`b` はそのフレームでもかまいません。前のフィールドから、`b = n` として今のフィールドが出ます。`b = 1` のときは状態の条件はありません。フレーム 1 の始まりはタイトルで Start を押したことから出ます（`Begin.start₁`）。

定理です。

```
Frames.late             :  s(0).t = t0,  n ≤ E + 1,  s(n).t ≤ u  ⟹  q · (t0 − u) ≤ E + 3q
Run.zero                :  timer(seq 0) = t0                （title と確かめ title_check から）
Run.quiet₀              :  hurryOn(seq 0) = false           （title と確かめ title_check から）
first_turn              :  hurryOn(seq 0) = false,  hurryOn(seq k) = true  ⟹  ∃ n < k,  First(n)
Begin.start₁            :  Start(seq 1)  ∧  seq 1 で音楽のビットなし        （title と確かめ title_check、hurry_near_check から）
HurryFrame.frame_start  :  Start(m),  off(m),  ∀ i, CleanM(tr(i)),  ctl(frame(m, i))  ⟹
                           frame(m, i) で音楽がキューにある  ∨  (Start(frame(m, i))  ∧  off(frame(m, i)))      （確かめ music_check から）
Run.startAt             :  音楽を始める最初のフレーム n で  Start(seq n)          （前のフィールド start）
Run.music               :  音楽を始める最初のフレーム n で  timer(seq (n + 1)) ≤ u
Run.late                :  1 ≤ q  ⟹  q · (t0 − u) ≤ E + 3q
Run.level_ge            :  1 ≤ q,  1748 + 3q ≤ q · (t0 − u)  ⟹  1748 ≤ L
hurry_1_1（非公開）      :  q = 24,  t0 = 401,  u = 100  ⟹  1748 ≤ L
```

`q · (t0 − u) = 24 · 301 = 7224`、`1748 + 3q = 1820` です。`k` は城に入るまでのどのフレームでもかまいません。`chg.entry₂` を満たさない走りでは、横の土管の入口のフレームです。

証明です。

* `hurryOn` はフレーム 0 で偽、フレーム `k` で真です。なので偽から真になる最初のフレーム `n < k` があります（`first_turn`）。`Run.startAt` から `Start(seq n)`、`Run.music` から `timer(seq (n + 1)) ≤ u`、`below` から `s(n + 1).t ≤ u` です。`n + 1 ≤ k ≤ E + 1` です。
* `Run.startAt`: `b` から `n` までのフレームの帰納法です。フレーム `b` は `Start` のとおりに始まります。`start` から、または `b = 1` なら `Begin.start₁` からです。フレーム `j < n` がそのように音楽なしで始まり、各命令が `CleanM` を満たし、操作できる状態で終わるなら、`HurryFrame.frame_start` から、音楽がキューにある状態で終わるか、音楽なしで `Start` の状態で終わります。フレーム `j + 1 ≤ n` が始まるとき音楽はないので（`First`）、後のほうです。
* `Frames.late`: どのフレームもタイマーの数字を上げません（`t_anti`）。なので `T = s(E + 1).t ≤ u` です。`hT` から `t0 − u ≤ ⌈p₁/q⌉ + ⌈p₂/q⌉ + ⌈p₃/q⌉` です。`p₁`、`p₂`、`p₃` は 3 つのエリアのプレイのフレーム数です。`q · ⌈p/q⌉ ≤ p + q − 1` で、`p₁ + p₂ + p₃ ≤ E` です。
* `Run.level_ge`: `L > E ≥ q · (t0 − u) − 3q ≥ 1748` です。

`hT` はどのサブカウンタから始めても成り立ちます（`playN_drop`）。プレイ `p` フレームで、タイマーの数字は `⌈p/q⌉` より多くは減りません。なので音楽の 1 フレームとタイマーの規則だけで足ります。

`Run.music`: `HurryFrame.frame_music` の歩きから、そのフレームは音楽なしで終わるか、タイマー `u` 以下で終わります。音楽ありで終わるので、タイマーは `u` 以下です。`u = 100` のとき、本物のフレームではそこで 99 です。

## 本物のフレームでの確認

`hurry-check FM2` です。終了コード 0 です。

```
動画、フレーム 0 が始まるとき             timer 401,  位相 2,  hurryOn false
動画、1760 フレーム                       音楽が始まるフレーム 0、Step に合わないフレーム（城まで）0
タイマーを書き換えた走り                  動画の 12 のフレーム（100 から 1100）で数字を 100、101、102、103、105、110、124 に書き換え、
                                          そこから動画の入力、または乱数の入力とポーズで 600 フレーム。168 回、100,800 フレーム
  音楽が始まるフレーム                    108。始まりのタイマーは全部 100。u = 100 を超えるものは 0
  Step に合わないフレーム（城まで）       動画の入力 0。乱数の入力 11。全部ルーチン 0 と 7、死んで面をやり直すフレーム
  横の土管の入口（フレーム 571）で音楽    23 回
```

音楽が始まらなかった 60 回は、タイマーが動かない切り替えか、触ったあとか、600 フレームでは 100 まで下がらない値です。

同じ確認で、音楽を始める 108 のフレームを 1 命令ずつ動かします。

```
Start                                      108 のうち 108（操作のルーチン 94、登場のルーチン 14）
始まりで音楽のビットなし                   108 のうち 108
CleanM を満たす命令                        521,286 のうち 521,286
終わりのタイマー                           108 全部で 99
何もしないループで終わる                   108 のうち 108
動画の操作中か登場中のフレーム             833。全部で Start、音楽なし、CleanM（4,034,601 命令）
```

108 のフレームはどれも何もしないループで終わります。ルーチンがフレームの中で終わります。なので次のフレームが始まるときの `clock` のカウンタは機械のもので、そこで `below` は等号で成り立ちます。

同じ確認で、各走りの、音楽を始める最初のフレームの前のフレームをたどります。`b` は、操作できない状態で終わる最後のフレームの次のフレーム、または走りの最初のフレーム（タイマーを書き換えたところ）です。これが `ctl` と `clean` のフレームです。

```
音楽を始める最初のフレーム                 108
フレーム b が Start で始まる               108 のうち 108（操作中 50: 走りの最初のフレーム。登場中 58: 切り替えのあとの最初の操作のフレーム）
b から音楽のフレームまでのフレーム         0 から 305、全部で 7,451。b が音楽のフレームそのものなのは 16
これらのフレームの各命令の CleanM          35,023,871 のうち 35,023,871
```

タイトルからの走りでは、`b` はフレーム 1 か、切り替えのあとの最初の操作のフレームです。上の走りはタイマーを書き換えたところから始まるので、フレーム 1 を含みません。フレーム 1 の始まりは定理 `Begin.start₁` です。

## 証明していないこと

* `music` はもうフィールドではありません。音楽のフレームの始まりと `clean` から、1 フレーム全体の歩きで証明します（[急ぎの音楽を始めるフレーム](0-6-4-2-1-HurryFrame-ja.md)）。
* 音楽のフレームの始まりはもうフィールドではありません。フレーム `b` からの帰納法で証明します（`Run.startAt`）。`start` はそれをフレーム `b` にだけ求め、`b = 1` なら状態の条件はありません。音楽のフレームが切り替えのあとにあるとき、`b` は切り替えのあとの最初の操作のフレームで、その始まりは仮定のままです（上の 108 回のうち 58 回。登場のルーチン）。`b` の `start` は前の `start` より弱い条件です。`b` を音楽のフレームとすると、前のフィールドから今のフィールドが出ます。
* `ctl` と `clean` は、`b` から音楽のフレームまでの各フレームが操作できる状態で終わること、その各命令が `CleanM` を満たすことです。1 フレームと 1 命令ごとの条件で、上の 108 回（7,559 フレーム）で確かめましたが、証明はしていません。音楽を始める最初のフレームと、その前の `b` からのフレームにだけ求めます。
* `below` は 1 フレームでだけ要ります。音楽を始める最初のフレームの次のフレームです。以前は `k` までの全部のフレームで要りました。カウンタと機械のつながりです。はみ出すフレームのない走りでは、`clock` のカウンタは機械から読んだ値なので、等号で成り立ちます。はみ出すフレームでは、境目の数字はルーチンが残す数字より小さくありません。ルーチンは数字を下げるだけだからです。これはコードから読んだものです。上の本物の 108 フレームでは等号で成り立ちます。
* `read₀` は、`Route.Run` と同じく、フレーム 0 が始まるときのカウンタと機械のつながりです。
* `title` は [タイトルの Start から操作できるまで](0-5-3-TitleStart-ja.md) の仮定です。押したあとの機械の 1 つの条件と、操作できるまでのゲームコアのフレームで Start を押さないことです。`zero` と `quiet₀` はもうフィールドではありません。ここから証明します（`Run.zero`、`Run.quiet₀`）。
* `clock` の `step` と `plan` は `Route.Run` と同じ仮定です（[1-1 全体](0-1-Route-ja.md)）。パワーアップのある走りと死ぬ走りは `plan` に従わないので、ここにも入りません。
