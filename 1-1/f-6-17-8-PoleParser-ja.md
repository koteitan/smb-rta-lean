# 旗のタイル: エリアの解析と画面の左の端

`PoleJoin.Run` のフィールド `tilesCol` はこう言います: 旗のページより 2 ページ以上前での横の確かめの読みで、ブロックバッファの旗の列を読んだなら、読んだバイトは旗のタイルではない（`PoleTileFar.TileCol`、[旗から遠い読みもブロックバッファの中にある](f-6-17-5-PoleTileFar-ja.md)）。

なぜ成り立つはずか。ブロックバッファは 16 px の列を 32 列持つので、そこでの旗の列は、旗より 512 px 前の列でもあります。エリアの解析は画面より先の列を、画面の左の端から決まった距離だけ先に描きます。旗の列を描くまで、その場所には 512 px 前の列があり、そこに旗のタイルはありません。旗の列を描くとき、端は旗の近くにあり、マリオは旗の 2 ページ前にはいられません。

このページはその議論の一部を証明します: 操作の始まりの不変式、決まりがそれを保つこと、本物のフレームでの決まりの前半、`tilesCol` が出る足し算と引き算。フィールド `tilesCol` は変わりません。

## 解析のバイト（コードから）

`PoleParser.places` はバイトをプログラムから見つけます: `UpdScrollVar` の最初の読み（画面のバッファの制御のバイト）、残りの仕事の数 `N` の読み、スクロールの数え `S` の読みのオペランド。仕事の係の呼び出し。仕事の係の中の仕事のルーチンの呼び出し。そのルーチンの最初の行き先は列の 1 歩で、その二つの `INC` が解析の列とそのページです。画面の左の端は押し戻しのもの（`ScreenClamp.places`）。ファイルに番地はありません。

## 一つの状態の不変式

`col` を解析の列（ページ込み、1 ページ 16 列）、`p(N) = [N ≥ 1] + [N ≥ 5]` を残りの仕事でこれから来る列の 1 歩の数、`edge` を画面の左の端（px）と書きます。

```
Inv(L, m)  :=  N ≤ 8  ∧  16·col + 16·p(N) + S = edge + L
```

1 フレームの決まり（`Rule`、コードから）:

* スクロールの係が、スクロールの量 `Y` を `S` と `edge` に足す（`Scroll`）。
* 次に（`Parse`）: 画面のバッファの制御のバイトが 6 なら、それ以上なし。`N = 0` で `32 ≤ S < 160`（コードの `CMP` と `BMI`）なら、`S − 32` で、`N` は 8 になる。ほかの `N = 0` なら、それ以上なし。そのあと仕事 `N − 1` が走り、`N` が 1 減る。仕事 0 と 4 が列を 1 進める。

証明（足し算と引き算だけ）:

* `inv_rule : Inv(L, a) ∧ Rule(a, b) ⇒ Inv(L, b)`。フレームの並びには `inv_frames`。
* `col_rule`、`edge_rule`: 列と端は下がらない。
* `col_le : Inv(L, m) ⇒ 16·col ≤ edge + L`、`edge_of_col : Inv(L, m) ∧ c ≤ col ⇒ 16·c ≤ edge + L`。

## 操作の始まり

`inv₀`。横の土管から出る切り替えの行から（`PoleTileCtl.watch₀` と同じ）: 操作の始まりの機械は `Inv(L, m)` を満たし、ブロックバッファに旗のタイルはない（`NoTiles`）。ROM の確かめは `invCheckK`。非公開の証明 `pole_parser_rows` が `L = 384` でそれを示します。

## `UpdScrollVar` までの 1 フレーム

三つの部分を `frame_toU` でつなぎます。初めの二つは `EdgeStep`（端の二つのバイト、パート e）の歩きで、端のバイトの代わりに解析のバイトを追います。三つ目は `ScrollRule`（パート e）の部分に、スクロールの数えを加えたものです。

* `keep_qP`、`keep_noCutP`: フレームの始まりからスクロールの係まで、`N`、`S`、列、ページの四つのバイトは保たれる。プレイヤーのルーチンに来ないフレームもそれらを保つ（確かめ `qCheckP`）。
* `scroll_callS`: スクロールの係の呼び出しからその次の命令まで、端と `S` は両方保たれるか、両方が同じ `Y` だけ動く（確かめ `checkS`: `ScrollRule` の部分で、細かい位置の代わりに `S` を置いたもの。だから位置を保つ部分はどれも `S` を保つ。スクロールそのものは二つに切る。初めの五つの命令が `S` を `Y` だけ動かし、次の命令が端のピクセルを繰り上がりと共に `Y` だけ動かす。押し戻しの部分は端と `S` を保つ）。
* `keep_uP`: スクロールの係は `N`、列、ページを保つ（それぞれを追う真ん中の歩き）。その呼び出しの次の命令から最初の `UpdScrollVar` まで、解析の四つのバイトと端の二つのバイトは保たれる（`UpdScrollVar` までの歩き。押しと押し戻しの外での、番地によるマリオの位置への書き込みで道を切る。フィールド `posW` がそれを除く。この切りは城のループ戻しを止める。ループ戻しは解析のページを戻す）。そしてフレームは呼び出しの次の命令に一度だけ来る（`EdgeStep` のフレームの終わりまでの歩き）。確かめ `uCheckP`。`walkQP`、`live_stepQP`、`qP_run` が、決めた場所までの、切りのある歩きです。

`frame_toU`: 操作できるフレームは、フレームの中のある `k₂` で `UpdScrollVar` に来て、そこで

```
N、列、ページ  =  フレームの始まりのもの、
(端, S) = 始まりのもの   または   ∃ Y,  端 = (端₀ + Y) mod 2¹⁶  ∧  S = (S₀ + Y) mod 256。
```

これは本物のフレームでの `Rule` の `Scroll` の部分です。非公開の証明 `pole_parser_q`、`pole_parser_u`、`pole_parser_s` が三つの確かめを示します（地上、エリアの種類 1）。四つの確かめを持つ非公開のファイル `Proof/PoleParser.lean` は、ネイティブで 25 秒から 44 秒で構築できます。同じ確かめを、違うバイトや違う値で試すと、偽になります: プレイヤーのルーチンの前のフレームの数え、スクロールの係の中の端のピクセルと `S`、`UpdScrollVar` の直前のボタンのバイト、1 多い数えの部分、細かい位置の場所での数えの部分。

確かめのほかに `frame_toU` が要るもの: どの命令も、解析と端のバイトごとの歩きの守りの `CleanK` を満たす（`hH`: 添え字かポインタを通したどの書き込みもそれを書かない。端の二つのバイトでは `FrameKeep.guardE` の一部。解析の四つではそうでない）。スクロールの係からのフィールド `posW`（`hp`）。フレームの時間（`ht`、`CleanK` が与える形）。これらは定理の仮定で、フィールドではありません。ルートはまだこれを使いません。

## 走り: 不変式に残るもの

`inv_run`: 走りのフレーム `ms (n + 1) = frame(ms n, ins n)` で、不変式が最初（操作の始まりの `inv₀`）で成り立ち、どのフレームも `Rule` に従うなら、不変式はどのフレームの始まりでも成り立つ。

* `rule_of_noCut`: プレイヤーのルーチンに来ないフレームは六つのバイトを保つ（`keep_noCutP`、`EdgeStep.keep_noCut`）ので、`Rule` に従う。
* `rule_of_toU`: `frame_toU` の結論を持つフレームは、スクロールが一回りせず（`S + Y < 256`、`端 + Y < 2¹⁶`）、`UpdScrollVar` から終わりまで `Parse` に従うなら（`ParseU`）、`Rule` に従う。

だから走りのどのフレームの始まりでも不変式が成り立つことは、プレイヤーのルーチンに来る各フレームの三つのことに残ります: 解析の四つのバイトの守り（`hH`）、一回りしないこと（測ったところ、フレームの始まりで `S ≤ 31`、`Y ≤ 3`）、`ParseU`。

## `tilesCol` が何から出るか

`tileCol_of`（足し算と引き算だけ）: `TileCol` の前提が成り立つ状態で、次が成り立てば、読んだバイトは旗のタイルではない。

* （`hslot`）旗の列で旗のタイルを読んだなら、解析の列は旗の列まで来ている。
* （`hcol`）`16·col ≤ edge + L`（`Inv` から）。
* （`hnear`）`edge ≤ マリオのピクセル + δ`。
* （`hread`）読みは、ブロックバッファの 32 列（列の番号 mod 32）で、マリオのピクセルに足す数 `a < A` を足した列にある。

ただし `A ≤ 16`、`L + δ ≤ 496`。数の理由: マリオのページは旗のページ − 2 以下で、足す数は 16 未満なので、マリオのピクセルに足す数を足したものは旗のページより前の列にある。読みは 32 列で数えた旗の列にあるので、その列は旗の列 `colPole` より 32 列以上前で、`ピクセル < 16·colPole − 496`。旗のタイルがあれば `16·colPole ≤ 16·col ≤ edge + L ≤ ピクセル + δ + L < 16·colPole − 496 + δ + L` で、`L + δ ≤ 496` なら偽。

## 証明していないこと

* 決まりの、1 フレームの残り: `UpdScrollVar` からフレームの終わりまでの `Parse`（解析自身のコードと、仕事のルーチンがバイトを保って戻ること）。
* 走りのフレームでの、解析の四つのバイトの守り（`hH`）。測ったところ、添え字かポインタを通した書き込みはそれらを書かない。`FrameKeep.guardE` には入っていない。
* フレームをまたぐ `hslot`: エリアの解析は旗のタイルを旗の列にだけ描き（`bufAll` の一部）、ブロックバッファの列は解析の列 mod 32 であること。
* 各フレームでスクロールが一回りしないこと（`S + Y < 256`、`端 + Y < 2¹⁶`）。
* 触るフレームでの `hnear` と `hread`。

だから `tilesCol` は残ります。
