# 城に入ったあとの星の旗の規則

**主張.** これは部分的な結果です。城に入ったあとの最初のフレームの機械が 1 つの条件 `Good` を満たし、処理が 2 で、旗が作られた高さにあるとします。そのあとレベルが変わるまで、入力に Start がないとします。すると本物の機械のカウンタは、レベルが変わるまでの全部のフレームで 1 フレームの規則 `FlagRun` に従います。レベルが変わるのは、処理 5 で始まるフレームです。これで [城から 1-2 まで](g-1-CastleToLevel-ja.md) の `Flag` のフィールド `step`、`task_E`、`y_E`、`task_L` が定理になります。条件 `Good` は、城に入ったときの 1 つの状態についての仮定として残ります。

`seq(n)` はフレーム `n` が始まるときの機械、`inp(n)` はその入力です（[1-1 全体](0-1-Route-ja.md) の `Changes`）。`seq(n + 1) = frame(seq(n), inp(n))` です。`m[b]` は `m` のバイト `b` です。`E` は城に入るフレームです。`r` は基準の機械です。自分の道筋（`CastleWalk`）で遅れなしに城に入り、タイマーは本物のままです。`lim`、`w₀` は [城から 1-2 まで](g-1-CastleToLevel-ja.md) と同じです。

## 文

```
x(m)  = (task, t, y, w, ph)    m のカウンタ（flagOf）。旗は最初の敵スロット

After(seq, inp, E, T, c, L) :
  Good(seq(E + 1))
  task(seq(E + 1)) = 2,   y(seq(E + 1)) = y(r)
  t(seq(E + 1)) = T,      ph(seq(E + 1)) = c
  E < L
  ∀ n,  E < n ≤ L  →  inp(n) に Start がない
  level(seq(L + 1))                         レベルの番号か面の番号が 0 でない
```

定理です。

```
flagCheck(C, d) = true  →  Checked(C, d)                         checked_of_check

Checked(C, d),  Good(m),  i に Start がない  →
  frame(m, i).frame = m.frame + 1
  ¬ level(m),  ¬ level(frame(m, i))
  FlagRun(lim, w₀, x(m), x(frame(m, i)))
  task(frame(m, i)) = 5  ∨  Good(frame(m, i))                     frame_step

Checked(C, d),  ∀ n, seq(n + 1) = frame(seq(n), inp(n)),  After(seq, inp, E, T, c, L)  →
  Flag(lim, w₀, E, T, c, L)                                        flagOf_after
```

`flagCheck` は ROM の確認です。非公開の証明で `native_decide` が示します（`flag_check`）。`C` は確認の文脈（`r`、知っているバイト、名前）、`d` はそこから計算する抽象状態です。

`flagOf_after` が作る `Flag` では、`x(n)` は最初の処理 5 のフレームまでは `seq(n)` のカウンタです。そのあとは最初の処理 5 のフレームの値で止めます。止めたフレームを `lag` にします。それより前に `lag` のフレームはありません。`Good` の機械のフレームは全部、待ちの繰り返しで終わるからです。

## 条件 `Good`

`Good(m)` は次のことです。

* `m` は 240 個の抽象状態 `B₀` のどれかに含まれます。パッドは知りません。
* `ph < 21`、`task ∈ {2, 3, 4}`。
* タイマーの 3 つの数字は、ある `t ≤ tmax` の数字です。`tmax` は 1-1 が始まるときのタイマーの値に 1 を足したものです。
* マリオの数 `(v, F, f, A, C, s)` は集まり `Q` に入ります。`v` は速さ、`F` と `f` は 2 つの力の端数、`A` は速さの大きさ、`C` は当たりのビット、`s` は横に当たってからのタイマーです。`Q` は、壁に当たったときの数から 1 フレームずつたどった 6714 個です。壁に当たったときは `v = 0`、`s` は当たったときの値、`F` は 4 の倍数、`f` は 16 の倍数です。
* `RunningSpeed` と `Player_MovingDir` は `r` と同じです。
* `task ≠ 4  →  lim − 1 ≤ y ≤ y(r)`、`task = 4  →  w ≤ w₀`。

`B₀` は ROM と `r` から計算します。`B₀` の状態は次のことを知っています。

* フレームは待ちの繰り返しで終わっています。プログラムカウンタ、スタック、PPU のフラグ、ドットの範囲です。
* 345 バイトが `r` と同じ値です。`knownNames` の名前のバイトと、1 つ目のブロックバッファの全部です。モード、面と面の番号、マリオの状態と大きさと位置、ゲームのタイマーの制御、音の一部、スプライトの割り当て、浮かぶ数字の制御、大砲のバイトなどです。
* 星の旗は最初の敵スロットにあります。ほかの 4 つのスロットは空か、全部が花火です。
* `EventMusicBuffer` は `r` の値か 0 です。画面の左と右の x と `ScrollThirtyTwo` は上のビットだけ知っています。

ほかのバイトは何でもかまいません。スコア、コイン、乱数、フレームカウンタ、`HorizontalScroll`、音楽の位置（四角波 1 は値ごとに分けます）、花火の状態、カウンタの値です。

## 確認のしくみ

1 フレームを 13 の名前のある場所で切ります。`SoundEngine`、`MusicHandler`、`ReadJoypads`、`DecTimers`、`NoDecTimers`、`PlayerEndLevel`、`PlayerSubs`、`GetXOffscreenBits`、`GetPlayerOffscreenBits`、`RunStarFlagObj`、`FloateyNumbersRoutine`、`FlagpoleRoutine`、`RunGameTimer` です。最後はフレームの終わりです。機械が最初にその場所に来たときを次の段とします（`Next`、`Arr`）。

各段で、[抽象機械](b-2-3-TaintRun-ja.md) の歩きを 3 種類確かめます（`Checked`）。

* 覆う: 段の状態から、次の場所で次の段の状態に来ます（`CoverP`）。
* 事実: ある値なら、次の場所でどれかの値です（`FactP`）。位相、インターバルタイマー、横のタイマー、マリオの動き（4844 通り）、壁、タイマーの数字、旗の高さ、花火の数、最後の待ちです。
* 保つ: ある条件のもとで、バイト `b` は変わりません（`KeepP`）。値が 2 以上のときは `b` をカウンタにした歩き（`Env.rkI`）です。0 と 1 は値を知った歩きです。

`frame_step` はこれらを順につなぎます。カウンタが規則どおりに変わり、マリオの数が `Q` に戻り、フレームの終わりで `B₀` に戻ります。

音楽と花火のバイトも知らないと、40 万ステップで 84 の失敗です。最初の失敗は四角波 1 のデータを読む繰り返しです。位置を知らないと 0 のデータで終わりません。なので四角波 1 の位置は、その場所で値ごとに分けます（`splitAt`）。

## 証明していないこと

* `Good(seq(E + 1))`、`task = 2`、旗の高さは仮定です。城に入るまでのフレームからは証明していません。上の走りで確かめました。
* `E` のあとに Start がないことは仮定です。ポーズのある走りには定理が使えません。
* `Good` の外は扱いません。大きいマリオ、ほかのスロットにある旗、花火でない物のあるスロット、`Q` の外のマリオの数、`tmax` より大きいタイマー、`B₀` と違うバイトです。
* `t(seq(E + 1)) = T`、`ph(seq(E + 1)) = c` は `Frames` とつなぐフィールドのままです。
* `GMerge`（1-1-g-2-3）はここでは扱いません。
