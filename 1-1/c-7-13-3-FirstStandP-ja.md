# 最初の立ちの前の位置

[ボーナス部屋をつなぐ](c-5-RoomJoin-ja.md) のフィールド `stand_P` は、落下中（`C + 34` より前）の立ちの 1 つ前のフレームで、位置が `standP = 3712`（14.5 px）かそれより左だ、と言います。このラウンドでは、落下の最初の立ちの 1 つ前のフレームだけで求めます。これを使う 2 つの定理 `stand_first` と `wall_turn` は、ほかのフレームを使いません。

## 命題

`P(n)` はフレーム `n` の終わりの位置（1/256 px）、`st(n)` はそこでのプレイヤーの状態です。

```
stand_P（フィールド、狭めた）:
  C ≤ n,  n + 1 < C + 34,  (∀ j, C < j ≤ n → st(j) ≠ 0),  st(n + 1) = 0   →   P(n) ≤ standP
  （前は 3 つ目の前提なしで同じもの）
```

- `stand_first` は落下の最初の立ちについての定理です。その前提 `∀ j, C < j ≤ n → st(j) ≠ 0` が新しい前提です。
- `wall_turn` は、壁での立ち `i` のフレームが `hstep` に従わない最初のフレームのとき、それを使います。`i` は最初の立ちです（`hfirst`）。

## 上限がこの値のわけ（数。証明ではない）

- `standP = 3712 = 13·256 + 384`。測った壁での立ちは、すべて移動の終わりで `x = 12` です（ラウンド 21）。`x ≤ 12` で、左への移動が多くて 24/16 px（`RunningSpeed` 0 の空中の速さ）なら、`P(n) ≤ 3327 + 384 = 3711` です。
- 止めるフレームのモデル（`TopSpeed.Frame`）は、移動のあとの速さを `top = 40` でしか押さえません: `3327 + 640 = 3967`。
- `wall_turn` には `P(n) < P0 − leftDist(Φ₀, 14) = 3904` が要ります（`stand_far`、余裕 192）。これで最初の立ちは `C + 15`（`wallP = 3968` と `P0 − leftDist(Φ₀, 13) = 4192` で `wall_far` が出すもの）から `C + 16` になります。なので 3967 では足りません。

## 測ったこと

- `room-stand-first FM2 300`（このラウンド、TAS と自分の走り 2,100 本、126,060 フレーム）: フレーム 51 より前で床のほかに立つのは 49 回で、すべて落下の最初の立ちで、フレーム 18 から 30 です。なので前のフィールドと狭めたフィールドは、測ったフレームでは同じものを求めます。
- `room-approach-check FM2 300 1` と `… 300 0`（このラウンド）: `C + 34` より前の立ちは 44 回（大きい）と 50 回（小さい）で、そのそれぞれの 1 つ前のフレームで `P ≤ standP` です（いちばん大きい `P` は 3632。いちばん小さい `−V` は 3952 と 4256 で、`standV = 3584`）。

## 残ること

ラウンド 30（[最初の立ちの前の位置を証明する](c-7-13-4-StandHit-ja.md)）: `stand_P` はなくなりました。`wall_turn` の場合は証明しました（`RoomCore.stand_hit`）。`stand_first` は `RoomRun.fall_left` と `InRoom.wall` の歩き（`WallX`、`WallF`）から位置を得ます。以下はラウンド 29 の状態です。

最初の立ちの 1 つ前のフレームでのフィールド。証明には次が要ります。壁での立ちは移動の終わりで `x ≤ 12`（`RoomWall` と同じような移動の終わりからの歩きで、`x` が 13 から先）。そしてそのフレームの左への移動は多くて 24/16 px（止めるフレームでの移動の終わりの移動のモデル）。
