# 部屋のフレームの `RunningSpeed`: `stop_run` を証明する

[ボーナス部屋をつなぐ](c-5-RoomJoin-ja.md) のフィールド `stop_run`（項目 1-1-c-7-4。ラウンド 30 で狭めた: [左の壁が止めるしくみ](c-7-4-1-StopRun-ja.md)）は、落下のあとで `hstep` に従わないフレームは `RunningSpeed` を 0 のままにする、というものでした。このラウンドでは、プレイヤーのルーチンからフレームの終わりまで `RunningSpeed` を追う、部屋のフレーム全体の歩きで証明します。フィールド `stop_run` はなくなりました。代わりにもっと小さいフィールド `ab_run` が入ります: `C + 37` からの地面のフレームの一部で、フレームが読む保存された速さが走りのしきい値より下であること。

## 命題

`fm(n)` はフレーム `n + 1` が始まる機械、`end(n)` はその終わりの機械、`T_k` はフレームの `k` 命令あとの機械です。プレイヤーのルーチン（`T_k.pc = PlayerCtrlRoutine`）で: `rs` は `RunningSpeed`、`st` はプレイヤーの状態、`xa` は保存された速さ `Player_XSpeedAbsolute`、`a` はジョイパッドのバイトのビット 7（いまの A）、`p` は 1 つ前のフレームの A のビット 7 です。`R = RunSpeedMin` は走りのしきい値（1 フレームに 1.75 px）で、`GetPlayerAnimSpeed` が保存された速さとくらべるバイトです。

数の側では: `rs(n)` はフレーム `n` の終わりの `RunningSpeed`（0 かそうでないか）、`v(n)` は速さ、`st(n)` は状態、`ab(n)` はフレーム `n + 1` がプレイヤーのルーチンで読む保存された速さ、`inp(n + 1).jump` はその入力のジャンプのビット、`Follow(n)` はフレーム `n + 1` が `hstep` に従うことです。部屋の数は `fall = 34`、`hitF = 37`、`runF = 40` です。

```
RunIn(T)  :=  rs = 0  ∧  (st = 1  ∨  st = 2  ∨  (st = 0 ∧ (xa < R  ∨  (a = 1 ∧ p = 0))))

run_frame（証明、RoomRunSpeed）:
  フレームは部屋の条件で始まり、各命令は SiteOK を満たし、フレームはプレイヤーのルーチンの中で終わる、
  T_k.pc = PlayerCtrlRoutine,  T_k.frame = fm(n).frame,  RunIn(T_k)   →   rs(end(n)) = 0

InRoom.run（本物の機械で証明: Route.Run.roomRun）:
  C ≤ n,  n + 1 < E,  T_k.pc = PlayerCtrlRoutine,  T_k.frame = fm(n).frame,  RunIn(T_k)   →   rs(end(n)) = 0

RoomCore.stop_run（証明: RoomRun.stop_run_of。前はフィールド）:
  C + 34 ≤ n < C + 40,  rs(n) = 0,  |v(n)| < R,  ¬Follow(n)   →   rs(n + 1) = 0

ab_run（新しいフィールド）:
  C + 37 ≤ n + 1,  n < C + 40,  rs(n) = 0,  ¬Follow(n),  st(n) = 0,  inp(n + 1).jump = false,  ab(n) ≠ |v(n)|   →   ab(n) < R
```

前のフィールドは `C + 34 ≤ n < C + 40, rs(n) = 0, ¬Follow(n) → rs(n + 1) = 0` でした。`RoomCore.stop_run` には前提が 1 つ多くあります: `|v(n)| < R`。使うのは `rs_of_safe` と `no_wall_back` だけで、どちらも `safeFrom` からこれを知っています。

`stop_run_of` の筋道。プレイヤーのルーチンでの `RunningSpeed` はフレームの始めのもの（`InRoom.before`）なので 0 で、状態は 0、1、2 のどれか（`InRoom.cut`）です。空中と、地面で A を新しく押したときは、それが `RunIn` です。地面でジャンプがないとき、保存された速さはそこで読まれます（`read_ab`）。それは `|v(n)| < R` か、`C + 37` より前なら空中のしきい値より下（フィールド `ab_early` と `AirFastSpeed ≤ RunSpeedMin`。`CleanR` のフレームは `hstep` に従うので、このフレームは `CleanR` でない）か、`C + 37` からはフィールド `ab_run` で `R` より下です。すると `InRoom.run` で `rs(n + 1) = 0` です。

`ab_run` が求めるフレームは前の `stop_run` より少ないです。`ab_run` のフレーム（地面、ジャンプなし）では、プレイヤーのルーチンが `GetPlayerAnimSpeed` を呼び、`R` 以上の保存された速さを `RunningSpeed` に書きます。なので、このコードの読み（証明ではない）では、前のフィールドが成り立つところでは `ab(n) < R` も成り立っていました。`ab_run` は、`C + 37` より前のフレーム、空中かジャンプのフレーム、保存された速さが `|v(n)|` のフレームには何も求めません。1 つの命令での 1 バイトについての条件です。

## 歩きのしくみ

歩きは `RoomVert` の、部屋の 1 フレーム全体の歩き（`RoomMap` の抽象機械）に 1 ビットをつけたもので、`RoomFace` と同じ形です:

1. プレイヤーのルーチンで、歩きは状態をかけらに分けます（`piecesR`）。ビットつき: `rs = 0` で状態 1、状態 2、状態 0 で保存された速さが `R` より下のブロック（`lowB`）の中、状態 0 で `a = 1`、`p = 0`。`[2]` の印: `rs` のビットが立っているもの（8 つ）、状態 0 で保存された速さが `R` からのブロック（`highB`）の中で `a = 0` か `a = 1`、`p = 1` のもの、状態 3、ビット 1 より上のビットがある状態。ブロックは、あるビット `b` より上のビットが `R` と同じバイトの集まりです。`R` で立っているビットごとに `R` より下のもの（3 つ）、`R` で立っていないビットごとと `R` そのもので `R` からのもの（6 つ）があります。`blocksCheck` は 256 のバイトすべてで、`R` より下のブロックには `R` より下のバイトだけ、ほかには `R` からのバイトだけがあり、どのバイトもどれかに入ることを確かめます。かけらはどの機械もおおい（`piecesR_cover`）、ビットつきのかけらは `RunIn` の機械だけを、`[2]` のかけらは `RunIn` でない機械だけをおおいます（`piecesR_class`）。
2. ビットつきのかけらはリストにそのブロックを持ちます。探索が 2 つのブロックを合わせないためです（`R` より下の 2 つのブロックを合わせると `R` からのバイトが入りえます）。
3. 抽象機械は `RunningSpeed` の値を追います。フレームの終わりで、ビットつきの状態は `RunningSpeed` が 0 と知っているか、ルーチンのバイトを知っていてそれが参照のものでないこと（`finRS`）: フレームはプレイヤーのルーチンを出ています。
4. なので `RunIn` でプレイヤーのルーチンに来て、プレイヤーのルーチンの中で終わるフレームは、`RunningSpeed` 0 で終わります（`after_RS`）。

通るわけ（決めるのはチェックで、これはコードの読みにすぎません）: `RunningSpeed` を書くのは `GetPlayerAnimSpeed` だけで、地面と泳ぐときです。`R` とくらべて `R` 以上なら保存された速さを書き、そうでなければ 0 を書くか何も書きません。`R` より下のブロックでは抽象のくらべは決まる（ブロックのいちばん大きいバイトが `R` より下）ので、その書き込みに来ません。地面で A を新しく押すと、状態のルーチンより前にジャンプが始まり、状態のルーチンはジャンプのものになって `GetPlayerAnimSpeed` を呼びません。空中では状態のルーチンはジャンプか落下のもので、部屋では泳ぐ旗は 0 です。

チェックは `room_run_speed : RoomRunSpeed.checkR sy screenNames ctx = true` と `room_run_apart`（5 つのバイトが別、`RunSpeedMin` の `blocksCheck`）で、新しい非公開の `Proof/RoomRunSpeed.lean` で `native_decide` によります。プログラム（`room-run-check`）では探索に失敗はありません。フレームの終わりの状態は 210 で、そのうち 186 がビットつき、`finRS` が退けるものはありません。`checkR` は約 24 s（探索を表示するので全体で 86 s）です。

フレームが `hstep` に従わないわけ（`wall` と `late`、測っただけ。1 つのフレームにわけが 2 つ以上あることもある）:

| | `wall` 大きい | `wall` 小さい | `late` 大きい | `late` 小さい |

## 残ること（証明していない）

- `ab_run`: `C + 37` から `C + 40` で、地面でジャンプがないとき、古い保存された速さ（`|v(n)|` でないもの。止まる前に書かれたもの）が `R` より下であること。証明には、止まるフレームを通した保存された速さの上限が要ります。それは `ImposeFriction` を呼んだ最後のフレームでのそのあとの速さの大きさで、前のフレームのこともあります。ラウンド 32（[止まったあとの保存された速さ](c-7-4-3-AbsKeep-ja.md)）は、1 つ前のフレームが止まり、そのプレイヤーのルーチンに `AtCtrl` の状態で来るときにこれを証明し、フィールドをほかのフレームに狭めます。
- `wall` と `late`（変えていない）。測ったフレームはすべて、古い、隠された、押し戻しのどれかで、`C + 37` より前の押し戻しは左の壁だけです（上の表）。証明には、この 3 つのわけをフレームを通してたどることが要ります: 押し戻しは壁の近くだけ（壁から離れたところでは押し戻しがないことを示す、移動の終わりからの歩き）、古い保存された速さと隠された向きは押し戻しのあとだけ。
