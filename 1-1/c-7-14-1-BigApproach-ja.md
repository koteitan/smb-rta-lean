# かたまりの角での大きなプレイヤー

[地下の部屋をつなぐ](c-5-RoomJoin-ja.md) のフィールド `way` は、壁に触らず、`C + 37` から `t₀` まで止まらないとき、かたまりに着地する前の、床からの最後の跳び（`Approach`）を与えます。その一部 `low` は、そのジャンプの低いフレーム（足が角の高さかそれより下）はどれも `LowAt` だと言っていました。つまり、当たりの処理が角より左に保つか、止めるか、彼が左に動くかです。これは大きなプレイヤーの測った走りで偽です。このページは `low` を大きなプレイヤーでも成り立つ主張に置きかえ、大きなプレイヤーの速い跳びと、落下のあとの最初のフレームより後の遅い跳びを証明し、その最初のフレームでの大きなプレイヤーの遅い跳びに 1 つの仮定（`Approach.slowBig`）を残しました。ラウンド 26 でそれも証明しました: [C + 35 での大きなプレイヤーの遅い跳び](c-7-14-2-LandDist-ja.md)。ラウンド 27 から `low` は低いフレームの一部だけを求めます: [最初のジャンプの低いフレーム](c-7-14-3-ApproachJump-ja.md)。

**偽（測定、ラウンド 24）。** `Approach.low` は大きなプレイヤーで偽です。壁に触らず、止まらず、かたまりに着地する測った 2 つの走りで、最後の低いフレーム（跳んでから 10 フレーム、高さ 138、右に動く）は角から 336/256 ピクセルと 48/256 ピクセル先で終わり、止まっていません。原因: 大きなプレイヤーの横の判定には、頭から 8 ピクセルと 24 ピクセル下の 2 点があります。高さ 136 から 151 では上の点がかたまりの上の行にあり、そこではかたまりの左の列の上にコインがあります。処理はコインを取って横の判定を抜けるので、そのフレームでは下の点が押し戻しません。そのあとコインはないので、これは 1 フレームだけです。

## 主張

`P(n)`、`vs(n)` は、フレーム `n` の終わりの位置（1/256 ピクセル単位）と縦の状態です。`c_P` は角（51 ピクセル）、`S_low = 415/256` ピクセル、`G_P` はゴール（かたまりの右の端）です。`T1 + 1` は跳ぶフレーム、`s = T1 + 1 + u.low` はジャンプの最後の低いフレーム、`L` はかたまりの上のフレームです。`sz` は最初の操作でのプレイヤーの大きさのバイトで、0 が大きいです。`LowAt(n) := P(n) ≤ c_P + S_low ∧ (Stop(n) ∨ P(n) < c_P ∨ v(n) < 0)`。`fast` は、跳ぶときに読んだ速さが 25 以上だったことです。

```
Approach.low（フィールド。前は  ∀ n ∈ [T1 + 1, s],  LowAt(n)）:
  ∀ n ∈ [T1 + 1, s],   LowAt(n)  ∨  (sz = 0  ∧  n = s  ∧  P(n) ≤ c_P + S_low)

Approach.slowBig（ラウンド 25 のフィールド。ラウンド 26 でなくなった。LandDist.slow_short で証明）:
  sz = 0  →  fast = false  →  ¬LowAt(s)  →  T1 = C + 34  →  C + 98 < t₀

slowBigOk（新しい確認、Checks.roomBig の中）: 遅い組 (q₁, q₂) ∈ {(10, 17), (11, 16)} のそれぞれで
  c_P − 1 + 384·(q₂ + 1 − q₁) + capDist(98 − (34 + 2 + q₂))  <  G_P

fast_short（証明）: 跳ぶフレームのあと L' 個の低い空中フレームについての FastTakeoff の探索（L' ≤ 8）があるとき、
  壁に触らず、C + 37 から t₀ まで止まらず、t₀ ≤ C + 98、C + 40 までの速い跳び、n ≤ T1 + 1 + L' のどの n でも P(n) < c_P   →   False

landed_short（証明、主張は同じ）: 壁に触らず止まらないとき、かたまりへの着地は C + 98 < t₀ を与える
```

`landed_short` は `LowAt(s)` で分けます:
- `LowAt(s)`（大きくないプレイヤーではいつも）: 前と同じです。低いフレームはどれも `LowAt` なので、`s` までのどのフレームも角より左です（`left_at`）。遅い跳びは空中の速さの上限で足りません（組 `(10, 17)`、`(11, 16)`、余りは 65/256 と 193/256 ピクセル）。速い跳びは、低い空中フレーム 8 個の `FastTakeoff` の探索（`roomOk`）で足りません。
- `LowAt(s)` でない: このとき `sz = 0` で、角の先に出られるのは最後の低いフレームだけです。`s − 1` までのどのフレームも角より左です（`left_at`、`w = s − 1`）。速いジャンプには低い空中フレームが 8 個以上あります（`s ≥ T1 + 9`）。だから跳ぶフレームのあとの 7 個の空中フレームは角より左で、低い空中フレーム 7 個の `FastTakeoff` の探索（`roomB`、新しい確認 `Checks.roomBig`）が矛盾を与えます。`C + 35` より後の遅い跳び（`T1 ≥ C + 35`）は `s − 1` からの上限を使います。空中のフレームは 1 つ増えますが、着地も 1 フレーム遅く、`capDist(n + 1) ≥ 384 + capDist(n)` です。組 `(q₁, q₂ + 1)` の `pair_bound` と `slowBigOk` が矛盾を与えます。`C + 35` での遅い跳びは `slowBig` でした。ラウンド 26 からは `LandDist` の探索です（`Checks.slowLand`）。

**`slowBig` をここで証明しなかった理由**（ラウンド 26 で、着地のあとのフレームの表と部屋の最初のフレームからの探索で証明: [C + 35 での大きなプレイヤーの遅い跳び](c-7-14-2-LandDist-ja.md)）。 `C + 35` では着地は遅くなりません。`P(s − 1) < c_P` からだと、遅い跳びの上限には空中の速さのフレームが 1 つ増えます: `c_P − 1 + 384·8 + capDist(46)` は `C + 98` でゴールより 319/256 ピクセル先です（`P(s) < c_P` からでは 65/256 ピクセル足りませんでした）。着地かそれより前の条件では足りません: 測った大きなプレイヤーの走りは着地のフレームで `P(L) − c_P = 2880/256` ピクセルですが、上限にはおよそ 2752 以下が要ります。ゆるいのは着地のあとです: `capDist(46)` は 28480 で、TAS はその 46 フレームで 27984 進みます。もっときつい上限には、着地のあとの新しい探索が要ります（ラウンド 26: 正確な表だけではまだゴールを 15/256 ピクセル越えます。部屋の最初のフレームからの探索で閉じます）。

## 測ったこと

- TAS（小さい）: `C + 35` で跳び、最後の低いフレーム `C + 45` は角より 16/256 ピクセル左、`C + 52` でかたまりに着地、`t₀ = C + 99`。`C + 98` でゴールに 592/256 ピクセル足りません。フレーム `C + 46` で、小さなプレイヤーの横の判定が同じコインを取ります。
- 大きなプレイヤー（最初の操作で大きさのバイトを大きいにした、人工の状態）。TAS の入力からの自分の入力の山登り: 最後の低いフレーム `C + 45` で、角から 208/256 ピクセル先でコインを取り、押し戻されません。いちばんよい走りは `C + 98` でゴールに 320/256 ピクセル足りず、`t₀ = C + 99` です。そのフレームからのビーム探索（フレームごとに 300 状態、左右同時押しを含む 16 の入力）も同じ −320 です。TAS の `C + 45` の状態からは −544 です（TAS は −592）。
- 低い空中フレーム 7 個の `FastTakeoff.roomCheck` は、8 個と同じく真です（ネイティブで約 1.4 秒）。
- `room-approach-check FM2 300 1`（大きい。TAS、自分の入力の 2,700 の走り、山登りの走り。`t₀` か 300 フレームまで）: 壁に触らず止まらずかたまりに着地する走りが 38、低いフレームが 437。前の `low` はそのうち 3 で偽（上の 2 フレームと、山登りの走りのフレーム `C + 45`）。新しい `low` はすべてで成り立ちます。`slowBig` の前提は 2 つの走りで成り立ち（`t₀ = C + 108` と `C + 99`）、どちらでも `slowBig` は成り立ちます。`fast_short` や `slowBigOk` に反する走りはありません。`… 300 0`（小さい）: そのような走りが 37、低いフレーム 428 はすべて `LowAt`。
- 測っていない見積もり: 最初の操作での TAS の状態からは `P` は 16/256 ピクセル刻みで動くので、大きなプレイヤーの `P(C + 44) ≤ c_P − 16` で、速さは 24 以下なので `P(C + 45) ≤ c_P + 368` です。山登りの走りより 160/256 ピクセル多いだけです。着地のあとの測った動きでは、`C + 98` でゴールにおよそ 160/256 ピクセル足りません。そのようなフレーム `C + 45` のいちばん遠いものを探しましたが、山登りの走りより先には行きませんでした。

## 残ること

- `slowBig`: ラウンド 26 で証明しました（[C + 35 での大きなプレイヤーの遅い跳び](c-7-14-2-LandDist-ja.md)）。フィールドはなくなりました。
- `Approach.low` 自体はまだフィールドです。当たりの処理が低いフレームを `LowAt` に保つこと（または大きなプレイヤーの最後のフレームを角から遠くない所に保つこと）は導いていません。

**ファイル。** `Theorems/RoomJoin.lean`: `Approach` が `sz` を取る（`low` を変え、`slowBig` が新しい）。`Way` と `RoomFields`、`RoomCore` が `sz` を取る。`RoomRun` はそれを `S.seq b`（最初の操作の機械）の大きさのバイトにする。新しい `roomB`、`slowBigOk`、`Checks.roomBig`、`fast_short`。`landed_short` の主張は同じ。非公開: `room_checks` の `roomBig`（`Proof/RoomJoin.lean`）。プログラム `room-approach-check`、`room-big`（probe、beam、fast）。

**再現。**
```
.lake/build/bin/smbrta room-approach-check FM2 300 1      # 大きい。最後を 0 にすると小さい
.lake/build/bin/smbrta room-big fast 7                    # 低い空中フレーム 7 個と 8 個の FastTakeoff の探索
.lake/build/bin/smbrta room-big probe FM2 3000            # 両方の大きさでの TAS の部屋のフレームと山登り
.lake/build/bin/smbrta room-big beam FM2 300 45 INPUTS    # フレーム C + 45 からのビーム探索
```
