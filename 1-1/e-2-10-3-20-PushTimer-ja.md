# 彼を動かす押し戻しは横のタイマーを 16 にする

第 30 回は、フィールド `endKeep` で次のことを仮定しました: 横の当たりのタイマーが高々 1 で終わるフレームでは、フレームの終わりでの彼のピクセルは、スクロールの処理の戻りの命令でのものと同じ（スクロールの処理のあとで押し戻しか補正を呼ぶフレームで。第 31 回は右への速さを保たないフレームに狭めました）。ここでは、タイマーが高々 1 で終わるすべてのフレームでこれを証明します。`endKeep` には場所のバイトの部分だけが残り、フレームの終わりの 1 つの状態についての条件になりました。ピクセルの部分のかわりに、1 つの命令についての新しい条件 `sideW` を置きます。`endKeep` が何かを求めるフレームで求めます。

ゲームのコードでの理由: 押し戻し（ImpedePlayerMove）が彼を 1 px 動かすのは、先に横の当たりのタイマーに 16 を（彼の速さに 0 を）書く道だけです。タイマーが減るのはタイマーのルーチンだけで、それはフレームの始め、プレイヤーのルーチンより前にあります。画面の端での補正はスクロールの処理の中、その戻りより前にあります。だから、タイマーが高々 1 で終わるフレームでは、スクロールの処理のあとの押し戻しは彼を動かしていません。

**第 33 回.** 歩きは彼の速さも追い（3 つめの歩き、`PushTimer.pvI`）、その守りは彼の速さと状態も守ります（`guardS`。`FrameKeep.guardE` がそれらを守るので、`cleanS_of` はなお成り立つ）。だから `pix_end` は、そのようなフレームは R の速さで終わる、とも言います。歩きの終わりは、バイトをまだ追っているか、タイマーが押し戻しの書く値（`pushT`、押し戻しのコードから読む。16）と知られていることを求めます（2 以上のかわりに）。だから `pix_end` は、タイマーがその値で終わらないどのフレームでも成り立ちます（第 32 回: 高々 1）。[補正が止めるフレームは画面の左端で終わる](e-2-10-3-23-StopClamp-ja.md) がこれを使います。また `pix_end` は、タイマーに届きうる書き込み（`NearW`）でだけ `SideW` を求めます。ほかでは定理 `sideW_far` です（[横のタイマーに届きうる書き込み](e-2-10-3-22-SideNear-ja.md)）。`sCheck` はタイマーの添え字が 256 以上であることも求めます。下の主張は第 32 回のものです。第 33 回で `pvI` の 3 つのバイトについて成り立ちます。

**主張（第 32 回）.** 次のように書きます。

```
side(m)    = m での横の当たりのタイマー
pix(m)     = m での彼のピクセルとページ（2 バイト）
R          = スクロールの処理の呼び出しの次の命令（PlayerSubs + 3）、同じフレームの中
SideW(m)   := m での添え字かポインタを通した書き込みは、横の当たりのタイマーを書かない
```

`PushTimer.pix_end`: 地上の、操作の中の数えるフレームを、`EdgeStep.keep_r` の仮定とともにとります（待ちのループから始まり、各命令で `FrameKeep.guardE` の `CleanK`、ルーチン・モード・タスクを番地で書かない、エリアの値）。フレームはプレイヤーのルーチンのあと、初めて `kq` でスクロールの処理に来ます。`kq` から先のフレームの各命令が `PosW`（フィールド `posW`）と `SideW`（新しいフィールド `sideW`）を満たすなら、スクロールの処理の呼び出しの次の命令 R について

```
side(フレームの終わり) ≤ 1  →  pix(フレームの終わり) = pix(R)
```

スクロールの処理の戻りの命令 `Rt` は R の 1 歩前で、その 1 歩は RAM を変えません（`SurfaceFrames.ret_step`）。だから pix(R) = pix(Rt) です。`OnFrames.nearStepAt` では、タイマーが高々 1、ロックが 0、場所のバイトがしきい値以上で終わるすべてのフレーム（`NearM` がピクセルを必要とするフレーム）で、これが `endKeep` のピクセルの部分のかわりになります。押し戻しや補正を呼ぶフレームでも呼ばないフレームでも同じです。そこではフィールド `sideW` が `SideW` を与えます。

定理は `PushTimer.pix_end`、`endKS`、`live_stepKS`、`cutS_spec`、`posW_plain`、`cleanS_of`、`sideWL_of` です（公理 `propext`、`Classical.choice`、`Quot.sound`）。ROM の確認は `PushTimer.sCheck` で、`numbersCheck` の新しい部分です。非公開の証明 `pole_numbers` がそれを `native_decide` で確かめます。ネイティブでは `sCheck` は約 2 秒です。

**証明.** TaintRun の抽象機械の歩きです。`EdgeStep.keep_r` の 2 番目の歩きと同じ形です: `CtrlKeep` の歩きで切れ目まで、`AfterKeep` の最初の歩きでスクロールの処理まで、`EdgeStep` の中の歩きで R まで、そして R からフレームの終わりまで、`pix` の 2 バイトのそれぞれについてもう 1 つの歩きです。

* 歩きはそのバイトを追います（TaintRun のカウンタ）。そのバイトを番地で書く命令の直前で、追うのをやめます（`CollideKeep.rkOff`）。
* フレームの終わりで、そのバイトをまだ追っているか、横のタイマーが 2 以上と分かっていることを求めます（`finS`）。
* 押し戻しの、彼を動かす道では、タイマーへの 16 の書き込みが、ピクセルとページへの書き込みより先にあります。だからそのあと、歩きはタイマーを 16 と知っています。
* そのために、歩きの守りはタイマー、彼のピクセル、ページを守ります（`guardS`）: 歩きが行き先を知らない書き込みでも、それを忘れません。本物の機械でのこの守りの `CleanK` は 3 つのことから出ます（`cleanS_of`）:
  * `FrameKeep.guardE` の `CleanK`（フィールド `keep.cleanE`）;
  * タイマーについては `SideW`（フィールド `sideW`）;
  * ピクセルとページについては `PosW`（フィールド `posW`）: 押し戻しと補正の外では、添え字かポインタを通した書き込みは彼の位置のバイトを書きません（`posW_plain`。どの添え字でも届かない基準からの書き込みには `PositionKeep.ordinary_absFar`）。歩きは、添え字かポインタを通したそれぞれの書き込みで、それが押し戻しや補正の中にないこと、割り込みが待っていないこと、命令がプログラムの側の番地にあることを求めます（`okS`）。
* 押し戻しと補正の外で彼の位置を番地で書くところでは、道を止めます（`EdgeStep.cutPos`）。`posW` がそれを除きます。
* 歩きは、移動のルーチンの入口で添え字を 0 と 0 でないものに分けます。スクロールの処理のあとの 0 の道では、移動の、添え字を通した彼のピクセルへの書き込みに来てしまいます。本物の機械はそこにありません: その書き込みは `posW`（タイマーなら `SideW`）を破るからです。そこで歩きは、行き先を知っている添え字を通した書き込みで、行き先が 3 バイトのどれかなら、道を止めます（`cutS`、`cutS_spec`）。
* フレームの終わりで: タイマーが 2 以上と分かっていれば、本物のタイマーも 2 以上です。だからタイマーが高々 1 で終わるフレームは、そのバイトを追ったまま、つまり R での値のまま終わります。

**道の上で.** フィールド `endKeep` のピクセルの部分はなくなりました。`endKeep` は、触れる前の最後のフレームを除く数えるフレームのそれぞれの終わりの、1 つの状態についての条件になりました:

```
endKeep : ∀ j, 1 ≤ j → j + 1 < g → EndKeep(seq j)
EndKeep(b) := side(b) ≤ 1 → lock(b) = 0 → thr ≤ pfs(b) → pfs(b) = (pixel16(b) − left16(b)) mod 256
```

（第 31 回: `∀ j kq k, … → EndKeep(Calls(Q) ∧ ¬(0 < v(Q) ∧ v(seq j) = v(Q)), Rt, seq j)`。押し戻しか補正を呼び、右への速さを保たないフレームでは pixel16(seq j) = pixel16(Rt) も求めていました。）1 つの命令についての新しいフィールド:

```
sideW : ∀ j, 1 ≤ j → j + 1 < g → side(seq j) ≤ 1 → lock(seq j) = 0 → thr ≤ pfs(seq j) →
          ∀ k n, arr(j) ≤ k → k ≤ n → pc(trace k) = PlayerSubs → frame(trace n) = frame(fm j) → SideW(trace n)
```

`sideW` が何かを求めるのは、`EndKeep` が求めるように終わるフレーム（タイマーが高々 1、ロックが 0、場所のバイトがしきい値以上）だけです。そこでは、スクロールの処理からのすべての命令で求めます。押し戻しも補正も呼ばないフレームや、右への速さを保つフレームでもで、そこでは古いピクセルの部分は何も求めませんでした。位置についての `posW` と同じく、1 つの命令についての条件です。プログラムは `SideW` をすべてのフレームでも測りました（`sideW on every frame (measured only)`）: 失敗 0。`numbersCheck` の新しい確認: `PushTimer.sCheck`（`Numbers.pushC`、`AreaRun.pt`）。`OnFrames.nearStepAt` は `OnFrames.stillAt`、`OnFrames.keepAt`、フィールド `clampR` をもう使いません。`clampR` は `AfterP.keep` のために `OnFrames.keepAt` がまだ使います。`guardE` が守るバイトは増えないので、`keep.cleanE` と `chg.upCleanU` が求めることは変わりません。

**ここで証明していないこと.** `endKeep` の場所のバイトの部分: 描画（RenderPlayerSub）は、RelativePlayerPosition がピクセル − 左端として計算した相対位置から、彼の画面上の場所を書きます。TaintRun の機械の歩きは 1 つ 1 つのバイトのビットを知るだけで、2 つのバイトの間の関係は知りません。だからこの差を追えません。また、けがのタイマーが動いている間は 1 フレームおきに描画が飛ばされるので、歩きはそのタイマーをすべてのフレームで 0 と知る必要もあります（それは間隔のタイマーで、毎フレーム添え字を通して書かれます）。`Moves.stop`（測ったフレーム 6 つ。どれも左端での補正が 1 回、押し戻しはなし。第 32 回で狭めた: [画面の左端で彼を止めるフレーム](e-2-10-3-21-StopEdge-ja.md)）。`collide`、`posW`、`clampR`、`sideW`。
