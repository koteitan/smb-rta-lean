# 右への速さを保つか、呼び出しをしないフレームは、スクロールの処理からあと位置を保つ

**主張.** 操作中のフレームを考えます。仮定は `PositionWriters.writers_end` のものです。Q をスクロールの処理での機械（命令 q）、b をフレームの終わりの機械とします。q からフレームの終わりまでの各命令 R について、2 つの条件を仮定します。

- `PosW(R)`: R が位置のバイト（ピクセル、ページ、端数）を番地で書くなら、R は押し戻し（`ImpedePlayerMove`）か画面端の補正の内側にあります（`innerP`）。また R がその外にあって単純でない（添字かポインタで書く）なら、R は位置のバイトを書きません。第 23 回: 2 つめの部分は、絶対番地と添字で書き、その基の番地からどの添字でも位置のバイトに届かない命令には求めません（`absFar`、下）。
- `ClampR(R)`: R が補正の入口で v(R) > 0 なら、補正先は P(R) です。

このとき（`keep_frame`）:

```
0 < v(Q)  ∧  v(b) = v(Q)   →   P(b) = P(Q)
```

これはフィールド `AfterP.keep` です。もうフィールドではありません。地上のフレームでは定理 `SurfaceFrames.OnFrames.keepAt` で、`posW` と `clampR` が `OnFrames` の新しいフィールドです。どちらも 1 命令ずつの条件です。同じ定理がこれらのフレームの `CollideS.P` も出します。なので `collide` は、0 < v(Q) で v(b) = v(Q) のフレームでは位置を求めません。

2 つ目の定理は `PosW` だけを使います（`still_frame`）。q からフレームの終わりまでのどの命令も押し戻しの入口でも補正の入口でもなければ

```
P(b) = P(Q)
```

です。地上のフレームではこれは `SurfaceFrames.OnFrames.stillAt` で、`collide` は、スクロールの処理からあとで押し戻しか補正を呼ぶフレームにだけ位置を求めます（`Calls`）。

**証明.** そのようなフレームでは、q からあとのどの機械も速さ v(Q) を持ちます（`FrameW.kept`。速さの歩きから）。q から b までは切れ目の列（`PositionDispatch.Edge`）で、どの切れ目も位置を保ちます（`piece_keep`）。

- 押し戻しの入口 R: 動かす押し戻しは速さを 0 にします（`ImpedePosition.routine_return`）。押し戻しのあとの速さは v(Q) ≠ 0 なので、押し戻しは動かしません。効果は 0 です。ルーチンからは P(あと) ≡ P(R)（2²⁴ を法として）が出て、どちらも位置の範囲にあるので P(あと) = P(R) です。`PositionWriters.ready_all` が求めていた余白 256 ≤ P(R)、P(R) + 256 < 2²⁴ は要りません。
- 補正の入口 R: v(R) = v(Q) > 0 なので、`ClampR` から補正先は P(R) です。なので補正先は位置の範囲にあり、補正の効果は 0 です。`ready_all` の条件 Y = 0 は要りません（`AtW` から Y ∈ {0, 1}）。
- ほかの到達した命令 R: R は 2 つの呼び出しの内側にありません（`reached_in`）。R が単純なら、歩きの `AtW.rom` と `PosW` から、R は位置のバイトを書きません（`PositionWriters.ordinary_plain`）。単純でなく `absFar(R)` なら、`ordinary_absFar` がそれを出します（第 23 回）。それ以外は、`PosW` がそのまま言います。

列は b に着くので、P(b) = P(Q) です（`keep_end`）。呼び出しのないフレームでは、どの切れ目も普通の 1 歩なので（`piece_ord`）、やはり P(b) = P(Q) です（`still_end`）。`keep_frame` はこれを本物のフレームの上に置きます。スクロールの処理の機械はフレームの中にあるか、フレームの終わりの機械です（`PositionWriters.subs_frame`）。フレームは `fuelPerFrame` 命令のうちに終わります（`FrameW.ends`）。ROM の確認は `pCheck` です（9 個の書き込みの一覧を持つ `PositionWriters` の歩き、押し戻し、補正、スクロールの処理が 2 つの呼び出しの内側にないこと、アイドルループ）。`numbersCheck` の一部です。

**第 23 回: 絶対番地と添字で書く命令（`absFar`、`ordinary_absFar`）.** R が番地 b + X か b + Y に書くとします（`StepWrites.wOf` が `wAbx` か `wAby` とする命令）。b は命令の次の 2 バイトです。0 から 255 のどの添字 u でも b + u の RAM のバイトが位置のバイトでなければ、R は添字によらず位置のバイトを書きません。

```
absFar(R)  :=  op(R) ∈ absXOps ∪ absYOps  ∧  ∀ u < 256, ramIdx(b + u) ∩ {ピクセル, ページ, 端数} = ∅
absFar(R)  →  Ordinary(R)                                   （ordinary_absFar。R の命令と次の 2 バイトはプログラムの半分にある）
```

証明は 1 歩で書くバイト（`StepWrites.stepLocs`）を読みます。割り込みはスタックのページに積み、止まった機械は何も書かず、それ以外では書く先は `ramIdx(b + X)` か `ramIdx(b + Y)` です。確かめるのは命令自身のバイトなので、歩きも ROM の確認も変わっていません。`posW` はこれらの命令で 2 つめの部分を求めません。プログラム `pos-index-sites` は、スクロールの処理からの `PositionWriters` の歩きの状態で、単純でない命令を数えます: 729 個。押し戻しと補正の内側には 0 個。そのうち 306 個が `absFar`。ほかに 111 個が、位置に届きうる絶対番地と添字で書きます。312 個がゼロページと添字（`STA`、`STY`、`INC`、`DEC`）かポインタ（`STA (zp),Y`）で書きます。なので `posW` が 2 つめの部分を求めるのは 729 個のうち 423 個です。

**フィールドの変化.**

- なくなった: `AfterP.keep`（フィールド `moves` は `AfterP` 全部を求めていました。いまは `AfterP.stop` だけ: `Moves.stop`）。
- 狭くなった: `collide`（`CollideS.P`）は、スクロールの処理からあとで押し戻しか補正を呼ぶフレーム（`Calls`、`CollideS` の新しい引数）にだけ求め、0 < v(Q) で v(b) = v(Q) のときは求めない。下の測ったフレームでは、66,609 のうち 56,083 が呼び出しをしません。
- 新しい: `OnFrames.posW` と `OnFrames.clampR`。触る前の各数えるフレームの、スクロールの処理からフレームの終わりまでの各命令について。
- 第 23 回: `OnFrames.clampR` は、スクロールの処理で右へ動き、その速さで終わるフレーム（0 < v(Q)、v(seq j) = v(Q)）だけで求めます。`keep_frame` が `ClampR` を使うのはそこだけだからです。仮定 `hcr` は次のように変わりました。

```
hcr : ∀ k n, n₀ ≤ k ≤ n,  pc(trace k) = PlayerSubs,  0 < v(trace k),  v(frame) = v(trace k),  trace n はフレームの中  →  ClampR(trace n)
```

`posW` は、21 回目の条件 1 と 2（`ready_all`）のうち歩きが証明しない部分です。位置を番地で書く命令は 9 個だけで、ほかの単純な命令は位置のバイトを書かないことを、歩きが証明します。9 個のうち 4 個は押し戻しと補正の内側です。`posW` は、ほかの 5 個（横に動く足場のルーチン、つたのルーチン、城のループ）が動かないことを言います。21 回目の条件 3 と 4 は求めません。

**証明していないこと.**

- `posW`: 外の 5 個の命令は、面のデータ（横に動く足場がない、つたがない、ループの命令がない）が遠ざけます。歩きはこのバイトを知りません。また歩きが会う 423 個の命令が、位置に届きうる添字かポインタで書きます（第 23 回。第 20 回は別の歩きで 402 個と数えた）。
- `clampR`: 左端の補正が、右へ動くときに位置を保つのは、彼が画面の左端より左にいないときだけです。これはフレームをその前のフレームにつなぎます。第 23 回: フレームの始まりの関係 left(M) ≤ pixel(M) は本物の走りで偽です（フレームは端より 1 px 左で始まることがあります。そのとき速さは 0 で、右は塞がれています）。[フレームの始めの画面の左端](e-2-10-3-10-ScreenEdge-ja.md) を見てください。右への速さを保つフレームでは、測ったどのフレームでも成り立ちました。
- `AfterP.stop` と、呼び出しのあるフレームの `CollideS.P`: フレームの中の呼び出しの回数（順序は証明しました: [1-1-e-2-10-3-9](e-2-10-3-9-PositionOrder-ja.md)）と、補正の端とフレームの始まりの関係が要ります。第 23 回: `CollideS.P` は本物のフレームで偽です（[1-1-e-2-10-3-10](e-2-10-3-10-ScreenEdge-ja.md)）。

**測ったこと.** `pos-keep-real`（プログラムで、証明の一部ではありません）は、スクロールの処理からあとの各命令で `posW`（強い形: 押し戻しと補正の外の命令は位置のバイトを書かない）と `ClampR` を確かめます。走りは `pos-after-real` のものです: フレーム 852 からの TAS、操作からの乱数の走り、画面の左端へ向かう走り、TAS のフレーム 1002〜1091 からの乱数の走り、Select を押す走り。

| 走り | Q に来るフレーム | `posW` を確かめた命令 | `posW` の失敗 | 補正 | v > 0 の補正 | `ClampR` の失敗 | 0 < v(Q)、v(b) = v(Q) のフレーム | そこで P(b) ≠ P(Q) |
|---|---|---|---|---|---|---|---|---|
| フレーム 852 からの TAS | 239 | 699,151 | 0 | 0 | 0 | 0 | 233 | 0 |
| 操作からの乱数の走り 64 回 | 12,677 | 40,928,879 | 0 | 2,152 | 126 | 0 | 7,015 | 0 |
| 左端へ向かう走り 120 回 | 35,938 | 118,047,278 | 0 | 6,359 | 721 | 0 | 16,705 | 0 |
| TAS のフレーム 1002〜1091 からの乱数の走り 128 回 | 14,416 | 26,981,577 | 0 | 268 | 11 | 0 | 8,023 | 0 |
| Select を押す走り 32 回 | 3,339 | 11,150,049 | 0 | 377 | 15 | 0 | 2,061 | 0 |
| 全部 | 66,609 | 197,806,934 | 0 | 9,156 | 873 | 0 | 34,037 | 0 |

2 回呼ぶフレームはありませんでした。Q のあと、どのフレームも、呼び出しなし、補正 1 回、押し戻し 1 回のどれかでした。0 < v(Q) で速さ 0 で終わるフレームでは、P(b) − P(Q) は 0 か −256 でした（`AfterP.stop` は成り立ちました）。

`surface-frames-check` は、読む clean なフレームのどれでも `posW` と `clampR` を確かめ（`movesScan`）、狭くなった形の `collide` も確かめます。乱数の走り 200 回で、そのようなフレームは 215,433、失敗は 0 でした。`collide-real` は呼び出しの条件なしで `CollideS.P` を確かめます。
