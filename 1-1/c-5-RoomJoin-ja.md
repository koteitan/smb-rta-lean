# 地下の部屋をつなぐ

**主張.** `C` を地下の部屋で最初に操作できるフレーム、`E` をマリオが横の土管に入るフレームとします。構造体 `RoomRun` のフレームを持つ走りでは、

```
E ≥ C + 111
```

TAS は `C` = 459、`E` = 570 です。この構造体は本物の走りが与えるものです。フレーム、位置、高さ、覚えている速さ、跳ぶフレーム、着地、かたまりからの離れ方、入るフレームです。そのフィールドは仮定です。本物のフレームがそれを満たすことは、Lean では証明していません。フィールドはできるだけ 1 フレームについての形にしました。

左の壁に着地して跳び、床に一度も触らない走りも定理に入ります。本物のフレームで `E` = `C` + 134 でした（下の「左の壁に立つ走り」）。

`P(n)` はフレーム `n` の終わりの位置で、単位は 1/256 ピクセルです。`c_P` はかたまりの角、`G_P` はその右端を越えた位置、`M_P` は土管の口の左端です。`t₀` は `P ≥ G_P` になる最初のフレームです。`T` は `t₀` の前に床から最後に跳ぶフレーム、`s` はそのジャンプで足が低い最後のフレーム、`L` はかたまりへの着地、`F` はかたまりからのジャンプが床に届くフレームです。`stop(n)` は、フレーム `n` の終わりに遅くて角からあまり先にいないことです。`Φ(n) ≤ Φ_s`、`P(n) ≤ c_P + S` です。

```
no_landing   :  床またはかたまりの横から跳んだジャンプが t₀ でまだ続いている  →  ありえない
stop_short   :  stop(h),  C + 37 ≤ h ≤ t₀ ≤ C + 98  →  P(t₀) < G_P
wall_short   :  C + 37 より前に左の壁に触った,  C + 37 から t₀ まで stop がない,  t₀ ≤ C + 98  →  P(t₀) < G_P
landed_short :  壁に触らない,  C + 37 から t₀ まで stop がない,  かたまりに着地した,  t₀ ≤ C + 98  →  ありえない
past_late    :  t₀ > C + 98
entry_ge     :  E ≥ C + 98 + 13        (数は引数で C + goalF + aboveF)
room_join    :  r : RoomRun  →  r.C + 111 ≤ r.E        (非公開、数は native_decide)
```

次の補題は、1 フレームのフィールドから導きます。証明は「フレームから導くもの」にあります。

```
corner_late  :  C ≤ n < C + 37,  n ≤ t₀  →  P(n) < c_P
low_by       :  C ≤ n ≤ C + 43,  n ≤ t₀  →  P(n) ≤ c_P + S_low
floor_low    :  壁に触らない,  T ≤ C + 40,  C + 37 ≤ n ≤ T  →  LowAt(n)
early_of     :  壁に触らない,  T ≤ C + 40  →  T までのフレームは FastTakeoff のフレーム
stand_gap    :  C ≤ i < j < C + 34,  i と j で立っている  →  i + 8 ≤ j
run_short    :  stop(h),  C + 37 ≤ h ≤ C + 40,  RunningSpeed(h) ≠ 0,  t₀ ≤ C + 98  →  P(t₀) < G_P
mouth_of     :  P(E) ≥ M_P
ab_clean     :  フレーム n + 1 がモデルに従う  →  ab(n) = |v(n)|
```

Lean: `Theorems/RoomJoin.lean`、非公開の `room_nums`、`room_checks`、`room_join`、`room_floor_arcs`。`#print axioms room_join` に `sorryAx` はありません。`native_decide` の分があります。

## しくみ

場合分けは `cases` と `by_cases` で書いたので、Lean の中で全部の場合を尽くしています。余裕は、どれだけ足りないかで、`room-join-check` で測りました。

| 場合 | 足りない理由 | 余裕（1/256 ピクセル） |
|---|---|---|
| 1 回のジャンプでかたまりを越える、着地なし | しきい値より遅いと 1 フレームに 1.5 ピクセルまで。しきい値以上なら、低い 8 フレームのあとは最高速。一番長いジャンプは `arcCheck` から | 1792; 97 |
| `C + 37` 以降に stop がある | 速さがほぼ 0 で、そのあとは [進める距離の上限](../0-0/0-2-Reach-ja.md) のポテンシャル | フレーム 37 で 225、フレーム 41 で 241 |
| stop なし、`C + 37` より前に壁に触った | ジャンプを見ません。壁のフレームからのポテンシャル（下の `wall_short`） | 48; 96; 128; 512 |
| stop なし、`C + 41` より後に跳ぶ | `T + 8` で角のあたりまで、そのあとは最高速 | 97 |
| stop なし、壁に触らない、`C + 41` までに遅く跳ぶ | `P(s) < c_P`、そのあとは [空中の速さの上限](c-1-AirCap-ja.md) と [ジャンプの高さ](c-2-Jump-ja.md) の組。`landing_bound`、`landing_later` | 65; 193 |
| stop なし、壁に触らない、`C + 41` までに速く跳ぶ | [速いジャンプ](c-3-FastTakeoff-ja.md)。右に動いているとありえない。左に動いていると足りない | |

そのあと `t₀ > C + 98` のもとで、かたまりから離れるのは次の 3 つです。

| 離れ方 | 理由 |
|---|---|
| 速いジャンプ | `dropOk` から `t₀ − 1 + 13 ≤ F ≤ E`。なので `E ≥ C + 111` |
| 遅いジャンプ | `t₀ − 1 + 12 ≤ F`。なので `E` < `C + 111` には `E = F = C + 110` が必要。`C + 98` から `E` までは全部しきい値より遅い空中のフレームなので `P(E) < G_P + 12·1.5 ピクセル`。土管の口に 1024/256 ピクセル足りない |
| 歩いて降りる | `walkOk` から `t₀ + 16 ≤ F ≤ E` |

床でぶつかって、覚えている速さが古いまま跳ぶ場合は、別の場合にしていません。これは stop で、`stop_short` は次のジャンプを見ません。かたまりの横から跳ぶ場合も同じ定理に入ります。この跳び方はジャンプの表にはありません。

当たり判定のルーチンがすることで、道筋のページに書いてなかったことが 3 つあります。

* **左に動いていると止められません。** 角より先の低いフレームで `v < 0` なら、ルーチンは止めません。なので `LowAt` は 3 つの場合です。止まっている、角より左、左に動いている。フレームをさかのぼると、角より先で左に動くフレームの前には stop があります。なので stop がなければ、低いフレームではいつも `P < c_P` です（`left_of_corner`）。
* **足でも止められます。** かたまりの上面の少し下で頂点になるジャンプでは（足がかたまりに 5 ピクセル以上入っていて、上昇中でない）、足の判定で止められ、毎フレーム 1 ピクセル戻されます。角の高さより上です。エミュレータでは角から 1136/256 ピクセル先で止められました。なので `S` は低いフレームの余裕よりずっと大きくしてあります。
* **かたまりの横から跳べます。** 足がかたまりの上にあって落ちていて、足が段に入っている深さが 5 ピクセル未満なら、その段に着地します。状態は地面で、高さはかたまりの中です。同じフレームで横の判定に止められ、次のフレームで跳べます。なので最後に跳ぶのは床からとは限りません。これには必ず stop がつくので、`C + 37` 以降に stop があれば定理は跳ぶフレームを使いません。`Approach` は stop がないときだけ求めます。

ぶつかったあとのフレームは、全部が `hstep` に従うわけではありません。次のフレームでは止められた側のボタンが効かず、覚えている速さは、更新するフレームまで古いままで、そのフレームはより大きな加算を使います。`stop` はこれを含みます。`Φ_s` は端数、最大の加算 1 フレーム分、向きの分の和です。

## フレームから導くもの

**`corner_late`。** 何にも触っていなければ、落下のフレームは空中です（`fall_air`）。立っているのは止められたフレームのあとだけで（`stand_wall`）、落下中は床にいない（`fall_long`）からです。向きは右のままです。`Ψ` を次のように決めます。`a₁` は加速の量の表の 2 番目、`g_slow = 2·a₁` です。

```
V ≥ 0                     :  Ψ = V + w
256 − g_slow ≤ V < 0      :  Ψ = V + a₁
−g_slow ≤ V < 256 − g_slow:  Ψ = V + g_slow
−g_slow − a₁ ≤ V < −g_slow:  Ψ = V + g_slow + a₁
それより小さい V          :  Ψ = 0
```

左に動くと加算は 2 倍なので、0 のすぐ下の状態は、戻るときに多く得ます。下の 3 行はその分です。

`airCheck` は、右向き、`|v| < v_A`、`RunningSpeed` 0 の全部の状態（53248 回の `hstep`）と空中の入力 4 通りを確かめます。

```
向きは変わらない,   Ψ' ≤ Ψ + a₁,   V − V' ≤ g_slow
```

なので `16·v ≤ 16·⌊Ψ/256⌋`、`Ψ(C + j) ≤ Φ₀ + a₁·j` です。`airDist(p, j) = Σ_{i=1..j} 16·⌊(p + a₁·i)/256⌋` と書くと、`P(C + 34) ≤ P(C) + airDist(Φ₀, 34)` です。そのあとの 2 フレームは [空中の速さの上限](c-1-AirCap-ja.md) の `capDist`。足すと角より 81/256 ピクセル左です。

壁は 1 フレームのフィールドです。`C + 37` より前で `hstep` に従わないフレームは左の壁に止められたフレームで、その前後で `P ≤ P_w`（`WallAt`）。壁は最初の位置から遠いので、最初の壁のフレームのあとは `C + 15` 以降です（左へ動く距離の上限 `leftDist`）。壁のあとは `P(n) ≤ P_w + dbound(Φ_s, n − C − 15)`。これは `C + 37` より前で角に届きません。余裕は 3680/256 ピクセルです。

**`low_by`。** 壁に触らないとき、`C + 34` で床にいます（`floor_at`）。そのあとのフレームは `VFrame` です。床にいれば、とどまるか跳ぶ。空中なら `vstep` のフレームか、落ちているフレーム。`arcCheck` と `floorArcOk` により、床からのどのジャンプも、跳ぶフレームのあと 8 フレームは足が低く、上昇中で、空中の状態です。なので着地しません。`C + 37` から `C + 43` まで足は低く、`low_at`（足が低いフレームでの当たり判定）から `P ≤ c_P + S_low` です。壁に触ったときは、`P_w + dbound` と最高速で `C + 43` までに足ります。余裕は 31/256 ピクセルです。 `t₀` までのフレームは入る前に終わります。`t₀ < E`（`t0_lt_E`）なので、`vfloor` と `varc` はそれらについて言います。

**`floor_low`。** 壁に触らず `T ≤ C + 40` なら、`C + 34` から `T` まで床にいます。もっと前に跳ぶと、`T` がまだそのジャンプの低いフレームに入り、床にいません。床のフレームは足が低いので `low_at` です。

**`early`。** 壁に触らないとき、`early_of` が `FastTakeoff` のフレームを作ります。`hstep` のフレームは壁に触らないことそのものです。落下のフレームは `fall_air` です。地面のフレームは `floor_low` の床から、跳ぶフレームと空中のフレームは `VFrame` からです。空中のフレームはジャンプの低い 8 フレームで、かたまりへの着地より前（`land_late`）、つまり入る前です。

**`wall_short`。** `C + 37` より前に壁に触り、`C + 37` から `t₀` まで stop がなければ、ジャンプを見ずに `P(t₀) < G_P` です（`t₀ ≤ C + 98` のとき）。なので `Approach` は壁に触らない走りにだけ求めます。`b` を最後の壁のフレームとします。`b` のあとは全部 `hstep` のフレームで、`P(b) ≤ P_w`、`Φ(b) ≤ Φ_s`、`b ≥ C + 15` です。

```
b ≥ C + 22                 :  P(t₀) ≤ P_w + dbound(Φ_s, 76) < G_P        余裕 128
b < C + 22,  b + 1 で右向き :  wall_right
b < C + 22,  b + 1 でほかの向き :  wall_turn
```

**`wall_right`。** フレーム `b + 1` はどんなフレームでもかまいません（跳ぶ、地面、空中）。`Φ(b + 1) ≤ Φ₁ = nxt(Φ_s)` です。そのあと `C + 34` まで空中のフレームです。立つには止められたフレームが要るのに、`b` のあとにはないからです。なので `Ψ` は 1 フレームに `a₁` しか増えません。`Q = Φ₁ + a₁·18` とします。

```
Φ(C + 34) ≤ Q  :  P(t₀) ≤ P_w + 16·⌊Φ₁/256⌋ + airDist(Φ₁, 18) + dbound(Q, 64) < G_P                                   余裕 48
Φ(C + 34) > Q  :  V(C + 34) < 0,  −V ≥ u = Q + 1 − 2c
                  P(t₀) ≤ P_w + 16·⌊Φ₁/256⌋ + airDist(Φ₁, 9) − backD(u, 9) + capDist(64) < G_P                         余裕 512
```

`V ≥ 0` なら `Φ = Ψ ≤ Q` なので、2 行目では左に動いています。`V` は 1 フレームに `g_slow` までしか下がらないので、その前の 9 フレームも左に動いて戻っています。

**`wall_turn`。** 空中のフレームと跳ぶフレームは向きを変えません（`facing`）。なので右以外を向くには、`b` までに跳ばない地面のフレームが要ります。その前のフレーム `i` で立っています。`i` は最初に立つフレームです。もっと前に立っていれば、`stand_gap` で `i ≥ C + 15 + 8` になり、`i ≤ b < C + 22` に合いません。`stand_P` と `leftDist` で `i ≥ C + 16` です。`j = i − C` とします。

立つのは止められたフレームなので `Φ ≤ Φ_s` です。次に立つには `−V ≥ 256·14` が要ります（`stand_fast`）。`iterN(Φ_s, 6) < 256·14` なので、2 回立つ間は 8 フレーム以上あきます。これが `stand_gap` です。

`b` までジャンプはなく、`b` のあとは床のほかに立てません。なのでジャンプがないまま、高さは `vfall` で決まります。`Y = 256·y + 端数`、`W = 256·vy + 端数`、`f` を落下の力とします。

```
Y(C + j) ≤ Y₀ + Σ_{l<j} (W₀ + f·l)
Y(i) ≤ その段 + 255,   W(i) = 0        (stand_row)
Y(i + e) ≤ Y(i) + Σ_{l<e} f·l
```

表 `gaps` は `(j, k)` です。`i + k` まで床に届きません。

```
(16, 32) (17, 32) (18, 28) (19, 28) (20, 28) (21, 25)
```

`i + k` まで空中のフレームなので、`v_A` より遅いままです。`capRamp(p, n)` を `dbound` の速さを `v_A − 1` で抑えたものとします。

```
P(t₀) ≤ P_w + capRamp(Φ_s, k + 1) + capDist(98 − (j + k + 1)) < G_P        余裕は 96 以上
```

**`run_zero`。** このフィールドはなくしました。必要なのは `C + 37` から `C + 40` までの stop の `RunningSpeed` です。`J` の 3 つ目の条件がそれを使います。

```
壁に触った                 :  P(h) ≤ P_w + dbound。RunningSpeed によらず short          余裕 1280 以上
右に動いて落下が終わる      :  safeCheck。|v| は C + 39 まで走りのしきい値より小さい       RunningSpeed = 0
Φ(C + 34) ≤ 上限            :  同じ
左に速く動いて落下が終わる  :  backD で P(C + 34) が小さい。P(h) ≤ backP、fastDist でも short  余裕 144
```

`safeFrom` は小さい探索です。`Φ` の上限で決まらない状態だけ、次の入力に進みます。`hstep` に従わないフレームは `RunningSpeed` 0 を残します（`stop_run`）。`hstep` に従うフレームは `stepOk` です。

**`slow_capped`、`stale`。** `ab(n)` は、フレーム `n + 1` が操作のルーチンに来たときに読む覚えている速さです（`read_ab`）。跳ぶフレームはこれを読みます（`x_ab`）。モデルに従うフレームでは `ab(n) = |v(n)|` です（`ab_clean`）。`AtCtrl` がそれを求め、操作のルーチンの前に速さを書くものはないからです。ほかのフレームは止まった状態にします（`clean`）。なので跳ぶフレーム `T` で次のどちらかです。

```
フレーム T + 1 がモデルに従う  :  ab(T) = |v(T)|
そうでない                     :  stop(T + 1)
```

遅いジャンプなら `ab < v_A` です。1 つ目なら `|v(T)| < v_A`。2 つ目なら `stop(T + 1)` から `|v(T + 1)| < v_A` で、空中の速さの上限は 1 フレームあとから始めます。速いジャンプで、`C + 37` 以降に stop がなければ、2 つ目は `T + 1 < C + 37` のときだけで、そのとき `ab < v_A` です（`ab_early`）。なので 1 つ目だけが残り、`|v(T)| ≥ v_A`。

空中の速さの上限では速いジャンプは扱えません。速いジャンプは跳ぶフレームの 13 フレームあとにかたまりに着地し、空中の速さとそのあとの `capDist` では、上限がゴールを 1727/256 ピクセル越えます。

**`mouth`。** フレーム `E` は本物の機械で入るフレームです。ある命令が横の土管のルーチンを書きます（`enters`）。`P(E)` は、ほかのフレームを `read_P` が読むのと同じく、フレームの終わりで読みます（`read_PE`）。[横の土管に入るフレーム: 終わりの位置](c-7-18-2-SideEntryEnd-ja.md) が、そこでの位置は `M_P` より左ではないことを、位置についての仮定なしに証明します（`InRoom.mouthE`、`Route.Run.roomMouthE` が証明）。書き込みまでの歩きと、そこからフレームの終わりまでの部屋の歩きです。

## 前提（Lean では証明していない）

どれも `RoomRun` か、その中の構造体のフィールドです。下の「1 フレーム」は、1 フレームだけについての事実です。

* 機械はもう欄ではありません（項目 1-1-0-4）。`RoomRun` は走り全体の本物のフレーム（`FrameKeep.RealRun`、`Route.Run.base`）と最初の操作のフレーム `b` をとり、部屋のフレーム `n` は `seq(b + (n − C))` で終わります（`RoomRun.fm`）。入力は `pad n` です。なので `next` は定理（`RoomRun.next`）、最初の操作の機械は `seq b`（`RoomRun.fm_C`、`Route.Run.roomCtl`）、フレーム `E` は走りのフレーム `b + (E − 1 − C)` です（`Route.Run.roomEnter`）。いまは部屋のフレーム `n` は `seq(b + ix(n − C))` で終わります。`b` から後で止まっていない状態で終わる `(n − C)` 番目のフレームの終わりです（`RoomRun.fe`）。部屋のフレーム `n + 1` は `seq(b + ix(n + 1 − C) − 1)` からの本物のフレームです（`RoomRun.fm`）。そのあいだの止まった状態で終わるフレームは数えません。それらはモデルが読むものを保ちます（`InRoom.keep`）。最初の操作の機械は `seq b` です（`RoomRun.fe_C`）。[部屋で一時停止する走り](c-7-1-4-RoomLag-ja.md) を見てください。

これらのフィールドは、このリポジトリにないプログラムで本物のフレームと比べました。TAS ではすべて成り立ち、`E` = `C` + 111 です。なのでフィールドは矛盾していません。ランダムな操作で最初の操作から 2800 回走らせて、成り立たないフィールドは 0 でした（4 種類の操作を 700 回ずつ。TAS の入力を少し変えた走りも含みます）。そのうち 740 回がかたまりの端を越えました。510 回は左の壁に触りました。一番早い `E` は TAS を少し変えた走りの `C` + 111 で、それより早いものはありません。

落下中に立つ走りは、ランダムな操作ではほとんど出ません。なので、立つまでの 27 通りの操作に、立ったあとの 7 通りの入力と 9 通りの A の長さをつけて 1701 回走らせました。成り立たないフィールドは 0 でした。434 回は床に触らずにかたまりの端を越えました。壁に立った走りの `t₀` は一番早くて `C` + 115、`E` は床に触った走りで一番早くて `C` + 154 です。床に触らない走りは、かたまりの上で速さを落とすと `E` = `C` + 134 で入ります。立って跳んでまた立つ走り 1152 回でも、成り立たないフィールドは 0 でした。

「かたまりを越える」場合は本物の走りがないので、そのフィールドは試せていません。大きいマリオは含みません。

## 左の壁に立つ走り

落下は 34 フレームで床に届きます。壁に触っても着地しなければ同じです。左へ走ると、落下中に左の壁の段に着地することがあります。足が壁の列に入り、段の深さが 5 ピクセルより浅いときです。状態は地面で、同じフレームで横の判定に止められます（`C + 37` より前の `wall`）。次のフレームで跳ぶか落ちます。

本物のフレームで見たことです。

* ランダムな走り 20000 回では、最初に立つのは `C + 18`、`C + 19`（床の 4 段上）、`C + 22`（3 段上）、`C + 26`（2 段上）、`C + 30`（1 段上）でした。それ以外は全部 `C + 34` の床です。一番早い壁のフレームは `C + 16` でした。
* 立ったあと左を押すと、そのフレームは壁のフレームで、左を向き、1 ピクセル押し戻されて落ちます。左向きのまま空中で右を押すと、加算は 2 倍です。これが `wall_turn` の場合です。左右を同時に押しても向きが変わります。
* 立ったあと落ちると、床は遅れます。試した 5 つの走りでは `C + 46` から `C + 50` でした。
