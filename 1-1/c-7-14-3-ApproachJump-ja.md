# 最初のジャンプの低いフレーム

[地下の部屋をつなぐ](c-5-RoomJoin-ja.md) のフィールド `way` は、壁に触らず `C + 37` から `t₀` まで止まらないとき、かたまりへの着地の前の、床からの最後の跳び（`Approach`）を与えます。その部分 `low` は、そのジャンプのどの低いフレームでも当たり判定を求めます。`LowAt`、または大きなプレイヤーの最後の低いフレームでは `P ≤ c_P + S_low` だけです（[かたまりの角での大きなプレイヤー](c-7-14-1-BigApproach-ja.md)）。

これらのフレームのいくつかは、別の使い道のためにもう証明しています。落下の終わりから床にいて跳んだジャンプの、`C + 43` までのフレームで、ジャンプのどのフレームも高さ 152 かそれより下で終わる間です（`RoomCore.low_jump`、[ジャンプを通した縦のページ](c-7-5-18-RoomHigh-ja.md)）。このページはそれを `landed_short` で使います。また、角より左のフレームは定義から `LowAt` です（`P < c_P ≤ c_P + S_low`）。なので `low` が求めるのは、角かその先のほかのフレームだけです。

## 主張

`P(n)`、`y(n)` は、フレーム `n` の終わりの位置（1/256 ピクセル単位）と高さです。`c_P` は角（51 ピクセル）、`S_low = 415/256` ピクセル。`T1 + 1` は跳ぶフレーム、`s = T1 + 1 + u.low` は最後の低いフレーム、`sz` は最初の操作での大きさのバイト（0 が大きい）。`fall = 34`、`lastG = 6`、`rise = 8`、`cy = cornerY`（136 ピクセル）。`LowAt(n) := P(n) ≤ c_P + S_low ∧ (Stop(n) ∨ P(n) < c_P ∨ v(n) < 0)`。

```
Approach.low（フィールド、狭めた）:
  ∀ n ∈ [T1 + 1, s],  c_P ≤ P(n)  →                                                            （新しい前提）
    (C + fall + lastG < T1  ∨  C + fall + 1 + rise < n  ∨  ∃ j, T1 < j ≤ n ∧ y(j) < cy + 16)     （新しい前提）
    →  LowAt(n)  ∨  (sz = 0  ∧  n = s  ∧  P(n) ≤ c_P + S_low)

landed_short の中（証明）。壁に触らず、止まらず、T1 ≤ C + fall + lastG（C + 40）のとき:
  ∀ n ∈ [T1 + 1, s],  n ≤ C + fall + 1 + rise  ∧  (∀ j, T1 < j ≤ n → cy + 16 ≤ y(j))  →  LowAt(n)
```

2 行目の証明:

- `T1` は `C + fall` から床にいて（`floor_all`）、`LowAt(T1)` です。`C + 37` より前なら角より左（`corner_late`）、そうでなければ床の上（`floor_low`）。
- `T1 + 1` から `n` までのフレームは `T1` からのジャンプの上です（`arc_from`。`n ≤ C + 43` で `C + 34 ≤ T1` なので、跳ぶフレームから多くて `rise` フレーム）。
- すると `RoomCore.low_jump` が `LowAt(n)` を与えます。

`landed_short` は `low` を 3 か所で使います。`C + 40` より後に跳んだときの `T1 + 1 + rise`（`P ≤ c_P + S_low` だけ）、`s` より前の低いフレーム、`s` です。角より左ならそのフレームは `LowAt` です。`C + 40` より後に跳んだときはフィールドを使います（前提の 1 つ目）。そうでなければ、上の行が当てはまるところではそれを、当てはまらないところではフィールドを使います。

## 測ったこと

`room-approach-check FM2 300 1`（大きい。最初の操作で大きさのバイトを大きいにした、作った状態）と `… 300 0`（小さい）: それぞれ TAS と自分の入力の 2,700 の走りのうち、壁に触らず、止まらず、`t₀` までにかたまりに着地する走り。

| 大きさ | 走り | 最後の跳びの低いフレーム | 狭めたフィールドのもの（角かその先） | 証明（角より左、または `low_jump`） | フィールドが偽 | 証明したフレームで `LowAt` でない |
|---|---|---|---|---|---|---|
| 大きい | 38 | 437 | 3 | 434 | 0 | 0 |
| 小さい | 37 | 428 | 0 | 428 | 0 | 0 |

大きなプレイヤーの 3 個のフレームは、かたまりの左の列の上のコインを取るフレームです。`LowAt` ではなく、フィールドの 2 つ目の場合が成り立ちます（最後の低いフレームで、角から多くて 336/256 ピクセル）。

## 残っていること

- `C + 40` より後に跳んだとき、`C + 43` より後、または 136 から 151 ピクセルで終わるジャンプのフレームのあとの、角かその先の低いフレームでの `low`（測ったフレームは 3 個で、どれも大きなプレイヤー）。`RoomCore.low_floor` と `low_jump` は `C + 43` までしか証明しておらず（縦の状態は落下の終わりから 1 つのジャンプの間だけ追う）、ブロックの左側の歩きは 152 ピクセルかそれより下だけです（136 から 151 ピクセルの高さに何が要るかは [低いフレームごとの上限](c-7-5-20-LowBound-ja.md)）。

**ファイル。** `Theorems/RoomJoin.lean`: `Approach.low` を狭めた。`landed_short` の中で、最初のジャンプの低いフレームを `low_jump` で（`alow`）。プログラム `room-approach-check`（上の数）。

**再現。**
```
.lake/build/bin/smbrta room-approach-check FM2 300 1      # 大きい。最後を 0 にすると小さい
```
