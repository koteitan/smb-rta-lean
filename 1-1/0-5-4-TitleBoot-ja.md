# 電源から Start を押すまで

**命題.** 電源を入れたところからの走りを考えます。電源を入れたときの RAM は分かりません。ウォームブートの印がないか、そのうち 2 バイトが 0 とします。押す前のフレームには Start も Select もありません。押すのは Start で、A はあってもなくてもよく、ほかのボタンはありません。押すフレームは、電源から数えて 32 から 508 です。すると、押したフレームのあとの機械は、[タイトルの Start から操作できるまで](0-5-3-TitleStart-ja.md) の条件 `Press` を満たします。

**これは仮定つきの定理です.** 仮定は `TitleBoot.Run` のフィールドで、下に全部挙げます。1 つの状態（電源を入れたときの機械）と、1 つずつの入力の条件です。`Press` は道筋のフィールド `title.press` でした。いまは定理 `TitleStart.Begin.press` です。道筋のフィールドは `title.boot` で、型は `TitleBoot.Start` です。走りが `TitleBoot.Run` のとおり電源から来るか、押したあとの機械が `Press` そのものを満たすかです。2 つ目は前の仮定です。この組の外の走りのために残します。なので外れる走りはありません。

## ゲームがすること

電源を入れると、リセットのコードは画面を 2 回待ちます。待つあいだ RAM を読まず、RAM に書きません。これが最初のフレームです。次に RAM の終わりのバイトを見ます。トップスコアの 6 桁が数字で、バイト `WarmBootValidation` にゲームの印があれば、終わりの 41 バイトを残します（ウォームブート）。そうでなければ、それも消します（コールドブート）。ほかのバイトは全部消します。ただしスタックのページの 160 バイトは消しません。どのコードも書く前に読まないバイトです。

そのあとフレーム 3 から 30 でタイトル画面を作ります。メニューはフレーム 31 から動きます。メニューの各フレームで、ゲームコアがボタンなしで 1 回動きます。プレイヤーは 1-1 の最初の画面に立っています。なのでタイトルの状態はフレームごとに変わります（タイマー、フレームカウンタ、乱数のバイト、スプライトの順）。しかし A、B、方向のボタンにはよりません。

Start だけ、または A と Start で、ゲームが始まります。A と Start は前のゲームのワールド（`ContinueWorld`）から始めます。コールドブートのあとはワールド 1 です。Select は人数を変え、デモのタイマーを入れ直します。B はワールド選択が有効なとき（`WorldSelectEnableFlag`）ワールドを変えます。コールドブートのあとは無効です。デモのタイマーはフレーム 4 で 24 になり、21 フレームごとに進みます。フレーム 509 で切れます。デモが始まり、そこで Start を押すとタイトルに戻ります。

フレーム 31 ではゲームコアがまだ動いていません。そのフレームで押すとゲームは始まりますが、そのあと `FetchNewGameTimerFlag` は 2 で、`Press` が求める 1 ではありません。フレーム 32 からは 1 です。

押しっぱなしの Start は 2 回数えません。Start のあるフレームの次のフレームで押しても何も起きません。

## 定理

`pm n` は電源から `n` フレームあとの機械、`pi n` はその入力、`kp` は押すフレームです。`P` は電源を入れたときの基準です。カートリッジをリセットしたあとの機械です（プログラムカウンタはリセットベクタ、フレームのドット 21、vblank のフラグは立っている）。印は、押したあとの基準の機械での `WarmBootValidation` の値です（リセットのコードが書きます）。

```
PowerOn(m)    :  ∃ r,  |r| = 2048,  m = P の RAM を r にしたもの,  かつ
                    r[WarmBootValidation] ≠ 印
                 または r[WorldSelectEnableFlag] = r[ContinueWorld] = 0
noSS(i)       :  入力 i に Start も Select もない
onlyStart(i)  :  入力 i は Start、または A と Start
```

押したフレームのあとの機械 `m` についての `TitleBoot.Run(m)` のフィールドです。

```
next     pm(n + 1) = frame(pm n, pi n)
power    PowerOn(pm 0)                         （1 つの状態）
quiet    n < kp  ⟹  noSS(pi n)                （1 つずつの入力）
start    onlyStart(pi kp)                      （1 つの入力）
lo, hi   32 ≤ kp ≤ 508
after    m = pm(kp + 1)
```

定理です（`title_check` は ROM での確かめで、`native_decide` によります。32 から 508 の範囲は、非公開の証明を作るときに探索で見つけ、文脈 `titleCtx` に入っています）。

```
TitleBoot.Run.press     :  Run(m)  ⟹  Press(m)
TitleBoot.Start(m)      =  power(Run(m))  |  press(Press(m))
TitleStart.Begin.press  :  Press(tm 0)                  （Begin.boot : TitleBoot.Start(tm 0)。前はフィールド press）
```

## 証明

**最初のフレーム.** `TaintRun` の抽象機械は、スプライト 0 のフラグがドットの関数であることを求めます。電源を入れたときはこれが偽です。ドット 21 でフラグは立っていません。なので最初のフレームは歩きません。基準の機械を記録つきで走らせると（`PipeTransitionAll`）、最初のフレームは、Start も Select もない 64 通りの入力のどれでも、RAM のバイトを読みません。なので `PowerOn` の機械は全部、基準と同じレジスタ、PPU の状態、ドットで最初のフレームを終えます。その走りの各ステップは、書き込まない命令か、RAM の外の番地への `STA` です。なのでどのステップも RAM に書かず（`StepWrites`）、最初のフレームのあとの RAM は電源を入れたときの RAM です（`frame_keeps`、`boot_frame`）。

**最初の段.** 9 つの状態を持ちます。1 つは 2 バイトが 0 であることを知っています。8 つは `WarmBootValidation` の 1 ビットを知っていて、それは印のビットと違います。印でないバイトは、どこか 1 ビットが印と違うからです（`mask_of_ne`）。この 8 つからは、リセットのコードの印の調べが外れるので、歩きはコールドブートに進み、RAM は全部消えます。

**段.** そこからは抽象機械がすべての機械を追います。いくつかのビットは分かっていて、ほかは分かりません。分からないビットでの分かれ道は両方に進みます。段 `j` は、フレーム `j + 1` が始まるときの状態を持ちます（`TitleBoot.Row`）。押す前のフレームのパッドは、Start と Select が 0 と分かっていて、ほかのボタンは分かりません。

* `linkOK`: ある段のフレームの終わりは全部、次の段の状態。
* `pressOK`: 押すときのパッド（Start は 1、A は分からない、ほかは 0）で、ある段のフレームの終わりは全部 `Press` を満たす。

フレーム 32 からは、状態は RAM を 178 バイトを除いて全部知っています（フレーム 2 のあとは 194 バイト）。スタックのページの 160 バイト、ウォームブートが残すバイト（トップスコア、点数）、前のフレームのボタンです。メニューの段は 2 つの状態を持ちます。フレームがドット 0 で始まるか、ドット 1 から 9 で始まるかです。フレーム 2、4、5 の段は 20 個、226 個、177 個の状態を持ちます。その前のフレームがループの中で終わるからです（リセットのコードのループ、タイトルを作るルーチンのループ）。508 段の状態は全部で 1,440 個です。

メニューはボタンを 2 回調べます（Start、次に A と Start）。A が分からないと、抽象機械は両方の調べに落ちる道を通れます。なのでボタンのバイトを A のビットで分けて読み、分けたものを別々に保ちます。

探索は証明の一部ではありません。`check` は 508 段を全部歩きます。押す前のフレームの表の状態は 5,041 個、押すフレームの表の状態は 4,208 個です。ネイティブで約 3.8 秒です（探索 1.8 秒、最初のフレーム 0.2 秒、押す前のフレーム 1.3 秒、押すフレーム 0.6 秒）。これを入れて、ROM での確かめ `title_check` は約 8 秒です（前は 4 秒）。証明はフレームについての帰納法です。`n < kp` なら `pm (n + 1)` は段 `n` にあります（`Run.covered`）。段 `kp − 1` からの押すフレームが `Press` を与えます（`press_frame`）。

## 本物の走りで

`title-boot-check FM2`、終了コード 0 です。どの走りも電源から始めます。この組の走りの RAM は、全部 0、種から作ったバイトで 2 バイトが 0（印と数字のトップスコアがあるもの、ないもの）、種から作ったバイトで印がないもの、全バイト 255 です。

```
組                                                                 走り   タイトルを出る   Press を満たす
この組                                                              566        566              566
フレーム 31 で押す                                                    2          2                0
フレーム 509 から 548 で押す                                         40          0                0
最初のデモのあとに押す（フレーム 1600 から 2200、7 つごと）          86         66               66
押す前のフレームに Select                                           200        200              200
押す前のフレームに Start とほかのボタン                             200        109              109
押すフレームで Start とほかのボタン                                 100          0                0
印と数字のトップスコアがあり、1 つ目のバイトが 1 の RAM              20         20                0
```

動画の最初の Start はフレーム 39 です。動画はこの組の走りです。

## 証明していないこと

* **押す前の Select.** Select はデモのタイマーを 24 に戻します。段はタイマーの値ごとに 1 つの状態が要ります。歩くフレームは 477 ではなく約 6,200 になります。測った 200 通りは全部 `Press` を満たします。これらの走りでは、条件はまだ仮定です（`TitleBoot.Start` の 2 つ目の場合）。
* **押す前の Start.** ほかのボタンと一緒の Start はタイトルで何もしませんが、段は Start がないことを求めます。こういう走り 200 のうち 109 が押したフレームでタイトルを出て、その全部が `Press` を満たします（Select と同じく仮定です）。残りの 91 では、前のフレームで Start が押されていて、押しても何も起きません。
* **フレーム 31 で押す.** ゲームは始まりますが、`Press` は偽です（`FetchNewGameTimerFlag` が 2）。フレーム 0 と操作は、それでも [タイトルの Start から操作できるまで](0-5-3-TitleStart-ja.md) の定理のとおりです（タイマー 401、位相 2、速さ 0）。これは `TitleBoot.Start` のどちらの場合にも入らない本物の走りです。
* **フレーム 508 よりあとに押す.** デモはフレーム 509 から 1628 まで動き、そこで Start を押すとタイトルに戻ります。デモのあとタイトルがまた来ます。フレーム 1658 から 2123 の Start は `Press` を満たします（測定: タイトルを出た 66 のうち 66）。フレーム 1657 はフレーム 31 と同じです。段は 508 で終わります。
* **印があり、2 バイトのどちらかが 0 でない RAM.** `WorldSelectEnableFlag` が 1 だと、測った 20 通り全部で `Press` は偽です。ゲームはハードモードで始まります。
* **押すフレームで Start とほかのボタン.** ゲームは始まりません（100 のうち 0）。
* **リセット.** `P` は電源を入れたときの機械です。リセットのあとの走りや、ゲームオーバーのあとのタイトルは、`TitleBoot.Run` の走りではありません。

**再現.**
```
.lake/build/bin/smbrta title-boot-check FM2
```
