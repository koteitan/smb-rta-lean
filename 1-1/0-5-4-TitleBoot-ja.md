# 電源からタイトルを出るまで

電源からの走りを考えます。RAM にウォームブートの印がないか、ワールド選択とコンティニューのワールドのバイトがゼロとします。押す前に Start も Select もなく、フレーム 31 から 508 で Start を押すなら、そのフレームのあとの機械は `Press` を満たします。A は一緒に押してもよいです。

出る前に Start があっても扱えます。`TitleBoot.Menu.Run` は、最初にタイトルを出るフレームで走りを表します。最初の入力には Start も Select もありません。出るまでの入力には Select がありません。出る前の機械はタイトルにいます。出るフレームは 31 から 508 です。押しっぱなしの Start は、出るのを遅らせてもよいです。

これは仮定つきの定理です。道筋のフィールドは `title.boot : TitleBoot.Start` のままです。場合は `power`（元の入力の組）、`menu`（最初に出るフレームの組）、`later`（デモのあとの最初の範囲）、`press`（ほかの走りのための、1 つの状態の条件）です。

## 出たあとの条件

`Press` は、基準と同じ何もしないループとスタックポインタ、フレームの始まりの NMI の条件、ポーズでないこと、バイト `K` が基準と同じ値であることを求めます。また `FetchNewGameTimerFlag` がゼロでないことを求めます。このフラグは `K` の外です。

このフラグは、プレイヤーが入るときにゲームタイマーを読み込ませます。メニューの最初のフレームでは、あとのメニューのフレームと違う値になります。ゲームが調べるのはゼロかどうかだけです。前の等号の条件は、メニューの最初のフレームを除外していました。ゼロでないという条件なら含められます。

`TitleStart` の歩きは、このフラグを環境のバイト `D` にし、`dg` でゼロでないと知って始めます。歩きはフラグの調べと消去を追います。フレーム 0 と、操作できるときの速さの結論は同じです。

## 仮定

`pm n` は電源から `n` フレームあとの機械、`pi n` は入力、`kp` は出るフレームです。`PowerOn` は基準のレジスタと PPU の状態を持ち、上に述べた RAM を許します。

元の `TitleBoot.Run` のフィールドです。

```
next       pm(n + 1) = frame(pm n, pi n)
power      PowerOn(pm 0)
quiet      n < kp なら pi n に Start も Select もない
start      pi kp は Start、または A と Start
lo, hi     first <= kp <= last
after      m = pm(kp + 1)
```

`TitleBoot.Menu.Run` は `next`、`power`、`lo`、`hi`、`after` と、`quiet`、`start` の代わりに次のフィールドを持ちます。

```
bootInput  pi 0 に Start も Select もない
quiet      n <= kp なら pi n に Select がない
stays      2 <= n <= kp なら pm n はタイトルにいる
left       m はタイトルの外にいる
```

`stays` と `left` は、1 つずつの状態のモードのバイトを読みます。これで、最初の 2 フレームを除いた最初の出るフレームを表します。リセットが動く前の RAM のモードのバイトは、どの値でもよいです。前のフレームに Start がないという条件はありません。ゲームは押しっぱなしの Start を無視してもよいです。

## 証明

最初のフレームは RAM を読まず、RAM に書きません。記録つきの走りと `StepWrites` から、基準が許したすべての電源の RAM を追うと証明します。最初の段は 9 つの抽象状態です。保護した 2 バイトがゼロか、ウォームブートの印のどこか 1 ビットが違います。

元の段は、押す前に Start も Select もない入力を使います。`pressOK` が出るフレームを確かめます。段の帰納法から `Run.press` が出ます。

メニューの段は Start を許し、Select を許しません。各フレームの終わりは、次の段でタイトルにいるか、タイトルの外で `Press` を満たすかです。前者だけから次の段を作ります。`Menu.link_frame` がこの分け方を証明します。`Menu.Run.press` は、`stays` で途中で出る場合を除き、`left` で最後もタイトルにいる場合を除きます。

デモのあとの最初の範囲は、フレーム 1657 から 2123 です。押す前に Start も Select もない、元の `Run` を使います。非公開の証明を作るときに `windowAfter` が範囲を見つけます。`Start.later` がこれを使います。最初の 2 フレームと最初のデモ全体も、段の中です。

ROM の確かめは `TitleBoot.check`、`TitleBoot.Menu.check`、`TitleBoot.check (TitleBoot.later b)` で、全部 `TitleStart.check` の中です。道筋に仮定は増えません。`TitleBoot.Start.cond` と `TitleStart.Begin.press` が、4 つの場合で `Press` を与えます。

## 本物の走りで

元の組から選んだ 566 通りは、メニューの最初のフレームも含めて全部 `Press` を満たしました。TAS が出るのはフレーム 39 です。実行する確かめも、ゼロでないフラグを含む新しい `Press` を読みます。

最初の退出の組は、Select のない乱数入力、前に Start とほかのボタン、種から作った RAM の 3 組で、それぞれ 200 通りです。最初の退出 600 通りは全部 `Press` を満たし、反例はありません。TAS も通ります。デモ後の範囲では、種から作った RAM と Start も Select もない乱数入力の 100 通りも `Press` を満たします。

ネイティブの確かめは、元の範囲が約 3.2 秒、最初の退出の段が約 6.4 秒、デモ後の範囲が約 9.4 秒です。数秒より長い確かめです。走りの仮定は増やしません。元のタイトルから操作までの確認は 392 通りで、操作まで進んだ 339 通りに反例はありません。

## 証明していないこと

出る前の Select、証明した 2 つの範囲の外で出る走り、リセット、ゲームオーバーのあとのタイトルには、まだ状態の条件 `Start.press` を使います。ウォームブートで別のワールドが残ると `Press` は偽になり得ます。`Menu.Run` の最初の入力は、まだ Start と Select を除きます。

ファイルは `Theorems/TitleBoot.lean` と `Theorems/TitleStart.lean` です。再現は `smbrta title-boot-check FM2`、`smbrta title-menu-check FM2`、`smbrta title-check FM2` です。

Start を許したメニューの段をデモまで延ばすと、段 511 へつなぐ確かめが偽になり、その段にはタイトルの状態がありません。何度でもデモを繰り返す場合は証明していません。
