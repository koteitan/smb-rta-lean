# エリアの読み込みのループの、横のタイマーに届きうる書き込み

第 34 回は、フィールド `sideW` を、2 つのコードにある横の当たりのタイマーに届きうる書き込みでだけ求めました（[エリアの読み込みの外の、横のタイマーに届きうる書き込み](e-2-10-3-24-SideRange-ja.md)）。2 つのコードとは、エリアの読み込みのコードと、頭がブロックに当たるときのコードです。その書き込みは 29 ありました。ここでは同じ歩きに、細かい表と分けを 1 つ加えて、そのうち 4 つを除くすべてでこれを証明します。だからフィールドは、その 4 つでだけ求めます。

**主張（第 35 回）.** 次のように書きます。

```
s          = 横の当たりのタイマー、RAM の添え字として
SideW(m)   := m での添え字かポインタを通した書き込みは s を書かない
NearW(m)   := 第 33 回（ある添え字が元のアドレスを s に運ぶ、絶対アドレスに X か Y を足した書き込み、または STA (zp),Y）
Code(m)    := 第 34 回の Resid(m): AreaParserCore ≤ pc(m) < GetBlockBufferAddr、または PlayerHeadCollision ≤ pc(m) < BlockObjectsCore
Resid(m)   := （Code(m) で、m の命令が STA (zp),Y）              （ポインタを通した書き込み）
              または CRendLoop ≤ pc(m) < ChkCFloor                （城の行のループ）
```

`SideLoop.near_side`: `SideRange.near_side` の仮定を満たす操作中のフレームをとります（待ちのループで始まり、各命令は `FrameKeep.guardE` の `CleanK` を満たし、どの命令もルーチン、モード、タスクをアドレスで書かず、n₀ でプレーヤーのルーチンに来る）。すると、n₀ より後の最初の kq でスクロールの処理の呼び出しに来て、

```
フレームの中の ∀ j ≥ kq:  NearW(trace j) ∧ ¬Resid(trace j)  →  SideW(trace j)
```

`lCheck` が ROM の上の確かめです。公理: `propext`、`Classical.choice`、`Quot.sound`。ゲームのデータはありません: 城のループは 2 つの記号（`CRendLoop`、`ChkCFloor`。`tools/smb-symbols.txt` に新しく加えた）で、逆アセンブルから読みます。`0x91` は 6502 の `STA (zp),Y` の命令の番号です。

新しい場所は第 34 回の場所の一部です（`SideLoop.resid_old`、AreaParserCore ≤ CRendLoop と ChkCFloor ≤ GetBlockBufferAddr のもとで）。プログラムにはそのような書き込みが 4 つあります: エリアの読み込みのポインタを通した書き込み 1 つ、頭がブロックに当たるときの 2 つ、城のループのメタタイルのバッファへの書き込みです。第 34 回の場所でも求めた歩きは、そのうち 3 つで外れます。4 つ目の、ブロックの上を見るルーチンのポインタを通した書き込みは、そこに届く道では頭がブロックに当たるときのもう 1 つの書き込みのあとに来るので、道はその前で止まります。道がそこまで進むと、そこでも外れます: 第 34 回は第 34 回の歩きで、ここでは下に書く X の分けで（そこで 54 の外れ）。

**歩き.** 第 34 回の歩きです（`SideRange.walkR`: 表の状態での X と Y の範囲、添え字を数える命令の前の分け、届かない書き込みをこえるゼロページ）。変えたのは 2 つで、どちらも `Code` のコードの中だけです:

1. **表の鍵**（`keyL`）が、状態の知る X、Y、ゼロページの 0 番のバイトも持ちます。前は、ループの頭での状態が表の 1 つの状態にまとめられていました。すると、ゼロページにあるループの数えが知っているビットを失い、抽象のループが終わらず、添え字がすべての値に広がりました。今は、そのようなループの 1 回ずつがそれぞれ表の状態を持ちます。たとえば背景の景色のループで、ゼロページの 0 番のバイトで回数を数え、Y を通して書きます。
2. **`LDX abs,Y` の前の分け**（`spL`、`cov_spL`）: Y を、わからないビット 8 までなら、そのすべての値に分けます。すると、Y の値ごとに、読んだあとの X が分かります。これが要る読み込みは 2 つです: 階段の行（階段の制御、フレームをこえて残るバイトを添え字として表から読む）と、城の橋と鎖の行（ゼロページの 0 番のバイトを添え字として読む）。Y の 256 の値のどれでも、階段の表とそのあとのバイトは、タイマーに届く行を与えません。

鍵は歩きが証明するものの一部ではありません: 状態が表の状態で覆われるのは、知っているビットと範囲がそう言うときだけです（`SideRange.coverR`）。`okL_spec` は、新しい場所での `SideRange.okR_spec` の証明です。

**ルートでは.** `OnFrames` のフィールド `sideW` は、前提 `SideRange.Resid(trace n)` のかわりに `SideLoop.Resid(trace n)` を持ちます:

```
sideW : ∀ j, 1 ≤ j → j < g → side(seq j) ≠ t₁₆ →
          ∀ k n, arrAt ≤ k → k ≤ n → pc(trace k) = PlayerSubs → frame(trace n) = frame(fm j) → NearW(trace n) → Resid(trace n) → SideW(trace n)
```

`OnFrames.sideWAt`（第 33 回のフィールド）は、ほかの書き込みで `SideLoop.near_side` を使います。`numbersCheck` では、確かめ `SideRange.rCheck` を `SideLoop.lCheck` にかえました（`Numbers.rangeC`、`AreaRun.rg`）。フィールドが求めるものは少なくなりました: 同じフレームで、各フレームでは新しい `Resid` の 4 つの書き込みだけです（第 34 回: 29）。

**ここで証明していないこと.** `Resid` の書き込みでの `SideW`。そこで歩きが知らないのは、フレームをこえて残るバイトです:

- エリアの読み込みの、ブロックのバッファへのポインタを通した書き込み。ポインタの上のバイトは、`BlockBufferColumnPos ÷ 16` を添え字としてプログラムの表から読みます。添え字が 15 なら、読むバイトは、その鏡がタイマーを持つページで、下のバイトと Y の和の範囲はタイマーの場所に届きます。`BlockBufferColumnPos` < 240 なら書き込みはタイマーを外れます。プログラムがそのアドレスで書くところは、どれも 32 より小さく保ちます。
- 頭がブロックに当たるときの、ポインタを通した書き込み。その前の、`SprDataOffset_Ctrl` を添え字とするゼロページへの書き込み（`sta Block_State,x` と、`InitBlock_XY_Pos` でのブロックの位置とページ）が、歩きの知る限りでは、ポインタを書きえます。プログラムが `SprDataOffset_Ctrl` をそのアドレスで書くのは 1 か所だけで、ビット 0 を反転します（`eor #1`）。それらの書き込みの前で X をそのすべての値に分けることも試しました: すると歩きはもっと多くの場所で外れます（外れ 685、表の状態 344,988）。X = 0 と X = 1 の切れ端でも、歩きは書き込みのところでポインタの上のバイトのビット 3、5、6、7 しか知らず、ほかの切れ端では、歩きの知らないバイトを書き込みがポインタに書くからです。
- 城のループの書き込み。ループは、エリアのデータから読んだ行から行 10 までを書き、行が 11 になると止まります。始めの行が 11 以上なら、ループはページ全体を回り、タイマーに届きます（逆アセンブルは、ゲームが止まると書いています）。

これを証明するには、そのようなバイトの範囲をフレームからフレームへ保つ歩きが要ります。その最初の段を測りました: スクロールの処理のあと、この歩きの知る限りでは、6 つの場所の書き込みが `BlockBufferColumnPos` を書きえ（どれもブロックのバッファへのポインタを通した書き込み）、19 の場所の書き込みが `SprDataOffset_Ctrl` を書きえます。だから、そのような範囲には、まずほかの範囲が要ります。

**ラウンド 36.** ブロックのバッファの列と `SprDataOffset_Ctrl` がその範囲で始まり、添え字かポインタを通した書き込みがそれを書かないフレーム（`SideAcross.FactsAt`、パート f のフィールドが与える）では、4 つの書き込みも証明し（城のループは始めの行についての新しいフィールド `castleRow` で）、`sideW` はほかのフレームでだけ求めます（[フレームをまたいで残る 2 つのバイトと城の始めの行、横のタイマーに届きうる書き込み](e-2-10-3-26-SideAcross-ja.md)）。
