# 旗に触るフレーム: 1 フレーム全部

**主張.** 旗に触る本物のフレームでは、旗のルーチンを書く前の移動の終わりの位置は、旗の範囲の左端より左ではありません。証明は、触るフレーム全部を抽象機械で追います。NMI の前の待ちのループからフレームの終わりまでです。[横の土管に入るフレーム: 1 フレーム全部](c-7-16-SideFrame-ja.md) と同じやり方です。このフレームは走りのフレームの列（`PoleJoin.Run.keep`）のフレーム `g` です。ですからフレームの始まり（`StartK`）と各命令の条件（`CleanK`）は [操作中の 1 フレーム全部](f-6-19-FrameKeep-ja.md) から出ます。

ですから `PoleJoin.Run` の仮定 `pass` と `pos` はなくなりました。`fm` と `inp` もなくなりました。触るのは `keep` のフレーム `g` です。新しい仮定は、2 つの土管と同じ `moved` と `edge`、それと横の判定が読んだバイトの条件 `tiles` です。

`tr(j)` は触るフレームの `j` 命令あとの機械です。`fm g = all(ix g − 1)` から入力 `pad g` で動きます。`rt(m)` は `GameEngineSubroutine`、`e_f` は旗のルーチンです。`px(m) = 256·page(m) + x(m)` はピクセルの位置、`L = 3158` はピクセルでの旗の範囲の左端、`pg = 12` は旗のページ、`col` は旗の列です。`T_b`、`T_s` は旗の玉と棒のタイルです。`w_edge` は画面の端でのスクロール処理の位置の書き込み、`h` は頭がブロックに当たったときのルーチンです。

```
WriteStep(n)    :=  rt(tr(n)) ≠ e_f  ∧  rt(tr(n + 1)) = e_f
Touches         :=  ∃ n,  WriteStep(n)
SideRead(m)     :=  pc(m) = ブロックバッファのルーチンの読み込みの次の命令  ∧  ルーチンの番号は横の判定のもの
read(m)         :=  ポインタ + Y: 読み込みが読んだ RAM の場所
TileRead(m)     :=  SideRead(m)  ∧  A(m) ∈ {T_b, T_s}   →   read(m) は旗の列  ∧  pg ≤ page(m) + 1
HypT(m)         :=  (pc(m) = PlayerSubs → px(m) < L)  ∧  TileRead(m)  ∧  pc(m) ∉ {w_edge, h}
```

```
no_write_frame      :  frameCheck,  s(j + 1) = step(s(j)) (j ≤ n),  frame(s(j)) ≤ frame(s(0)),  FrameStart(s(0)),
                       ∀ j ≤ n,  CleanK(s(j)) ∧ HypT(s(j))                                   →   rt(s(n + 1)) ≠ e_f
touch_right_of_left :  poleFrameCheck,  Touches,  StartK(fm g),  ∀ j,  CleanK(tr(j)),
                       ∀ n,  WriteStep(n) → ∀ j ≤ n,  TileRead(tr(j)) ∧ pc(tr(j)) ∉ {w_edge, h}
                       →   ∃ n j,  WriteStep(n) ∧ j ≤ n ∧ pc(tr(j)) = PlayerSubs ∧ L ≤ px(tr(j))
inRange_of_frame    :  同じ仮定,  ∀ n j,  WriteStep(n) → j ≤ n → pc(tr(j)) = PlayerSubs → P = posP(tr(j))     →   P₀ ≤ P
Run.inRange         :  poleFrameCheck,  Run,  Start(seq 0),  fracCheck,  keepCheck,  AtCtl(seq 0)   →   P₀ ≤ P₂(g)
pole_frame_check（非公開） :  poleFrameCheck(sy, m₀) = true（native_decide）
```

`P₀ = 256·L` は `poleP` です。`posP(m) = 256·px(m) + 端数` です。`Run.inRange` は、フレームの始まりを `FrameKeep.Frames.start` から、`CleanK` を `keep.clean`（`Frames.cleanAt`）から取ります。ROM のない定理が使う公理は `propext`、`Classical.choice`、`Quot.sound` だけです。

## しくみ

**1 歩.** 抽象機械は `FrameKeep` のもの（`kstep`、`preK`）です。`PipeWrites` の 1 歩に、移動のルーチンの端数の書き込みと、下位ビットの足し算を加えたものです。ですから 1 命令の条件は `CleanK` です。`keep.clean` が、触るまでのどのフレームにもこれを仮定しています。ガードは `FrameKeep` のもの（`guardK`）で、ルーチンだけ旗のものにします。

**4 つの場所で分けます.** どれも機械の変更ではありません。状態を部分に分けるだけです。

* **移動の終わり（`PlayerSubs`）.** `px < L` のもとで、位置を 8 つの部分に分けます。ページが `{0, …, 7}`、`{8, 9}`、`{10}`（旗のページより 2 つ以上前、ピクセルはわからない）。ページ 11（ピクセルはわからない）。ページ 12 でピクセルが `[0, 63]`、`[64, 79]`、`[80, 83]`、`[84, 85]`。この位置を、スクロール処理、当たり判定の箱、頭と足の判定を通して覚えておきます。
* **旗に近い横の判定の足し算.** ページが 11 か 12 かもしれないとき、ピクセルを値ごとに分けます。これで読む列とブロックバッファがわかります。
* **旗に近い横の判定の高さのマスク.** 高さと足し算の値の和の上位ビットで分けます。これで読む行がわかります。
* **横の判定の読み込みのあと.** ページが 10 以下か、読んだ場所がわかっていて旗の列でないなら、`TileRead` から、読んだバイトは旗のタイルではありません。このバイトを、`T_b` と `T_s` が同じ値のビットで `T_b` と違う部分に分けます（`PoleEntryRule.tilesCover`）。

**旗の列を読むとき.** ページ 12 で右側が旗の列に届くのは、ピクセルが 83、84、85 のときだけです。読んだバイトはわかりません。でもピクセルの下位 4 ビットは 3、4、5 で、6 より小さいです。ですから、のぼる処理（`HandleClimbing`）は旗のタイルとの比べる前に抜けます。ページ 11 では、横の判定は旗の列を読みません。

**ルーチンのバイトは旗のものになりません.** 歩きは、フレームの終わりまでどの状態でも、ルーチンのバイトが `e_f` でないとわかっていることを確かめます。

**`TilesOK` でなく `TileRead` にした理由.** 前の仮定 `TilesOK` はブロックバッファのバイトについての条件でした。高さ `0xD8` 以上の小さいマリオは、横の判定で 13 行目を読みます。奇数のページでは、それは 2 つ目のブロックバッファの終わりより後ろで、描いている列のバッファの中です。そこには旗のタイルが入ることがあります。前の `Pass` は `RowOK` でこれを除いていました。`TileRead` は、横の判定が読んだバイトだけについての条件です。場所はどこでもかまいません。本物のフレームでは、ブロックバッファの外を読んだ横の判定はありませんでした（下）。

**大きさ.** 8,075,357 歩、分かれ 833,579（部分を含む）、失敗 0、表 326,976。探すのに 19 秒、確かめるのにプログラムで 42 秒です。`Proof.PoleFrame` のビルドは 44 秒です。`SideEntryRule` の部分で作った最初の版は 791,304 回失敗しました。旗の 2 つのタイルは 1 ビットだけ違います。そのビットの部分が棒のタイルを含んでいました。

## 本物のフレームで

プログラム（`pole-frame-check FM2 1200`、終了コード 0、bad 0）。[旗に触るフレームを本物のフレームで](f-6-1-PoleEntryRule-ja.md) の走りと、ムービーのフレーム 1002 から 1091 からのランダムな入力です。

| 走り | フレーム | 横の判定の読み込み | 触る |
|---|---|---|---|
| ムービー、最初の操作のあとフレーム 1 から 1239 | 1,239 | 2,797 | 1 |
| ムービーのフレーム 1089 まで、そのあと `02808080` | 20 | 13 | 1 |
| ムービーの 2 つのフレームから、左右 A B の全部の入力を 6 フレーム | 12,912 | 29,872 | 48 |
| 同じく 5 フレーム、位置を 5 通り前に動かして | 4,688 | 16,960 | 2,873 |
| 旗に向かうランダムな入力 | 10,940 | 40,619 | 87 |
| 同じ、大きいマリオに書き換えて | 3,778 | 14,044 | 30 |
| ムービーの 22 のフレームから 7 通りの長さのジャンプ | 10,192 | 37,824 | 14 |
| 旗の列の近くの高さと位置ごとに 1 フレーム（書き換え） | 6,864 | 17,301 | 936 |
| ムービーのフレーム 1002 から 1091 からのランダムな入力（1,200 回） | 137,055 | 521,670 | 675 |

* 操作中のどのフレームも `StartK` を満たします。どの命令も `CleanK` を満たします。横の判定のどの読み込みも `TileRead` を満たします。ブロックバッファの外を読んだ横の判定はありません。
* 触るどのフレーム（4,665）でも、書き込みの前に切った場所に来ません。書き込みの前に `PlayerSubs` に 1 回だけ来ます。そこでの位置は `L` より左ではありません（3158 から 3161、3174 から 3177）。そこでの位置は、フレームの始まりの位置をそこでの速さで動かしたものです（`P₂ = P + 16·v₂`、`moved`）。
* 切った場所に来るフレームは 1,361 です。どれも触る書き込みより前ではありません。

## 仮定（Lean では証明していないもの）

* **`tiles`**: 書き込みまで `TileRead`。旗の列をブロックバッファに描くコードは追っていません。
* **`edge`**: 書き込みまで `w_edge` にも `h` にも来ない。2 つの土管と同じです。
* **`moved`**: `P₂(g)` は書き込みの前の `PlayerSubs` での `posP`。本物のフレームからフレームのモデルを作ることの一部です。2 つの土管と同じです。
* `touches` と、`keep` のフレーム（それ自身の仮定）。

使うのは範囲の左端だけです。高さは読む行を決めますが、高さの範囲は出していません。

**ファイル.** `Theorems/PoleFrame.lean`、`Theorems/PoleJoin.lean` の `Run`、非公開の `Proof/PoleFrame.lean`（`pole_frame_check`）。

.lake/build/bin/smbrta pole-frame-search          # 歩きを探して確かめる（約 1 分）
