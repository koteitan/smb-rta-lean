# 城に入ったあとのポーズ

**主張.** 城に入ったあとは、Start も含めてどんな入力でも星の旗の規則が成り立ちます。ポーズで終わるフレームはカウンタを変えず、そのあとも条件 `Good` が成り立ちます。これで `Route.Run` のフィールド `flag.noStart`（城に入ってからレベルが変わるまで Start を押さない）がなくなりました。証明は [城に入ったあとの星の旗の規則](g-2-1-FlagRule-ja.md) の ROM の確認で、城に入ったときの同じ条件 `Good` のもとです。

## ゲームがすること

各フレームで、フレームの処理は音を鳴らし、パッドを読み、それからポーズの処理をします。ゲームコアでは、ポーズの処理は次のように動きます。

* Start を押したあと、処理はいくつかのフレームを待ちます。そのあいだ Start は何もしません。
* そのあと Start を押すと（前のフレームから押し続けていなければ）、`GamePauseStatus` のビット 0 が反転し、ポーズの音を頼みます。
* ビット 0 が 1 のとき、そのフレームはタイマーとモードのルーチンを飛ばします。`SkipMainOper` へ行き、フレームの終わりへ行きます。星の旗のカウンタには触れません。

ポーズの音は音のエンジンを占めます。`PauseModeFlag` が 0 でないあいだ、エンジンはポーズの音だけを鳴らし、効果音と音楽を飛ばします。`MusicHandler` を通らずに `SkipSoundSubroutines` へ行きます。ゲームが動き出したあとも、しばらく `PauseModeFlag` は 0 になりません。

## 文

```
paused(m)  =  (m[GamePauseStatus] &&& 1 ≠ 0)

Good(m)  →  paused(frame(m, i))  →  x(frame(m, i)) = x(m)  ∧  Good(frame(m, i))            frame_step（どの i でも）

lag(n)  =  E < n  ∧  (task(x(n)) = 5  ∨  paused(seq(n + 1)))                               flagOf_after
```

`x(m)` は星の旗のカウンタ、`Good` は [城に入ったあとの星の旗の規則](g-2-1-FlagRule-ja.md) の条件です。`lag` のフレームはレベルの変化を遅らせるだけです。`Flag.hL` はどの `lag` でも成り立ちます。

## 確認がポーズをどう扱うか

* パッドは何でもかまいません（`AB.top`）。前は Start のビットが 0 と知っていました。
* `B₀` はポーズのバイトを一部だけ知っています。`GamePauseStatus` は 0、1、0x80、0x81 のどれか、`PauseModeFlag` と `PauseSoundQueue` は 3 以下、`GamePauseTimer` は何でもかまいません。
* `GamePauseStatus` はビット 0 と 7 で分けて読みます（`Env.splits`）。読むと状態は 4 つの値に分かれます。
* 探索は `GamePauseStatus` を分けたままにします。こうしないと、探索はビットで分かれる前にポーズの状態とポーズでない状態を合わせました。すると歩きはビットを知らずに両方へ進み、ポーズのフレームでゲームコアへ入る道ができました（パッドの段で 34687 の失敗）。
* 2 つの段は 2 つ目の終わりの場所を持ちます。機械は、その段の場所のうち最初に来たところで段を終えます（`Arr`、`Next` は場所のリストを取ります）。そこから始まる段は `nextIdx(j, pc)` です。

```
0 → 1 → 2 → 3 → 4 → … → 12 → 13 → フレームの終わり、ビット 0 は 0 と知っている
    1 → 14 → 3                          ポーズの音: 段 1 は SkipSoundSubroutines で終わる
             3 → 15 → フレームの終わり、ビット 0 は 1 と知っている    ポーズのフレーム: 段 3 は SkipMainOper で終わる
```

* 段 14 は `SkipSoundSubroutines` から `ReadJoypads` まで、段 15 は `SkipMainOper` からフレームの終わりまでです。どちらでも、規則の 15 バイトを保ちます（`KeepP`、`EndKeepP`）。ほかの段と同じです。
* 段 13 の終わりはビット 0 が 0 と知っていて、段 15 の終わりは 1 と知っています（`EndCoverP`、`bit0_of`）。なので、`lag` のフレームはちょうど段 15 を通ったフレームです。

## 遅すぎた案

前の回の案は、音を `SoundEngine` から `SkipSoundSubroutines` までの 1 つの段にまとめるものでした。確認は通りましたが、まとめた段は 55 秒かかりました。「保つ」の歩き 1 本が 0.48 秒です。効果音から音楽へ入る道ごとに、四角波 1 の位置を 256 の値に分けることを約 21 回しました。その歩きが 45 本あります。`SkipSoundSubroutines` を 2 つ目の場所にして音楽の段を分けたままにすると、新しい 2 つの段は 3 ミリ秒と 2 ミリ秒です。

## 測ったこと

`B₀` は前と同じ 240 個です。変更の前、確認は 34 秒でした。変更のあと、ほかの作業者が 5 人同時にビルドしているとき（28 コアで負荷平均 15〜20）、2 回で 56 秒と 61 秒でした。このとき、変えていない、ほかのスロットの段は前の 1.6 倍と 1.9 倍（26.6 秒と 30.8 秒、前は 16.3 秒）でした。この倍率で割ると確認は 33〜35 秒で、前と同じです。

## 本物のフレーム

`flag-rule-check` は、ポーズを入れた TAS と、Start をよく押す走りを動かします。最初の処理 5 のフレームまでの全部のフレームで機械は `Good` にあり、ポーズで終わるフレームはカウンタを保ち、ほかのフレームは `FlagRun` に従います。

```
走り                                  L       Start  ポーズ  Good でない  規則に合わない
TAS、E + 60 から 80 フレームのポーズ    1828    2      80      0           0
TAS、E + 1 から 99 フレームのポーズ     1847    2      99      0           0
TAS、処理 4 でのポーズ                1808    2      60      0           0
TAS、最後のフレームでのポーズ          1803    2      55      0           0
TAS、44 フレームごとに Start           2276    24     528     0           0
TAS、E + 30 から Start を押し続ける     -       50     3970    0           0
TAS、Start もある乱数 2 通り           -       2000   2014    0           0
基準 r、50 フレームごとに Start         E+2749  54     1350    0           0
```

全部の表は [城に入ったあとの星の旗の規則](g-2-1-FlagRule-ja.md) にあります。`-` は、動かした 4000 フレームの終わりまでポーズのままです。

## 証明していないこと

* 城に入ったときの `Good(seq(E + 1))`、処理 2、旗の高さは仮定のままです（1-1-g-2-2）。
* 城に入る前のポーズはここでは扱いません（切り替えのフィールド `noStart₁`、`noStart₂` と、タイトル）。
