# 画面端での位置

`ScreenClamp.clamp_return` は、本物の機械で `KeepOnscr` の補正を、呼び出し元に戻るまで証明します。前提は `Good`、ROM の検査、入口のプログラムカウンタ、Y が 2 種類の画面端のどちらかを選ぶことです。最初のスタックポインタとフラグは任意です。

R を入口、B を戻った機械とします。T は、選んだ現在の画面端から ROM の量を引き、元の位置の端数を付けた値です。表とそのバイトは ROM の検査の引数です。

```
k ≤ 37
pc(B) = returnPc(R)
SP(B) = SP(R) + 2
fraction(B) = fraction(R)
P(B) ≡ T  (mod 2²⁴)
```

`exact_target` は、0 ≤ T < 2²⁴ のとき P(B) = T を与えます。これは入口の機械に対する明示した範囲の条件です。画面端がプレイヤーの近くにあることは仮定していません。

`pieceY_spec` は、画面端の選択が既知で、スタックポインタが任意で変化しない命令の区間を証明します。検査はスタックの全バイトを追います。ピクセルは 512 通り、ページと繰り下がりは 1,024 通り、末尾は 2 通りです。引き算と繰り下がりは計算で証明し、呼び出し元への復帰は元のスタックのバイトで証明します。

## 残ること

画面端の補正は、1 ピクセルより大きく動くことがあります。この局所的な結果だけでは `SurfaceFrames.CollideS` や `AfterP` は出ません。現在の画面端とフレーム開始時の位置の関係、補正を呼ぶ分岐、そのあとのほかの位置変更をつなぐ必要があります。全体のフィールドを、新しい前提で置き換えてはいません。

**ファイル:** `Theorems/ScreenClamp.lean`、非公開の `Proof/ImpedePosition.lean`。

## 実データでの検査

`pos-after-real FM2 200` は TAS と自作の入力で 128,679 フレームを検査しました。押し戻しは 3,053 回、画面端の補正は 13,551 回です。入口の `Good`、復帰、速さ、端数、位置の合同式、余白と補正先の範囲の失敗は 0 回でした。スクロール処理のあと、二つの処理の外で位置に書く命令も 0 回でした。実行は終了コード 0 です。対象は、操作できる状態で始まり、ルーチン・モード・タスクに書かないフレームです。これは実行例の検査であり、全フレームについての証明ではありません。

ROM の検査は、押し戻しが 430 ms、画面端の補正が 6 ms で、ともに真でした。二つの非公開の事実は `native_decide` で生成します。実データで見た補正は一方の画面端だけで、ROM の検査と一般定理は両方を扱います。

[PositionPieces](e-2-10-3-5-PositionPieces-ja.md) は、補正の復帰までの正確な効果と、最後の補正先に後続の押し戻しを足す形を出します。補正先がフレームの始まりの位置以下という強い上限は、実際の走りで偽でした。1 ピクセルの余裕と、その後の呼び出しへの接続には証明が必要です。
