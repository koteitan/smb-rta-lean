# 縦の土管に入るフレームを本物のフレームで

**主張.** これは部分的な結果です。「入る」を本物の機械の上で定義します。あるフレームが入るなら、そのフレームの足の判定が右足のブロックを読みにいくとき、マリオの位置は土管の範囲の左端より左ではありません。証明は足の判定の 1 回の通過を抽象機械で追います。フレームの残りは追いません。残りは仮定 `Pass` と `pos` です。

`Route` はこのページの `Pass` を使いません。[1 フレーム全部を追う定理](a-5-2-PipeWrites-ja.md) を使います。

名前は [縦の土管に入る](a-4-PipeEntry-ja.md) と同じです。`frame(m, i)` は入力 `i` の本物の 1 フレームです。`tr(n)` は、そのフレームの `n` 命令あとの機械です。`rt(m)` は `GameEngineSubroutine` です。`e_v` は土管のルーチンの番号です。`page(m)` は `Player_PageLoc`、`x(m)` は `Player_X_Position` です。`w` は `HandlePipeEntry` の中で `rt` を書く命令です。`T_R` は土管の右のタイル、`d_R` はそのブロックバッファの場所です。

```
Enters(m, i)    :=  rt(m) ≠ e_v  ∧  rt(frame(m, i)) = e_v
WriteStep(n)    :=  rt(tr(n)) ≠ e_v  ∧  rt(tr(n + 1)) = e_v
px(m)           :=  256·page(m) + x(m)
L_px            :=  256·pg + x_lo

Start(m)        :=  pc(m) = DoFootCheck、スタックポインタは決まった値、足の加算の番号のバイトは大きいマリオか小さいマリオの値、
                    ドットは vblank が終わったあとでフレームの終わりより前、NMI も vblank もなし、ストローブなし
AtEntry(m)      :=  pc(m) = BlockBufferCollision  ∧  レジスタ Y は右足の番号
AtRead(m)       :=  pc(m) = このルーチンの `LDA (zp),Y`  ∧  保存した Y は右足の番号
RowOK(m)        :=  Y mod 16 = 0  ∧  Y < 16·R  （R はブロックバッファの行の数）
TilesOK(m)      :=  page(m) ≤ pg  →  ∀ ブロックバッファの場所 d,  mem(d) = T_R  →  d = d_R  ∧  pg ≤ page(m) + 1
Pass(n)         :=  pc(tr(n)) = w  ∧  ∃ n₀ ≤ n,  Start(tr(n₀))
                    ∧  (∀ j ∈ [n₀, n],  pc(tr(j)) ∉ {DoPlayerSideCheck, AwardTouchedCoin, HandleAxeMetatile, ImpedePlayerMove})
                    ∧  (∀ j ∈ [n₀, n),  AtRead(tr(j))  →  RowOK(tr(j)) ∧ TilesOK(tr(j)))
```

```
no_write            :  ruleCheck,  s(j + 1) = step(s(j)) (j < n),  Start(s(0)),
                       (∀ j < n,  AtEntry(s(j)) → px(s(j)) < L_px),  (∀ j < n,  AtRead(s(j)) → RowOK ∧ TilesOK),
                       出口に行かない (j ≤ n)                                  →  pc(s(n)) ≠ w
entry_right_of_left :  ruleCheck,  Enters(m, i),  (∀ n,  WriteStep(n) → Pass(n))
                       →  ∃ n j,  WriteStep(n) ∧ j < n ∧ AtEntry(tr(j)) ∧ L_px ≤ px(tr(j))
rule_on_frames      :  ruleCheck,  ∀ t,  Enters(fm t, inp t) → (∀ n, WriteStep(n) → Pass(n)),
                       (P₂(t) は右足のときの位置: P₂(t) = 256·px(tr(j)) + f,  0 ≤ f)
                       →  ∀ t,  Enters(fm t, inp t)  →  L ≤ P₂(t)
pipe_rule_check（非公開）    :  ruleCheck(sy, m₀) = true（native_decide）
```

`L = 256·L_px` は [縦の土管に入る](a-4-PipeEntry-ja.md) の `windowP` です。ROM のない定理が使う公理は `propext`、`Classical.choice`、`Quot.sound` だけです。

Lean: `Theorems/PipeEntryRule.lean`、非公開の `Proof/PipeEntryRule.lean`（`pipe_rule_check`、`pipe_rule_real`）。`Route` が使う `pipe_no_entry_real` は [1 フレーム全部](a-5-2-PipeWrites-ja.md) と [土管までのフレームを機械から読む](a-5-5-PipeFrames-ja.md) にあります。

## しくみ

**抽象機械.** [地上への切り替えのはじめのフレーム](d-2-2-SideChangeBound-ja.md) の機械です。`Start` の状態から始めます。わかっているのはスタックポインタと足の加算の番号だけです。ほかの RAM、レジスタ、位置、速さ、ブロックバッファは全部わかりません。パッドもわかりません。

**4 つの場所で分けます.** どれも機械の変更ではありません。歩くときに状態を部分に分けるだけです（`preR`）。

* 右足で `BlockBufferCollision` に入るとき: 仮定 `px < L_px` のもとで、位置の値ごとに分けます。ページの数は高々 `pg + 1` です。これでポインタの値がわかります。
* 左足の読み: ポインタの 8 ビットで分けます。読んだ値はわかりません。
* 右足の読み: `RowOK` で行の値に分け、`TilesOK` で「読むバイトは `T_R` のあるビットと違う」という形に分けます。分ける前に、どの行も場所 `d_R` でないこと、または `T_R` がまだそこにないことを確かめます（`safe`）。
* 同じポインタの状態はそのあと 1 つにまとめます（表）。

**読んだ値のその後.** 読んだバイトのわかっているビットは一時的なバイトに入ります。`HandlePipeEntry` の `CMP` がそのビットを見て、等しくないとわかります。ですから `w` に行く道はありません。全部の道が、出口に行くか、表の状態に入ります（`walkR`）。

**大きさ.** 46,751 ステップ、17,580 の枝分かれ、失敗 0、表 493。プログラムで 1 秒台、非公開の証明のビルドで約 3 秒です。

## 1 フレーム全部を追うとどうなるか（測定）

プログラムで測りました。定理ではありません。フレームは TAS の、土管に入る直前のフレームです。敵は 1 つです。「まとめない」は、マリオのバイトをまとめない探索です。「ポインタを分ける」は、ブロックバッファの読みでポインタの 8 ビットに分けることです。

| わからないもの | ステップ | 枝分かれ | 失敗 | 最初の失敗 |
|---|---|---|---|---|
| パッドだけ。まとめない | 484,361 | 29,913 | 179 | `GetBlankPal`（時間がフレームの終わりに届く） |
| パッドだけ | 7,009 | 210 | 4 | `BlockBufferCollision` |
| パッドだけ。ポインタを分ける | 233,976 | 34,284 | 160 | `DBlockSte` |
| `x`、`y`、2 つの速さ。敵のフラグは 0 | 198,605 | 20,729 | 144 | `BlockBufferCollision` |
| 同じ。ポインタを分ける | 513,200 | 75,456 | 316 | `DBlockSte` |
| マリオの 31 バイト。敵のフラグは 0 | 101,641 | 10,425 | 110 | `JumpEngine` |
| 同じ。ポインタを分ける | 376,546 | 51,237 | 272 | `JumpEngine` |
| `x`、`y`、2 つの速さ。枠の敵は本物の値。ポインタを分ける | 284,659 | 44,884 | 158 | `DBlockSte` |
| マリオの 31 バイト。枠の敵は本物の値。ポインタを分ける | 198,583 | 27,583 | 186 | `JumpEngine` |
| 同じ。敵の 56 バイトもわからない（フラグと ID は本物） | 84,843 | 16,095 | 156 | `JumpEngine` |
| 音のバイト 35 個 | 1,857,523 | 4,656 | 650 | `HandleSquare2Music` |
| 画面のバッファ | 34 | 0 | 1 | `UpdateScreen` |

ですから、この表の機械では 1 フレーム全部は閉じません。失敗の場所は次のとおりです。ここに足りないものを条件にして足すと閉じます（[次のページ](a-5-2-PipeWrites-ja.md)）。

* わからないポインタを通す読み: `BlockBufferCollision`、`DBlockSte`、`HandleSquare2Music`、`UpdateScreen`。
* わからないポインタを通す書き込み: `ErACM`。
* `Player_State` がわからないときの間接ジャンプ: `JumpEngine`。
* マリオのバイトをまとめないと、時間がフレームの終わりに届きます: `GetBlankPal`。
* 位置がわからないと、面の読み込みが枝分かれします。`ProcessEnemyData` の 1 つの分岐で 2,632 回です。

音のバイトと画面のバッファはフレームごとに変わるので、1 つの値に固定できません（コードから読みました）。

逆に、フレームの一部分は小さいです。この定理の通過は上のとおりです。`PlayerCtrlRoutine` から `PlayerBGCollision` までは、4 バイトだけ知っていて 1,804 ステップです（失敗 8 個は `UseAdder` で、始めの X がわからないまま添字で書くためです）。パート a、c、e、f の 1 フレームの事実は、フレーム全部ではなく、名前のある場所から名前のある場所までの部分で進めるのがよさそうです。

**書き込みの候補（コードから数えました。証明ではありません）.** `rt` を直接書く命令は 12 個で、`e_v` を書くのは `w` だけです。ゼロページの添字つきの書き込みは 338 個です。`(zp),Y` の書き込みは 9 個です。ですから項目 1-1-a-5-2 を証明するには、この 347 個の添字とポインタの範囲が要ります。

## 本物のフレームで確かめたこと

プログラムです（`pipe-rule-check`）。

| 走り | フレーム | 足の判定（操作） | 入ったフレーム |
|---|---|---|---|
| TAS の入るまで | 368 | 368 | 1 |
| TAS の入ったあと | 1,300 | 347 | 0 |
| 入る前の状態から歩いて下 | 5,480 | 5,480 | 161 |
| 入る前の状態から跳んで、下を押して着地（大きいマリオに書き換えたものを含む） | 25,308 | 24,161 | 14 |
| 入る前の状態から乱数の入力 | 26,855 | 26,143 | 1 |
| 同じ。大きいマリオに書き換え | 9,000 | 8,457 | 0 |

* どの行でも、操作のフレームの足の判定はすべて `Start` を満たします。すべての右足の読みは `RowOK` と `TilesOK` を満たします。
* 入った 177 フレームは全部 `w` で書き、全部 1 回の通過の終わりです。位置は範囲の 9 個の値全部に出ます。範囲の外はありません。足の判定のあとで位置は変わりません。

## 前提（Lean では証明していない）

* **`Pass` の書き込みの部分（[1 フレーム全部](a-5-2-PipeWrites-ja.md) では条件 `FrameStart`、`Clean` になります）.** `rt` を `e_v` にする命令は `w` だけ。そのフレームの中で、それより前に足の判定を始めている。そこから出口に行っていない。コードから読みました。上の表の本物のフレームで確かめました。フレームの残り（NMI、音、画面、敵）は追っていません。
* **`Start`.** スタックポインタ、足の加算の番号、ドット、フラグです。水の中の大きいマリオの値も入れました。
* **`RowOK`.** コードの `AND`、`SBC`、`TAY` と、足の判定の始めの `CMP` から読みました。このページでは仮定です。[1 フレーム全部](a-5-2-PipeWrites-ja.md) では仮定しません。
* **`TilesOK`（項目 1-1-a-5-3）.** 手で書いたブロックバッファと同じ、という前提より狭くなりました。右のタイルについてだけです。ページの条件は、2 つ前のページ（偶奇が同じ）にいるあいだは土管の列がまだバッファにないことです。
* **`pos`.** `P₂` は右足の読みに入るときの位置です。本物のフレームから `Frame` を作る話（項目 0-0-0-3-1）の一部です。
* **範囲の右端と、`rule` の残り.** ここでは左端だけを出します。`Route` が使うのは左端だけで、`Route.Pipe` は `rule` のかわりに `start`、`clean`、`tiles`、`edge`、`moved` を持ちます。右端、下ボタン、着地は [縦の土管に入る](a-4-PipeEntry-ja.md) の `rule` のままで、手で書いたバッファの上の話です。

**ファイル.** `Theorems/PipeEntryRule.lean`、非公開の `Proof/PipeEntryRule.lean`。

**再現.**

