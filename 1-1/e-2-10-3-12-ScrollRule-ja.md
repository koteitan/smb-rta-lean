# スクロールの規則

**主張（第 25 回）.** スクロールの処理（プレイヤーのルーチンの終わり `PlayerSubs` の最初の呼び出し）の入口にある本物の機械 R を、`Good` とともにとります。するとフレームの中のいくつかのステップのあと、それは画面の端の補正の呼び出し（`ChkPOffscr`）にあり、次が成り立ちます:

```
s(R') = s(R)                                     スタック
位置のピクセル、ページ、端数: 変わらない
left16(R') = left16(R)
  ∨ ( Allows(R) ∧ ∃ Y, Y ≤ X(R) ∧ left16(R') = (left16(R) + Y) mod 2¹⁶ )

left16(m)  = 画面の左端の 256·ページ + ピクセル。補正の 2 つのオペランドで読む（ScreenClamp.places）
X(m)       = スクロールの量のバイト + 足場がスクロールに加える力、バイトとして（amountOf）
Allows(m)  = スクロールの止め = 0 ∧ 画面の上の彼の場所 ≥ thr1 ∧ 横の当たりのタイマー = 0 ∧ 1 ≤ X(m) ≤ 128
thr1       = コードの彼の場所の 1 つ目の確かめのしきい値（プログラムから読む。80 px）
```

これは `ScrollRule.scroll_rule` です（公理は `propext`、`Classical.choice`、`Quot.sound`）。ROM の確認 `ScrollRule.check` を仮定に持ちます。スタックのすぐ上の 2 つのバイト（戻り先）も保ちます。

**呼び出し全体.** 呼び出し（`PlayerSubs`、`Good` とともに）にある本物の機械 Q から、呼び出しの次の命令（`PlayerSubs + 3`）まで、値はすべて Q で読みます（`scroll_call`、`scroll_edge`）:

```
s(R') = s(Q)
edge(R') = edge(Q)  ∨  ( Allows(Q) ∧ ∃ Y, Y ≤ X(Q) ∧ edge(R') ≤ edge(Q) + 256·Y )        edge = SurfaceRead.edgeOf = 256·left16 + 255（edgeOf_left16）
```

スクロールのあと、画面の端の補正と画面の外のビットのルーチンは端の 2 つのバイトを書かず、スクロールの処理は戻ります。非公開の証明がそれを確かめます（`scroll_rule_check`、`genScrollRule` が作る。ファイルの読み込みを入れて native で約 3 秒）。

言葉で: スクロールは左端を多くてスクロールの量だけ動かし、4 つのバイトが許すときだけ動かします。補正の前に、ほかのものが端や位置を動かすことはありません。量はフレームの動きの整数ピクセル（動きのルーチンが書く）に、足場の力を足したものです。

**証明.** [補正](e-2-10-3-4-ScreenClamp-ja.md)と同じく、ROM のコードを区切って確かめます。番地はプログラムから来ます: スクロールの処理は `PlayerSubs` の呼び出しの行き先で、その読み込み（`LDA`、`LDY` の絶対番地）、分かれ道、最後のジャンプが区切りとバイトを与えます（`ScrollRule.places`）。端の 2 つのバイトは補正のオペランドです。それぞれの区間で、確認は分かれ道が読むバイトのすべての値でコードを歩きます:

| 区間 | から | まで | 分かっている値 |
|---|---|---|---|
| `amountCheck` | 入口 | スクロールの止めの読み込み | 量のバイトと足場の力（65,536 組）: 量はその和 |
| `lockCheck` | スクロールの止めの読み込み | 画面の上の彼の場所、またはスクロールなし | スクロールの止め（256） |
| `pfsCheck` | 画面の上の彼の場所 | タイマー、またはスクロールなし | 彼の場所（256）: `thr1` 以上 |
| `sideCheck` | タイマー | 量、またはスクロールなし | タイマー（256） |
| `ldyCheck` | 量 | 彼の場所の 2 つ目の確かめ（Y が分かっている）、またはスクロールなし | 量（256）: `1 ≤ X ≤ 128`（1 を引いて負にならない）。Y = X、または X − 1（コードの量の確かめによる） |
| `nearCheck` | 彼の場所の 2 つ目の確かめ | スクロール、または量のもう一度の読み込み | Y と彼の場所（65,536） |
| `ldy2Check` | 量のもう一度の読み込み | スクロール（Y = X） | 量（256） |
| `scrCheck` | スクロール | 端のページの読み込み | Y と端のピクセル（65,536）: ピクセル + Y と繰り上がり |
| `pgCheck` | 端のページの読み込み | 補正の呼び出し | スタックのバイト、ページ、繰り上がり（131,072）: ページ + 繰り上がり。画面の右端を決める呼び出しは戻る |
| `initCheck` | スクロールなし | 補正の呼び出し | なし |
| `jsrCheck` | `PlayerSubs` の呼び出し | スクロールの処理の入口 | スタックのバイト（256）: スタックの上の戻り先 |
| `tailCheck` | 補正の呼び出し | 呼び出しの次の命令 | スタックのバイト（256）と戻り先: 端の 2 つのバイトは書かれない |

どの区間もスタックを保ち（`pgCheck` の中の呼び出しは戻る）、位置の 3 つのバイトを書きません。スクロールの前の区間は端のバイトを書かず、あとの区間は端のもう一方のバイトを保ちます。`scroll_rule` はそれらをつなぎ（`Seg`、`Seg.trans`）、ピクセルとページを繰り上がりとともに足します（`left_add`）。`scroll_call` は呼び出しとスクロールの処理の残りを足します。`Y ≤ X` は `xOK_range` と `dec_toNat` です。しきい値と量の確かめの定数はプログラムから読み（`Places.thr1`、`thr2`、`two`）、ファイルには書きません。なので式の中で `Y` は 0 でもよい（そのとき端は動かない）。

**ここで証明していないこと.** これはフィールド `edge` を証明しません（[1-1-e-2-10-3-11](e-2-10-3-11-EdgeStart-ja.md)）。そのためにはさらに 3 つが要ります: 端の 2 つのバイトがフレームの始めから呼び出しまで、そして呼び出しの次の命令からフレームの終わりまで保たれること（2 つのバイトを追う、フレーム全体の歩き）。スクロールが許されるのは彼が端から十分右にいるときだけであること（画面の上の彼の場所は前のフレームで書かれるので、これは 2 つのフレームの関係）。`scroll_rule` はまだルートで使っていません。フィールドは変わりません。

**測ったこと**（`edge-real FM2 256`、第 25 回。表は [1-1-e-2-10-3-11](e-2-10-3-11-EdgeStart-ja.md)）: 端が 1 フレームに動いたのは多くて 3 px で、そのフレームの彼の動きより多く動いたことはありません。端が動いた 11,289 フレーム（137,955 のうち）では、スクロールの処理で彼は端より少なくとも 81 px 右に、フレームの終わりで少なくとも 79 px 右にいました。
