# ポーズで終わるフレームはモードのルーチンを呼ばない

**主張.** アイドルループで操作できる状態で始まり、モードのルーチンを呼ぶフレームは、ポーズのバイトの最下位ビットが 0 で終わります。なので、ポーズで終わるフレームは
ルーチンを呼びません。ただし、フレームの各命令が `Clean` で、添字やポインタを通る書き込みでポーズのバイトを書かないときです。縦の土管まで、数えないフレームは
ポーズで終わります（新しいフィールド `lags.paused`）。なのでルーチンを呼ばず、[土管までの数えないフレーム](a-5-5-3-LagFrames-ja.md) の確認により、速さ、端数、位置を変えず、
操作できる状態で終わります。前のフィールド `lags.game` はなくなりました。

記号. `tr(m, i, k)` は、入力 `i` での `m` のフレームの `k` 命令あとの機械、`frame(m, i)` はその終わりの機械です。`c` はモードのルーチンの呼び出し（`SkipMainOper` の前の命令）です。
`g` はポーズのバイト（`GamePauseStatus`）の RAM の番号で、`bit₀(m)` は `m` でのその最下位ビットです。`FrameStart(m)` と `Clean` は、[土管までの数えないフレーム](a-5-5-3-LagFrames-ja.md) と同じく
`PipeWrites.guardOf` のものです。`KeepsPause(m)` は、`m` での添字やポインタを通る書き込みがバイト `g` を書かないことです。
`seq(n)`、`sin(n)` は走りのフレーム `n`（全部のフレームを数える）の機械と入力で、数えるフレーム `t` はフレーム `ix(t)` です。

```
ends_unpaused      :  pauseCheck,  FrameStart(m),  ∀ k, Clean(tr k),  ∀ k, KeepsPause(tr k),
                      ∃ k,  frame(tr k) = frame(m)  ∧  pc(tr k) = c          →   bit₀(frame(m, i)) = 0
no_call_of_paused  :  同じ前提,  bit₀(frame(m, i)) = 1                        →   ¬ ∃ k,  frame(tr k) = frame(m)  ∧  pc(tr k) = c

Lags   （新しいフィールド。数えないフレーム  1 ≤ t < E,  ix t < n < ix(t + 1)  で）
  paused  :  bit₀(seq(n + 1)) = 1
  keeps   :  ∀ k,  KeepsPause(tr(seq n, sin n, k))
Lags.no_call       :  pauseCheck,  Lags,  FrameStart(seq n)   →   フレーム n は c を呼ばない
```

`pauseCheck` は ROM での確認で、非公開の `pause_check`（`Proof/LagPause.lean`）が `native_decide` で示します。ネイティブで約 6 秒かかります。
ROM のない定理が使う公理は `propext`、`Classical.choice`、`Quot.sound` だけです。

Lean: `Theorems/LagPause.lean`、`Theorems/PipeFrames.lean` の `Lags.paused`、`Lags.keeps`、`Lags.no_call`、非公開の `Proof/LagPause.lean`。

## しくみ

* **理由.** NMI がモードのルーチンを呼ぶのは、ポーズのバイトの最下位ビットが 0 のときだけです（コードから読んだこと: `lda GamePauseStatus; lsr; bcs SkipMainOper`）。
  呼び出しのあと、ポーズのバイトを書く命令はありません。なのでビットはフレームの終わりまで 0 のままです。下の 2 つの歩きが ROM でこれを示します。
* **ガード.** 歩きは、`guardOf` の、行き先のわからない書き込みが触れないバイトにポーズのバイトを加えたもの（`guardP`）を使います。`Clean` と `KeepsPause` から
  `guardP` の `Clean` が出ます（`clean_with`）。なので歩きは、そういう書き込みのあともポーズのバイトのわかっているビットを覚えています。
* **1 つ目の歩き** は、ポーズのバイトの最下位ビットがわかっている状態（0 か 1 の 2 つ。フレームの早いか遅いかで 4 つ）からアイドルループで始めます。呼び出し `c` まで
  フレームをたどります。ポーズの処理はビットを反転させることがあります（Start）。歩きは各道でビットを知っています。`c` では、ビットが 0 とわかっていること、
  2 つ目の歩きの表の状態がその状態を覆うことを求めます。`c` の前にフレームを終える道には何も求めません。
* **2 つ目の歩き** は [操作中の 1 フレームは見張るビットを保つ](f-6-19-FrameKeep-ja.md) の歩き（`FrameKeep.walkK`）で、`c` での状態からモードのルーチンを通ってフレームの終わりまで
  たどります。終わりでは、ビットが 0 とわかっていることを求めます（`fin`）。
* **証明**（`frame_runP`）は、機械を 2 つの歩きに沿って 1 命令ずつたどります。フレームが `c` に来るなら、`c` での機械は 2 つ目の歩きの状態に覆われ、フレームはビットが 0 と
  わかっている状態で終わります。来ないなら、フレームのどの命令も `c` にありません。
* **探索のキー.** 探索のキーには、ポーズのバイトのわかっているビットと、ポーズのバイトへ `A` を書く命令でのレジスタ `A` を入れます。`A` がないと、ポーズの処理の 2 つの道
  （ビットを反転するか、しないか）がその書き込みで合わさり、ビットがわからなくなります。
* **数.** 1 つ目の歩き: 5,812 段、分かれ 755、失敗 0、表は 566 状態、`c` での状態は 3（どれもビットが 0 とわかっている）。2 つ目の歩き: 1,902,459 段、分かれ 194,062、
  失敗 0、表は 127,977 状態。探索はネイティブで約 3.9 秒、確認の全部は約 6 秒です。

## 本物のフレームで確かめたこと

プログラムです（`lag-pause-check`）。2 つの探索と確認をネイティブで動かします。本物の走りの各フレームで、`c` を呼ぶか、添字やポインタを通る書き込みがポーズのバイトを書くか、
終わりのビットを調べます。インターバルタイマーが動かないフレームを数えないフレームとします。走りは、入ったところか、操作できない状態で終わる最初の数えるフレームで止めます。

| 走り | 数えるフレーム | 数えないフレーム | ポーズで終わる | ポーズのバイトへの書き込み | `c` を呼ぶ | `c` を呼んでポーズで終わるフレーム |
|---|---|---|---|---|---|---|
| TAS の操作から入るまで | 368 | 0 | 0 | 0 | 0 | 368 のうち 0 |
| Start のある自分の入力、小さい・大きい（60 回） | 18,382 | 18,414 | 18,414 | 0 | 0 | 18,382 のうち 0 |
| 入る前にポーズ、そのあと TAS の入力（200 回、入るのは 40 回） | 1,480 | 14,140 | 14,140 | 0 | 0 | 1,480 のうち 0 |
| スーパーの状態の大きいマリオ、自分の入力（60 回） | 18,076 | 19,157 | 19,157 | 0 | 0 | 18,076 のうち 0 |
| 操作できない数えるフレームのあとも続けた走り（60 回、確認には入れない） | 19,980 | 22,020 | 21,187 | 0 | 831 | 20,811 のうち 0 |

* 定理の中の走りでは、数えないフレームはどれもポーズで終わります。新しいフィールド `paused` は成り立ちます。添字やポインタを通ってポーズのバイトを書く命令はありません。`keeps` も成り立ちます。
* `c` を呼んでポーズで終わるフレームはありません。けがや死のあと（最後の行）もです。`ends_unpaused` の言うとおりです。
* 最後の行では、数えないフレームのうち 833 がポーズで終わりません。けがや死のあと、タイマーの制御がタイマーを止めているときです。そういう走りは入る前に操作できない数えるフレームを
  持つので、定理の外です（`lags.ctl`、項目 1-1-0-6-2、1-1-0-6-3）。

## 前提（Lean では証明していない）

* **`lags.game` はもう仮定しません.** 数えないフレームはモードのルーチンを呼びません。これは `paused` と `keeps` からの定理になりました。
* **`lags.paused`**: 操作から入るまでの各数えないフレームは、ポーズで終わる。1 つの状態（フレームのあとの機械）の条件です。土管までの数えないフレームはポーズのものです。
  どれが数えないフレームか（`gap`）は、インターバルタイマーとつながっていません。最初の切り替えの `chg.paused₁`（項目 1-1-b-3-8）と同じ形の条件です。
* **`lags.keeps`**: 数えないフレームのどの命令も、添字やポインタを通ってポーズのバイトを書かない。`Clean` と同じ種類の条件で、バイトが 1 つ増えたものです。
* **証明していないこと: タイマーの制御が 0 のままであること.** いまは要りません。

**ファイル.** `Theorems/LagPause.lean`、`Theorems/PipeFrames.lean`、`Theorems/Route.lean`、非公開の `Proof/LagPause.lean`。
