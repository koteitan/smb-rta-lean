# 画面の端での補正の向き

スクロールの処理の終わりで、ゲームはプレイヤーの画面の外のビットのルーチン（`ChkPOffscr`）を呼びます。それは画面の右端を読み、次に左端を読み、彼のピクセルを読みます。見つけたビットから、[画面の端での補正](e-2-10-3-4-ScreenClamp-ja.md)を `Y = 0`（左端）か `Y = 1`（右端）で呼ぶか、呼びません。[補正](e-2-10-3-4-ScreenClamp-ja.md)と[スクロールの規則](e-2-10-3-12-ScrollRule-ja.md)は補正とスクロールを追いますが、この選び方は追いません。ここでその選び方を示します。

**主張（第 30 回）.** ルーチンの始め（`ClampSide.places.chk`）にある本物の機械 R を、`Good` とともにとります。次のように書きます。

```
pix16(m)     = 彼の位置の 256·ページ + ピクセル
edge16(t, m) = 画面の左端（t = 0）または右端（t = 1）の 256·ページ + ピクセル
D_t(R)       = (edge16(t, R) − pix16(R)) mod 2¹⁶                     コードが端 t について求める差
selM(R)      = selOf(bits(1, D_1))          bits(1, D_1) ≠ 0 のとき
               selOf(bits(0, D_0))          そうでないとき               ∈ {none, some 0, some 1}
```

`bits(t, D)` は、コードが `D` の上のバイトと下のバイトから求める画面の外のビットのバイトです（表は ROM から読みます: `ClampSide.xOf`、`divX`、`bitsOf`）。`selOf(b)` は、`b` のビット 7 が立っていれば `some 0`、ルーチンのマスクが立っていれば `some 1`、どちらでもなければ `none` です。

1. `chk_run`: フレームの中のいくつかのステップのあと、機械は `selM(R) = some t` のとき `Y = t` で補正の入口にあり、`selM(R) = none` のときスクロールの処理の戻りの命令にあります。スタック、彼の位置（ピクセル、ページ、端数）、2 つの端、スタックのすぐ上の 2 つのバイト（スクロールの処理の戻り先）は R のものです。
2. `clamp_end`: フレームの中のいくつかのステップのあと、機械 R' はスクロールの処理の戻りの命令にあり、スタック、2 つの端、端数、スタックのすぐ上の 2 つのバイトは R のもので、

```
pix16(R') = pix16(R)                                   selM(R) = none のとき
pix16(R') = (edge16(t, R) − amount(t)) mod 2¹⁶          selM(R) = some t のとき
```

`amount(t)` は `Y = t` のときの補正の量です（ROM から読みます。左端で 0 px、右端で 16 px）。

3. `left_after`: さらに右端が左端の 255 px 右にあるとき、

```
edge16(1, R) ≡ edge16(0, R) + 255   (mod 2¹⁶)
```

スクロールの処理の戻りの命令で

```
(pix16(R') − edge16(0, R)) mod 2¹⁶ < 256
```

言葉で: 補正のあと、彼は画面の左端にいるか、その右 255 px 以内にいます（2¹⁶ を法として数えます）。彼が左端にいるかその左にいるとき、または右端より右にいるとき、補正は彼を左端に置きます。右端の手前の最後の 16 px にいるとき、右端から 16 px 左に置きます。それ以外では動かしません。`d = D_1`（右端から彼のピクセルを引いたもの）で、確認はこの ROM で次を示します: `d < 16` で右端、`16 ≤ d < 255` で補正なし、`d ≥ 255` で左端。

これらは `ClampSide.chk_run`、`ClampSide.clamp_end`、`ClampSide.left_after` です（公理は `propext`、`Classical.choice`、`Quot.sound`。`left_of` は、`clamp_end` の結果からの `left_after` のピクセルの部分）。ROM の確認 `ClampSide.checkAll` と `ScreenClamp.check` を仮定に持ちます。非公開の証明が `checkAll` を確かめます（`clamp_side_check`、`genClampSide` が作る。native で数秒）。

**証明.** [補正](e-2-10-3-4-ScreenClamp-ja.md)や[スクロールの規則](e-2-10-3-12-ScrollRule-ja.md)と同じく、ROM のコードを区切って確かめます。番地はプログラムから来ます: 画面の外のビットのルーチンは、ルーチンの始めの呼び出しの行き先です。その中のループ、端のページの読み込み、割り算の呼び出し、ビットの読み込みは決まった位置にあり、区間がそれを確かめます。それぞれの区間で、確認は比べるバイトのすべての値でコードを歩きます:

| 区間 | から | まで | 分かっている値 |
|---|---|---|---|
| `jCheck` | ルーチンの始め | ループ（`Y = 1`、`X = 0`） | スタックのバイト（256）: スタックの上の戻り先、保存した添字 0 |
| `s1Check` | ループ | 端のページの読み込み | `Y`、端のピクセル、彼のピクセル（2 × 65,536）: 差の下のバイトとそのキャリー |
| `s2Check` | 端のページの読み込み | ビットの読み込み、または割り算 | `Y`、端のページ、彼のページ、キャリー（2 × 131,072）: 差の上のバイトが決める。`X` は表の位置 |
| `s3Check` | 割り算（呼び出し） | ビットの読み込み | `Y`、下の差、スタックのバイト（2 × 65,536）: 下の差から `X` |
| `s4Check` | ビットの読み込み | `Y = 0` のループ（右端でビットが 0）、またはルーチンの終わり: `Y` つきの補正の入口か、スクロールの処理の戻りの命令 | `Y`、16 より小さい `X`、スタックのバイト（2 × 4,096） |
| `cpX`、`cpP`、`cpT` | 補正の入口 | その戻りの命令 | `ScreenClamp` と同じ。2 つの端も保つ |
| `relCheck` | | | 左端が右端の 255 px 左にあるとき、すべての `d < 2¹⁶` での向き: 補正なしは `d ≤ 255` のときだけ。左端の補正の量は 0 |

`side_run` は 1 つの端の区間をつなぎ、`fin_run` と `loop_run` はループの終わりを、`chk_run` はルーチン全体をつなぎます。`lo_hi` は、コードの 2 つのバイトが 16 ビットの差のバイトであることを示します。だから、右端が左端の 255 px 右にあるとき、`selM` は `D_1` の `selD` です（`selM_rel`）。`clamp_run` は、端を保つことも示す `ScreenClamp.run` の補正です。

| 確認 | 何を | 結果 |
|---|---|---|
| ネイティブの試し | `checkAll` | true。非公開の証明 `clamp_side_check` は数秒で通る |
| `edge-real FM2 256` | すべてのフレーム（5 つの集まり、137,955 フレーム、clean でもそうでなくても）の画面の外のビットのルーチンで | どのフレームでも右端は左端 + 255 px だった（反するもの 0）。向き: 補正なし 89,665、左端 48,290、右端 0。どのフレームでも、本当の補正の呼び出しとその `Y` は `selM` のとおりで、戻りの命令での彼のピクセルは `pixAfter` で、`left_after` の結論が成り立った |

**ルートの上で（第 30 回）.** `OnFrames.nearStepAt` が `left_after` を使います: 前のフィールド `nearStep`（[1-1-e-2-10-3-17](e-2-10-3-17-SideTimer-ja.md)）は定理です。右端の関係は新しいフィールド `rightRel` です: タッチの前の最後のもの以外の数えるフレームのそれぞれで、ルーチンの始めで、右端は左端 + 255 px（2¹⁶ を法として）で、左端のページは 255 ではありません。スクロールの処理の戻りの命令のあとのフレームは、新しいフィールド `endKeep` です: フレームが横の当たりのタイマー 1 以下、スクロールのロック 0、画面での彼の場所がしきい値以上で終わるとき、スクロールの処理のあとに押し戻しか補正を呼ぶフレームでは、終わりでの彼のピクセルは戻りの命令でのものと同じです（ほかのフレームではこれは定理です: `OnFrames.stillAt` が位置を保ち、ルーチンは補正を選ばない、`chk_run`）。場所のバイトは pixel − 左端 mod 256 です（終わりでの左端が戻りの命令でのものと同じことは定理です: 戻りは呼び出しの次の命令に行き（`ret_step`）、そこからは `EdgeStep.keep_r` の歩きが端を保ちます）。すると、フレームの始めでの条件なしに、フレームの終わりで `NearM` が成り立ちます。`numbersCheck` は `checkAll` と、しきい値が 2 px 以上であることを確かめます。`endKeep` は `nearStep` より弱くはありません: `nearStep` が 2 px の限りだけを求めたところで、正確なピクセルと場所のバイトを求めます。

**ここで証明していないこと.** `rightRel`: フレームの始めからスクロールの処理までと数えないフレームで右端の 2 つのバイトを追う歩き、スクロールの中で左端から右端を決めるルーチン、コントロールの始めの状態が要ります。`endKeep`: 呼び出しのあとは押し戻しだけが彼を動かすこと、横の当たりのタイマーが 1 以下で終わるフレームでは呼び出しのあとに押し戻しがないこと（第 29 回: タイマーの歩きは、添字かポインタでの 18 の書き込みでタイマーを見失う）、フレームの終わりの描画が画面での彼の場所を pixel − 左端 mod 256 として書くこと（けがのタイマーが動いている間は、1 つおきのフレームで飛ばされる）が要ります。`Moves.stop` にはフレームの始めでの端が要ります: 測ったフレームでは左端の補正が彼を P(Q) に置くので、フレームが左端かその右で始まること、または左端の 1 px 左で遅い速さで始まることを求めます。

**ファイル:** `Theorems/ClampSide.lean`。`Theorems/SurfaceFrames.lean` が使います（`EndKeep`、`RightRel`、`ret_step`、`pix16_of_posP`、`nearM_of_end`、`OnFrames.nearStepAt`、フィールド `rightRel`、`endKeep`）。`Main.lean`: 生成するもの `genClampSide`（`gen-proofs` の中）と、`edge-real` の第 30 回の部分。
