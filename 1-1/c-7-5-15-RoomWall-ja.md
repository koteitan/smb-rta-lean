# 部屋で床のほかに立つフレーム

[地下の部屋をつなぐ](c-5-RoomJoin-ja.md) のフィールド `stand_wall` は次のことを言います。`C + 51` より前で、床のほかに立つのは `hstep` に従わないフレームの終わりだけです。本物のフレームでは、そのように立つのは部屋の左の壁の列に着地するときです。同じフレームで横の判定が壁を見つけ、`ImpedePlayerMove` が速さを 0 にして 1 ピクセル右へ押します。このページは、1 フレームのこの部分を、移動の終わりからフレームの終わりまで機械の上で証明します。部分的な結果です。フィールド `stand_wall` は残ります。

## 主張

`Q` はフレームの移動の終わり（そのフレームの最初の `PlayerSubs`）です。`Q` で、`x` は横の座標、`pg` はページ、`y` は高さ、`st` は状態、`vy` は縦の速さ、`v` は速さ、`yhigh` は縦のページです。`G` は `PlayerSubs` の中で当たり判定のルーチンを呼んだ次の命令です。`yF` は床の高さ（176 ピクセル）です。`speeds` は速さ 0 と、−127 から −1 までの負の速さです。

```
Q で:  yhigh = 1,  pg = 0,  x < 16,  32 ≤ y < 207,  st ≤ 2,  vy ≥ 0,  v ∈ speeds                                    （条件）

wall_at    :  条件  →  ∃ k ≤ 3200,  stepN k Q  は G にあり、同じフレームで、スタックは Q のもの、そして
              st ≠ 0  ∨  (st = 0 ∧ y = yF)  ∨  v = 0
after_G    :  フレームが G に来て、プレイヤーのルーチンの中で終わる  →  フレームの終わりの v, x, pg, st, y は G のもの
wall_frame :  条件があり、フレームがプレイヤーのルーチンの中で終わる  →  フレームの終わりで
              st ≠ 0  ∨  (st = 0 ∧ y = yF)  ∨  v = 0
neg_of_check : inD(s),  V(s) ≤ −standV  （standV = 256 · 14: 速さ −14 以下、1 フレーム 0.875 ピクセル）  →  ∀ i ∈ inputs,  sbyte(hstep(s, i).v) < 0  ∧  hstep(s, i).v ∈ speeds
not_follow_of : n + 1 < C + 34,  st(vs(n + 1)) = 0,  フレーム n + 1 が arr(n) 以降のある PlayerSubs j に来る  (hQ),
                (arr(n) 以降の PlayerSubs のどの j でも:  v(trace j) ∈ speeds  →  フレームの終わりの v = 0)  (hq)   →   ¬Follow(n)
```

`not_follow_of` が使うのはフィールド `stand_fast` と `clean`、そして `neg_of_check`（`w = standV`）です。`stand_wall` は使いません。`hq` は、移動の終わりで `wall_at` のほかの条件が成り立つとき、`wall_frame` がそのフレームで与えるものです。

なので、移動の終わりが条件を満たす部屋のフレームは、速さが 0 でないまま床のほかに立って終わることはありません。

## 証明の流れ

1. 1 つ目の歩き（`check1`）は `Q` の切れ目から始まります。切れ目は `Q` から 13 バイトを写します。`RoomLand.keys` のバイト（当たり判定を止める旗、縦のページ、ルーチン、座標 3 つ、画面の 5 バイト、ジャンプ台）と状態です。さらに、3 つの足し算の位置について、頭、両足、横のマスを地図からとります（21 マス）。速さ、大きさ、しゃがみの旗、泳ぎの旗、向きは写しません。歩きがそれぞれの両方の分岐をたどります。
2. 1 つ目の歩きは `G` で止まるか、状態が 0 と分かっていて高さが床でないときに `ImpedePlayerMove` で止まります。`G` では `endOK` を求めます。状態が 0 でないか、状態が 0 で床の高さか、速さが 0 と分かっていることです。`ImpedePlayerMove` では、横のバイトが 2（左の横）、状態が 0、スタックの 2 つの戻り先、そして速さが `Q` から書かれていないか 0 と分かっていることを求めます（画面の左の端では、当たり判定のルーチンより前に `ScrollHandler` が速さを 0 にすることがあります）。
3. 2 つ目の歩き（`check2`）は、`speeds` の 128 通りの速さそれぞれを写して `ImpedePlayerMove` から始まり、速さ 0 で `G` に戻ります。
4. `wall_end` が 2 つの歩きをつなぎます。`wall_at` は切れ目のバイトを本物の機械からとります。ルーチン、画面のバイト、ジャンプ台、当たり判定を止める旗は部屋の歩きから（`RoomLand.controls_at_subs`）、マスは `Q` での `Solid` から、残りは条件からです。歩きの集まりは x 0〜15、y 32〜206、状態 0, 1, 2 です（8,400 通り）。もう 1 つの確認で、どのマスもブロックバッファの中にあり、コインでありません。
5. `after_G` は部屋のフレーム全体の歩き（`checkW`、`RoomVert.after_Q` と同じ形）です。`G` で状態に印をつけます。`G` のあとで速さ、位置、状態、高さを書くかもしれない一歩は印を外し、そのような状態はプレイヤーのルーチンの外でフレームを終えなければなりません。
6. `wall_frame` は同じフレームの上の `wall_at` と `after_G` です。
7. `neg_of_check` は `hstep` の確認（`negCheck`）です。`V ≤ −standV` の定義域のすべての状態（39,942 通り）と、正規化したすべての入力（38 通り）で確かめます。`Potential.check_of` がポテンシャルの確認をすべての状態に広げるのと同じやり方です。
8. `not_follow_of`: `Follow` のもとでは、`v(n + 1)` は `hstep(hs n, inp(n + 1))` の速さです。`stand_fast` から `V(hs n) ≤ −standV`、`far_inD` から `inD(hs n)` なので、`neg_of_check` からその速さは負で `speeds` の 1 つです。フィールド `clean`（`CleanW.after` か `ReadW.collide`）から、フレームの終わりの速さは `j` での速さか 0 です。0 ではないので `j` での速さで、それは `speeds` にあり、`hq` から 0 です。矛盾です。

ROM の確認は非公開の `Proof/RoomWall.lean` にあります（`room_wall`、`room_wall_after`、`room_wall_apart`、`room_wall_neg`）。このファイルはネイティブで約 75 秒でビルドされます。ほとんどは 1 つ目の歩きの集まりです。歩きが知らないバイトで分かれるので、抽象的な一歩が 9,700 万あります。`hstep` の確認は約 15 秒です。

## 測ったこと

`room-wall-real FM2 100 16 32 207`: 部屋での TAS 自身のフレームと、TAS の部屋での最初の操作から、7 種類の自分の乱数の入力 700 本（それぞれ 60 フレーム）。

- 42,060 フレーム。そのうち 13,186 で `Q` が条件を満たします。そのどれでも `G` で `endOK` は偽になりません。
- 床のほかに立つのは 15 回。12 回はフレーム 51 より前です。12 回とも `Q` で条件を満たし（x 12、y 112、116、129、163、状態 2、速さ −17〜−20）、12 回とも `G` とフレームの終わりで速さ 0 です。残りの 3 回は TAS のフレーム 52〜54 で、部屋のかたまりの上に立っています（x 61〜64）。
- どのフレームでも、フレームの終わりの速さと位置は `G` のものです。
- 各種類 300 本（`room-wall-real FM2 300 16 32 207`）: 126,060 フレーム、条件を満たすのは 39,908、`endOK` が偽になるものはなし。床のほかに立つのは 53 回。49 回はフレーム 51 より前で、どれも `Q` で条件を満たし（x 12、y 112〜163）、速さ 0 で終わります。残りの 4 回のうち 3 回は TAS のフレーム 52〜54 でかたまりの上、1 回はちょうどフレーム 51 でかたまりの左の横に着地する走りです（x 52、y 160、`Q` での速さ +20、1 ピクセル左へ押されて終わりの速さ 0）。なので、かたまりの上に立つのはフレーム 51 にも来られます。`stand_wall` が話すフレームのすぐあとです。

## 残るもの

フィールド `stand_wall` は残ります。`C + 34` より前を `not_follow_of` から証明するには、まだ次が要ります。

- `C + 34` より前で床のほかに立って終わるフレームでの `hq`。移動の終わりでの `wall_at` の条件（`x < 16` はフィールド `stand_P` と移動から。高さ 32〜206。縦のページ 1。ページ 0。状態。`vy ≥ 0`）と、`wall_frame` が求める本物の機械でのフレームの事実（部屋の条件、`SiteOK`、`Solid`、`Q` での `Good` とスタック、フレームの時間、フレームがプレイヤーのルーチンの中で終わること）です。`Route.Run.roomLand` が `InRoom.land` のために与えるのと同じものです。
- `hQ`。空中で始まるフレームでは `InRoom.land`、立って始まるフレームでは `InRoom.floor` が与えます。
- `stand_fast` は `C + 34` より前だけです。`C + 34` から `C + 50` のフレームでは速さを与えるものがありません。これらのフレームは `wall_turn` が（`st_ne` を通して）使います。
- `wall_frame` は `Q` の速さが 0 か負であることを求めます。速さが正だと、壁の列への着地で速さは残ります（`ImpedePlayerMove` は右向きの速さを残します）。`C + 34` より前で `Follow` のもとでは、速さは負です（上のとおり）。本物のフレームで、正の速さで壁の列に着地するものはありません。壁の列の中で終わるフレームが要るからです。
