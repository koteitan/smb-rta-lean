# `C + 37` より前の保存された速さ: `ab_early` は落下の終わりからだけ

[ボーナス部屋をつなぐ](c-5-RoomJoin-ja.md) のフィールド `ab_early`（項目 1-1-c-7-6）は、`C + 37` より前でモデルに従わないフレームが読む保存された速さは空中のしきい値より下である、というものです。定理がこれを使うのは落下の終わりからだけです。このラウンドでは、そこだけで求め、そのうち 2 つ目のフレームでは、1 つ前のフレームが `AtCtrl` の状態で止まらないときだけ求めます（止まるときは、[止まったあとの保存された速さ](c-7-4-3-AbsKeep-ja.md) の `RoomRun.ab_fresh` が保存された速さをくれます）。

## 命題

`ab(n)` はフレーム `n + 1` がプレイヤーのルーチンで読む保存された速さ、`CleanR(n)` はフレーム `n + 1` がモデルに従うこと（`FrameModel.CleanR`）、`Stop(n)` はフレーム `n` が止めること、`A = AirFastSpeed` は空中のしきい値（1 フレームに 1.5625 px）です。`fall = 34`、`hitF = 37` です。

```
ab_early（RoomRun のフィールド。狭めた、ラウンド 32）:
  C + 34 ≤ n,  n + 1 < C + 37,  n < t0,  ¬CleanR(n),  (n = C + 34  ∨  CleanW(n − 1)  ∨  ¬AtCtrl(n − 1))   →   ab(n) < A
  （前は C + 34 ≤ n の代わりに C ≤ n で、最後の前提はなかった）

RoomCore.ab_of（証明: RoomRun.ab_of_run。2 つ目の場合を同じように変えた）:
  C ≤ n < t0   →   ab(n) = |v(n)|  ∨
    (Stop(n + 1) ∧ (C + 34 ≤ n → n + 1 < C + 37 → ab(n) < A  ∨  (C < n ∧ ab(n) = |hstep(hs(n − 1), inp(n)).v|)))
```

`CleanW(n − 1)`、`AtCtrl(n − 1)` は [止まったあとの保存された速さ](c-7-4-3-AbsKeep-ja.md) と同じです: フレーム `n` がモデルに従う。フレーム `n` がプレイヤーのルーチンに保存された速さ `|v|`、隠されていない向きで来る。なので `ab_early` が求めるのは 36 フレームの代わりに 2 フレーム、`n = C + 34` と `n = C + 35` で（フレーム `C + 35` と `C + 36` が保存された速さを読む）、`n = C + 35` ではフレーム `n` が `AtCtrl` の状態で止める（`ReadW`）ときは求めません: そのときは `ab_fresh` が `ab_of` の最後の場合をくれます。

これで足りるわけ: `ab_early` を使うのは 2 つです。`RoomRun.stop_run_of` は `C + 34` から求めます。`ab_fresh` の場合は、`RoomCore.stop_run` の前提（前の状態からのモデルのどの入力も速さを走りのしきい値より下に保つ。`safeFrom` から）が代わりに保存された速さを抑えます。`RoomCore.ab_of` は `T ≥ C + 34` の踏み切りのフレーム `T + 1`（落下のあとの床からの踏み切り: `Approach.T1_ge`、`v_chain2`）で、壁に当たらない走りで使い、ほかの 3 か所は 1 つ目の場合だけを使います。壁に当たらないならフレーム `T` は `hstep` に従う（`NoWall`）ので `hstep(hs(T − 1), inp(T)) = hs(T)` で、新しい場合は `ab(T) = |v(T)|` を言い、それはその証明がもう扱っています。落下の中のフレームの保存された速さを求める定理はありません。

## 測ったこと

`room-ab-check FM2`（TAS と、最初の操作からの自分の入力の走り 2,800 回）:

| | フレーム |
|---|---|
| `C + 37` より前で、モデルに従わない（前のフィールド。TAS にはない） | 10,184 |
| そのうち落下の終わりから | 516 |
| そのうち `n = C + 34`（フィールド） | 316 |
| そのうち `n = C + 35` で、フレーム `n` が `AtCtrl` の状態で止める（`ab_fresh` で証明） | 117 |
| そのうち保存された速さが `|hstep(hs(n − 1), inp(n)).v|` でない（`ab_fresh` のまちがい） | 0 |
| そのうち `n = C + 35` のほかのフレーム（フィールド） | 83 |

なのでフィールドが求めるのは測ったフレームのうち 399 です。その保存された速さは 1 フレームに 0.5 px 以下で、どれも空中のしきい値（1 フレームに 1.5625 px）より下です。

## 残ること（証明していない）

- `n = C + 34` での `ab_early` と、`n = C + 35` でフレーム `n` がモデルに従うか、古い保存された速さか隠された向きでプレイヤーのルーチンに来るときの `ab_early`。`n = C + 34` での `ab_fresh` の場合には、落下の中の `C + 33` の状態からの `hstep` の上限が要りますが、`stop_run` を使う側はそれを持っていません（`safeFrom` は落下の終わりから始まる）。ラウンド 33（[モデルに従うフレームのあとの保存された速さ](c-7-4-4-StoredClean-ja.md)）が、隠された向きと、空中で左も右も押さずに古い保存された速さで来る場合をのぞいて、これらを証明します。残りはそちらに書きます。
