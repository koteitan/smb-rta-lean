# 1-1 の道筋: 1-2 が始まるフレームの下界に向けて

**目標.** 1-1 で操作できるようになった最初のフレームを 0 として、1-2 が始まる（面の番号が変わる）のは
1748 フレーム目より前にはならない、を示すこと。1748 は HappyLee の TAS の値。

このページは途中経過の記録です。区間ごとに、**Lean の定理**、**エミュレータでの確認**（Lean ではない）、
**未解決** を分けて書きます。数はフレームと、TAS との距離の差（ピクセル、または 1/256 ピクセル）で書き、
ROM の番地や表の値は書きません。

## TAS の道筋

| フレーム | 出来事 |
|---|---|
| 0 → 368 | 出だし（32 フレームで最高速）、最高速で走る、4 本目の土管に入る |
| 368 → 459 | 土管を下りる、場面の切り替え、地下の部屋に天井から入る |
| 459 → 570 | 地下の部屋: 床に落ちる、レンガのかたまりに跳び乗る、横の土管に着地で入る |
| 570 → 852 | 横の土管、場面の切り替え、地上の土管から上がる |
| 852 → 1092 | 土管の上で加速、最後の階段を越える、旗の土台の横に降りて小さく跳び、上昇中に旗をつかむ |
| 1092 → 1218 | 旗の上で待つ、城まで自動で歩く（城に入る） |
| 1218 → 1748 | 残り時間の点数化、旗を上げる、21 フレームの格子に合わせた待ち |

## 区間ごとの結果

### 1. 走って土管に入る（0 → 368）: 最短

- 32 フレーム目までの距離は、[出だしの最適性](../Theorems/Opening-ja.md) の定理から TAS 以下。
  そのあとは [最高速の上限](../Theorems/TopSpeed-ja.md) から、1 フレーム 2.5 ピクセル以下。
  TAS はこの 2 つの上限ぴったりに走る（32〜362 フレーム目まで、毎フレームちょうど上限）。
- 土管に入れるのは、両足が土管の上面にあり、下を押していて、着地のコードを通るフレームだけです。つまり上面に落ちるか、立っているときです（[縦の土管に入る](../Theorems/PipeEntry-ja.md)）。地面で左か右といっしょに下を押しても数えません。フレームのコードが消すからです。上限によると、フレーム 367 でマリオはその範囲に 112/256 ピクセル（0.44 ピクセル）足りません。なので 368 より前には入れません。
- 状況: 上限、土管の上面の近くの全部の状態での判定ルーチンと規則の比較、その結合は、規則に従うフレームについての Lean の定理です。前提: 本物のフレームが規則と上限に従うこと（ルーチンは単独で確かめています）。368 で実際に入るのは、エミュレータでの TAS です。

### 2, 4. 土管と場面の切り替え: 長さは決まっている（エミュレータでの確認）

```
地下で操作できるフレーム = 土管に入ったフレーム + 91
地上で操作できるフレーム = 横の土管に入ったフレーム + 282
```

入力、土管の上での位置や速さ、21 フレームの格子のどれにもよらない（それぞれの処理は入力を読まないか
上書きする。21 フレームの格子で待つ処理は、この 2 つの切り替えでは飛ばされる）。何もしないフレームを
はさむと、ちょうどその分だけ遅れる。一時停止は長くするだけ。

パート 2 の状況: [地下への切り替え](../Theorems/PipeTransition-ja.md) は、そこに挙げた入る状態についての Lean の定理です。本物の走りの 1 つの入る状態からは、Start と
Select を除くすべてのフレームのすべての入力で、ちょうど 91 フレーム目に操作できます。これには仮定 `Merge`（ボタンをそのまま写すバイトだけが違う状態は同じように動く）を使います。
入力なしなら仮定なしで、範囲のほかのピクセル、ほかの速さ、大きいマリオ、本物の走りで続けてずらした 21 個の入るフレームで同じです。どの走りのどの入る状態でも同じになることは
証明していません。Start を押すと一時停止しますが、切り替えの一部のフレームでは無視されます（コードから読み、エミュレータで試した）。パート 4（+282）はエミュレータでの確認のままです。

### 3. 地下の部屋（459 → 570）: 570 より前には入れない

入るのに必要なこと（コードから）:

- 横の土管には、入口の前の床で入る。早くても、そこに着地するフレーム。空中で入口の上の部分にぶつかると止められる。
- その床へは、レンガのかたまりの右端を上から越えるしかない。右端を越えた最初のフレームを `t` とする。落ちる時間は、かたまりからの
  離れ方で決まる（[ジャンプの高さ](../Theorems/Jump-ja.md)）。

  | かたまりからの離れ方 | 床に着くのは |
  |---|---|
  | 1.5625 ピクセル／フレーム以上のジャンプ | `t` の 12 フレーム以上あと |
  | それより遅いジャンプ | 空中に 32 フレーム以上いて、そのあいだ 1.5 ピクセル／フレーム以下: 569 で入口の 25 ピクセル手前 |
  | 歩いて落ちる | `t` の 16 フレーム以上あと |

  （速いジャンプはちょうど 1 フレームに 4 ピクセル落ちる。遅いジャンプは約 4.2 ピクセル落ちるので、別に扱う。）
  TAS は 558 で越えて 570 で入る。なので 569 に入るには 557 で右端を越えている必要があり、それは TAS より 592/256 ピクセル（2.31 ピクセル）先。

557 フレーム目の上限（全部の入力について）:

1. 天井からの落下は入力によらないので、床に着くのは 493。最初のジャンプは 494。
2. 足がかたまりの上面より低いあいだは、角より左にいないといけない。当たると速さがほぼ 0 になる。かたまりに乗る前の、
   低い最後のフレームを `s` とする。TAS は `s` = 504 で、当たる位置の 15/256 ピクセル手前。
3. 1.5625 ピクセル／フレームより遅く跳ぶとき: `s` から [空中の速さの上限](../Theorems/AirCap-ja.md) が使える。全部の
   跳ぶ速さと A の押し方（[ジャンプの高さ](../Theorems/Jump-ja.md)）で、いちばん早い組（`s`、かたまりに乗るフレーム）は (504, 511)（TAS）と (505, 510)。
   ほかは乗るのが遅い。定理から `s` から 557 までは 121.75 ピクセル以下。なので 557 に TAS より先に行けるのは 527/256
   ピクセルまでで、65/256 ピクセル（0.25 ピクセル）足りない。
4. 1.5625 ピクセル／フレーム以上で跳ぶとき: 速く上がるが、`s` は跳んでから 8 フレーム以上あと。[速いジャンプ](../Theorems/FastTakeoff-ja.md) は、459 から横のフレーム `hstep` を
   全部の入力でたどる。右に動いていると、500 までのジャンプは 8 フレームのあいだ角より左にとどまれない。左に動いていると、500 までのジャンプはモデルの中にあるが、とても後ろにいるので、
   そのあと何をしても 557 で目標に届かない。500 より後に跳ぶと、角から最高速でも間に合わない。
5. `s` で角に当たると速さがほぼ 0 で、8 ピクセル以上足りない。跳ぶ直前に床で当たる場合（覚えている速さの絶対値が
   消えないので、速いジャンプになる）も、3 ピクセル以上足りない。

状況: 3 の上限、4、ジャンプの表はモデルの上の Lean の定理。入る条件はコードから読んだ。合わせる部分は足し算で、Lean にはしていない。4 のモデルに部屋の左の壁は入っていない。`hstep` は 460〜557 の全部のフレームで TAS と一致する。
大きいマリオでも、角での判定の高さは同じなので、上限は同じ。

### 5a. 地上での加速（852 → 892）: 旗の範囲に早く届かない（エミュレータでの確認）

- 852 の TAS の状態から、40 フレームのあいだ全部の入力を、本物のフレームでたどった（同じ状態はまとめ、
  ポテンシャルの上限で、もう追いつけない状態を捨てる）。892 フレーム目に TAS より先に行けるのは、多くて
  144/256 ピクセル。
- 892 以降は、最高速の上限から 1 フレーム 2.5 ピクセル以下。TAS はここでも上限どおりで、損は 980 フレーム
  目の 16/256 ピクセルだけ。なので 1085 フレーム目に TAS より先に行けるのは、多くて 160/256 ピクセル。
- 旗をつかめる範囲に入るには、1085 フレーム目に TAS より 528/256 ピクセル先にいる必要がある。なので
  1085 までには入れない。
- 前提: 捨てた状態が本当に追いつけないことは、開けた場所でのポテンシャルの上限による。

### 5b. 旗をつかんで城に入る: 城に入るのは 1218 より前にはならない

旗のまわりの仕組み（コードから）:

- 旗に触れるのは、マリオの右側が旗の柱に 3〜6 ピクセル入る 4 ピクセルの範囲に、旗の土台より上の高さでいるとき。地面の高さで走ってくると、
  その手前で土台のブロックに止められる。この範囲の左端を `x₀` とする。
- 上昇中に土台に近い高さで触ると、旗をすべり降りずに、その場で終わりの処理に入る。城に入るのは
  **触ったフレーム + 126**。それ以外で触ると、旗が下りきるのを待つので、約 39 フレーム遅い。5a から 1086 より前には
  触れないので、この場合に城に入るのは 1251 以降。

なので 1217 以前に城に入るには、`g ≤ 1091` のフレームで、この上昇中のつかみが必要。それが起きない理由（コードから。
どの速さ、どの落下の速さ、どの入力でも成り立つ）:

1. **上昇中だけ。** その高さで落ちているときは、土台の上に着地するか、横の判定の前に止められる。その高さで上昇するのは、
   地面からフレーム `T` に跳んだときだけで、`g = T + 2`（1.5625 ピクセル／フレーム以上で跳ぶと `g = T + 1`）。地面に着く
   フレームを `L` とすると `T ≥ L + 1` なので、`L ≤ 1088`。
2. **小さなジャンプでは進まない。** 土台の横で、上面より低いあいだは、右に動いているか止まっていると、速さが 0 になって
   1 ピクセル左に押される。左に動いていれば何も起きない。もっと左からは `x₀` の手前で止まる。なので `x(g) ≤ x(L)` で、
   `x(L) ≥ x₀` で着地する必要がある。土台の左の端より先なので、上から来るしかない。
3. **端を越える。** `L` の前に、最後に土台の上の位置（`x ≥ x₀ − 2`）に入るフレームを `e`、`k = L − e` とする。その前の
   フレームはそれより左なので、当たる前の `x(e) < x₀ + 0.5`。
   - フレーム `e`: 1 ピクセル戻り、速さ 0。
   - `e` と `L` のあいだ: 1 フレームに 1 ピクセルまで進む。それには左を押して、押し戻しを右向きにする（下の TAS の技）。
   - フレーム `L`: 1/8 ピクセルまで進んだあと（右を押す。TAS の 1089）、1 ピクセル戻る。右への押し戻しがあると次のフレームの
     左ボタンが効かないので、左に動いていない。この押し戻しを避けられるのは `k ≤ 1` のときだけ。

   ```
   x(L) ≤ x(e) + k − 3 + 1/8   (k ≥ 2)
   x(L) ≤ x(e) − 1             (k ≤ 1)
   ```
4. **時間が足りない。** `L ≤ 1088` から `e ≤ 1088 − k`。5a から `x(1085) ≤ x₀ − 1.44` で、それより前は 1 フレームごとに
   2.5 ピクセル少ない。

   | k | e の最大 | x(L) の最大 |
   |---|---|---|
   | 0, 1 | どれでも | `x₀ − 0.5` |
   | 2 | どれでも | `x₀ − 0.375` |
   | 3 | 1085 | `x₀ − 1.31` |
   | 4 | 1084 | `x₀ − 2.81` |
   | それ以上 | | 1 フレームごとに 1.5 ピクセル少ない |

   どれも `x₀` に届かない。TAS は `e` = 1086、`k` = 3、`L` = 1089、`g` = 1092 で、ちょうど 1 フレーム遅い。
5. **速いジャンプ。** 覚えている速さの絶対値が高いままである必要があるので、`e` から `L` まで左右を押せず、`T = L + 1`。
   すると毎フレーム押し戻され、`x(g) < x₀ − 0.4`。

エミュレータで確かめたこと:

- 1084 フレーム目の状態（まだ土台に触れていない）の高さ（13 通り）、横の位置（TAS より 1 ピクセル後ろから 160/256 ピクセル
  先まで、10 通り）、向き（3 通り）を変えた 390 通りで、8 通りの入力で 8 フレーム: 1217 以前に城に入れるものはなかった。
- 遅い落下、遅い速さ、左だけの入力: 160/256 ピクセル先（1 系列は 0）で、高さ 15 通り、速さ 2.5 か 1.5 ピクセル／フレーム、
  落下の速さ 4、2、0 ピクセル／フレームの 135 通りで、左右と A、B の全部の入力を 1091 まで: 上昇中のつかみはなかった。
- 式は実際にほぼ一致する。1084 で TAS より 4 ピクセル低い位置で、全部の入力のとき、544/256 ピクセル先にすると 1091 に上昇中の
  つかみができ、540/256 ピクセルではできない。式では 496/256 ピクセル以上が必要で（残りの 48/256 は左を押すフレームと小さな
  ジャンプの分）、5a から届くのは 160/256 ピクセルまで。

TAS の細かい技: 土台の横で左右同時押しをすると、右がふさがっているので左を押した扱いになり、進む向きが左に
なる。すると土台からの押し戻しが右向きになり、旗の範囲にとどまれる。

状況: 2〜4 の位置の上限は、当たり判定の規則に従うフレームについての Lean の定理（[旗を下からつかむ](../Theorems/PoleGrab-ja.md)）で、規則は土台の近くの
全部の状態でゲームのルーチンと比べて確かめた。1 のフレームは移動ルーチンについての Lean の定理（[ジャンプの高さ](../Theorems/Jump-ja.md)）。5 の条件はコードから読んだもの、
1085 の上限は 5a（エミュレータ）から。旗の近くに敵がいないことを前提にしている。

### 城から 1-2 まで: 式で分かった（コードから）

```
L = E + T + D + 107 + ((c − T − D) mod 21)
  E: 城に入ったフレーム   T: 残り時間（旗に触ったときから止まっている）
  D: 33（花火なし）       c: そのときのインターバルタイマーの位相
```

最後の待ちは 21 フレームごとの格子に揃えられる。TAS は格子のちょうど上で待ちを始めるので、20 フレーム余分に
待っている。城に入るのが 1218 なら 1748、1217 なら 1727（21 フレーム早い）。

## まとめ

```
1-2 の開始 ≥ 1748
  ⟸ 城に入るのが 1218 以降                     （城から 1-2 までの式）
  ⟸ 地上で操作できるのが 852 以降、かつ 5a と 5b
  ⟸ 横の土管が 570 以降（+282）                 （区間 3）
  ⟸ 地下で操作できるのが 459 以降（+91）
  ⟸ 土管が 368 以降                              （区間 1）
```

各段の時刻が遅れれば、その先も同じだけ遅れる（遅れて着くと得をすることはない）ことも前提にしている。
どの段にも理由がついた。残っているのは、Lean の定理でない部分を Lean にすること。

## 再現

TAS の映像ファイル（fm2）を用意して、`git/` で:

```
.lake/build/bin/smbrta tas-trace FM2                    # 道筋と、上限との比較
.lake/build/bin/smbrta tas-seg FM2 A B                  # A〜B フレームの位置、速さ、高さ
.lake/build/bin/smbrta tas-insert FM2 AT K              # AT に何もしないフレームを K 個はさむ
.lake/build/bin/smbrta seg-search FM2 852 40            # 5a の探索（10 分以上）
.lake/build/bin/smbrta end-poke FM2 1084 Y DX FD 8      # 5b の 1 通り（Y: 高さ、DX: 横のずれ、FD: 向き）
.lake/build/bin/smbrta pole-check                      # 旗の近くの当たり判定のルーチンと規則の比較
.lake/build/bin/smbrta jump-table                      # 地面とかたまりからの全部のジャンプ
.lake/build/bin/smbrta pipe-check                      # 土管の上面の判定のルーチンと規則の比較
.lake/build/bin/smbrta pipe-change-check               # 地下への切り替え
.lake/build/bin/smbrta takeoff-check                   # 地下の部屋の速いジャンプの探索
.lake/build/bin/smbrta flag-poke FM2 1084 Y DX V VY FD 7 GY   # 上に速さと落下の速さを足し、全部の入力で（GY: つかむ高さ）
.lake/build/bin/smbrta room-bound FM2 459 493 557 CX CY WLO WHI TX
    # 地下の部屋: ジャンプの表と 557 の上限。CX, CY: 角（y ≥ CY のあいだ x ≥ CX で当たる）。WLO..WHI: 落ちてきて
    # かたまりに乗る高さ。TX: かたまりの右端を越える x。どれも部屋のブロックと当たり判定のコードから読む。
```
