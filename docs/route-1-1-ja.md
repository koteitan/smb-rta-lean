# 1-1 の道筋: 1-2 が始まるフレームの下界に向けて

**目標.** 1-1 で操作できるようになった最初のフレームを 0 として、1-2 が始まる（面の番号が変わる）のは
1748 フレーム目より前にはならない、を示すこと。1748 は HappyLee の TAS の値。

このページは途中経過の記録です。区間ごとに、**Lean の定理**、**エミュレータでの確認**（Lean ではない）、
**未解決** を分けて書きます。数はフレームと、TAS との距離の差（ピクセル、または 1/256 ピクセル）で書き、
ROM の番地や表の値は書きません。

## TAS の道筋

| フレーム | 出来事 |
|---|---|
| 0 → 368 | 出だし（32 フレームで最高速）、最高速で走る、4 本目の土管に入る |
| 368 → 459 | 土管を下りる、場面の切り替え、地下の部屋に天井から入る |
| 459 → 570 | 地下の部屋: 床に落ちる、レンガのかたまりに跳び乗る、横の土管に着地で入る |
| 570 → 852 | 横の土管、場面の切り替え、地上の土管から上がる |
| 852 → 1092 | 土管の上で加速、最後の階段を越える、旗の土台の横に降りて小さく跳び、上昇中に旗をつかむ |
| 1092 → 1218 | 旗の上で待つ、城まで自動で歩く（城に入る） |
| 1218 → 1748 | 残り時間の点数化、旗を上げる、21 フレームの格子に合わせた待ち |

## 区間ごとの結果

### 1. 走って土管に入る（0 → 368）: 最短

- 32 フレーム目までの距離は、[出だしの最適性](../Theorems/Opening-ja.md) の定理から TAS 以下。
  そのあとは [最高速の上限](../Theorems/TopSpeed-ja.md) から、1 フレーム 2.5 ピクセル以下。
  TAS はこの 2 つの上限ぴったりに走る（32〜362 フレーム目まで、毎フレームちょうど上限）。
- 土管に入れるのは、両足が土管の上にあって（9 ピクセルの範囲）、落下中か着地のフレームで、下を押して
  いるとき（コードから）。上限から、367 フレーム目には範囲の左端に 0.44 ピクセル届かない。なので
  368 より前には入れない。
- 状況: 上限の部分は Lean の定理。土管に入れる条件はコードから読んだもので、前提。2 つを合わせる部分は
  足し算で、Lean にはしていない。

### 2, 4. 土管と場面の切り替え: 長さは決まっている（エミュレータでの確認）

```
地下で操作できるフレーム = 土管に入ったフレーム + 91
地上で操作できるフレーム = 横の土管に入ったフレーム + 282
```

入力、土管の上での位置や速さ、21 フレームの格子のどれにもよらない（それぞれの処理は入力を読まないか
上書きする。21 フレームの格子で待つ処理は、この 2 つの切り替えでは飛ばされる）。何もしないフレームを
はさむと、ちょうどその分だけ遅れる。一時停止は長くするだけ。

### 3. 地下の部屋（459 → 570）: 570 より前には入れない

入るのに必要なこと（コードから）:

- 横の土管には、入口の前の床で入る。早くても、そこに着地するフレーム。空中で入口の上の部分にぶつかると止められる。
- その床へは、レンガのかたまりの右端を上から越えて落ちるしかない。落ちるのは 1 フレームに 4 ピクセル以下なので、
  着地は右端を越えた最初のフレームの 12 フレーム以上あと。TAS は 558 で越えて 570 で入る。なので 569 に入るには
  557 で右端を越えている必要があり、それは TAS より 592/256 ピクセル（2.31 ピクセル）先。

557 フレーム目の上限（全部の入力について）:

1. 天井からの落下は入力によらないので、床に着くのは 493。最初のジャンプは 494。
2. 足がかたまりの上面より低いあいだは、角より左にいないといけない。当たると速さがほぼ 0 になる。かたまりに乗る前の、
   低い最後のフレームを `s` とする。TAS は `s` = 504 で、当たる位置の 15/256 ピクセル手前。
3. 1.5625 ピクセル／フレームより遅く跳ぶとき: `s` から [空中の速さの上限](../Theorems/AirCap-ja.md) が使える。全部の
   跳ぶ速さと A の押し方（測った）で、いちばん早い組（`s`、かたまりに乗るフレーム）は (504, 511)（TAS）と (505, 510)。
   ほかは乗るのが遅い。定理から `s` から 557 までは 121.75 ピクセル以下。なので 557 に TAS より先に行けるのは 527/256
   ピクセルまでで、65/256 ピクセル（0.25 ピクセル）足りない。
4. 1.5625 ピクセル／フレーム以上で跳ぶとき: 速く上がるが、`s` は跳んでから 8 フレーム以上あと。500 より後に跳ぶと、
   角から最高速で走っても間に合わない。500 までに跳ぶ場合は、459 から全部の入力で横の動きのフレーム `hstep` を
   たどるプログラムで調べた。どれも 8 フレームのあいだ角より左にとどまれない。
5. `s` で角に当たると速さがほぼ 0 で、8 ピクセル以上足りない。跳ぶ直前に床で当たる場合（覚えている速さの絶対値が
   消えないので、速いジャンプになる）も、3 ピクセル以上足りない。

状況: 3 の上限は Lean の定理。ジャンプの表はエミュレータで測った。4 はモデルの上のプログラム。入る条件はコードから
読んだ。合わせる部分は足し算で、Lean にはしていない。`hstep` は 460〜557 の全部のフレームで TAS と一致する。
大きいマリオでも、角での判定の高さは同じなので、上限は同じ。

### 5a. 地上での加速（852 → 892）: 旗の範囲に早く届かない（エミュレータでの確認）

- 852 の TAS の状態から、40 フレームのあいだ全部の入力を、本物のフレームでたどった（同じ状態はまとめ、
  ポテンシャルの上限で、もう追いつけない状態を捨てる）。892 フレーム目に TAS より先に行けるのは、多くて
  144/256 ピクセル。
- 892 以降は、最高速の上限から 1 フレーム 2.5 ピクセル以下。TAS はここでも上限どおりで、損は 980 フレーム
  目の 16/256 ピクセルだけ。なので 1085 フレーム目に TAS より先に行けるのは、多くて 160/256 ピクセル。
- 旗をつかめる範囲に入るには、1085 フレーム目に TAS より 528/256 ピクセル先にいる必要がある。なので
  1085 までには入れない。
- 前提: 捨てた状態が本当に追いつけないことは、開けた場所でのポテンシャルの上限による。

### 5b. 旗をつかんで城に入る: 城に入るのは 1218 より前にはならない（エミュレータでの確認）

旗のまわりの仕組み（コードから）:

- 旗に触れるのは、マリオの右側が旗の柱に 3〜6 ピクセル入る 4 ピクセルの範囲に、旗の土台より上の高さでいるとき。地面の高さで走ってくると、
  その手前で土台のブロックに止められる。
- 上昇中に土台に近い高さで触ると、旗をすべり降りずに、その場で終わりの処理に入る。城に入るのは
  **触ったフレーム + 126**。それ以外で触ると、旗が下りきるのを待つので、約 39 フレーム遅い。

1217 以前に城に入るための必要条件（式で）:

1. 1091 以前に、上昇中で土台に近い高さのまま、旗の範囲に入る。
2. そうなれるのは、地面から跳んで 2〜3 フレーム目だけ。1.5625 ピクセル／フレーム以上で跳ぶ道は、地面で土台の横に来た時点で
   速さが 0 にされるので使えない。なので、土台の横の地面に上から降りてから、小さく跳ぶしかない。
3. それには 1087 までに着地が要る。落下の最高速では 1 フレームにちょうど 4 ピクセル落ちる（最高速で端数が
   0 にされる）ので、1084 フレーム目に地面まで 12 ピクセル以内にいないといけない。

確かめたこと: 1084 フレーム目の状態（まだ土台に触れていない）の高さ（13 通り）、横の位置（TAS より 1 ピクセル
後ろから 160/256 ピクセル先まで、10 通り）、向き（3 通り）を変えた 390 通りの全部から、8 通りの入力で 8 フレーム
を全部たどった。1217 以前に城に入れるものはなかった。

TAS の細かい技: 土台の横で左右同時押しをすると、右がふさがっているので左を押した扱いになり、進む向きが左に
なる。すると土台からの押し戻しが右向きになり、旗の範囲にとどまれる。

調べていない着き方: 1084 での落下が最高速より遅い場合、横の速さが最高速より遅い場合、左だけを押す入力。

### 城から 1-2 まで: 式で分かった（コードから）

```
L = E + T + D + 107 + ((c − T − D) mod 21)
  E: 城に入ったフレーム   T: 残り時間（旗に触ったときから止まっている）
  D: 33（花火なし）       c: そのときのインターバルタイマーの位相
```

最後の待ちは 21 フレームごとの格子に揃えられる。TAS は格子のちょうど上で待ちを始めるので、20 フレーム余分に
待っている。城に入るのが 1218 なら 1748、1217 なら 1727（21 フレーム早い）。

## まとめ

```
1-2 の開始 ≥ 1748
  ⟸ 城に入るのが 1218 以降                     （城から 1-2 までの式）
  ⟸ 地上で操作できるのが 852 以降、かつ 5a と 5b
  ⟸ 横の土管が 570 以降（+282）                 （区間 3）
  ⟸ 地下で操作できるのが 459 以降（+91）
  ⟸ 土管が 368 以降                              （区間 1）
```

各段の時刻が遅れれば、その先も同じだけ遅れる（遅れて着くと得をすることはない）ことも前提にしている。
残っているのは、5b に「調べていない」と書いた部分。

## 再現

TAS の映像ファイル（fm2）を用意して、`git/` で:

```
.lake/build/bin/smbrta tas-trace FM2                    # 道筋と、上限との比較
.lake/build/bin/smbrta tas-seg FM2 A B                  # A〜B フレームの位置、速さ、高さ
.lake/build/bin/smbrta tas-insert FM2 AT K              # AT に何もしないフレームを K 個はさむ
.lake/build/bin/smbrta seg-search FM2 852 40            # 5a の探索（10 分以上）
.lake/build/bin/smbrta end-poke FM2 1084 Y DX FD 8      # 5b の 1 通り（Y: 高さ、DX: 横のずれ、FD: 向き）
.lake/build/bin/smbrta room-bound FM2 459 493 557 CX CY WLO WHI TX
    # 地下の部屋: ジャンプの表と 557 の上限。CX, CY: 角（y ≥ CY のあいだ x ≥ CX で当たる）。WLO..WHI: 落ちてきて
    # かたまりに乗る高さ。TX: かたまりの右端を越える x。どれも部屋のブロックと当たり判定のコードから読む。
```
